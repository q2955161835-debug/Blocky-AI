## 用户希望采用的方式

前8分钟保留部分已经准备好的细节，让后7分钟更容易围绕熟悉内容追问。辅导明确谈到这种“留空”方式，也提醒了评委可能不问的风险。

痛点本身是理解项目价值的前提，建议用一个具体任务和30—45秒讲清，不全部省略。可以不在主讲展开痛点调查方法、样本来源、对比过程，但不能暗示自己已经完成尚未做过的调研。

每个预留点应独立满足：主讲结论已有依据；展开内容真实；评委不问不影响主线；能回答至少两层追问。先准备三处即可，避免每页都故意制造缺口。

## 三个优先预留点

### 1. 模型改作品，怎么防止改坏？

主讲引导：“构建助手经共享CLI协助搭建，改动保留结构校验、差异和撤销边界。”

30秒回答草案：构建助手默认经CLI执行当前项目任务，启动时不增加额外批准窗；共享领域层仍检查结构、基线和权限，文件差异与撤销按工具契约保留。需要审批的实际动作仍须授权，文件版本冲突也不会被自然语言任务绕过。

60秒展开：举一项真实候选修改，展示拒绝、接受和撤销的结果；解释画布已变化时旧候选被拒绝。权限声明接受与实际工具运行审批不同，文件撤回也不是跨系统副作用的万能回滚。

连续追问：撤销能恢复已发邮件吗？答：已发生的外部动作需要具体补偿或人工处理，不能承诺都能回滚。这个例子要用实际演示证据，不声称本次运行过发邮件。

可用于追问的证据：修改前后差异、拒绝/接受/撤销结果和安全边界。没有现场截图时先标待制作。

### 2. 带引用回答，怎么知道它不是胡编？

主讲引导：“回答可以回查资料来源，运行轨迹能看到检索与执行。”

30秒回答草案：资料进入可检查的解析、分段、检索链路，回答附可定位出处，引用约束检查来源有效性。证据不足时应说明不足或澄清。我们把检索和评估工具做进产品，但不能承诺大模型永远正确。

60秒展开：展示一个有资料支持的问题与一个无资料问题，回查原文，区分引用存在和回答语义正确；解释版本绑定测试集与逐例评估。实际演示结果需先跑过再填。

连续追问：检索命中率是否代表学生学得更好？答：不是同一指标，课堂效果需要真实教学对照与样本，目前不能用工程测试替代。

可用于追问的证据：问题、引用原文、回答、错误类别、测试范围。不要把验收阈值当作本次现场或所有数据集成绩。

### 3. 为什么要用积木，现成聊天工具不就够了吗？

主讲引导：“用户可以看到角色、知识、工具和权限，也能修改并追踪执行。”

30秒回答草案：目标任务需要用户理解和调整作品结构。积木让模块、条件和权限可见，运行轨迹把结构与实际执行连接起来；构建助手能协助搭建，用户仍可审阅修改。这是我们的产品取舍，易学程度还要用真实用户测试验证。

60秒展开：用同一个带引用助教任务，指出哪些结构用户可以独立修改、哪些失败可以定位、哪些能力需要授权。讨论学习过程的可见性，而不泛泛宣布所有聊天产品没有工具或工作流。

连续追问：你们做过学生对比试验吗？答：目前没有可作为真人教学成效的证据，下一步按同任务测首次成功时间、独立修改能力、解释正确率和复现情况。

可用于追问的证据：同一任务的结构和轨迹，拟开展用户测试的样本与指标。竞品优劣结论需另外实际比较。

## 还应准备的问题

| 问题 | 回答准备方向 |
|---|---|
| 客户痛点是真需求吗？ | 已有具体任务观察与尚未开展的访谈分开，不能用自己的推测冒充教师意见 |
| AI在哪里？ | 具体展示检索、生成、工具决策、可观察运行及其约束，不只罗列模型名字 |
| 成本如何控制？ | 实际模型用量、预算和估算公式，区分测试Token与每用户成本 |
| 商业模式和定价？ | 个人软件免费与机构服务、托管积分分别说明；99/199/999元为咨询拟案，实际单位成本及企业方案仍须验证 |
| 是否已进入课堂或有收入？ | 没有材料就直接说明验证阶段，给出可执行试点计划 |
| 能离线用吗？ | 本地后端及具体能力条件，不能承诺所有云模型和服务离线工作 |
| 为什么不是必须用内置助手？ | CLI允许能执行命令的外部开发Agent参与，保留既有工作方式；自定义积木提供两类能力扩展 |
| 开源与自主创新怎样区分？ | Blockly、Tauri、Pi等依赖与自身作品格式、语义编译、权限及工作台集成分开说明 |
| 什么做完，什么还没做？ | 直接引用06完成表和规划边界，选现场已经实测的内容展示 |

遇到完全未准备的问题，先确认评委关注的是技术、用户或商业哪一层。回答已知事实，说明未知或未验证部分，给出可检验下一步，避免编造数字。两名成员的技术/应用/商业分工后续按实际擅长确认。

评委没问预留点时，不必把全部备份内容强塞回主讲。只在结束或相关追问中补一句关键边界；不要因为等待提问而丢掉决定评分的主讲信息。
