# Blocky 宣传片试片独立视听制作验收

角色：面向普通创作者的独立视听制作验收人员，从观众角度判断宣传片，不参与镜头、代码、音轨、素材或时间线实现。沿用用户已确认的三类范围：创意节奏、视觉连续性、播放与来源；本次仅按用户纠正修订具体维度，不新增审批环节。

当前核心：Agent 开发中的代码审查转成积木审查，降低理解和修改门槛，兼顾入门学习与专业场景；直观实时观察运行。后段可示意 Codex / Claude Code 通过 CLI 开发。旧片荒诞剧情及其升级次数不再作为通过标准。以下标准用于后续冻结成片，本模板不给尚未完成 v3 的结论。

## P01 · 观众迅速理解审查转变与使用价值

场景：第一次按正常速度观看宣传片，理解 Agent 开发为何可以从读代码变为看积木。

- 前几秒直接解释或展示“代码审查 → 积木审查”的转变；观众能指出正在审查什么，以及积木如何帮助理解。不得用长段与产品无关的剧情延迟核心信息。
- 同一开发意图、判断或问题在代码与嵌套积木间有可辨识对应；观察关系、发现问题、调整积木及检查结果的因果清楚。只将代码文字换成彩色块，不足以证明审查门槛降低。
- 入门学习价值和专业使用价值围绕同一核心展开：可看懂、可检查、可修改、可观察运行；避免为了覆盖场景堆砌无因果的功能清单。片中表达的收益不得超出画面及来源能支持的程度。
- 运行观察与前面的审查/修改有清楚联系。若后段出现 CLI 开发，观众能理解其如何接续作品开发，而非突兀加入厂商品牌或终端截图。
- 节奏给关键对应关系、修改目标与结果足够的阅读和理解窗口；字幕辅助画面，不以字幕存在、无空镜或文件解码正常推导吸引力通过。
- 用户本轮新增审美返修：采用用户指定蓝色Codex伙伴和棕橙Clawd，与Blocky形成持续协作动画；有可辨识的笑点铺垫、动作/反应和兑现，避免整片依靠大字广告卡推进。幽默需围绕Agent搭建、审查、运行或CLI协作，不能重新引入延迟核心的无关支线。检查实际运动，漂亮首帧或网络梗文字不能单独推导幽默通过。
- 失败判据：开场核心不明；主要时长被无关剧情占用；代码与积木对应关系看不懂；审查/修改/运行因果错位；产品价值仅靠口号；用户明确否定核心表达而报告仍判通过。
- 证据：标注核心首次出现、代码与积木对应、修改及运行反馈、场景价值与收尾的实际时间点。记录观察者、播放方式/速度、观察区间及是否获得实际声音；正常速度连续观察或针对指定冻结版本的明确用户观看反馈才能支持节奏裁决。
- 静态抽帧可核对文字与内容位置，不能证明完整实时节奏、真人听感或用户审美。缺少必要观察证据的维度明确记未执行或阻塞，不代签通过。

## P02 · 嵌套积木、运行高亮与轨迹关系可读

场景：观众从代码审查进入积木审查，并观察同一作品的执行过程。

- 积木展示遵循 Blocky 的 Scratch 式嵌套结构：容器、顺序、条件/循环范围及字段关系与所示作品一致。不得将积木重画为通用节点连线工作流，也不得用连线图替代真实嵌套关系。
- 被检查或修改的积木、字段、所在容器与上下文可辨；镜头移动、缩放和高亮不能遮掉判断所需关系。代码与积木的对应若为示意，仍须保留一致的语义与层级，不能将不相关片段伪装成同一作品。
- 运行段检查高亮积木、轨迹事件、调用/输出及其顺序是否对应。高亮应让观众辨认当前步骤，轨迹应对应正在解释的动作；不能只播放随机闪烁或无关日志来暗示真实执行。
- 若演示条件、循环、停止或失败，仅按片中出现的场景核对相应状态与轨迹，不扩大到全产品回归。示意运行的动画也须内部一致，但不能因此称其为真实运行。
- 角色/界面及多来源片段的视觉衔接不打断理解；主要字段、运行目标、轨迹与字幕在正常速度具有可读窗口。区分有意裁切和关键信息误裁切，记录具体时间。
- 三角色动画核对Codex圆头屏幕脸、Clawd方眼四短腿轮廓、Blocky双凸点积木的区分和连续性；关键协作/放大镜/积木递交不穿模、不无故换角色，实体支撑、接触阴影、镜头运动与材质共同提供清楚的3D体积。仅验片中采用范围，不要求等同官方原图或扩大到厂商品牌认证。
- 失败判据：积木被画成通用连线图；嵌套层级/执行顺序错误；修改对象不可读；高亮与所示事件错位；无关轨迹被当作对应证据；转场遮掉关键因果；明显空帧或正常速度无法看清主要信息。
- 证据：关键画面的作品/界面来源，嵌套关系与字段定位，运行高亮和轨迹对应的时间点或事件标识。对镜头边界及高风险动作可定向加密抽帧；连续运动和显示窗口裁决需明确正常速观察证据及限制。P01 判信息价值与节奏，P02 判画面关系和呈现，不重复计同一问题。

## P03 · 播放、真实来源与示意边界

场景：用户打开最终成片，并能定位其时间线、产品画面与开发示意的来源。

- 独立读回最终 MP4 的 SHA256、时长、画幅、音视频规格并与冻结清单对应；全文件解码无错误。以本轮冻结规格为准，正常时间基/padding 不机械计作失败。
- ChatCut 多源可编辑时间线应有项目/时间线版本、素材与片段对应记录；最终成片绑定具体导出。仅提交平面成片不能替代本轮要求的可编辑时间线。只读检查本片直接范围，不修改时间线或扩大产品回归。
- 按片段区分真实产品界面采集、真实运行事件、预设演示和用户允许的虚拟信息。真实界面只能证明界面出现，不能单独证明模型调用、桌面 Runtime 或作品运行；预设动画/轨迹不冒充真实事件。
- 真实修改须核对可见字段或结构、底层读回、来源声明与最终采用一致；操作发生不等于修改已生效。真实运行须有同一作品/执行来源、事件顺序及画面时间的可核对证据；来源缺失不得写真实运行通过。
- Codex / Claude Code 的虚拟终端、任务文字或 CLI 开发信息可按用户允许用于示意，须在来源记录中明确示意范围。仅出现 CLI 字样、品牌或终端输出，不构成该厂商官方集成、认证、插件接入或实际执行证据；不得据此扩大宣传声明。若声称实际执行，另核对本轮真实命令/过程及对应产物。
- 若采用本机 MiniMax 或其他生成素材，逐段记录任务 ID、完成/fetch 状态、候选文件及采用区间，实际长度如实写明；失败或弃用保留事实，不套用旧片 ID 或未采用候选。
- MP4 不应包含有效密钥、账号隐私、聊天历史、开发规则或内部验收材料。对可见文字和源清单做有边界的检查；示意终端只用虚构或已允许公开的信息，不把该检查称为全面隐私/渗透审计。
- 证据：独立 ffprobe、全文件解码、SHA256、时间线/素材读回、界面修改断言、真实运行事件对应及虚拟信息清单、采用素材回执。声音检验说明方法：波形/响度/解码不等于真人听感，未实际听到不得声称音乐或声画节奏已主观确认。

## 报告与结论边界

等待最终成片冻结清单后由独立角色统一验收；不检查未完成 v3，不预先签结论。报告含汇总表格与详细报告，按用户功能一级、使用场景二级组织，列涉及模块、L2、结果、问题风险及证据限制，结论仅用项目允许值。关键维度缺少必要证据时不得写整体通过。

旧片失败与用户否定保持在原历史报告，不抹去也不复用其创意通过依据。新报告路径由本轮冻结交付指定。验收通过不等于用户审美确认、公开发布、main 合并或 GitHub 推送授权；此处说明结论边界，不增加新的审批流程。
