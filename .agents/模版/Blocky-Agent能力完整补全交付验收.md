# Blocky Agent 能力完整补全：独立验收角色

状态：2026-09-30 用户已确认。角色：采购并使用 Blocky 的桌面创作者与 Agent 系统验收工程师，未参与被验收部分实现。最终/复杂功能使用最新版 sol + medium；独立权限与隐私专项使用不低于 sol + xhigh。角色名称不替代以下检查要求。

## 检查维度

1. 从用户安装和配置开始，在普通包搭建资料助手、工具办事助手和规则/学习模型协作助手；检查入口可发现、资源可替换、结果可核对、失败可恢复。
2. 通过 CLI 执行共享能力，读取 Schema、状态与错误；必要 GUI 证据覆盖资源配置、文档/分段/引用预览、积木组合、结果和原生文件交互，不重复全套 CLI 业务验证。
3. 核验真实执行：工具由实际模型选择，解析处理真实二进制文件，嵌入/重排/分类使用真实推理；确定性夹具、离线本地模型、远程 API 三种证据分别标明。
4. 从用户数据所有者视角验证来源删除/撤权、索引迁移、记忆隔离、Skill/MCP 权限、子 Agent 继承、媒体存储、取消和恢复后的副作用状态。
5. 核验旧项目和既有工作区、默认模型、画布、构建助手、运行轨迹、审批与 RPA 直接影响范围；核对普通包来源、许可证、秘密扫描和退出清理。

## 失败判据

- 只有 Schema、菜单、资源字段或测试替身，普通包没有对应真实执行路径：相关项不能通过。
- 将顺序调用误报为自主工具循环，将规则评分误报为神经重排，将模拟/分类接口误报为 JEPA：不通过。
- 新端点、MCP、Skill 或子 Agent 绕过 Host 权限，秘密进入项目/前端/日志/最终包，用户 PTY 被接管：不通过。
- 索引签名不匹配仍继续查询、来源撤权仍返回内容、共享记忆泄漏、取消后发起新动作、恢复重复已完成副作用：不通过。
- CLI 缺少已交付共享功能，错误无可定位来源/恢复说明，旧项目迁移丢失编辑事实：相关项不通过。
- 缺少实测后端、来源提交或普通包证据时保留阻塞/未执行；不能用文档、旧版本或 API 配置存在替代结果。

## 证据要求与结论

- 每项记录源码提交、包标识、用户场景、实际步骤、输入类型、预期/实际结果、负例以及最少必要的结构化记录或截图。
- API 只记录 Provider、实际模型、请求/响应 ID、时间、用量及稳定结果；本地推理记录模型版本/工件哈希和实际后端。没有用量则标未提供，不编造。
- 依照本次任务的 17 项验收分工，一条证据可被引用；不重复测试或扩展到无关模块。最终记录由独立 Agent 签发，主 Agent 不代签。
- 最终结论只用项目允许的六种状态。有条件通过默认不合并或发布；本轮全量交付需要全部必需项通过。
