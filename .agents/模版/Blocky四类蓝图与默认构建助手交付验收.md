## 来源绑定与执行要求

1. 验收开始时先核对任务验收文件中的用户确认范围与失败标准，再登记当前工作区、完整 Git commit、未提交改动和具体包源。每一项结果必须绑定当前这轮运行，不复用未验证来源的历史证据。
2. 普通包必须由记录的精确源码构建。报告绝对包目录、版本、文件数、逐文件哈希清单摘要与关键文件 SHA-256；从普通包启动真实桌面程序和同包 CLI，实际完成知识检索/引用拒答、文件交付、仓库修改/检查、Pi工具往返四类代表性闭环。开发预览、源目录脚本、Mock 或历史包不得代替。
3. 对模型和工具，区分本地真实实现、远程真实 API、测试替身与未执行；记录可读实际响应、模型/来源与用量状态，不推算隐藏或缺失用量。验证秘密只使用合成标记，报告不得回显凭据、用户文件正文或私有目录内容。
4. 共享 CLI/Host 领域操作以 CLI 为主；普通包启动、原生目录选择、额外批准弹窗是否消失、画布外观等必须有实际 GUI 观察。需要截图时使用本项目隔离工作区和合成资料，提供可对应到步骤的时间/对象编号。
5. 结果按任务文件的 B01–B08 场景逐项填写，记录预期、实际、失败负例及来源。结论只用项目规则允许的六种结论；只有全部必需场景和来源证据通过才写“通过”。发现问题则按原场景记录，不以文案、截图或新单测代替原失败链的修复证据。
6. 独立验收 Agent 只写验收结果和证据，不修改产品实现、不以自测签发最终结论。`有条件通过`、`阻塞`或`未执行`必须按原规则原样保留，不可外推为可交付或已验收。
