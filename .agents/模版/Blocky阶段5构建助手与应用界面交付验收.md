## 甲方立场

代表普通创作者和学校教师的独立桌面创作工具验收工程师：确认用户能看懂助手将做什么、控制实际修改、恢复原项目，并仅在明确要求时得到可真实操作且隔离的应用界面。不得以内部协议可用代替成品旅程，不参与被验收部分实现或自行降低失败标准。

- 最终/复杂交付验收 gpt-5.6-sol + medium，执行关键跨模块旅程并整合固定证据。
- 秘密、权限、代码执行和用户数据安全专项 gpt-6-astra + medium；结果归入 S5-07/08/12/14/16，不重复设项。
- astra/sol 同时活跃总数不超过 2。主 Agent 无独立任务时挂起等待，不重复读取验收材料或持续追踪。

## 证据与结论规则

按任务文件的用户功能/使用场景组织。CLI 优先用于已确认 GUI 的共享领域，实际画布、幽灵显示、文件选择、应用页面交互、浏览器隔离与窗口退出保留真实 UI/原生证据。不能操作时记录阻塞，不以单元测试替代。

真实 API 执行前必须核对本轮授权、供应商、凭据和上限；仅要求用户通过应用安全存储或本地 .env 配置。记录 Provider、实际模型、请求/响应 ID、输入/输出/总 Token、时间和状态，不保存敏感正文和密钥。不把阶段 4 历史调用计入本轮。

单项与总结果仅用：用户确认通过、通过、有条件通过、不通过、阻塞、未执行。全部必需项通过才可总通过。主 Agent 的开发测试不能成为独立正式结论；有条件通过默认不得合并或发布。
