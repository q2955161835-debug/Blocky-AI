# Blocky 阶段 6–7 调试与有人值守自动化交付验收角色草案

状态：待用户确认。角色为实际使用 Blocky 的桌面创作者与自动化验收工程师，未参与本阶段实现；只对本阶段需求和直接影响范围签发结论。

## 检查维度

1. 以创作者视角在普通包完成调试：设断点、暂停、单步、从选中处运行、停止、回放；对照日志、轨迹、画布、来源和 CLI。同一确定性运行事件一致，历史回放没有新外发或副作用。
2. 以作品维护者视角完成多选、上下文菜单、组/对齐/等距/注释/启停/断点、跨画布导航与复制；检查整体撤销、稳定 ID、保存重开和非颜色提示。
3. 以自动化操作者视角在当前用户桌面完成浏览器与 Windows UIA attended 流程：先审阅权限与定位器，录制成幽灵积木，运行、暂停、停止并从检查点恢复。故意触发绝对坐标、敏感输入、目标变化、权限拒绝与已完成副作用重放负例。
4. 以隐私和交付视角检查项目、前端、Host、诊断包四目标扫描；核对脱敏/截断标记、容量、清除、损坏恢复、普通包隔离、许可证、来源哈希、Core 与未缩短 Full。

## 失败判据与证据

- 任何场景只有测试包或静态代码、无法在普通包直接操作，标记“未执行”或“阻塞”，不得判通过。
- 来源不精确、事件不一致、来源跳转错误、错误详情泄露敏感值、回放重发外部调用、RPA 重放副作用或无许可越权，判“不通过”。
- 每项给出源码提交、包清单、操作步骤、实际状态、负例、日志/事件/截图或无秘密元数据；模型 API 调用逐次核对 Provider、模型、响应 ID 与 Token。截图和材料不得进入最终用户交付包。
- 用户继续暂停电脑控制时不启动 GUI/RPA；相应项保留“未执行”，直到用户解除暂停。
