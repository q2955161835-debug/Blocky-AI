## 一、产品与技术

<a id="q01"></a>
### Q01．用一句话说明Blocky是什么，主要服务谁？

对应：P1—3；计划书第3—4页，执行摘要、1.1节。

> Blocky是一款用积木创作智能体的软件，用户可以组合角色、模型、资料、记忆和工具，再查看和修改运行过程。我们优先验证教育场景，让学生从得到答案走向设计作品；专业创作者也共享这套底座。当前Windows已有阶段成果，课堂效果和商业采用还需要真实使用验证。

继续追问：[Q21 教学效果](#q21)、[Q54 专业与企业拓展](#q54)。

<a id="q02"></a>
### Q02．故事分支只是条件判断，为什么说这是人工智能产品？

对应：P4—7；计划书第4—6页，1.1节。

> 森林和花园的对照是确定性规则，用来让学生看清一个修改怎样改变路线。生成式部分则把角色、任务、资料和路线交给模型，组织回应或题目。Blocky把规则与模型能力组合成可修改作品。我们已经验证规则对照，但完整故事教学仍是设计，不能把固定分支输出说成模型生成效果。

继续追问：[Q26 关键词判断](#q26)、[Q07 四类能力](#q07)。

<a id="q03"></a>
### Q03．为什么采用嵌套积木，而不是普通节点连线？

对应：P3、P12、P15；计划书第4—5页，1.1节。

> 我们采用类似Scratch的嵌套结构，把条件、循环和任务步骤直接放进作品层级，让用户沿着结构阅读和修改。教育入口可以先展示少量部件，专业使用再展开更多能力。它提供了一种可读的创作语言；哪种表达更适合某个年龄和任务，还要通过同任务操作比较，不能只凭界面形式下结论。

继续追问：[Q17 竞品比较](#q17)、[Q22 年龄与入口](#q22)。

<a id="q04"></a>
### Q04．积木怎样变成真正能运行的智能体？

对应：P15—17；计划书第4—5、8—9页。

> 用户用积木或文字描述任务，作品结构先经过编译和校验，再由共享运行内核按步骤执行，调用获准的模型和工具。执行事件保留对应积木的位置，所以用户能从实际步骤回到画布检查和修改。界面、构建助手和命令行入口共用作品能力，密钥与工具范围由桌面端管理。

继续追问：[Q08 运行映射](#q08)、[Q09 权限控制](#q09)、[Q10 修改保护](#q10)。

<a id="q05"></a>
### Q05．目前到底完成了什么，哪些还只是规划？

对应：P10—12、P16、P19；计划书第3、8—9、22页，表5、表21。

> 当前已有Windows测试安装包、四类可改造蓝图、空白作品、保存重开、构建助手、开放命令行入口和运行定位等基础。班级作业后台、完整自定义积木编辑与分发、托管计费、独立应用导出和多端仍在建设。源码公开也是后续发布方向，公开安装包并不等于源码已经开放。

<a id="q06"></a>
### Q06．构建助手和作品Agent有什么区别？

对应：P7、P11、P16；计划书第5、8页，表2、表5。

> 构建助手帮助用户搭建和修改作品，它读取当前项目上下文，把自然语言需求落实到积木结构。作品Agent则按照已经保存的角色、任务和工具安排实际运行，比如出题或整理资料。前者主要改变设计，后者执行设计；用户仍要检查改动和运行结果，不能只看助手说已经完成。

继续追问：[Q10 修改保护](#q10)、[Q19 自然语言创作](#q19)、[Q36 额度归属](#q36)。

<a id="q07"></a>
### Q07．模型、记忆、知识和工具分别起什么作用？

对应：P6、P12；计划书第4—6、8页。

> 模型负责理解任务和组织回应，记忆保留需要延续的对话信息，知识提供可查询的资料，工具完成明确的计算或文件操作。例如海底向导可以记住上次目的地、查资料，再用统计工具检查长度。教学设计中一次只增加一种能力，比较结果并说明理由；这个课堂安排还需要试用验证。

继续追问：[Q27 海底向导](#q27)、[Q23 学习观察](#q23)。

<a id="q08"></a>
### Q08．运行轨迹是不是把模型的思考过程展示出来了？

对应：P7、P11、P15—17；计划书第4—5、7页。

> 我们展示的是实际执行事件，例如走了哪个分支、调用了什么工具、出现了什么结果。编译时保存结构与积木位置的对应关系，运行后可以定位回相关部件。它帮助用户核对设计和动作，不等于展示模型内部思维，也不能单靠轨迹证明回答正确；输出内容仍要根据资料和任务检查。

继续追问：[Q04 技术架构](#q04)、[Q59 回答可靠性](#q59)。

<a id="q09"></a>
### Q09．智能体调用工具或修改文件，怎样限制权限？

对应：P15、P17；计划书第5、9、16页。

> 工具和资源需要明确声明，桌面端在调用时检查允许的能力和范围，文件操作受用户选择的工作目录约束。积木结构也让用户在运行前查看资料、工具和权限，运行后核对实际动作。这些机制用于限制越界和便于回查，不能保证任意作品绝对安全，开放新工具还需要核对具体版本和场景。

继续追问：[Q10 修改保护](#q10)、[Q30 学生信息与课堂](#q30)、[Q59 可靠性](#q59)。

<a id="q10"></a>
### Q10．构建助手会不会覆盖我的新改动，改错以后怎么办？

对应：P11、P15；计划书第4—5页。

> 系统应用修改时会核对作品状态，避免用针对旧版本的方案覆盖用户的新修改，同时检查相关资源和权限。有效的作品修改进入编辑与撤销记录，用户可以继续检查和调整；项目也能保存副本、重开。这里的撤销指作品编辑，不表示已经发生的外部文件或业务动作都能自动回滚。

继续追问：[Q09 权限](#q09)、[Q29 副本与教师恢复](#q29)。

<a id="q11"></a>
### Q11．“真实Pi代码积木化”具体是什么意思？Codex等也完成了吗？

对应：P16；计划书第3、8、22页，表5、表21。

> Pi蓝图以真实上游Agent核心为基础，把智能体循环和相关能力接入Blocky的作品与运行体系，让用户能够展开查看和改造。它不是只借用Pi名称，也不是声称我们独立发明了上游核心。Codex、DeepSeek Harness和Hermes等专业架构蓝图是后续方向，需要逐一核对许可、结构和实际运行。

继续追问：[Q15 自主贡献](#q15)、[Q12 外部Agent入口](#q12)。

<a id="q12"></a>
### Q12．开放CLI是不是任何Agent都能接入，“零迁移”是不是任意代码都能转换？

对应：P16；计划书第5、8—9页。

> 能执行命令行的开发Agent，可以通过Blocky的接口查询、修改、校验和运行作品，所以用户有机会保留原来的开发工具。计划书中的零迁移主要指不必更换开发Agent，不表示任意代码都能自动完整转换。实际接入仍要核对命令覆盖、作品结构、资源和权限，外部Agent的费用也按它自身服务结算。

继续追问：[Q13 自定义积木](#q13)、[Q36 托管额度](#q36)。

<a id="q13"></a>
### Q13．自定义积木能扩展什么，现在能用到什么程度？

对应：P16、P19；计划书第5、8—9、22页。

> 规划有两种形式，一种把常用积木结构封装成可复用部件，并能展开修改；另一种用代码扩展算法、工具接口或业务能力，再声明输入输出、依赖和权限。当前已有受控工具与转换基础，完整编辑、封装和社区分发仍待建设。扩展也要遵守运行限制，不能把未声明的副作用藏进积木。

继续追问：[Q09 权限](#q09)、[Q56 应用导出](#q56)。

## 二、创新点与竞争

### Q15．用了Blockly、Tauri和Pi，你们自己的创新在哪里？

对应：P15—17；计划书第4—5、7、16—17页。

> Blockly提供积木编辑，Tauri提供桌面基础，Pi提供Agent循环，我们会明确说明这些来源。Blocky的工作是把作品格式、积木语义、编译校验、运行定位和受控修改组织成同一个创作过程。用户可以对照设计与实际动作继续修改，这是我们提出的积木审阅价值；其使用优势还需要真实任务比较。

继续追问：[Q18 壁垒](#q18)、[Q57 开源与权利](#q57)。

### Q16．为什么不直接用ChatGPT或代码助手，非要用Blocky？

对应：P2—3、P15；计划书第4—5、7页。

> 直接对话适合获取答案，代码助手也能帮助开发。Blocky关注的是用户怎样继续理解和维护智能体，把角色、资料、步骤和工具组织成可修改作品，再核对实际运行。例如学生改一个条件后能比较路线，专业用户能检查工具调用。具体任务是否值得使用Blocky，要比较理解、修改和复用成本。

<a id="q17"></a>
### Q17．与Scratch、AI积木工具和Dify相比，优势有证据吗？

对应：P14—15；计划书第7页，表4。

> 我们把这些工具作为同任务参照，不能只看公开功能就断言谁更强。Blocky重点检验的是Agent结构、可审阅修改和运行定位能否帮助用户理解、修订和复用作品。比较会使用相同任务、时间和帮助规则，记录准备耗时、修改和解释结果。目前还没有完成这种比较，不能报提升百分比。

<a id="q18"></a>
### Q18．大厂也能做积木，你们的护城河是什么？

对应：P14—17；计划书第7、16—17页。

> 积木外观和免费入口本身容易被复制，我们目前也不能宣称已有很高的长期壁垒。持续积累的方向是可执行作品语义、修改与运行的一致性、经过验证的蓝图和组件，以及教师复用与真实任务记录。竞争时需要用相同任务证明理解、可靠执行和维护成本的价值，而不是仅靠页面或模型名字。

继续追问：[Q15 自主贡献](#q15)、[Q58 风险与转向](#q58)。

<a id="q19"></a>
### Q19．既然自然语言就能搭建，积木是不是多余？

对应：P11、P15—16；计划书第4—5页。

> 自然语言是我们已有的创作入口，构建助手可以把需求落实到作品。积木保留的是搭建之后可检查、可修改的结构，用户能核对规则、资料和权限，再把运行步骤对应回部件。这样既能让助手帮助搭建，也能让人继续判断和维护；自然语言入口并不替代对作品和结果的检查。

继续追问：[Q06 两个助手](#q06)、[Q08 轨迹](#q08)。

<a id="q20"></a>
### Q20．学校已有免费工具，为什么要换？你们怎样降低采用成本？

对应：P8—10、P14；计划书第7、10—11页。

> 教师学习新工作台、准备资料和配置设备都会产生转换成本，所以我们不会要求学校一次重建全部课程。计划从一个可编辑作品和小范围活动开始，提供指南、配置与恢复支持，再观察教师第二次能否独立复用。若已有工具更适合任务，就应承认差异；是否采用取决于真实任务收益和准备成本。

继续追问：[Q29 教师复用](#q29)、[Q32 免费软件与服务](#q32)。

<a id="q24"></a>
### Q24．H0到H3是什么？老师帮了以后还能算自主完成吗？

对应：P6—7、P13；计划书第18—19页，表16。

### Q49．拿不到180万元怎么办？节约与高投入情景有什么区别？

> 三种情景都保留五人和五个研发订阅席位，变化的是工资、汇率、任务强度、采购与储备。首年覆盖目标分别一百四十、一百八十和二百九十万元。资金不足时，应缩小首期功能和试用范围，延后多端及经营配套，再重算排期；不能靠假设收入、免费劳动力或未知折扣，让原来全部承诺看起来仍能完成。

继续追问：[Q51 近期研发](#q51)、[Q58 风险与转向](#q58)、[Q50 敏感性](#q50)。

<a id="q50"></a>
### Q50．合作费、模型预付和保证金，为什么对资金需求的影响不同？

对应：计划书第16、18、27页，表25。

> 非退合作费是新增费用现金，还会按模型规则增加风险预留。模型额度预付是在付款时占用现金，后面使用应抵扣，不能再把同一用量费用加一遍。可退保证金主要是现金占用，不当费用计算风险。计划书把这些条件分开，确认合同与时点后再重算；延期回款也不能提前当成可用资金。

## 十二、术语口述速查与练习顺序

| 术语 | 可以怎样解释 |
|---|---|
| Agent | 按任务调用模型和获准工具的智能体 |
| 蓝图 | 可展开改造的起始作品，不是只能聊天的固定功能 |
| CLI | 命令行接口，让外部开发Agent操作作品 |
| API | 模型或服务的调用接口，产品请求按对应服务结算 |
