# Blocky 当前积木功能清单

整理日期：2026-10-03。本清单面向查阅、教学设计和竞品对照，依据当前源码与本机 CLI 目录读回，不代替功能验收。

本清单绑定 2026-10-03 的产品快照。2026-10-04 起始项目方向已更新；本页历史目录读回不代表旧软件起点仍在当前产品目录，当前规划见[四类起始蓝图](Blocky-四类起始蓝图.md)。

## 1. 当前范围

当前注册 **68 种积木、12 个专业分类**。产品版本为 `0.8.0`，积木目录版本为 `0.5.0`，两者不是同一个版本号。源码快照为 `1664cb82bfeeb6bdd4ffae0b1e2d28a7f00c6cc1`。

本机执行 `./blocky.cmd catalog list --limit 100 --json` 成功，读回 68 种；与8个源码目录文件逐项比较，稳定 ID 差异为0、重复 ID 为0。表格描述积木的设计用途及已存在的执行路径；依赖模型、资料、工具、权限或硬件的积木仍需正确配置。本次没有逐项运行68个场景，也没有重做普通安装包验收。

## 2. 逐项功能

### 2.1 触发与交互：3种

| 积木名称 | 稳定 ID | 功能与使用场景 |
|---|---|---|
| 收到问题 | `core.interaction.chat` | 声明聊天触发入口；用户提问后启动所属流程。 |
| 文本聊天入口 | `core.interaction.chat_entry` | 将聊天入口的可用能力与处理程序分开组织，适合具有明确内部结构的作品。 |
| 接受文本 | `core.interaction.accept_text` | 在文本入口处理流程中接收用户输入，供计算或回复使用。 |

### 2.2 智能体：2种

| 积木名称 | 稳定 ID | 功能与使用场景 |
|---|---|---|
| 智能体 | `core.agent` | 用角色要求与主体积木组织一个Agent，例如“只根据课程资料回答的助教”。 |
| 智能体容器 | `core.agent.define` | 定义具有名称的智能体容器，组织其成员、聊天入口和能力。 |

### 2.3 指令与上下文：1种

| 积木名称 | 稳定 ID | 功能与使用场景 |
|---|---|---|
| 补充指令 | `core.prompt.context` | 给后续模型请求追加文本要求，例如语气、格式、任务限制；不是知识库摄取或无限历史存储。 |

### 2.4 模型：4种

| 积木名称 | 稳定 ID | 功能与使用场景 |
|---|---|---|
| 组织回答 | `core.model.compose` | 使用所选模型资源组织回答；实际模式由资源与适配器决定，存在此积木不代表每次都调用外部API。 |
| 调用可用工具 | `core.reason.tool_loop` | 模型在显式提供的工具范围内进行多轮工具调用；限制轮数和输出Token预算。 |
| 英文候选评分（实验） | `core.model.score` | 使用锁定本地评分模型及规则，为英文输入选择候选标签；有阈值和回退标签。分数是相关性logit，不是概率，不是通用中文分类器。 |
| 添加项目图片 | `core.media.image` | 将已有项目图片绑定到运行上下文，核对媒体ID、哈希和版本；配合支持图片的模型使用，不负责生成图片。 |

### 2.5 知识库：8种

| 积木名称 | 稳定 ID | 功能与使用场景 |
|---|---|---|
| 查看资料来源 | `core.knowledge.source` | 查看知识资源的来源信息，确认要使用哪份资料。 |
| 预览解析片段 | `core.knowledge.parse` | 查看资料解析后的内容片段，帮助发现正文提取问题。 |
| 预览资料分段 | `core.knowledge.chunk` | 按分段长度与重叠长度预览切分结果，帮助调整资料颗粒度。 |
| 同步资料 | `core.knowledge.sync` | 将资料按配置摄取、同步到知识集合；受资源绑定与相关权限控制。 |
| 建立向量索引 | `core.knowledge.embed` | 使用指定嵌入模型建立向量索引，供语义检索使用。 |
| 查看索引状态 | `core.knowledge.index` | 查询知识集合索引状态，判断资料是否准备好供检索。 |
| 查找资料 | `core.knowledge.retrieve` | 根据用户问题检索知识资源，得到资料片段和引用；检索方式依资源配置。 |
| 检查并纠正检索 | `core.knowledge.correct` | 检索后通过模型判断证据相关性，必要时在次数上限内改写查询并重新检索；不保证一定找到答案。 |

常见组合：查看来源 → 预览解析/分段 → 同步资料 → 建立索引；问答时使用查找资料 → 组织回答 → 回答。资料管理与问答可以分为不同流程。

### 2.6 记忆：6种

| 积木名称 | 稳定 ID | 功能与使用场景 |
|---|---|---|
| 读取记忆 | `core.memory.read` | 按作用域和键取出记忆，例如之前保存的偏好。 |
| 保存记忆 | `core.memory.write` | 将输入或当前结果写到指定键；持久性取决于作用域及对应服务。 |
| 删除记忆 | `core.memory.delete` | 删除指定作用域中的记忆项。 |
| 搜索记忆 | `core.memory.search` | 通过查询和条数上限找到相关记忆。 |
| 保存有来源的记忆 | `core.memory.update` | 更新带来源的记忆；可配置覆盖/合并/拒绝策略、有效期和来源引用，并进行版本检查。 |
| 撤销来源记忆 | `core.memory.revoke_source` | 按来源引用撤销关联记忆，适合原资料失效或用户要求撤销的场景。 |

### 2.7 工具：13种

| 积木名称 | 稳定 ID | 功能与使用场景 |
|---|---|---|
| 工具入口 | `core.tool.entry` | 将模块里的处理流程声明为可调用工具入口，供其他模块使用。 |
| 提供给模型的工具 | `core.tool.expose` | 在模型工具循环内声明允许模型调用的工具资源；它本身不是一次工具执行。 |
| 调用工具 | `core.tool.invoke` | 按输入或当前结果执行指定工具资源，取得结果；须满足工具权限与输入契约。 |
| 连接 Windows 窗口 | `core.computer.attach` | 建立受控Windows目标窗口会话，内部嵌套操作步骤；依赖Host及授权。 |
| 查找窗口控件 | `core.computer.find` | 按定位器查找控件，在超时限制内返回匹配结果。 |
| 读取窗口控件 | `core.computer.read` | 读取授权目标控件的信息。 |
| 操作窗口控件 | `core.computer.act` | 对目标控件执行配置动作，例如点击或填入值；受定位、输入和权限检查。 |
| 等待窗口控件 | `core.computer.wait` | 等待目标控件满足定位条件，超过时限则失败。 |
| 捕获窗口区域 | `core.computer.capture` | 对受控目标区域进行捕获，返回与执行步骤绑定的证据。 |
| 打开隔离浏览器 | `core.browser.navigate` | 打开指定网址并建立隔离浏览器会话，供内部网页步骤使用。 |
| 操作网页控件 | `core.browser.interact` | 按网页定位器执行点击、输入等配置动作。 |
| 读取网页控件 | `core.browser.extract` | 提取目标网页控件的信息，供后续流程使用。 |
| 转写项目音频 | `core.media.transcribe` | 转写已有项目音频，并核对媒体哈希和版本；不等于实时麦克风录音或语音合成。 |

### 2.8 技能与扩展：4种

| 积木名称 | 稳定 ID | 功能与使用场景 |
|---|---|---|
| 发现已安装 Skill | `core.skill.discover` | 查询当前可发现的已安装技能。 |
| 加载 Skill 指令 | `core.skill.use` | 读取并加载选定技能指令，绑定版本与内容摘要；指令不能扩大授权或自动执行附属脚本。 |
| 执行 Skill 声明工具 | `core.skill.execute` | 执行Skill声明且当前权限允许的工具；不是任意Shell。 |
| 读取 Skill 附属资料 | `core.skill.read_resource` | 读取技能中的受控文本资料，核对来源与内容绑定。 |

### 2.9 协作与编排：16种

| 积木名称 | 稳定 ID | 功能与使用场景 |
|---|---|---|
| 调用模块 | `core.module.call` | 调用其他模块的稳定导出入口；模块改显示名不应破坏稳定引用。 |
| 发送事件 | `core.event.send` | 将输入或当前结果发送到指定会话事件通道。 |
| 接收事件 | `core.event.receive` | 在时限内接收事件，分别处理收到与空/超时分支；事件队列本身不是持久消息队列。 |
| 并行计算后汇合 | `core.flow.parallel` | 并行运行左右两个受限制的计算分支后汇合；不能据此推断任意副作用都能并行。 |
| 等待一段时间 | `core.flow.delay` | 等待指定毫秒数，支持取消。 |
| 报告流程失败 | `core.flow.fail` | 主动使流程失败，适合验证失败处理或拒绝继续执行。 |
| 重复执行 | `core.flow.repeat` | 将内部步骤重复指定次数；当前实现限制0–100次并共享运行预算。 |
| 逐项处理 | `core.flow.foreach` | 对数组逐项执行并收集结果；配置最多项目数，上限100。 |
| 满足条件时循环 | `core.flow.while` | 根据输入、结果或记忆判断是否继续循环；有最大循环次数，上限100。 |
| 尝试并处理错误 | `core.flow.try` | 执行尝试分支，在可恢复错误时执行错误分支；权限、取消和不确定副作用等错误不被吞掉。 |
| 安全重试 | `core.flow.retry` | 对允许重试的步骤重试，当前最多3次；不允许把不安全副作用当成普通失败重复执行。 |
| 持久工作流 | `runtime.task.durable` | 将内部步骤按持久任务状态管理，支持受控暂停与恢复；恢复须核对绑定和副作用状态。 |
| 执行步骤与补偿 | `runtime.compensate` | 配置正向动作及失败后的补偿动作；补偿逻辑由用户声明，不保证任何现实操作都能撤销。 |
| 等待业务审批 | `core.human.approve` | 在持久工作流中暂停并等待业务决策；与Host资源权限审批是两种不同机制。 |
| 保存工作流检查点 | `runtime.checkpoint.save` | 在持久工作流中保存执行进度，供后续受控恢复。 |
| 委派 Agent 子任务 | `core.agent.delegate` | 将任务委派给已绑定模块工具资源；支持顺序/并行、停止/收集失败策略，子任务共享预算且权限不能超过父任务。 |

### 2.10 护栏与权限：2种

| 积木名称 | 稳定 ID | 功能与使用场景 |
|---|---|---|
| 运行预算 | `core.run.budget` | 限制步骤数、调用数、输出Token与总时限，避免失控运行。 |
| 引用护栏 | `core.guardrail.evidence` | 配置证据引用为必需或可选，并接入引用验证；不能证明回答里每个事实都是真实。 |

权限检查贯穿Host、资源、运行时与工具，不只靠这两个积木；没有“跳过授权”积木。

### 2.11 数据与逻辑：4种

| 积木名称 | 稳定 ID | 功能与使用场景 |
|---|---|---|
| 自定义计算 | `core.data.transform` | 对JSON参数执行项目声明的受控计算，返回JSON值；不是任意本机代码或Shell执行。 |
| JSON 值 | `core.data.literal` | 构造常量JSON数据，例如对象、数组、数字或字符串。 |
| 设置结果 | `core.data.set` | 将当前流程结果设置为指定JSON值，供后续步骤使用。 |
| 如果 | `core.logic.condition` | 根据输入、结果或记忆与目标值作判断，分别进入THEN/ELSE分支。 |

### 2.12 输出与渠道：5种

| 积木名称 | 稳定 ID | 功能与使用场景 |
|---|---|---|
| 回答 | `core.output.answer` | 将流程结果输出为回答，按可选方式组织呈现。 |
| 创建消息 | `core.message.create` | 把内容构造成消息值，供消息回复使用。 |
| 回复消息 | `core.message.reply` | 将消息返回到对应文本交互入口。 |
| 结构化输出 | `core.output.structured` | 按项目中的Schema解析并校验输出，失败则报错；不会自动修正所有格式错误。 |
| 文件输出 | `core.output.file` | 生成供输出渠道处理的文本或JSON文件结果；当前仅支持text/json，最多8项、每项不超过64KiB，不是任意路径写入或通用Office文件生成器。 |

## 3. 用作品理解这些积木

以下是组合思路，不是本次新运行或课堂效果证据。

| 想做的作品 | 主要组合 | 用户能修改什么 |
|---|---|---|
| 课程资料问答助手 | 智能体 → 收到问题 → 查找资料 → 组织回答 → 回答 | 人设、资料范围、引用要求、回答方式 |
| 记住偏好的互动助手 | 读取/搜索记忆 → 条件分支 → 组织回答 → 保存有来源的记忆 | 记忆内容、作用域、有效期、撤销来源 |
| 批量整理文本 | JSON值/设置结果 → 逐项处理 → 自定义计算 → 结构化输出 | 输入列表、处理规则、结果格式 |
| 音频内容整理 | 转写项目音频 → 补充指令 → 组织回答 → 文件输出 | 音频来源、整理要求、文本/JSON格式 |
| 有人值守自动化 | 连接Windows窗口/打开隔离浏览器 → 查找/读取/操作/等待 | 目标、控件定位、动作、时限；仍须授权 |
| 可恢复业务流程 | 持久工作流 → 执行步骤与补偿 → 业务审批 → 检查点 | 步骤顺序、审批位置、补偿行为 |

## 4. 容易误认为“已有积木”的内容

| 内容 | 当前准确说法 |
|---|---|
| 旧《积木完整清单》里的全部条目 | 是完整产品设计目录，不能全部计入当前68种实现。该文档仍是设计依据，无需因本次整理删除。 |
| 七个入门分类 | 目录声明了“开始、角色、会思考、会查找、会记住、会行动、会回答”名称；本次读取的工具箱实际按12个专业分类生成，不能只凭名称声明确认已交付独立入门视图。 |
| 检索重排、压缩、引用 | 可能属于知识检索配置或内部实现；当前目录没有独立的rerank/compress/cite积木，不重复计数。 |
| MCP、模型厂商管理、本地模型安装、触发器、状态机/行为树配置 | 有各自资源/配置或CLI入口，但不能因此虚构同名独立积木；本清单只统计注册目录。 |
| 构建助手 | 是帮助用户修改文件与项目的内置代码Agent；与用户画布里定义的作品Agent不同，不算第69种积木。 |
| Blocky蓝图与六个兼容模板 | 是可组合/改造的项目起点或复用结构，不按实例数量增加原子积木总数。 |
| Scratch式角色移动、造型、舞台碰撞、乐器、画笔 | 当前68种目录没有对应基础积木；不能因为使用Blockly画布便宣称已经具备Scratch舞台能力。 |
| 图片/视频/语音生成 | 当前图片积木绑定已有图片，音频积木转写已有音频；不存在独立的绘图生成、视频生成或语音合成积木。外部工具资源的扩展能力须另行核实。 |

## 5. 核对依据与限制

- 注册清单：`packages/block-catalog/src/catalog.ts`，合并definitions、knowledge、text、event、flow、workflow、rpa、agent八个JSON目录。
- 画布注册与分类：`packages/ui-editor/src/blocks.ts`。
- 编译检查：`packages/compiler/src/module.ts`、`interaction.ts`、`link.ts`。
- 执行路径：`packages/runtime-core/src/runtime.ts`、`agent-execution.ts`、`control-flow.ts`、`skill-execution.ts`、`delegation.ts`、`rpa-execution.ts`及`workflow/`。
- 当前功能用途来自源码检查与目录读回，不把仓库历史验收结论写成本次新执行。
- **真实大模型API调用：否。** 本次仅做目录读取、代码检查和公开资料研究，没有运行模型请求。

竞品功能另见[Scratch与其他竞品积木功能清单](2026-10-03-Scratch与其他竞品积木功能清单.md)。
