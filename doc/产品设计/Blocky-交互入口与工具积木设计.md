## 1. 目标

本规格解决五个核心问题：

1. 桌面右侧栏同时承担“帮助用户搭建积木”和“与用户作品 Agent 交互”，但两者不能混用会话或权限。
2. 运行输入栏不是固定产品 UI，而是用户通过积木声明出的 Agent 交互入口。
3. 工具调用是 Agent 的一等能力，工具不能继续隐藏在通用定义积木中。
4. 关键 Agent 语义需要容易识别，同时只保留少量可学习、可组合的连接规则。
5. 纯积木、自定义积木和受控代码共同保证表达能力，不能为了“全部图形化”制造无法阅读的积木墙。

## 2. 右侧栏的两个独立标签页

### 2.1 搭建助手

`Blocky 构建助手` 以 Blocky 自有 BuilderAdapter、Build Spec、语义补丁和权限协议为产品边界，Pi SDK 是首选内部引擎候选。模型来源可配置且不绑定单一厂商；没有可用模型时只禁用助手对话，不影响手工编辑、保存和本地确定性校验。

搭建助手只获得作用域明确的 Blocky 工具：

| 工具面 | 允许行为 |
|---|---|
| 目录读取 | 查询稳定积木 ID、类型、模板和说明 |
| 项目检查 | 读取当前项目摘要、选区、错误和只读运行状态 |
| 语义修改 | 提交 Build Spec 或语义补丁，不直接编辑 Project Manifest、任一模块 Blockly Workspace、IR 或 `.blocky` 容器 |
| 校验与模拟 | 运行类型、权限、依赖、确定性模拟和结构测试 |
| 真实运行 | 只能在用户签发的单次、短期、作用域授权内执行 |

搭建助手提供两种用户可切换模式：

- 审阅模式：默认模式。先显示幽灵积木、增删标记、接口和权限差异，用户接受后才写入。
- 直接搭建：每轮修改前自动创建项目检查点，完成后显示摘要，可按整轮或选定积木撤销。

删除、对外发送、公开发布、真实支付、原生配置写回和其他高风险外部副作用不能因“直接搭建”而免除确认。Pi SDK 的内部嵌入和 Pi、Codex、OpenCode 等外部编程 Agent 接入是两种边界：外部客户端只能通过官方 CLI、Skills 和插件使用同一补丁协议，不能取得内置助手权限。

### 2.2 运行 Agent

`运行 Agent` 是用户作品的通用交互面。它不预置固定输入能力，完全由聊天入口积木编译出的交互能力清单驱动。

- 作品没有有效聊天入口时，整个标签页禁用并定位缺失位置。
- 标签页只显示当前入口允许的文本、图片、文件、语音、Skill 和插件能力。
- 搭建助手会话与运行 Agent 会话、附件、权限、上下文和工具结果完全隔离。
- 运行消息必须定位到入口稳定 ID、所属 Agent、触发积木和执行轨迹。

## 3. 聊天入口积木

### 3.1 外观与连接

聊天入口使用专属“交互入口帽 + 能力区 + 处理区”形态：

```text
聊天入口 [输入 1]
  允许的输入能力：
    接受文本
    接受图片 [格式/大小]
    接受文件 [类型/数量]
    接受语音 [保留原音/转写方式]
    向用户开放 Skill [选择]
    向用户开放插件 [选择]
  收到输入后：
    [处理消息的积木……]
```

积木内部不放测试输入框或发送按钮。设计测试和真实对话统一从右侧 `运行 Agent` 标签页发送，避免形成第二套输入状态。默认 Prompt、系统指令、占位说明和自动发送消息由独立 Prompt、消息或界面说明积木表达。

### 3.2 多入口与命名

- 聊天入口属于一个明确的 Agent，可以在同一 Agent 内创建多个。
- 默认名称按所属 Agent 内的创建顺序生成“输入 1”“输入 2”等本地化文案。
- 用户可以重命名；同一 Agent 内名称重复时编辑器必须提示并在运行选择器中消歧。
- 内部连接只使用不可变稳定 ID，重命名、切换语言或重新排序不会破坏消息路由。
- 多 Agent 作品按“Agent 名称 → 入口名称”分组显示，不能只凭入口名称猜测目标。

### 3.3 能力解锁

| 能力积木 | 右侧表现 | 运行语义 |
|---|---|---|
| 接受文本 | 显示文本输入与发送按钮 | 产生文本消息片段 |
| 接受图片 | 显示图片选择、粘贴或拖入 | 校验数量、格式、尺寸和模型支持 |
| 接受文件 | 显示文件选择与附件列表 | 校验类型、大小、数量和文件读取权限 |
| 接受语音 | 显示录音或音频选择 | 按配置保留音频、转写或同时输出两者 |
| 向用户开放 Skill | 显示明确的 Skill 选择/调用入口 | 只开放选定 Skill，不暴露全部已安装 Skill |
| 向用户开放插件 | 显示明确的插件动作入口 | 只开放声明动作并继续执行插件权限检查 |

Agent 内部拥有某个工具、Skill 或插件，不等于自动向用户输入栏公开。只有入口能力区中的显式积木可以改变右侧 UI。

切换入口时为每个入口分别保存未发送文本草稿。若图片、文件或语音能力被移除，不能静默丢弃尚未发送的附件；界面应保留本地草稿并要求用户删除附件或切回支持该能力的入口。

### 3.4 交互能力清单

画布编译为独立 `InteractionManifest`，至少包含：

```yaml
entries:
  - id: stable-entry-id
    ownerAgentId: stable-agent-id
    displayName: 输入 1
    acceptedParts: [text, image]
    exposedSkills: []
    exposedPluginActions: []
    executionRequirements: []
```

右侧栏、移动端 Agent 使用器、CLI 校验和自动化测试只读取该清单，不自行扫描积木猜测界面功能。清单是编译产物，事实来源仍是 Project Manifest、模块 Workspace 与 Module/Project IR。

## 4. 重要语义与连接语法

Blocky 将“语义重要性”和“连接几何”分开设计。下列能力拥有专属颜色、图标、轮廓、创建入口和编辑面：

1. Agent。
2. 交互入口。
3. 模型。
4. Prompt、指令与上下文。
5. 工具。
6. 记忆与知识。
7. Skill、插件与扩展。
8. 多 Agent 协作。
9. 护栏与权限。

它们仍复用事件帽、命令、类型值、条件、容器和引用六类连接规则。颜色或图标不能替代类型检查；专属外观也不能禁止不同语义通过明确接口组合。

控制流、变量、列表、记录、消息、文件和代码使用 Scratch 式通用形态。新积木进入核心目录前必须证明它具有独立用户意义，不能只因为某个框架使用不同类名就增加一种形态。

## 5. 工具是一等积木

### 5.1 工具容器

`core.tool.define` 使用专属工具容器，不再归入通用定义积木。默认简单视图包含：

- 名称与面向模型的说明。
- 输入参数表：名称、类型、必填、默认值和人话说明。
- 输出类型或结构。
- 所需权限与可能副作用。
- 实现区和出错时处理区。

高级展开视图显示完整 Schema、JSON、类名、底层 API、依赖、运行环境、超时、重试、流式结果、错误映射和原生字段。简单视图与高级视图必须无损往返；高级字段不能成为绕过权限或类型校验的后门。

工具实现区可以使用普通积木、子程序、HTTP、CLI、MCP、数据库、外部服务、纯积木自定义块或受控代码能力块。一个简单工具不要求用户为每个 Schema 关键字拼积木；需要高级控制时再展开参数和结果结构。

### 5.2 三种派生形式

创建工具后，系统从同一工具契约生成：

| 形式 | 用途 |
|---|---|
| 工具引用 | 放入 Agent 的工具栏，使模型可以根据说明与 Schema 自主选择 |
| 调用工具 | 放入确定性工作流，参数插槽按工具 Schema 生成 |
| 工具结果 | 读取成功状态、结构化输出、错误、追踪和原始响应 |

三种形式共享一个稳定工具 ID。修改工具参数后，所有引用和调用点进行类型迁移预览；无法安全迁移的连接保持原内容并标记错误，不能静默截断。

### 5.3 自主调用与显式调用

- Agent 自主调用只允许使用明确附着到该 Agent 且当前可见的工具。
- 确定性调用不依赖模型选择，但仍执行同一权限、预算、审批、追踪和错误契约。
- 动态工具发现必须返回工具引用并经过作用域规则，不能把发现结果自动升级为永久权限。
- 工具审批是工具契约的一部分；搭建助手、模板或高级 JSON 都不能删除宿主要求的确认。

## 6. 自定义积木与代码能力块

### 6.1 两类自定义积木

| 类型 | 实现 | 展开规则 |
|---|---|---|
| 纯积木自定义 | 由现有积木封装 | 必须可无损展开并重新封装 |
| 代码自定义 | 使用声明语言和运行环境实现 | 可展开查看与编辑源码、接口、依赖、权限和沙箱设置 |

两类都允许设置名称、外观、说明、输入、输出、默认值、错误处理、版本和许可证，并可保存到模板或发布到社区。自定义外观只能使用受控布局与连接 Schema，不能伪装成官方签名或改变其他积木的运行语义。

### 6.2 表达优先级

逆向 Agent、GitHub 项目转换和人工搭建统一使用以下顺序：

```text
官方原子积木
→ 可无损展开的组合积木
→ 纯积木自定义块
→ 代码自定义块
→ 原生兼容或未知保留块
```

Agent 拓扑、模型、Prompt、工具契约、权限、状态、记忆和控制流不能整体藏进一个代码块。无法合理图形化的局部算法可以保留为代码自定义块，但必须经过声明接口连接，不能暗中获得额外工具、Agent 或权限。

目标是保证代码可实现的 Agent 行为能够在 Blocky 中被组合、保留和运行，不承诺把任意语言的每一行源码机械转换为适合初学者阅读的积木。

## 7. 桌面与移动端职责

| 平台 | 产品形态 | 搭建 | 运行 |
|---|---|---|---|
| Windows | 完整 Blocky 桌面应用 | 完整 | 本地、远程或原生兼容运行时 |
| macOS | 后续与 Windows 功能一致的桌面应用 | 完整 | 本地、远程或原生兼容运行时 |
| Android | 后续 Agent 使用器 | 不提供积木编辑 | 能力协商后本地、桌面或服务器运行 |
| HarmonyOS | 后续 Agent 使用器 | 不提供积木编辑 | 能力协商后本地、桌面或服务器运行 |
| iOS | 后续 Agent 使用器 | 不提供积木编辑 | 能力协商后本地、桌面或服务器运行 |

移动端读取项目随附的交互能力清单和执行要求。运行目标解析顺序遵从用户选择、数据驻留策略、设备能力、依赖和权限：能安全本地运行时允许本地执行；需要终端、桌面文件、浏览器自动化、桌面插件或原生 Agent 运行时时连接 Windows、macOS 或服务器。

运行目标变化可能导致数据离开设备时必须再次提示目标和数据类别。不能为了“自动可用”而静默上传文件、消息、记忆或密钥。

## 8. 错误处理

- 入口缺少所属 Agent、重复稳定 ID、能力参数无效或处理区为空时，在运行前定位到具体积木。
- 入口显示名冲突是可修复警告；稳定 ID 冲突是阻止保存/运行的结构错误。
- 模型不支持图片、音频、工具调用或结构化输出时，右侧显示具体不兼容项和可选模型/运行目标。
- 工具参数不匹配在调用前阻止执行；运行错误返回工具 ID、调用积木、输入摘要、已产生副作用和可重试性。
- 代码能力块缺少运行时、依赖锁、权限或沙箱时不得降级为宿主机直接执行。
- 移动端找不到合格运行目标时保留会话草稿，并说明缺失依赖、设备连接或服务器能力。

## 9. 验收门槛

### 9.1 交互入口

- 同一 Agent 创建、重命名、重排和删除多个入口后，消息仍按稳定 ID 隔离。
- 增删每种能力积木后，右侧控件即时、准确地解锁或禁用。
- 入口切换保留各自文本草稿；能力移除不静默删除未发送附件。
- 没有入口时运行标签页禁用；搭建助手仍可独立工作。

### 9.2 工具

- 工具简单视图与高级视图往返后 Schema、权限、实现和错误语义一致。
- 工具引用、自主调用、显式调用和结果读取共享同一契约与稳定 ID。
- 修改参数后安全迁移连接；无法迁移的调用点明确报错且不丢内容。
- 普通积木、MCP、CLI、HTTP 和代码自定义实现执行相同的权限与追踪门禁。

### 9.3 自定义与代码

- 纯积木自定义执行“封装 → 展开 → 重封装”语义等价测试。
- 代码自定义的语言、依赖、接口、权限、资源预算和沙箱均可序列化与校验。
- 逆向报告逐项区分官方积木、组合积木、两类自定义积木、原生保留和未转换内容。

### 9.4 平台

- Windows 先通过完整搭建、运行和右侧双标签页验收。
- macOS 上线前对同一项目执行桌面行为对照，不因平台另建积木语义。
- 移动端对本地、桌面和服务器目标执行能力协商、数据外发、断线和恢复测试。
- 移动端不得出现可编辑 Blockly 画布或宣称与桌面搭建功能一致。
