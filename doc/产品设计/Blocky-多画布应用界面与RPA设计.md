# Blocky 多画布、应用界面与 RPA 设计

| 项目 | 内容 |
|---|---|
| 版本 | v0.1 设计基线 |
| 日期 | 2026-08-23 |
| 状态 | 已确认方向；尚未实现 |
| 适用范围 | 中间项目标签栏、多画布模块、跨画布链接、应用界面开发/预览、RPA、非传统 Agent 架构、Windows 通知区域 |

## 1. 产品决策

1. 中间工作区上方增加项目标签栏，首批只有 **画布** 和 **浏览器** 两种标签。
2. 一个项目可包含多个画布；每个 Agent、自动化流程或通用模块可独占一个画布，不要求把全部 Agent 堆在同一画布。
3. 跨画布关系使用有类型的模块/Agent 引用、消息、委派、交接、事件和调用连接；点击引用可跳到目标画布。
4. 用户主动提出“为这个 Agent 创建操作页面”或主动执行对应命令后，才创建 Web 应用界面和浏览器标签。完成 Agent 搭建本身不自动生成页面。
5. 浏览器标签主要用于打开和调试当前项目的 Web 前端页面；它不是 Blocky Web 版，也不默认变成任意网页浏览器。
6. RPA（机器人流程自动化）作为“工具”和“自动化模块”进入同一语言，可与 Agent、规则、状态机和人工确认组合。
7. Blocky 项目不强制以 Agent 为唯一根。事件驱动流程、状态机、规则系统、行为树、黑板协作、RPA、数据处理和混合架构都可使用同一画布语言创建。
8. Windows 最小化按钮默认把主窗口隐藏到用户截图所示的**通知区域**；任务栏最小化保留为设置选项。关闭、退出和后台运行是三个独立动作。

## 2. 中间项目标签栏

### 2.1 两种标签

| 标签类型 | 面向用户的用途 | 保存内容 | 不承担的职责 |
|---|---|---|---|
| 画布 | 编辑一个 Agent、自动化或通用模块 | 该模块的 Workspace JSON、稳定 ID、资源引用和入口 | 不保存运行轨迹或打开状态 |
| 浏览器 | 预览和调试用户主动创建的应用界面 | 对应 `AppSurface` 的来源、入口和调试配置 | 不保存密钥，不直接获得 Host/工具权限 |

标签栏支持：新建、关闭、固定、重命名、复制路径、向左/右移动、关闭其他/右侧标签、恢复最近关闭、溢出列表和按名称搜索。`Ctrl + Tab`/`Ctrl + Shift + Tab` 切换最近标签，`Ctrl + W` 关闭当前标签，`Ctrl + P` 或命令中心按项目对象打开。

打开了哪些标签、当前标签、标签顺序、浏览器视口和分栏属于用户工作区会话状态；Agent 运行语义不能依赖某个标签是否打开。模块本身、跨模块引用和应用界面来源属于项目数据。

### 2.2 多画布项目模型

正式项目编辑事实从“单个 Workspace”扩展为：

```text
Project Manifest
├── Module Index
│   ├── module-a → Workspace JSON
│   ├── module-b → Workspace JSON
│   └── automation-c → Workspace JSON
├── Resource References
├── App Surfaces（可选，默认 0）
└── Format / Migration Metadata
```

每个画布仍以 Blockly Workspace JSON 为该模块的唯一编辑事实。编译器分别生成 Module IR 和 source map，再解析跨模块引用形成 Project IR、InteractionManifest、ToolContract 和运行图。标签 UI、坐标缓存和预览状态不能成为运行事实。

旧单画布项目显式迁移为一个默认模块；格式升级不能改变现有稳定积木 ID 或运行语义。

### 2.3 模块类型不限制架构

模块可显示用途标签，例如“Agent”“自动化”“服务”“规则”“数据处理”，但用途标签只帮助模板、搜索和文档，不作为编译器限制。真正语义来自入口、积木和类型连接，因此用户可以：

- 在一个画布中创建对话 Agent；
- 在第二个画布中创建没有大模型的 RPA 自动化；
- 在第三个画布中创建规则、状态机或数据处理服务；
- 让它们通过类型明确的引用和事件协作。

## 3. 跨画布连接

### 3.1 连接方式

| 关系 | 来源积木 | 目标 | 运行语义 |
|---|---|---|---|
| 引用 Agent | `type.agent_ref` 与现有 Agent 引用 | 另一画布的 Agent | 委派、交接、消息或 Agent-as-tool |
| 引用通用模块 | `type.module_ref` | 另一画布的自动化/服务/规则模块 | 类型化调用并返回结果 |
| 发送事件 | 事件/消息积木 | 目标模块入口 | 异步投递、队列和超时 |
| 调用工具 | `type.tool_ref` | 另一模块导出的 ToolContract | 同步/流式工具调用 |
| 共享资源 | 资源引用 | 项目级模型、知识、秘密或连接器 | 共享配置，不共享隐式权限 |

跨画布引用在积木上显示目标名称、类型和画布路径，具有下划线/链接图标等非颜色提示。单击选中，双击或 `Alt + Enter` 打开目标；“返回来源”保留导航栈。

### 3.2 编译和错误

- 引用保存稳定 `moduleId`/`exportId`，显示名变化不破坏连接。
- 目标删除、接口改变、权限收紧和循环依赖产生可定位诊断，不按名称猜测新目标。
- 编译器允许经过声明的递归/循环消息拓扑，但同步调用环必须有深度、超时或显式队列边界。
- Project Map 显示模块和关系摘要，供导航与影响分析；它不是第二套节点工作流，也不能直接绕过画布编辑运行语义。
- 复制单个画布时，跨画布引用转为公开插槽、保留外部依赖或由用户选择一起复制，不能静默复制整个项目。

## 4. Agent 应用界面开发

### 4.1 显式创建原则

以下任一明确动作才创建应用界面：

- 用户对 Blocky 构建助手说“给这个 Agent 做一个操作页面/管理台/表单”；
- 用户从“构建 → 创建应用界面”选择页面模板；
- 用户导入本身包含前端并明确选择保留/适配。

仅完成 Agent、添加聊天入口、运行或发布 API 都不创建前端目录、浏览器标签、依赖或构建任务。构建助手也不能因为“通常需要页面”自行扩展范围。

### 4.2 页面产物

应用界面包含：

- `AppSurfaceManifest`：页面 ID、入口、关联模块、可用交互、输入输出 Schema、权限和构建状态；
- 前端源码与锁定依赖：存入项目声明的应用界面目录，框架可替换；
- `FrontendBridgeContract`：页面允许调用的 Agent/模块入口、订阅事件、上传附件、人工审批和取消接口；
- 构建/预览工件：可重新生成，不作为 Workspace 或 IR 的事实来源。

默认从 `InteractionManifest` 和 Tool/Output Schema 生成最小类型契约；构建助手可开发 React 等 Web 前端，但页面代码不能直接编辑 `.blocky`、调用任意 Host 命令或继承作品 Agent 的全部工具权限。

### 4.3 浏览器标签

浏览器标签提供：

- 启动/停止本地预览、刷新、前进/后退、地址与构建状态；
- 桌面/平板/手机视口和响应式检查；
- 页面日志、网络摘要、可访问性和前端错误，并能跳到来源文件/对应交互契约；
- 选择 UI 元素后查看绑定的 Agent 入口、Schema 和权限；
- 用户明确允许时打开远程测试地址，独立显示域名和数据外发提示。

每个预览使用独立浏览器上下文/存储分区；项目 A 的 Cookie、LocalStorage、会话和下载不能进入项目 B。预览页面运行在隔离 origin，不暴露 Tauri 全局对象；所有本机能力通过最小 `FrontendBridgeContract` 和 Host 再校验。

### 4.4 页面生成与验收闭环

```text
用户明确要求页面
→ 选择目标模块和用户任务
→ 生成 AppSurfaceManifest / Bridge Contract
→ 生成可审查文件差异
→ 用户接受
→ 安装锁定依赖（如需要）
→ 本地构建
→ 浏览器标签预览
→ 真实用户流程、可访问性、安全和性能验收
```

发布、域名、登录、数据库、计费和远程部署都不是“创建页面”的默认副作用，必须作为后续独立任务授权。

## 5. RPA 与 AI + RPA

### 5.1 产品定位

专业视图将 RPA 显示为“桌面自动化（RPA）”，归入“工具”与可复用自动化蓝图，不新增与 Agent 并列的封闭产品模式。RPA 流程可以：

- 单独运行，不调用任何大模型；
- 作为 Agent 的受控工具；
- 在规则或模型决定后执行；
- 在关键步骤暂停并请求人工确认；
- 作为另一画布模块被多个 Agent 复用。

首批真实场景：旧 ERP/CRM 录入、网页与桌面系统之间搬运、Excel/表单处理、对账和回填、客服工单操作、企业内部无 API 系统集成。

### 5.2 定位策略

RPA 目标定位优先级：

1. 浏览器语义定位和可访问性角色/标签；
2. Windows UI Automation 控件树、AutomationId、Name 和 ControlType；
3. 稳定应用/窗口/进程/页面上下文；
4. 图像/OCR 区域匹配；
5. 绝对坐标作为最后手段，并显示高风险警告。

定位器保存候选、版本、目标应用和回退策略，不只保存一次录制坐标。应用升级后先验证定位器，失败时暂停并要求修复，不能点击“看起来差不多”的位置。

### 5.3 通用积木

| 积木 | 作用 | 关键契约 |
|---|---|---|
| `core.computer.attach` | 连接指定应用/窗口 | 进程、签名、标题和用户选择 → `type.app_session_ref` |
| `core.computer.find` | 查找界面元素 | 会话、语义/UIA/图像定位器 → `type.ui_target_ref` |
| `core.computer.read` | 读取文本、值、状态或表格 | 目标、字段和脱敏策略 → 结构化值 |
| `core.computer.act` | 点击、输入、选择、滚动、快捷键或拖放 | 会话、目标、动作、前置/后置条件 → 结果 |
| `core.computer.wait` | 等待窗口/元素/值达到条件 | 目标、条件、超时 → 结果 |
| `core.computer.capture` | 获取窗口/区域证据 | 目标、遮罩和保留策略 → 图片引用 |

组合蓝图 `recipe.automation.rpa` 展开为“连接 → 查找 → 读取/操作 → 等待 → 校验 → 失败处理 → 可选截图/人工确认”。浏览器 RPA 复用 `core.browser.navigate/interact/extract`；桌面 RPA 使用 `core.computer.*`，两者共享超时、重试、权限、轨迹和敏感信息规则。

### 5.4 录制、执行与恢复

- 录制器是编辑器命令，不是运行积木；只有用户点击“开始录制”后采集操作。
- 录制结果先生成幽灵积木，用户可删除敏感输入、改定位器和增加校验后再保存。
- 密码、Token、验证码和隐私字段只生成 `type.secret_ref` 或人工输入步骤，不记录明文或截图。
- 每个副作用步骤声明幂等键、重复执行策略和补偿/人工处理路径。
- 运行前显示目标应用、窗口、账户、文件、网络和输入设备权限；运行时可随时暂停/停止。
- 恢复必须从显式检查点继续并重新验证窗口/页面/数据状态，不能盲目重放已完成操作。

### 5.5 企业扩展

阶段 7 的 RPA v1 只支持当前用户桌面上的 attended（有人值守）流程。阶段 11 才设计无人值守 Worker、凭据保管库、机器池、队列、调度、审计、录屏保留、并发许可和企业策略；无人值守能力不得通过普通积木或设置提前开启。

## 6. 非传统 Agent 架构

Blocky 语言以“模块、入口、状态、事件、工具、数据和控制流”为底层能力，Agent 只是常用模块形态之一。首批用蓝图验证：

| 架构 | Blocky 表达 |
|---|---|
| 有限状态机 | 状态 + 事件 + 条件 + 转移 + 终态 |
| 行为树 | Sequence/Selector/Condition/Action 的可展开组合蓝图 |
| 规则系统 | 事实/数据 + 规则条件 + 优先级 + 动作 + 冲突策略 |
| 黑板协作 | 共享状态资源 + 多模块事件 + 订阅/更新 + 仲裁 |
| Actor/事件驱动 | 模块邮箱 + 消息 + 队列 + 超时 + 监督/恢复 |
| 传统工作流 | 触发 + 顺序/并行 + 审批 + 补偿 + 持久检查点 |
| RPA 自动化 | 应用会话 + UI 目标 + 动作 + 校验 + 人工确认 |
| 混合 AI 系统 | 规则/RPA/检索先行，模型只在需要推理的步骤参与 |

框架名称不进入核心积木。若上述架构可由现有积木和组合蓝图表达，就不新增运行原语；只有类型、安全、可观察性或性能无法满足时才通过 ADR 增加核心语义。

## 7. Windows 最小化与通知区域

用户截图对应 Windows 任务栏通知区域的隐藏图标面板。Windows 首发行为：

- 标题栏保留标准最小化、最大化/还原和关闭按钮。
- 默认点击最小化后隐藏主窗口并保留 Blocky 图标在通知区域；设置可改为“最小化到任务栏”。
- 左键单击或双击通知区域图标恢复并聚焦最近主窗口；最终手势在 Windows 原生体验验收中确认，右键始终打开菜单。
- 菜单提供“打开 Blocky”“当前运行摘要”“暂停全部”“停止全部”“退出”。没有运行时相关项禁用，不制造虚假状态。
- 通知区域 Tooltip 只显示产品名和脱敏状态，不显示 Prompt、文件名、联系人、模型输出或错误正文。
- 最小化只改变窗口可见性，不自动启动任务、不扩大权限、不改变运行；用户已启动且允许后台继续的任务可以继续。
- 关闭按钮遵循未保存保护：无任务时正常退出；有运行/未保存内容时询问“返回、停止并退出、保留后台运行并隐藏”。最后一项只有项目和用户设置允许后台运行时出现。
- “退出”必须真正停止/结算 Host、sidecar、预览服务和托管运行时；通知区域无图标时不得留下不可见孤儿进程。
- 窗口位置、大小、最大化状态、显示器和 DPI 通过受控窗口状态存储恢复；显示器移除后回到可见工作区。
- 只允许单个主实例；第二次启动把参数交给现有实例并恢复窗口。

设置字段：

| 设置 | Windows 默认 | 说明 |
|---|---|---|
| `window.minimizeTarget` | `notification-area` | 可改为 `taskbar` |
| `window.closeBehavior` | `ask-when-dirty-or-running` | 关闭与最小化分离 |
| `background.continueUserRunsWhenHidden` | `true` | 仅继续用户已经启动且获权的运行 |
| `window.restoreState` | `true` | 恢复可见位置/大小/最大化状态 |

## 8. 安全与性能边界

- 浏览器预览、作品 Agent Web 访问、RPA 浏览器控制和 Blocky 自身 WebView 是四个独立能力域，不共享 Cookie、权限或调试钩子。
- 应用界面只能调用清单中声明的入口；前端源码或远程页面不能获得 Tauri 全局对象、任意文件系统、Shell、原生路径或安全存储。
- RPA 按应用、窗口、动作、数据范围和有效期授权；全屏截图、全局键盘、剪贴板、密码框和管理员窗口单独提高风险等级。
- 多画布按模块增量编译；关闭标签释放渲染资源但不卸载运行模块。大型项目只渲染当前/最近画布，Project IR 和诊断保持可查询。
- 浏览器标签按需启动预览服务和 WebView，关闭最后一个标签后按设置停止空闲服务；不能让几十个隐藏预览常驻。
- RPA 轨迹默认记录结构化动作、定位器摘要、耗时和结果；截图按需、脱敏、有保留期，不能无限累积。

## 9. 分阶段落地

### 阶段 1 Demo

- 建立项目标签栏、多个画布标签、一个跨画布 Agent 引用和返回导航；
- 用户明确执行“创建应用界面”后，生成固定本地前端夹具并在浏览器标签预览；默认项目没有 AppSurface；
- 实现 Windows 最小化到通知区域、恢复、右键菜单和真正退出的最小闭环；
- 所有固定实现走正式 `ProjectManifest/AppSurface/WindowLifecycle` 接口，不加入 Demo 专用字段。

### 阶段 2 正式地基

- 稳定 Project Manifest、多 Workspace、Module IR、跨模块引用和迁移；
- 稳定项目标签会话状态、增量编译、浏览器隔离、AppSurfaceManifest 与 FrontendBridgeContract；
- 补齐窗口状态、单实例、崩溃恢复和设置迁移。

### 阶段 5 构建助手

- 只有用户明确要求时，构建助手才规划/生成应用界面；
- 文件差异、依赖、构建命令和页面权限可审查；
- 浏览器标签完成真实 UI 流程验收，不以截图代替交互。

### 阶段 7 专业能力

- 完成 RPA v1、录制器、定位器编辑、权限、轨迹、暂停/恢复和 `recipe.automation.rpa`；
- 用状态机、规则、事件驱动、传统工作流和混合 AI 蓝图验证非传统架构；
- 完成多画布 Project Map、影响分析、跨画布复制和大型项目性能。

### 阶段 11 企业能力

- 无人值守 RPA、Worker/机器池、队列、计划任务、企业凭据、策略、审计和回滚；
- 应用界面的认证、部署环境、版本、团队审查、日志和可回滚发布。

## 10. 验收入口

人工流程统一进入[《Blocky 核心创作与项目积木化流程》](../验收/跨模块/验收-Blocky核心创作与项目积木化流程.md) U15–U18：

- U15：多画布创建、跨画布连接、跳转和删除/改接口诊断；
- U16：默认不创建前端，用户明确要求后生成并在浏览器标签操作；
- U17：Agent + RPA 有人值守流程、权限、暂停、恢复和负例；
