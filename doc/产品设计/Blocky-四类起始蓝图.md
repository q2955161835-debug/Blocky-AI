## 产品边界

内置蓝图按以下固定顺序提供：知识问答助手、工作助手、Coding 助手、Pi Agent。它们是普通 Blocky 项目底座，使用者可以改角色、模型、资料、工具、上下文、触发方式和输出，再保存为个人蓝图或继续编辑。它们不依赖固定题目、预写答案或不能拆改的演示流程。

蓝图已实现，并通过本轮普通包独立最终验收。新建空白项目继续可用，生成一个空白 `main` 模块，不预置资源或问句。个人蓝图和用户已有 `.blocky` 作品保留。移除旧软件项目起点不移除通用积木、运行时、个人蓝图或已有作品。

当前竞争框架可作为学习和研究来源；框架名称不构成 Blocky 起始蓝图、已集成运行时或兼容结论。Codex 官方插件与 Blocky 内置构建助手继续作为独立能力维护。

## 四类蓝图顺序与验收行为

| 顺序 | 蓝图 | 通用底座 | 可改造方向 | 必须证明的实际行为 |
|---|---|---|---|---|
| 1 | 知识问答助手 | 聊天入口、角色与预算、资料来源/同步/检索、证据约束、模型回答 | 产品手册、课程、法规和个人资料 | 导入并同步资料后，引用可回到原文核查；无命中、未同步或撤权时准确说明证据不足，不猜测答案 |
| 2 | 工作助手 | 任务入口、目标与上下文、受控工具反馈、会话记忆、可审阅交付物 | 资料整理、报告生成、专项重复任务和工作流 | 在用户所选目录读取合成资料、实际生成交付文件并给出结果回执；修改角色或工具后可完成另一专项任务 |
| 3 | Coding 助手 | 任务入口、仓库上下文、搜索/读取/修改、工具反馈、检查和差异 | Blocky 项目及普通代码仓库的专项开发 | 实际修改合成仓库、运行已支持的构建/测试、呈现差异和结果；失败可反馈修正，未执行的检查不能称为通过 |
| 4 | Pi Agent | 真实 Pi Agent 核心、上下文与会话、模型、工具声明和扩展 | 用户自定义工具、会话策略和角色 | 由锁定的真实 Pi Agent 完成模型→工具→后续模型循环；会话隔离、配置往返、预算和取消有证据 |

前三类按用户任务组织为可改造底座，不绑定竞争框架。Pi Agent 必须由真实上游 Pi Agent 运行语义积木化而来；把 Blocky 自有 `core.reason.tool_loop` 改显示名不满足要求。指定上游版本、commit、依赖和许可证审计证据，以实施设计及验收为准。未经专项审计和实际行为验证，不宣称 Pi 兼容。

需要配置的蓝图必须显示具体缺口，例如缺少模型、资料同步、工作目录或工具能力，并提供相应配置入口。蓝图不附带伪装成用户资料的知识库。工具权限和数据边界沿用 Host 的能力授权、Schema 校验、预算、取消结算和秘密隔离。

## 新建项目与改造

CLI 空白项目命令为：

```powershell
blocky project create [--name <name>] --output <file.blocky> --json
```

起始蓝图通过 `template list/show/status` 发现与检查，并由 `project create --template <knowledge-assistant|work-assistant|coding-assistant|pi-agent> [--model <resource-id>] --output <file.blocky> --json` 创建。省略 `--template` 始终新建空白项目；默认模型继承只作用于蓝图创建。这些入口已有普通包 CLI 与桌面创建/改造/保存重开证据，整体交付已通过[本次任务验收](../验收/任务/验收-2026-10-04-四类起始蓝图与默认构建助手.md)，具体配置状态见[CLI 使用说明](../../tools/blocky-cli/README.md)。

此命令只创建空白 `main` 模块，不添加资源、问句或 Agent 流程，因此空项目本身不是可直接运行的作品。需要运行时，使用者应从四类起始蓝图创建项目，或打开已有 `.blocky` 作品；再按项目的实际配置执行验证、运行和差异检查。

蓝图应用后仍是可编辑的普通 `.blocky` 项目。改造、保存、重开、原子积木展开和保存为个人蓝图都应保留用户差异；项目内只保存声明的资源引用和来源信息，不保存本机秘密或私有路径。
