# Scratch 与其他竞品积木功能清单

核查日期：2026-10-03。用户已确认“小猫快跑”指Scratch。本资料按积木的用户功能整理，供产品理解、教学设计与竞品对照使用。

## 1. 怎么读

Scratch部分覆盖九个基础分类的常见功能及重点扩展；同一功能的参数变化合并说明，不将隐藏兼容块、下拉菜单影子块和用户自定义实例算成新增功能。其他产品列出官方资料能够核实的积木/节点或功能组；官网未公开逐块目录的，不猜总数或名称。

**本次是公开资料核查，不是各产品运行实测。** 开源开发分支、官网教程和在线编辑器可能有版本差异；文中不把源码出现的隐藏条目自动视为当前界面可用。AI扩展、设备扩展及企业功能还可能需要服务、账号、模型配置、硬件或相应版本。

| 对象 | 主要创作方向 | 比较口径 |
|---|---|---|
| Scratch | 动画、故事、小游戏和交互作品 | 主要教育参照；基础积木与扩展 |
| Blocks Builder AI | 学习模型、提示词、上下文和AI应用逻辑 | 直接积木AI参照；公开六类功能 |
| Blockly AI Playground | 用积木实验模型和Agent | 第三方开源项目；自定义积木功能组 |
| mBlock | 舞台编程、机器人、AI识别与教育硬件 | 基础创作与扩展积木 |
| PictoBlox | 舞台作品、AI识别、机器学习、机器人 | 默认分类与AI扩展 |
| Kittenblock / 胖虎Agent | 图形化硬件编程、AI对话、自然语言硬件创作 | 二者分开说明 |
| Dify | AI应用、知识问答和工作流 | 连线节点，按功能比较 |
| 扣子（Coze） | AI应用、对话、数据和多媒体工作流 | 连线节点，按功能比较 |
| Blockly | 积木编辑器开发库 | 技术参照，不当成独立完整教育产品 |

## 2. Scratch：九个基础分类

### 2.1 运动：让角色在舞台上移动

| 积木/功能 | 能做什么 |
|---|---|
| 移动若干步 | 沿角色当前方向前进；负数可后退。 |
| 右转 / 左转若干度 | 改变角色方向。 |
| 移到指定目标 | 移到鼠标、其他角色或随机位置。 |
| 移到x、y坐标 | 直接设置角色位置。 |
| 在若干秒内滑行到目标 | 平滑移动到指定对象或随机位置。 |
| 在若干秒内滑行到x、y | 按时长完成坐标移动。 |
| 面向指定方向 / 面向目标 | 指定朝向或跟踪目标。 |
| 将x / y增加若干 | 分别改变横向、纵向位置。 |
| 将x / y设为指定值 | 设置某一个轴的位置。 |
| 碰到边缘就反弹 | 接触舞台边界时转向。 |
| 设置旋转方式 | 选择任意旋转、左右翻转或不旋转。 |
| x坐标 / y坐标 / 方向 | 读取角色的位置和方向。 |

典型作品：跑酷、追逐、迷宫、移动动画。运动主要作用于角色；舞台本身没有相同的运动积木面板。[官方运动积木源码](https://raw.githubusercontent.com/scratchfoundation/scratch-blocks/develop/src/blocks/motion.ts)

| 换背景并等待 | 切换背景后等待相应背景事件脚本处理。 |
| 将大小增加 / 设为百分比 | 放大、缩小角色。 |
| 将图形特效增加 / 设为指定值 | 调整颜色、亮度、虚像等特效。 |
| 清除图形特效 | 恢复特效。 |
| 显示 / 隐藏 | 控制角色可见性。 |
| 移到最前 / 最后 | 设置角色绘制层级。 |
| 前移 / 后移若干层 | 相对调整层级。 |
| 造型编号或名称 / 背景编号或名称 / 大小 | 读取当前外观状态。 |

典型作品：对话故事、换装、表情动画、场景切换。角色和舞台显示的条目不同。[官方外观积木源码](https://raw.githubusercontent.com/scratchfoundation/scratch-blocks/develop/src/blocks/looks.ts)

### 2.4 事件：决定什么时候开始运行

| 积木/功能 | 能做什么 |
|---|---|
| 当绿旗被点击 | 启动作品。 |

| 广播消息 | 发消息，同时继续当前程序。 |
| 广播消息并等待 | 发消息，并等待接收脚本执行完成。 |

典型作品：按键控制、按钮、角色对话、关卡切换。[官方事件积木源码](https://raw.githubusercontent.com/scratchfoundation/scratch-blocks/develop/src/blocks/event.ts)

### 2.6 侦测：知道舞台和用户发生了什么

| 碰到角色 / 鼠标 / 边缘？ | 检查接触。 |
| 碰到颜色？ / 颜色碰到颜色？ | 基于颜色进行碰撞判断。 |
| 到目标的距离 | 计算舞台上的距离。 |

| 计时器 / 计时器归零 | 读取或重置运行计时。 |

典型作品：问答游戏、计时挑战、鼠标跟随、碰撞系统。[官方侦测积木源码](https://raw.githubusercontent.com/scratchfoundation/scratch-blocks/develop/src/blocks/sensing.ts)

### 人脸感知：Scratch已有明确的AI扩展

官方Face Sensing教学材料给出了人脸检测、跟随鼻子等特征、脸部大小与倾斜角、检测/倾斜/接触触发等用法。可以做面部滤镜、用鼻子绘画和面部控制游戏；材料说明它不能识别这个人是谁，并有摄像头与识别限制。**因此，“Scratch没有AI”并不准确。** 人脸感知也不等于已经提供通用大模型Agent、RAG和工具编排。[Scratch官方人脸感知卡片](https://cms.scratchfoundation.org/assets/33c783a9-fc0a-4dfd-b10e-2f9a1d9d60ce)

## 4. Blocks Builder AI：六个AI概念分类

| 官方分类 | 积木功能 | 使用场景 |
|---|---|---|
| Model（模型） | 选择与配置AI模型 | 比较模型与设置对回答的影响 |
| Prompt（提示词） | 定义提示词和消息 | 指定任务、人设与输入要求 |
| Context（上下文） | 管理对话上下文 | 使用前文信息 |
| Output（输出） | 格式化、显示回答 | 呈现AI结果 |
| Interaction（交互） | 控制用户交互 | 聊天输入与响应流程 |
| Control（控制） | 流程控制与逻辑 | 控制应用执行顺序与条件 |

官网还披露真实模型连接、内置聊天测试、结果历史、逐步教程，以及Blocks to Prompt：把积木程序转成供开发Agent使用的提示词。这个转换工具是产品功能，不应直接算成一种独立原子积木。[官方功能页](https://blocksbuilder.ai/features)

**资料限制：** 官网能确认六个分类及用途，本次未取得在线编辑器完整逐块目录、参数或数量。无法从官网未列出RAG、记忆或工具细节推断产品完全不支持这些能力。

## 5. Blockly AI Playground：模型、上下文、界面和Agent

这是rozek维护的第三方开源项目，不能称为Google官方Blockly AI产品。README将其描述为MVP，并给出以下功能组。[项目原始说明](https://github.com/rozek/blockly-ai-playground)

| 积木功能组 | 可以做什么 |
|---|---|
| 上下文项 | 以名称保存、读取和删除字符串项；可在浏览器存储中保存/恢复。 |
| 可编程界面 | 添加输入、复选、单选、下拉、按钮和文本输出，并与上下文关联。 |
| 基础AI | 根据消息列表进行聊天生成，或按提示词生成文本；支持默认/指定配置。 |
| 检索与研究 | 网页搜索、文本网页读取、维基百科搜索/读取与研究工具。 |
| Agent | 示例将任务分解并调用研究/计算工具，保留步骤知识。 |
| 浏览器辅助功能 | 事件循环、暂停/恢复、弹窗、对象处理和浏览器语音功能。 |

适合观察积木如何表达Agent结构。本次未运行其示例或验证浏览器、供应商兼容性，无法据此评价与Blocky的稳定性高低。

| 文本转表情符号 | 对文字进行表情符号转换。 |
| 词性分析 | 分析文本中的词性。 |
| 同义词/反义词 | 查询相关词语。 |
| 简化文字 | 将文字改写得更容易理解。 |

具体功能依据[PictoBlox官方ChatGPT扩展文档](https://ai.thestempedia.com/extension/chatgpt/)。这是“在积木作品里调用生成式AI”的直接例子；不能把PictoBlox概括为只有传统编程和硬件。本次未核实其完整Agent循环、RAG或权限实现。

## 8. Kittenblock与胖虎Agent：区分积木与生成助手

Kittenblock来自小喵科技（Kittenbot），与“编程猫”不是同一产品名称。以下范围限定官方未来板Lite AI版教程，不能外推所有硬件。

| 功能组 | 积木/使用方式的功能 |

| 基础板载控制 | 读取传感器，控制屏幕、像素和彩灯。 |

来源：[图形化编程快速开始](https://www.kittenbot.cn/doc/hardware/future-lite-ai/kittenblock/quick-start/)、[智能对话教程](https://www.kittenbot.cn/doc/hardware/future-lite-ai/图形化编程/agent_application/ai-dialogue/)。上传模式不能把所有舞台角色积木一起变成可运行硬件代码。

**胖虎Agent**则是自然语言生成硬件程序的助手，官网披露屏幕、传感器、彩灯/电机等方向。它不是一套应该与Kittenblock基础积木重复计数的积木分类；更适合与Blocky构建助手比较生成与修改流程。[胖虎Agent官方说明](https://www.kittenbot.cn/doc/hardware/future-lite-ai/taro-agent/)

## 11. Blockly：技术库的通用积木

Blockly是给开发者嵌入积木编辑器的库，实际应用定义哪些积木、如何生成与运行结果。它可以表达逻辑、循环、数学、文字、列表、变量和过程等通用编程概念，但这些通用积木不会自动变成模型、知识库或Windows工具能力。[Blockly官方定位](https://docs.blockly.com/guides/get-started/what-is-blockly/)

例如，条件块表达判断，循环块重复步骤，数字/文字/列表块处理值，变量保存状态，过程封装复用逻辑；领域开发者还需定义自己的积木与执行契约。生成代码后的执行方式由应用负责。[官方代码生成说明](https://docs.blockly.com/guides/create-custom-blocks/code-generation/overview/)

## 12. 与当前Blocky的对应关系

以下是基于功能用途的分析，**“未核实”不能读成“没有”**；“无对应注册积木”仅指当前Blocky的68种目录，不否定经过另行配置的工具或代码可以实现相似任务。

### 12.1 对照Scratch基础能力

| Scratch能力 | 当前Blocky对应 | 差异 |
|---|---|---|
| 键盘、鼠标、绿旗事件 | 文本聊天入口、会话事件 | 启动机制不同，没有Scratch舞台的同名基础事件积木。 |
| 移动、旋转、碰撞、造型 | 无对应注册积木 | 当前主要创作对象是Agent及流程，尚未提供Scratch式角色舞台原语。 |
| 说话气泡、声音、音乐 | 消息回复、回答；音频转写 | 输出对象不同，没有对应的音乐演奏或语音合成注册积木。 |
| 如果、重复、等待 | 如果、重复执行、条件循环、等待 | 有共同控制逻辑；Blocky增加预算和次数边界。 |
| 变量、列表、运算 | JSON值、结果、自定义计算、逐项处理、记忆 | Blocky更偏结构数据与流程状态，没有逐个照搬Scratch数值和文字块。 |
| 广播 | 发送/接收事件 | Blocky会话队列与Scratch广播语义不同。 |
| 自制积木 | 模块调用、工具入口、蓝图 | 复用目标相近，连接类型、权限和保存方式不同。 |
| 摄像头、人脸感知、硬件 | 项目图片、受控桌面/浏览器工具 | 当前无对应摄像头人脸检测、传感器、电机注册积木。 |

### 12.2 对照AI功能

| 功能 | 当前Blocky | 已核实的竞品例子 |
|---|---|---|
| 模型与提示词 | 组织回答、补充指令、模型资源 | Blocks Builder AI六类；PictoBlox ChatGPT；Dify/扣子模型节点 |
| 知识问答 | 来源、解析、分段、索引、检索、纠正链 | Dify知识检索；扣子知识库节点 |
| 记忆 | 6种记忆积木与作用域/来源管理 | 扣子长期记忆；Playground上下文浏览器存储，二者语义不同 |
| 模型选用工具 | 调用可用工具、提供给模型的工具 | Dify Agent；Playground Agent示例 |
| 软件界面自动化 | Windows与隔离浏览器的9种会话/步骤积木 | 本次资料未核实其他产品同等桌面Host能力 |
| AI识别 | 英文实验评分、项目音频转写、图片绑定 | Scratch人脸感知；mBlock识别；PictoBlox视觉与机器学习 |
| 多媒体生成 | 当前无专门图片/视频/TTS生成积木 | 扣子图像/视频节点；PictoBlox等提供朗读扩展 |
| 流程可靠性 | 重试、错误处理、审批、检查点、补偿 | Dify/扣子有循环及流程逻辑；不能仅凭分类表断言恢复语义相同 |

### 12.3 这份清单能支持的判断

Scratch的积木细致地覆盖“角色在舞台上发生什么”；Blocky当前积木覆盖“Agent接收什么、使用哪些资料和工具、如何组织流程、如何回复”。两者有条件、循环、数据和复用等共同基础，创作对象与执行环境不同。

Blocks Builder AI及Blockly AI Playground已经公开提供积木化AI学习或Agent实验；PictoBlox、mBlock、Kittenblock也已有不同形态的AI功能。Blocky的比较应落在具体功能、可解释修改、权限与运行体验上，不能以“其他积木软件没有AI”为前提。

以上是用途分析，不是市场胜负、性能排名或小学教学效果结论。
