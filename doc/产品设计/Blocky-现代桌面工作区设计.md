# Blocky 专业生产力工作区设计（第二版）

状态：方案 B 已批准，书面规格待确认后实施

批准日期：2026-08-12

前置版本：第一版现代桌面工作区已于 2026-08-11 实施并验收。本文件在保留其真实 Blockly、统一深色工作台、侧栏收纳和防重叠能力的基础上，替代第一版交互规格。

适用范围：`try/windows-core-spike/` 当前可运行产品壳及其测试。实现继续复用现有 Blockly workspace JSON → 编译 → IR → InteractionManifest / ToolContract → 确定性运行时链路；本次不把尖峰目录整体迁移为正式 monorepo。

## 1. 产品定位与设计原则

Blocky 是文档驱动的桌面 AI 生产力应用，不是技术演示页。用户围绕一个可保存、可打开、可继续编辑的 Agent 项目工作：从积木库搭建逻辑，在同一窗口中通过对话测试效果，并通过执行过程定位问题。

本次改造遵循以下原则：

1. **真实可用优先**：可见菜单、搜索、快捷键、拖放、保存状态和面板切换必须连接真实行为，禁止用无功能控件凑齐桌面软件外观。
2. **文档模型一致**：新建、打开、保存、另存为和关闭保护围绕同一份当前文档状态工作，标题与保存状态不得写死。
3. **画布交互标准化**：选择、框选、平移、缩放遵循成熟白板与图形编辑器习惯；收纳侧栏只增加可见空间，不改变积木坐标、尺寸或比例。
4. **聊天即测试**：发送一条消息就是运行当前 Agent；删除独立“运行”按钮和重复入口。
5. **渐进披露技术细节**：右侧默认展示用户语言的对话结果；积木来源、耗时和运行事件收进可展开的“执行过程”。内部 schema、块 ID、尖峰名称和测试夹具不进入普通产品界面。
6. **单一事实来源**：菜单、命令中心、快捷键、积木目录、分类颜色和保存状态都由各自唯一注册表或状态机投影，禁止并行维护第二份文案与行为。

### 1.1 研究依据

本规格综合了当前 Blocky 实机审计、用户批准的第四版布局，以及以下成熟产品和公开竞品行为：

- [VS Code 用户界面](https://code.visualstudio.com/docs/editing/userinterface)与[默认快捷键](https://code.visualstudio.com/docs/reference/default-keybindings)：命令中心、菜单分组、真实启用态和键盘优先操作；
- [Blocks Builder](https://blocksbuilder.ai/)：左侧拖放积木、中央构建画布和内置聊天即时测试的核心闭环；
- [FigJam 选择与框选](https://help.figma.com/hc/en-us/articles/1500004292221-Select-move-and-order-objects-in-FigJam)：选择工具、Shift 多选和长拖框选的成熟交互习惯；
- [Blockly 缩放配置](https://developers.google.com/blockly/guides/configure/web/zoom)与[移动配置](https://developers.google.com/blockly/guides/configure/web/move)：缩放、平移和滚轮行为应由明确的单一输入规则控制；
- [Tauri Dialog 插件](https://v2.tauri.app/plugin/dialog/)：原生打开/保存对话框能力；本项目仍通过更窄的 Rust 文档桥封装路径权限，不直接把任意路径开放给前端。

这些参考用于确定交互习惯和完整工作流，不复制其品牌、视觉资产或内部实现。

## 2. 目标工作流

### 2.1 首次进入或新建项目

1. 窗口标题显示 `未命名 Agent`，状态显示 `未保存`。
2. 左侧默认打开积木库，中央画布为空，右侧默认打开“搭建助手”。
3. 搭建助手提供三个真实可执行入口：`添加 AI 伙伴`、`添加聊天入口`、`查看快速入门`；前两个调用现有积木插入能力，第三个打开应用内帮助。
4. 用户从左侧拖入积木或单击插入，画布立刻标记为脏状态；自动放置不得与已有顶层积木栈重叠。
5. 用户切到“对话测试”并发送消息；发送动作编译当前 workspace 并启动当前入口，完成后展示用户消息、助手回复和可展开执行过程。
6. 首次保存打开原生保存对话框；保存成功后标题使用文件名，状态变为 `已保存`。

### 2.2 继续编辑已有项目

1. `Ctrl+O` 或“文件 → 打开…”使用原生文件选择器选择 `.blocky`。
2. 加载前先校验文件容器和项目快照；失败时保留当前项目不变并显示安全、可操作的错误提示。
3. 若当前项目有未保存修改，新建、打开、关闭和退出都先进入统一的未保存保护流程：`保存并继续 / 不保存 / 取消`。
4. 打开成功后重建派生 IR 和清单并比较一致性；磁盘中的派生字段不作为可信事实。

## 3. 信息架构与布局

### 3.1 顶部应用栏

顶部保持一条 44px 左右的统一深色栏，顺序为：

- Blocky 标识；
- 左侧栏收纳按钮；
- `ArrowLeft20Regular` 撤销和 `ArrowRight20Regular` 重做，使用直线左右箭头并根据真实历史栈显示禁用态；
- `文件 / 编辑 / 视图 / 帮助`；
- 居中的命令搜索框；
- 当前文档保存状态；
- 右侧栏收纳按钮；
- Windows 最小化、最大化/还原、关闭。

顶部不再展示第二行工具栏，也不再出现画布级“运行”按钮。可拖拽标题栏区域不能覆盖菜单、搜索框、状态和窗口控件的命中区域。

### 3.2 命令搜索框

命令中心视觉与 VS Code 的命令中心一致：居中、紧凑、低对比度边框，默认提示 `搜索积木和命令`，快捷键为 `Ctrl+P`。

搜索结果合并两类数据：

- **命令**：来自唯一 `CommandRegistry`，展示名称、所属菜单和快捷键；回车执行。
- **积木**：来自现有积木目录，展示积木名称、分类和颜色；回车在画布当前视口安全位置插入真实积木。

支持键盘上下键、Enter、Escape；空结果展示明确提示。搜索框不是文件内容全文搜索，也不伪装尚未实现的云端检索。

### 3.3 左侧积木区

左侧继续拆成固定分类栏和当前分类积木列表：

- 分类、积木名称、顺序、颜色和类型从现有积木目录读取；
- 列表使用真实 Blockly SVG 预览；
- 鼠标或触控笔按下积木预览后可直接跨栏拖入主 workspace；
- 单击插入作为键盘和低精度输入的等价入口保留；
- 拖入和单击都调用同一 `BlockInsertionService`，使用相同坐标换算、防重叠和错误回滚；
- 收起左栏后，画布只获得更大可见宽度，不触发适配、居中、缩放或自动重排。

不得只依赖 HTML5 `dataTransfer` 自定义 MIME 完成主拖放，因为桌面 WebView 中跨 Blockly SVG 的拖动可靠性不足。实现应采用统一 pointer session：左侧按下时记录积木类型，移动时显示真实预览或同源拖动代理，释放时把屏幕坐标转换为 workspace 坐标并创建真实积木。

### 3.4 中央画布

画布仍是唯一可编辑 Blockly workspace。画布右上角仅保留保存图标；首次保存等价于“另存为”，已有路径时直接保存。画布右下角保留 `− / 百分比 / + / 适配画布`，删除 Blockly 原生垃圾桶。

删除积木使用标准操作：选中后按 `Delete` / `Backspace`，或从“编辑”菜单执行。删除多选内容前不弹出逐块确认；不可恢复的大范围清空项目必须使用单独确认流程。

### 3.5 右侧测试区

右侧标签改为：

- **搭建助手**：空项目或缺少必要入口时默认选中，展示与当前画布状态匹配的可执行引导，不展示“Windows Core 技术尖峰”等内部说明。
- **对话测试**：只要存在可运行聊天入口即可输入；发送一条消息即编译并运行。没有入口时输入区禁用并提供“添加聊天入口”按钮。

对话测试采用常见消息布局：用户消息靠右、助手回复靠左；运行中显示停止按钮和流式状态。每轮助手回复下方提供折叠的“执行过程”，按实际事件来源积木颜色展示步骤、耗时和必要摘要。默认不显示原始事件 JSON、内部事件版本、块 ID 或 schema 名称。

## 4. 真实菜单、命令与快捷键

### 4.1 唯一命令注册表

新增 `CommandRegistry`，每个命令包含稳定 ID、中文名称、菜单分组、快捷键、图标（如需要）、启用条件和执行函数。顶部菜单、命令搜索、快捷键监听和无障碍提示全部读取该注册表。

命令执行失败统一进入轻量通知；菜单不能吞掉错误，也不能在禁用条件不满足时执行。

### 4.2 文件菜单

| 命令 | 快捷键 | 行为 |
|---|---|---|
| 新建 Agent | `Ctrl+N` | 通过未保存保护后创建空白未命名文档 |
| 打开… | `Ctrl+O` | 通过未保存保护后打开原生 `.blocky` 选择器 |
| 保存 | `Ctrl+S` | 已有关联文件时原地保存，否则进入另存为 |
| 另存为… | `Ctrl+Shift+S` | 打开原生保存对话框并切换当前文档关联 |
| 退出 | `Alt+F4` | 通过未保存保护后关闭应用 |

原“重开项目”被“打开…”替代；“清空项目”不作为文件菜单常驻高频项，若保留则放入编辑菜单低优先级区域并带二次确认。测试专用“载入 100 块”不得出现在普通产品菜单。

### 4.3 编辑菜单

| 命令 | 快捷键 | 行为 |
|---|---|---|
| 撤销 | `Ctrl+Z` | 操作 Blockly 撤销栈 |
| 重做 | `Ctrl+Y` | 操作 Blockly 重做栈 |
| 全选 | `Ctrl+A` | 选择所有可编辑顶层积木栈 |
| 剪切 | `Ctrl+X` | 剪切当前选择，保留连接结构 |
| 复制 | `Ctrl+C` | 复制当前选择，保持稳定的相对布局 |
| 粘贴 | `Ctrl+V` | 粘贴到视口可见空位并生成新的稳定 ID |
| 删除 | `Delete` | 删除当前选择 |

撤销/重做按钮与菜单的启用态必须读取真实 `getUndoStack()` / `getRedoStack()`，不能只在点击后临时改变。

### 4.4 视图菜单

包括：显示/隐藏积木库、显示/隐藏右侧面板、选择模式、平移模式、放大、缩小、重置为 100%、适配画布。视图偏好可以本地持久化，但不得写入 Agent 项目文件。

### 4.5 帮助菜单

包括：快速入门、键盘快捷键、关于 Blocky。关于窗口只展示产品名称、版本、版权和必要开源声明，不出现尖峰、IR 版本、测试钩子或开发目录。

## 5. 文档模型与保存状态

### 5.1 前端文档状态机

新增 `DocumentSession`，至少包含：

- `documentId`：当前会话内稳定且不暴露路径的标识；
- `displayName`：`未命名 Agent` 或当前文件名；
- `saveState`：`clean | dirty | saving | error`；
- `lastSavedRevision` 与当前 workspace revision；
- `hasFileAssociation`：是否已由原生层关联文件；
- 可展示的上次保存时间和安全错误码。

状态投影规则：

- 空白新建：`未命名 Agent · 未保存`；
- 修改后：`文件名 · 未保存`；
- 保存中：`文件名 · 正在保存…`；
- 保存成功：`文件名 · 已保存`；
- 保存失败：`文件名 · 保存失败`，保留 dirty 状态并提供重试。

Blockly UI 事件、文件打开、程序化夹具载入和保存回放必须区分来源，避免打开文件后立即错误标记为未保存。

### 5.2 `.blocky` 容器

本阶段引入可识别版本的最小 `.blocky` 压缩容器，与产品方案中正式容器方向一致：

- 容器内至少包含 `project.json`，承载经 Zod 校验的当前项目快照；
- 容器声明独立的文件格式版本，不能把 `blocky.spike-project/v1` 冒充正式完整格式；
- 后续资源、依赖和插件清单使用可扩展保留项，本次不伪造未实现内容；
- 打开时限制容器大小、条目数、解压后大小、重复条目、路径穿越和非法编码；
- 加载后重新编译 workspace，并校验派生 IR / Manifest 一致性。

为保证向后兼容，现有应用数据目录的 `save_project / load_project` 契约继续用于恢复或既有测试，不与用户选择的文档文件混为同一概念。

### 5.3 原生文件边界

原生打开/保存对话框和路径访问只发生在 Rust Host。前端只发出 `new/open/save/save-as/close` 意图并接收文件名、文档标识、字节数、摘要与安全错误码；前端不得提交任意绝对路径，也不得在日志、事件或项目 JSON 中收到完整本机路径。

Rust 会话持有当前关联路径；`另存为` 成功后原子替换关联。写入采用临时文件、完整写入、同步和原子替换；取消文件对话框是正常结果，不显示错误通知。

### 5.4 未保存保护

新建、打开、关闭窗口和退出共用一个非浏览器阻塞式对话框：

- `保存并继续`：保存成功后继续原操作，失败则停留当前文档；
- `不保存`：放弃当前未保存修订后继续；
- `取消`：保持当前文档、视图和运行状态不变。

重复触发保护时只保留一个决策流程，禁止竞态打开两个文件或在保存完成前关闭。

## 6. 画布输入模型

### 6.1 两种持久工具

画布左上角提供紧凑的工具切换，不与保存和缩放组重复：

- **选择模式（V）**：默认。单击选择；空白处拖动形成框选；`Shift` 单击或框选增减选择；拖动任一已选积木整体移动所选顶层栈。
- **平移模式（H）**：拖动空白或积木覆盖区都只移动视口，不改变积木位置。

选择模式中按住 `Space` 临时进入平移，松开恢复；按 `Escape` 清除选择或取消当前拖动。工具按钮使用 Fluent 图标与可见选中态，不用“点击模式”等含糊文案。

### 6.2 框选与多选

- 从画布空白处按下并超过移动阈值后显示框选矩形；短按仍是清除选择。
- 完全落入或与框选范围相交的规则必须唯一且写入测试；本版采用“与框选范围相交即选中”。
- 只选择可编辑顶层积木栈；合法连接的子积木随根栈整体移动，不拆开连接。
- `Ctrl+A` 选择全部顶层栈；多选移动保持相对坐标。
- 多选复制/粘贴生成新的稳定 ID，并通过 `BlockPlacementService` 放到最近空位。

优先评估 `@mit-app-inventor/blockly-plugin-workspace-multiselect`，但只有在 Blockly 13.2.1 下通过序列化、撤销/重做、连接和原生 WebView 测试后才能采用。实现必须由 `CanvasInteractionController` 隔离插件，不能把未知兼容性扩散到应用组件。

### 6.3 滚轮缩放

鼠标位于画布时，普通滚轮以指针所在 workspace 位置为中心放大/缩小：

- 向上放大、向下缩小；
- 比例限制沿用安全的最小/最大范围；
- 右下角百分比实时更新；
- 侧栏、菜单、搜索结果和右侧对话区域继续正常滚动，不触发画布缩放；
- 画布平移由平移工具、Space+拖动或触控板明确手势完成，不再由普通滚轮抢占。

当前同时启用 `move.wheel` 与 `zoom.wheel` 的配置必须改为单一缩放行为，并通过浏览器和 Tauri 原生输入验证。

### 6.4 防重叠

防重叠仅处理未连接的顶层积木栈，合法连接和嵌套不是重叠：

- 左侧拖入、单击插入、搜索插入、复制粘贴和旧项目修复全部使用实际渲染边界寻找最近空位；
- 多选移动保持用户最终放置，不擅自拆散选择；若释放后与未选顶层栈重叠，则整体平移到最近空位；
- 侧栏收纳、窗口变化、容器刷新和普通缩放不得调用自动排列；
- 100 块夹具只可通过测试钩子载入，所有顶层边界两两不相交。

## 7. 对话驱动运行与执行过程

### 7.1 发送即运行

用户提交文本后：

1. 固定当前 workspace revision 并编译 IR、source map、InteractionManifest 和 ToolContract；
2. 若编译失败，在输入区附近显示可操作诊断并高亮来源积木，不生成虚假助手回复；
3. 若成功，追加用户消息并启动确定性运行时；
4. `model.chunk` 流式投影到同一助手消息；终态完成后固定内容；
5. 权限请求、取消和错误继续遵循现有 run token、修订与唯一终态契约。

发送按钮和 `Enter`（`Shift+Enter` 换行）是唯一普通运行入口。运行中发送新消息的策略为先明确停止当前轮，再开始下一轮；不允许两个运行无提示地写入同一对话。

### 7.2 执行过程投影

事件时间线从现有 `RuntimeEvent` 只读投影：

- 通过 source map / blockId 找到实际积木类型，再从单一积木目录取得分类名称与颜色；
- 每一步展示用户语言的动作名称、耗时或状态和必要摘要；
- 未找到来源时使用中性系统样式，并保留文字类别；
- 原始事件对象只允许在明确的开发构建调试器中查看，普通产品不提供。

### 7.3 会话与文档关系

当前阶段对话记录仍属于工作会话，不写入 `.blocky` 正式项目内容；打开或新建文档时清空右侧临时对话，并在有进行中运行时先安全取消。后续若决定持久化对话，必须单独版本化项目格式和隐私边界。

## 8. 组件与模块职责

| 模块 | 单一职责 |
|---|---|
| `CommandRegistry` | 定义命令、快捷键、启用条件和执行入口 |
| `DesktopTitleBar` | 渲染菜单、直线撤销/重做、命令中心、文档状态、侧栏和窗口控件 |
| `DocumentSessionController` | 管理新建、打开、保存、另存为、dirty 状态和未保存保护 |
| `NativeDocumentBridge` | 提供不暴露任意路径的原生文档意图与结果 |
| `BlockLibrary` | 读取单一目录并发起 pointer/click 插入意图 |
| `BlockInsertionService` | 屏幕坐标换算、真实积木创建、防重叠与回滚 |
| `CanvasInteractionController` | 选择/平移工具、框选、多选、复制粘贴和临时 Space 平移 |
| `BlocklyCanvas` | 持有唯一 workspace 并提供窄命令句柄与视图状态 |
| `WorkbenchLayout` | 只管理左右面板可见性和固定尺寸 |
| `ConversationPanel` | 管理输入、消息投影、运行取消和错误反馈 |
| `ExecutionTrace` | 将 RuntimeEvent 投影为按积木颜色表达的折叠执行过程 |

业务状态、Blockly 命令、原生 IPC、运行逻辑和 UI 渲染不得继续堆入 `App.tsx` 或单个巨型组件。

## 9. 错误处理与可恢复性

- 打开无效 `.blocky`：当前文档不变，提示“不受支持或文件已损坏”，提供关闭提示，不回显本机路径。
- 保存失败：dirty 状态不清除；展示重试和另存为，不伪报“已保存”。
- 原生对话框取消：静默返回当前状态。
- 未知积木类型或插入失败：回滚未完成创建并显示积木名称与恢复建议。
- 多选插件不兼容：在实现阶段失败关闭，不以半工作的框选上线；切换到受相同接口约束的本地实现。
- 编译或运行失败：保留用户输入与已完成消息，显示来源积木和稳定安全码。
- 运行中切换文档：先结算或取消旧运行，旧回调不得污染新文档。
- 本地视图偏好损坏：回退到选择模式、左右栏展开和 100% 缩放，不影响项目文件。

所有提示使用应用内通知、状态或模态组件，不使用 `alert` / `confirm` 等浏览器阻塞弹窗。

## 10. 可访问性与视觉完成度

- 所有常见操作使用项目锁定的 Fluent UI System Icons，不使用汉字、字符、emoji、手绘 SVG 或 CSS 图形冒充图标。
- 菜单、搜索、工具切换、面板收纳、保存和对话输入支持完整键盘路径、可见焦点和屏幕阅读器名称。
- 保存状态不能只依赖颜色；选择/平移模式同时使用图标、文字提示和选中态。
- 执行过程不能只依赖分类颜色，必须展示分类或动作文字。
- 1440×900 默认窗口和 1180×720 最小窗口不得裁切菜单、命令中心、画布控件或对话输入。
- 左右面板收纳动画期间不拉伸积木、不改变 workspace scale/translation；动画结束仅调用 Blockly 容器尺寸刷新。
- 视觉 QA 必须用相同视口把批准参考、改造前截图和新实现截图放入同一对比输入检查，截图本身不等于验收。

## 11. 测试策略

实施遵循先失败测试、后实现、再重构：

1. **单元测试**：CommandRegistry 冲突与启用条件、DocumentSession 状态机、`.blocky` 容器校验、未保存决策、坐标换算、防重叠、多选投影、事件到会话投影。
2. **组件测试**：菜单/快捷键/命令搜索共用命令；直线箭头与真实禁用态；无运行按钮/垃圾桶/尖峰文案；搭建助手真实 CTA；聊天发送与执行过程折叠。
3. **Blockly 行为测试**：pointer 拖入、单击/搜索插入、选择/平移切换、框选、Shift 多选、Ctrl+A、Delete、复制粘贴、滚轮中心缩放、侧栏收纳不改视图和全路径防重叠。
4. **Rust/Host 测试**：原生打开/保存/另存为、取消、原子写、无路径泄漏、压缩炸弹/路径穿越/无效格式/超限、关联路径会话和关闭保护。
5. **跨模块 E2E**：新建 → 拖积木 → 对话测试 → 保存 → 修改 → 关闭保护 → 重开；打开已有文件 → 修改 → 另存为；运行中切换文档；原生快捷键和窗口关闭。
6. **隔离与安全**：普通包无 WDIO 钩子、无“载入 100 块”菜单、无开发文案；四目标敏感扫描为零；前端 IPC 无绝对路径字段。
7. **视觉与输入**：浏览器构建和 Windows Tauri 对同一 1440×900/1180×720 状态截图对比；真实鼠标滚轮、拖放、长拖框选和高 DPI 坐标验证。

涉及 Host、文件格式、权限与核心文档流程，本任务验收等级为 L3。若实现改变保存循环、WebView 生命周期或长期运行状态，则重新执行未缩短的 `check:full`；否则执行相关单元/组件、`check`、`check:core`、Rust 测试和原生 E2E，并明确记录 `check:full` 未触发的依据。

8. L3 任务验收由独立子 Agent 执行并结论为“通过”，相关模块验收、任务归档、进展记录和视觉证据同步完成后，才允许合并 `main`。
