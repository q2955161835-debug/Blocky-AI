# Blocky 现代桌面工作区设计

状态：已批准，待实施

批准日期：2026-08-11

适用范围：`try/windows-core-spike/` Windows Core 尖峰界面

## 1. 背景与目标

当前尖峰界面沿用原始 Blockly 工具箱和传统三栏表单式布局，存在以下问题：

- 顶部样式与工作区割裂，主要操作仍以文字按钮堆叠。
- Blockly 分类工具箱和飞出层占用、覆盖画布，积木选择与编辑区域边界不清。
- 100 块夹具及自动插入场景可能产生顶层积木重叠。
- 左右侧栏不能收纳，画布空间无法按任务需要扩展。
- 画布缩放、保存、运行等控制离使用对象较远。
- 运行时间线没有利用积木分类颜色表达事件来源。

本设计把尖峰界面改为统一深色的桌面工作台，同时保持现有 Blockly workspace JSON、编译、IR、运行时、HostBridge 和项目快照契约不变。目标是提升可读性、操作效率和桌面软件质感，不把尖峰扩大为正式发行产品。

## 2. 已批准的视觉方向

采用“第四版专业工作台”布局：

1. 顶部只有一条统一深色桌面栏，包含 Blocky 标识、左侧栏收纳、撤销/重做、`文件 / 编辑 / 视图 / 帮助`、项目状态、右侧栏收纳和窗口控制。
2. 删除独立的第二行工具栏。
3. 左侧固定拆成“积木分类导航”和“当前分类积木列表”两个区域。
4. 中央是唯一 Blockly 编辑画布。
5. 保存和运行悬浮在画布右上角；缩小、当前比例、放大和适配画布悬浮在画布右下角。
6. 右侧保留“搭建助手 / 运行 Agent”面板，运行时间线根据来源积木颜色设计。
7. 左右侧栏可以分别收纳；收纳只增加画布的可见范围，不改变积木尺寸、缩放、坐标或视图原点。

设计示意图中的圆角矩形仅用于表达布局。实现必须使用真实 Blockly 积木的形状、字段、连接结构、渲染尺寸、目录数据和分类颜色，禁止用 CSS 矩形伪装积木。

## 3. 布局与尺寸

### 3.1 顶部桌面栏

- 高度目标为 44px，使用与工作区相邻面板一致的深色中性底色和边框。
- 图标使用项目内锁定的 Microsoft Fluent UI System Icons React 包；不使用汉字、字符或手绘 SVG 伪装常见操作图标。
- `文件 / 编辑 / 视图 / 帮助` 保留文字，因为它们是桌面应用菜单，而不是单一操作按钮。
- 左右箭头分别连接 Blockly 撤销、重做历史，并提供悬停提示、键盘快捷键和无障碍名称。
- Windows 版本使用 Tauri 自定义标题栏承载拖拽区及最小化、最大化/还原、关闭操作；Web 测试构建通过受控适配器模拟，不调用不存在的 Tauri API。

### 3.2 左侧积木区

- 分类导航目标宽度约 88–92px，展示 `AI 伙伴 / 交互入口 / 消息 / 工具 / 数据 / 流程`。
- 积木列表目标宽度约 212–220px，展示搜索、当前分类名称、数量和真实 Blockly 积木预览。
- 分类、积木类型、字段、颜色和顺序读取现有积木目录，不建立第二份手写目录。
- 积木列表使用与主工作区相同的 Blockly 注册表生成真实 SVG 预览；拖放或单击后在主工作区创建同类型真实积木。
- 左侧栏收纳时两个区域作为一个整体隐藏，不能留下覆盖画布的 Blockly 飞出层。

### 3.3 画布

- 画布使用深色中性背景和低对比度点阵，不改变实际积木主题色和连接语义。
- 画布是唯一可编辑 Blockly workspace；预览工作区只读且不参与编译、保存和运行。
- 保存、运行、缩放和适配按钮相对画布视口定位，不跟随 workspace 内容滚动。
- 保存和运行位于右上角；缩放组位于右下角；状态和提示不能遮挡可交互积木。
- 最小窗口宽度仍为 1180px。完全展开时侧栏保持固定宽度，中央画布吸收剩余空间；本次不增加可拖动分隔线。

### 3.4 右侧运行区

- 右侧目标宽度约 340–342px，作为“搭建助手 / 运行 Agent”的整体收纳单元。
- 时间线节点、左侧强调线和浅色背景来自事件对应积木的真实分类颜色。
- 时间线卡片保留事件名称、来源分类、时间或耗时、必要摘要。
- 右侧栏收纳后画布只扩大可见范围，不触发画布适配。

## 4. 组件与职责

### `DesktopTitleBar`

负责桌面菜单、撤销/重做、左右侧栏收纳、项目保存状态和窗口控制。窗口控制通过窄 `WindowChromeBridge` 隔离 Tauri 与 Web 测试实现。

### `WorkbenchLayout`

只管理 `leftCollapsed`、`rightCollapsed` 和固定面板尺寸。侧栏状态可以保存在设备本地界面偏好中，但不写入项目 JSON，不进入 IR。

### `BlockLibrary`

由 `BlockCategoryRail` 和 `BlockPalette` 组成。它读取单一积木目录，筛选分类并生成真实 Blockly 预览；只向主工作区发出“插入某类型积木”意图，不直接编译或保存。

### `BlocklyCanvas`

持有唯一可编辑 workspace，暴露插入、撤销、重做、缩放、适配、保存快照和运行所需的窄句柄。侧栏变化只调用容器尺寸刷新。

### `BlockPlacementService`

根据真实渲染边界放置顶层积木栈，负责自动插入、拖放结束、夹具载入和旧项目重叠修复。它不得改变连接关系、字段或积木类型。

### `CanvasControls`

承载画布右上角保存/运行和右下角缩放控制。按钮显示真实状态，禁用态和失败态必须可见。

### `RuntimePanel`

继续读取现有 `InteractionManifest` 和 `RuntimeEvent`。通过 source map 或事件来源积木 ID 获取分类与颜色，不扫描画布猜测能力。

## 5. 数据流与关键行为

### 5.1 插入积木

1. `BlockLibrary` 从现有目录获得积木类型和真实预览。
2. 用户拖放或单击积木。
3. `BlocklyCanvas` 在主 workspace 创建真实积木。
4. `BlockPlacementService` 使用已渲染的实际边界寻找最近空位。
5. Blockly 变更事件进入现有保存、编译和运行链路。

创建失败时撤销本次未完成创建并显示明确提示，不能留下半创建积木。

### 5.2 侧栏收纳

1. 用户点击顶部左侧或右侧收纳按钮。
2. `WorkbenchLayout` 改变固定网格列宽并更新无障碍状态。
3. React 布局完成后仅调用 Blockly 容器尺寸刷新。
4. 不调用 `zoomToFit`、居中、滚动重置、自动排列或任何改变 workspace scale/translation 的操作。

收纳前后必须满足：每个顶层积木的 workspace 坐标不变、workspace scale 不变、实际渲染尺寸不变、可见画布面积增加。

### 5.3 撤销与重做

顶部左右箭头操作 Blockly workspace 历史；无可撤销或重做内容时显示禁用态。`Ctrl+Z`、`Ctrl+Y` 和平台等价快捷键保持一致。

### 5.4 保存与运行

保存继续通过现有 `SpikeController` 和 `HostBridge` 契约生成规范快照；运行继续从同一 workspace 编译 IR、交互清单和 Tool 契约。按钮移动不改变数据契约。

### 5.5 时间线颜色

1. `RuntimeEvent` 通过现有 source map 或来源积木 ID 定位实际积木。
2. 从单一积木目录读取该类型所属分类和分类颜色 token。
3. 时间线使用该 token 生成节点、强调线和低对比度背景。
4. 无法定位来源时使用中性灰色并保留事件内容，禁止按事件文案猜颜色。

## 6. 防重叠规则

“不能重叠”适用于持久显示的顶层积木栈；合法连接、嵌套和吸附不是重叠。

- 自动插入：从当前视口附近开始，以稳定顺序寻找第一个不与其他顶层积木栈相交的位置。
- 拖放结束：若未连接的顶层积木栈与其他顶层积木栈相交，则移动到最近空位；已经合法连接的积木保持连接。
- 安全间距：碰撞检测在实际渲染边界外增加固定间距，避免视觉贴边。
- 100 块夹具：先按稳定根 ID 和实际栈边界进行网格/分栏排列，再执行一次两两碰撞检查；任何交集都使测试失败。
- 旧项目：载入后检测已有顶层重叠并进行确定性分离，显示整理提示；只有用户显式保存时才持久化新坐标。
- 侧栏收纳、窗口大小改变和普通 Blockly 容器刷新不得调用放置服务。

放置服务移动的是顶层根积木，连接的子积木随根积木整体移动；禁止拆开连接或改变业务结构。

## 7. 错误处理与降级

- 未知积木类型：不创建积木，显示类型名称和可恢复提示。
- 预览渲染失败：该条目显示不可用状态，主 workspace 和其他积木不受影响。
- 放置计算失败：回滚本次自动创建或恢复拖放前位置，记录无敏感值的错误类别。
- 时间线找不到来源积木：使用中性灰色，不阻塞运行结果显示。
- Tauri 窗口 API 不可用：Web 测试构建保持可操作外观，不尝试调用原生窗口方法。
- 侧栏状态损坏：回退到左右侧栏展开，不影响项目 JSON。

所有提示使用界面内状态或轻量通知，不使用阻塞式浏览器弹窗。

## 8. 可访问性与交互细节

- 常见操作使用 Fluent 图标；中文进入 `aria-label`、`title`、菜单和必要状态文本。
- 所有图标按钮具备可见悬停、聚焦、按下和禁用状态，键盘可以到达。
- 左右侧栏按钮使用 `aria-pressed` 或等价展开状态，并随状态更新“展开/收起”名称。
- 深色背景、文本、图标和焦点环达到桌面工作区可读对比度。
- 时间线不能只依靠颜色：必须同时显示来源分类文字。
- 保存、运行、搜索、切换标签、菜单和侧栏收纳属于核心流程，必须真实可用。

## 9. 测试与验收

实施采用先写失败测试、再实现的顺序。

### 9.1 组件与契约测试

- 顶栏只存在一组撤销/重做控制，没有重复第二行工具栏。
- 图标按钮具有正确无障碍名称和键盘行为。
- 左侧分类与真实积木列表分离，列表读取现有目录。
- 保存、运行位于画布右上角；缩放组位于右下角。
- 左右侧栏独立收纳，右侧作为两个标签的整体收纳。
- 时间线颜色来自积木目录映射，缺失来源时回退中性灰。

### 9.2 Blockly 行为测试

- 侧栏收纳前后 workspace scale、视图 translation、顶层积木坐标和渲染尺寸完全一致。
- 收纳后 Blockly 命中测试、拖放、连接和高亮仍工作。
- 连续单击插入和连续拖放不会形成持久顶层重叠。
- 合法连接和嵌套不会被碰撞修复拆开。
- 100 块夹具的所有顶层栈边界两两不相交，并能保存、重开后保持。
- 旧重叠项目能确定性分离，未显式保存时不改写磁盘数据。

### 9.3 回归与原生验证

- 运行现有单元、组件、`check` 和 `check:core` 门禁。
- 验证 Tauri 自定义标题栏的拖动、最小化、最大化/还原和关闭。
- 验证原生保存、重开、运行时间线、敏感扫描和普通构建测试钩子隔离。
- 在 1440×900 默认窗口和 1180×720 最小窗口检查无遮挡、无裁切和可读性。
- 将旧视觉证据与同状态新截图放入同一对比输入，检查间距、边界、文字、图标、控件状态和实际 Blockly 积木形状。

## 10. 范围边界

本次包含：尖峰桌面壳、布局、积木选择体验、画布控制、侧栏收纳、防重叠、时间线视觉和相关测试。

本次不包含：新增积木类型、修改 Blocky IR、修改项目格式、正式 311 块、模型/插件适配器、账号订阅、CLI、安装签名或正式发行架构迁移。

## 11. 完成标准

满足以下条件才可判定通过：

1. 第四版布局在 Web 测试构建和 Windows Tauri 窗口中真实可操作。
2. 所有积木展示和编辑均以实际 Blockly 渲染为准。
3. 左右侧栏收纳只增加可见画布空间，不改变积木尺寸、缩放或坐标。
4. 自动插入、拖放、100 块夹具和旧重叠数据不会留下持久顶层重叠。
5. 时间线颜色能追溯到真实来源积木，并同时有文字类别。
6. 保存、重开、编译、运行、HostBridge 和普通构建隔离回归通过。
7. 相关模块验收、任务验收、进展记录和视觉证据完成更新。
