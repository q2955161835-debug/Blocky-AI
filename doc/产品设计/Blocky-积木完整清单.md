## 1. 清单规则

- 稳定 ID 表示语义，不绑定中文文案、Blockly 外观、编程语言或某个 Agent 框架。
- 同一语义的模型、提供商、类名、JSON 字段和底层 API 使用高级下拉栏与适配器元数据，不复制积木。
- “原子”表示不可继续拆分且仍有独立用户意义；“组合”必须可无损展开成原子积木；“定义”声明普通可复用对象；Agent、交互入口、工具和自定义积木使用专属容器。
- 核心 Agent 语义可以使用专属外观，但必须复用统一的事件、命令、值、条件、容器和引用连接规则。
- 社区可以新增扩展积木，但不能占用 `core.*`、`protocol.*`、`runtime.*` 等官方命名空间。
- 本清单描述完整产品能力，不表示首个实施阶段会一次性实现，也不表示未来订阅权益归属。
- 清单总数不是产品目标；新增语义必须有实际场景、稳定 ID、类型/权限/运行契约和迁移方案，能由已有积木或可展开蓝图表达时不新增原语。

## 3. 六类连接语法

| 形态 | 连接规则 |
|---|---|
| 事件帽积木 | 只能位于脚本起点，不能接在其他命令下方 |
| 命令积木 | 上下连接，按顺序执行 |
| 类型值积木 | 只能插入兼容类型的普通值槽 |
| 六边形条件积木 | 只能插入真假条件槽 |
| C 形脚本容器 | 内部容纳一段或多段命令脚本 |
| 引用积木 | 连接 Agent、交互入口、Tool、Skill、记忆等已定义对象，只进入精确引用类型槽 |

重要语义外观：Agent、交互入口、模型、Prompt/上下文、工具、记忆/知识、Skill/插件、多 Agent 协作和护栏/权限分别拥有专属颜色、图标、轮廓和编辑面。定义容器、组合积木和自定义积木只是对这六类语法的专属外壳或封装；注释说明块完全不参与连接。专属外观不增加第七种连接规则，也不能替代类型校验。

## 4. Agent 定义与模型

“Agent 定义”是目录中的技术分类，用户界面使用“创建 AI 伙伴”。它表示创建一个可独立运行的 AI 角色，并在其专属容器中配置身份、指令、模型、工具、记忆、知识和护栏；不是让非技术用户编写类定义。

| ID | 用户可见积木 | 形态/层级 | 输入 → 输出 | 语义与复用说明 |
|---|---|---|---|---|
| `core.agent.define` | 创建 AI 伙伴 `[名称]` | Agent 容器/核心形态 | 配置与脚本 → Agent 引用 | 定义独立可运行 Agent，不预设主从关系 |

| `community.fork` | 派生为自己的积木包 | 编辑操作 | 来源包 → 新包 | 保留许可、作者和来源链 |

说明：本节包含部分编辑、安装和发布操作，以完整记录用户动作；它们不编译进 Agent 运行 IR，而进入项目编辑事务或社区服务协议。两类自定义积木都能声明说明、默认值、权限、版本和许可证，并可保存为模板或发布到社区。

## 22. 原生兼容与未知内容保留

| ID | 用户可见积木 | 形态/层级 | 输入 → 输出 | 语义与复用说明 |
|---|---|---|---|---|
| `compat.native_setting` | 原生设置 `[来源/字段]` | 命令/保留 | 未知原生值 → 无输出 | 已保留但尚未通用图形化的配置 |

## 25. 不应伪装成积木的产品能力

| 能力 | 正确归属 |
|---|---|
| 扫描 GitHub 仓库和识别 Agent 框架 | `blocky` CLI 分析器、转换领域服务与核心 `$convert-github-project-to-blocky` Skill；详见[项目积木化设计](Blocky-GitHub项目积木化与Agent组件设计.md) |
| 逆向映射、覆盖报告和行为对照 | 逆向转换服务、CLI 和兼容测试 |
| 内置搭建助手的模型会话与工具调度 | 桌面应用的 Builder Agent Host，不进入作品 Agent IR |
| 画布差异预览、检查点、逐块接受和整轮撤销 | Windows/macOS 编辑器事务层 |
| 根据交互入口生成右侧或移动端输入栏 | `InteractionManifest` 编译器与客户端渲染层 |
| 社区搜索、评论、举报和审核 | Blocky 社区服务与客户端页面 |
| 账号、订阅、席位和机构授权 | 账号与权益服务 |
| 包签名验证、恶意代码扫描和依赖求解 | 包管理与安全服务 |
| 原生运行时安装、升级和进程托管 | Host 与 Pi/Codex/OpenClaw/Hermes/OpenCode/DeepSeek Harness 兼容适配器 |
| Codex 等 Agent 的插件安装与发现 | 官方插件和 CLI 管理命令 |

这些能力可以创建、安装或操作积木，但不进入用户 Agent 的可执行语义，避免“每个产品按钮都是一块积木”。
