## 详细报告

### 1. 系统工具链

验证步骤：

1. 检查 Git、Node.js、pnpm、Rust、Cargo、rustup 和 JDK 17 是否可执行。
2. 检查 Visual Studio C++ Build Tools、Windows SDK 和 WebView2 Runtime。
3. 检查 Android API、Build Tools、Platform Tools、Command-line Tools、NDK 与 Android Studio。
4. 检查四个 Tauri Android Rust target。
5. 检查 DevEco Studio、HarmonyOS SDK、ohpm、hvigor 和 hdc。

验证命令：

```powershell
pwsh -NoProfile -File .\scripts\check-dev-environment.ps1 -Json
```

预期结果：所有必需检查为 `PASS`，JSON 根对象的 `ok` 为 `true`，进程退出码为 `0`。

结果：通过，26/26 项为 `PASS`。

### 2. Doctor 契约与负路径

验证命令：

```powershell
pwsh -NoProfile -File .\tests\dev-environment\doctor-contract.ps1
```

验证步骤：

1. 在隔离子 PowerShell 中运行健康 doctor，检查固定 26 项、零失败和退出码 `0`。
2. 分别注入无效 `ANDROID_HOME`、无效 `DEVECO_STUDIO_HOME`，检查仍返回 26 项并将依赖项标为 `FAIL`。
3. 将实际返回非零退出码的 `git.cmd` 夹具放在子进程 PATH 首位，检查 doctor 不把错误文本误报为版本成功。
4. 注入 Java 11 输出，检查最低 Java 17 门槛。
5. 注入有效的进程级 Android/NDK/DevEco 路径，检查其优先于用户级配置。
6. 注入没有 NDK 的 SDK 路径，检查返回可操作错误且不泄漏原始枚举异常。

预期结果：契约测试退出码为 `0`，输出 `PASS: development environment contract tests passed.`。

结果：通过。

### 3. 当前会话环境加载

验证步骤：点源 `scripts/use-dev-environment.ps1` 后，分别解析 `adb`、`sdkmanager`、`ohpm`、`hvigorw` 和 `hdc` 命令位置。

预期结果：五个命令均指向已验证的 Android 或 DevEco Studio 安装目录；脚本只修改当前 PowerShell 进程的 PATH。

结果：通过。

### 4. 用户级环境变量
