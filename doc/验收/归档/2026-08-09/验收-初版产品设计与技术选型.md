# 验收：Blocky 初版产品设计与技术选型

## 汇总

| 项目 | 内容 |
|---|---|
| 涉及模块 | 产品定义、教育版/专业版、视觉语言、跨端架构、项目格式、安全边界、MVP |
| 验收等级 | L1（文档与决策，不含应用代码或发布行为） |
| 验证结果 | 文档结构、相对链接、Git 空白字符与常见密钥模式检查通过；官方技术依据已核对 |
| 问题风险 | HarmonyOS ArkWeb 触控/SVG/桥接尚未实机验证；手机积木编辑体验尚无原型；原会话部分长回复与图像响应无法由接口完整逐字返回 |
| 最终结论 | 通过 |

## 详细报告

### 1. 需求覆盖

验证步骤：

1. 检查产品方案是否明确教育版、专业版的共同内核与差异。
2. 检查是否明确无 Web 版、Windows/Android/HarmonyOS 首阶段与 macOS/iOS 后续计划。
3. 检查“模块”的正式命名、社区分发单元和项目兼容规则。
4. 检查技术 ADR 是否给出主选、备选、取舍、风险和淘汰门槛。

预期结果：上述约束均能定位到明确章节，不以待定问题替代首版决策。

结果：通过。

### 2. 文件与格式

验证命令：

```powershell
git diff --cached --check
```

并使用只读 PowerShell 检查 Markdown 相对链接目标是否存在。

预期结果：无尾随空白/补丁格式错误；README 中的文档与图标链接均存在。

结果：通过，输出 `RELATIVE_LINK_CHECK_OK`。

### 3. 敏感信息

验证命令：

```powershell
rg -n -i "sk-[A-Za-z0-9]{16,}|Bearer\s+[A-Za-z0-9._-]{16,}|AKIA[0-9A-Z]{16}" --glob '*.md' --glob '.gitignore' .
```

预期结果：文档、README 与忽略规则中不存在常见真实密钥形态；`.env` 被忽略，`.env.example` 可提交。

结果：通过，输出 `SECRET_PATTERN_CHECK_OK`。

### 4. 品牌素材

验证步骤：读取 `logo/logo.png` 的格式、尺寸、字节数和 SHA-256，不改写图片。

预期结果：文件可读且为 PNG；产品方案不把概念母图误称为已完成的平台商店资源。

结果：通过。文件为 1254 × 1254、24bpp RGB PNG，SHA-256 为 `7C8C5FCFD55225DCF2969F942A357DE33AA1E7F7CBDFA026CA2F048B5B621936`。

### 5. 技术依据

验证步骤：查阅 Tauri、Blockly、Flutter 与 HarmonyOS 官方页面，核对支持平台、Blockly JSON 序列化/连接检查、Flutter 的 HarmonyOS 边界和 HarmonyOS 当前 API 信息。

预期结果：ADR 的主结论与官方资料一致，并将无法由文档证明的 WebView 触控/性能事项列为技术尖峰，而不是声称已验证。

结果：通过。

### 6. 未执行项与风险

- 未搭建代码、未安装依赖、未生成安装包，因此没有单元测试、构建或真机结果。
- Tauri 不支持 HarmonyOS；HarmonyOS 使用独立 ArkTS/ArkUI 薄壳是明确的维护成本。
- 只有三端技术尖峰通过后，ADR 才从“可执行选择”升级为“已验证架构”。
- 当前验收仅证明初版产品/技术方案交付完整，不证明应用功能已经实现。

## 最终结论

本阶段交付与用户要求一致，文档检查通过，可以合并 `main`。下一阶段应先进行三端技术尖峰，不应直接扩展社区或连接器。
