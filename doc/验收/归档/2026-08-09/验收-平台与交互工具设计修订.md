## 详细报告

### 1. 平台与产品职责

- 验证步骤：检查产品总览、README、ADR-001、专项交互设计与兼容模板的平台表述。
- 预期结果：Windows 为首发完整应用；macOS 后续提供同等完整应用；Android、HarmonyOS、iOS 只提供 Agent 使用器，不包含积木编辑，并通过能力协商选择本地或远程运行。
- 结果：通过。旧“三端共同编辑 Blockly”仅保留在明确标注为已放弃/被取代的说明中。

### 2. 双右栏与交互入口

- 验证步骤：执行 16 项关键决策文本断言，检查 `搭建助手`、`运行 Agent`、零入口禁用、多入口命名、能力解锁、无积木内发送框和 `InteractionManifest`。
- 预期结果：所有关键决定在专项规格、总设计和清单中均有可定位定义。
- 结果：16/16 通过；另执行 6 项旧口径禁用断言，6/6 通过。

### 3. Tool 与自定义积木

- 验证步骤：检查 `core.tool.define`、`core.tool.reference`、`core.tool.call`、结果/错误访问，以及 `custom.block.visual_body`、`custom.block.code_body` 的清单条目和契约说明。
- 预期结果：Tool 是一级容器；自主引用与显式调用复用同一契约；可视化/代码自定义积木都保留类型、错误、权限、版本与安全边界。
- 结果：通过。六类连接语法与专属语义外观已分离，未把定义、组合或注释误计为新的连接规则。

### 4. 清单完整性

- 验证步骤：PowerShell 读取《Blocky 积木完整清单》首列反引号 ID，分别统计目录 ID 与 `type.*`，按 ID 分组检查重复。
- 预期结果：ID 格式稳定且不存在重复；类型与目录分开统计。
- 结果：311 个目录 ID，311 个唯一；36 个类型 ID，36 个唯一。

### 5. 四类模板与逆向 Skill

- 验证步骤：人工对照 OpenClaw、Hermes、Pi、OpenCode 模板章节、ADR-002 和 `$reverse-agent-to-blocky` 规则。
- 预期结果：通用积木优先；Pi 保持 `read/write/edit/bash` 极简模板；OpenCode 覆盖主/子 Agent、工具权限、MCP、Skills/Plugins；所有模板使用固定上游运行时与可逆投影；逆向流程输出证据和覆盖报告。
- 结果：通过。旧双模板文档已由四模板文档替代，现行 Markdown 链接无断链。

### 6. 文档结构与安全扫描

## 问题与风险

- 本次只验证产品规格、语义目录和技术决策，没有创建应用代码，也没有证明 UI 可用性、运行性能、沙箱强度或任何上游 Agent 的真实兼容性。
- Pi 与 OpenCode 设计依据已核对其现行官方仓库/文档；所有上游版本、API、许可证和分发资产仍须在实现时重新锁定并验证。
- HarmonyOS 官方开发入口在本次研究中出现页面内部错误，因此没有据此新增具体 SDK 能力结论；进入实现前须重新核验官方文档。
- 账号、支付、折抵、机构授权和移动设备是否计入 3 台限额仍需独立商业规格和 L3 验收；本次未接生产支付。
