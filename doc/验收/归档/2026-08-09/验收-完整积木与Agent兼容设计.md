# 验收：Blocky 完整积木与 Agent 兼容设计

## 汇总

| 项目 | 内容 |
|---|---|
| 涉及模块 | 完整积木语言、项目模型、运行语义、多 Agent、社区扩展、主流 Agent 兼容、OpenClaw/Hermes、CLI、官方 Skills 包与插件 |
| 验收等级 | L1（产品与架构文档，不含应用代码、运行时或发布行为） |
| 验证结果 | 25 个类型与 293 个积木/动作/组合语义 ID 均唯一；表格、相对链接、关键需求、常见占位词、敏感模式和 Git 空白检查通过 |
| 问题风险 | 兼容结论目前仅为设计覆盖；所有框架行为、原生配置往返、扩展沙箱和大画布性能仍须锁定版本后以代码和夹具验证 |
| 最终结论 | 通过 |

## 详细报告

### 1. 用户需求覆盖

验证步骤：

1. 检查是否明确“先做完整产品、后切订阅权益”，且所有版本共用项目格式、积木语言和运行内核。
2. 检查界面是否固定为左侧积木库、中间 Scratch 式画布、右侧 Agent 运行对话栏，并明确不内置搭建辅助 Agent。
3. 检查是否支持由用户拼接结果形成单 Agent、主从、对等、群聊、动态团队和集群，而非预设固定拓扑。
4. 检查基础积木是否足够细、组合积木是否可无损展开、技术视图是否允许显示 JSON、类名和底层 API。
5. 检查自定义积木、模板、积木包和 Blocky 社区是否具备上传、下载、版本锁、派生、更新与可执行扩展安全边界。
6. 检查官方 Skills 包是否包含搭建 Agent、创建积木、GitHub 项目转换和现有 Agent 逆向积木四个入口。

预期结果：每项均能定位到明确语义和边界，不以框架品牌积木或未定义黑盒代替。

结果：通过。用户可见的“定义 Agent”已统一命名为“创建 AI 伙伴”；其含义被解释为描述并创建可运行伙伴，不要求用户理解代码类或编程声明。

### 2. 积木清单完整性

验证方法：只读解析 `Blocky-积木完整清单.md` 首列稳定 ID，并检查重复项与表格列数。

验证结果：

- 类型 ID：25 个。
- 积木、协议、运行、编辑动作与官方组合语义 ID：293 个。
- 稳定 ID 总数：318 个，唯一值 318 个，重复 0 个。
- Markdown 表格列数异常：0 个。
- 总设计引用但清单未定义的稳定 ID：0 个。

结果：通过。

### 3. 主流 Agent 兼容与积木复用

验证步骤：

1. 检查代表性语料是否覆盖 LangGraph、Google ADK、Microsoft Agent Framework、OpenAI Agents SDK、CrewAI、MetaGPT、CAMEL、PydanticAI、Mastra、Agno、LlamaIndex、Dify、smolagents、OpenHands 和 AutoGPT。
2. 检查覆盖矩阵是否将状态图、工具调用、交接、动态团队、RAG、代码执行、持久运行、HITL、追踪和部署映射到通用积木族。
3. 检查核心积木准入是否要求跨框架复用，单框架类名/API 是否进入高级映射，独有行为是否优先由组合积木或扩展积木表达。
4. 检查逆向流程是否按“原子积木 → 可展开组合积木 → 自定义代码/原生保留”降级，并输出逐项来源、覆盖、风险、配置往返和行为对照报告。

预期结果：不因 Agent 品牌复制核心积木；任何无法转换内容均可定位且不得静默丢失。

结果：通过设计验收。此结果不等于上述项目的真实运行兼容已经实现。

### 4. 文档结构与安全检查

验证命令与方法：

```powershell
git diff --check
```

并使用只读 PowerShell 检查全部 Markdown 相对链接、连续表格列数和本阶段文档占位词；使用正则扫描常见 API Key、Bearer Token、AWS Key 与私钥头。

预期结果：无失效相对链接、表格破损、未收口占位内容、疑似真实密钥或 Git 空白错误。

结果：通过。

### 5. 未执行项与风险

- 尚未创建 Windows 应用、Blockly 工作区、Blocky IR、运行内核、社区服务、CLI、Skills 或插件。
- 尚未克隆并锁定代表性 Agent 仓库的 commit，也未运行结构转换、配置往返或固定任务行为夹具。
- OpenClaw/Hermes 目前只有兼容原则和模板边界，未安装、托管或声明“与原版功能一致”。
- 社区可执行扩展必须先通过 Windows 及后续平台的沙箱、权限、签名和供应链技术尖峰。
- “无静态 Agent 数量上限”不代表无限设备资源；真实并发、费用、内存和副作用必须受运行预算控制。

## 最终结论

当前设计和清单可以作为后续评审基线，L1 验收通过。用户确认这版内容后，下一步应继续拆分可独立验收的子规格与实施计划；不能从文档检查结果推导出可运行产品或真实框架兼容已经完成。
