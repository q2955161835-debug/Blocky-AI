## 详细报告

### 图片问答

#### 将图片交给 Agent 并保存可读记忆

独立生成320×180合成图片（左黄三角、右绿圆），未复用主 Agent 的红圆/蓝方输入或响应。运行真实 `core.media.image → core.model.compose → core.memory.write(project, SOURCE=result) → core.output.answer`。在线响应正确识别颜色、形状和左右位置；完成状态为 completed。记忆 sourceRef 自动精确绑定 `media/<id>/<sha>/<version>`，无手工补齐结果或文本来源。

首次合成项目角色未禁止虚构引用，模型响应触发 BLK-GUARD-001，未绕过护栏；将合成测试项目角色明确为无文本引用，不改变产品规则。随后独立发现项目媒体记忆写入分支读取了 Host 外层 result.version，而真实响应是 `{ok,entry:{version}}`，导致写入后输出 BLK-MEMORY-STALE。主 Agent 改为读取 entry.version 并拒绝缺失 entry；保存修复前实际失败回执 `runtime-before-memory-fix.json`，修复后上述完整真实链通过。新 Host 集中复验实际 Whisper → 同一项目记忆写入 → 输出也完成。

#### 停止、不支持图片和失效引用

Runtime 无 media.read 时返回 BLK-PERM-001；text-only模型返回 BLK-MODEL-CAPABILITY，均未增加真实模型调用。跨项目摘要查询返回 BLK-MEDIA-NOT-FOUND；SHA和版本错配返回 BLK-MEDIA-CONFLICT。实际图像引用取得后立即取消，Runtime返回 cancelled，未发起后续模型动作。本例验证运行信号和动作边界，未替代在线请求已外发后的网络中断专项。

图片删除后 image-reference 返回 BLK-MEDIA-DELETED；来源记忆 read found=false、search结果为空，再运行同一图片链失败且模型计数未增加。另在真实模型已成功、项目记忆已写入时经正式媒体API删除源，接下来的输出失败，answer为空且所有 generations正文为空，证明在输出前重新验源并清理缓存。
