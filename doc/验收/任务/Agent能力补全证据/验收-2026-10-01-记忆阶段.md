## 详细报告

### 1. 保存、搜索和同键更新

#### 场景：普通用户保存条目并查看来源、摘要和当前版本

使用合成中文/英文内容、对象和 JSON `null`，实际执行 `memory preflight/execute` 的 upsert、read、search。原生账本保存来源、`extract/manual` 摘要类别、时间和版本；JSON `null` 读回 `found=true`，与没有条目及删除墓碑区分。人工摘要和原文摘取均按实际来源标明，没有把摘取称为模型推理。

项目搜索读取当前账本的获准有效条目；没有独立的旧索引结果绕过正文授权。会话搜索限定项目和会话，直接注入的另一项目/会话条目不返回。超过 32KiB 的会话结果受控失败，返回值复制后外部修改不能改变账本。

#### 场景：用户处理同键冲突而不覆盖别人的更新

实际验证 replace、merge、reject：对象合并保留旧字段，冲突或不可合并类型失败后旧状态不变；旧 `expectedVersion` 被拒绝。删除后保留递增版本，使用版本 0 重新写入不能形成 ABA。会话来源撤权的版本达到最大合法安全整数时，整次操作拒绝且账本、正文和撤权集合均不变。

证据：[CLI 实际进程结果](../../../../try/agent-capability-upgrade/memory-acceptance/native-process-results.json)、[初始独立探针](../../../../try/agent-capability-upgrade/memory-acceptance/probes-ts.log)、[版本边界修复复验](../../../../try/agent-capability-upgrade/memory-acceptance/cas-fix-retest.log)。

### 2. 内容失效与知识来源权限

#### 场景：到期、删除或撤销来源后不再查到旧内容

CLI 真实等待 TTL 到期，read 与 search 均不返回内容，版本仍保留。删除及显式 revoke-source 后查不到旧内容；allow-source 不恢复已删正文。直接读原生项目账本确认被显式撤销的合成正文已移除。

实际创建原生 KnowledgeStore 目录来源，将项目记忆绑定为 `knowledge/<collection>/<source>`。来源 ACL 变为不可读后，项目 read/search 不返回正文，新增来源记忆写入被拒绝；来源删除后仍不可读。Host 查询在事务前后核对来源 head/ACL，失败不提交新正文。

#### 场景：会话记忆也遵守知识来源当前 ACL

新增 `check-source` 通过原生 Host 检查当前来源，只返回 `readable`，不返回知识或记忆正文。独立脚本使用当前 release helper、正式 `nativeAgentServices` 的 CLI 审批协议和实际 KnowledgeStore 完成七个检查：初始可读、合法会话写入/搜索、实际 ACL 撤权、检查点恢复后的缓存拒绝、搜索/旧 read 过滤、拒绝新写入且原状态不变、删除来源后不可读。

会话知识来源没有原生检查通道时拒绝写入并隐藏恢复的条目。当前 ACL 过滤发生在搜索数量和 32KiB 结果预算之前；`LIMIT=1` 时首个原始命中已撤权，第二个获准命中仍能返回，撤权命中不消耗获准结果数量。

证据：[原生来源与会话桥接 7/7](../../../../try/agent-capability-upgrade/memory-acceptance/native-source-session-results.json)、[桥接日志](../../../../try/agent-capability-upgrade/memory-acceptance/native-source-session.log)、[会话 ACL 初验](../../../../try/agent-capability-upgrade/memory-acceptance/session-knowledge-acl.log)、[最后两项定向复验 2/2](../../../../try/agent-capability-upgrade/memory-acceptance/last-fix-retests.log)。

### 3. 资料目录、项目、会话与原生授权

#### 场景：另一作品或资料目录不能读取本作品的记忆

真实 CLI 使用两个隔离 profile 和两个项目，跨 profile/项目 read 均为没有条目。项目记忆允许同项目的新合法会话读取，符合项目持久化范围；会话记忆则不跨会话。

独立 Rust 授权测试实际验证伪造 token、跨项目、跨会话、过期、主动撤销以及 Host shutdown 后均不能写入；没有产生记忆目录。独立 TS 探针验证并发管理共享一次授权，晚到的授权在取消后被撤销且不开始管理请求，结束时等待已开始请求结算再撤销授权。

#### 场景：用户批准的是完整请求且只能使用一次

真实不同进程完成 preflight 和 execute；修改项目、会话或正文使原摘要不再获准。执行后不能重放 execute，也不能再次预检复活已消耗批准。实际原生批准账本的过期条目被拒绝。公开摘要与用量字段之外没有打印有效 token 或凭据。

证据：[Host 授权负例](../../../../try/agent-capability-upgrade/memory-acceptance/host-grant.log)、[Host 精确审批测试](../../../../try/agent-capability-upgrade/memory-acceptance/host-approval.log)、CLI 实际进程结果和独立 Runtime 探针。本轮跨用户证据为独立 profile 的数据命名空间；未切换到第二个 Windows 登录账户，不外推为完整 NTFS/DACL 审计。

### 4. 写入失败与恢复

#### 场景：磁盘写入失败时旧内容仍完整可用

已有项目账本建立后，实际将该合成账本文件设为 Windows 只读，再尝试 CAS 更新。原生保存返回 `BLK-AGENT-IO`，前后文件 SHA256 相同；恢复原文件属性后 read 仍返回旧内容。超过单条容量的请求在预检阶段返回 `BLK-AGENT-LIMIT`，原文件 SHA256 不变。会话超大值、结果超额、旧 CAS 及不可合并类型也没有部分提交。

证据：CLI 实际进程结果第九项和 `runtime.test.ts` 原子性探针。只读故障作用于本轮合成 profile，未修改任何真实用户配置文件。

### 5. 真实进程重启和检查点

#### 场景：重新启动后保留允许持久化的项目与会话内容

每个 CLI 命令启动新的 Node CLI 和 Rust helper 进程，保存后由另一个进程读取项目条目，来源、版本和摘要一致。独立 Node 子进程从序列化的 Agent 检查点恢复会话：live 条目的来源、人工摘要、TTL 与版本保留；expired、deleted、revoked 条目不被搜索，删除/撤权墓碑及撤权集合保留。

#### 场景：旧检查点不能重新加载无来源权限的上下文

新的检查点保存可重验的 memoryBinding。恢复后每次输出/外发按当前版本和授权核对；外部撤权使旧正文、生成结果、结构输出及文件全部失效。旧的无 binding 检查点丢弃缓存 memory，value 与 memory 相同时也丢弃，不能把旧缓存直接送入下一模型请求。跨项目的检查点被拒绝。

证据：[真实 Node 重启](../../../../try/agent-capability-upgrade/memory-acceptance/session-process-restart.log)、[新旧上下文检查](../../../../try/agent-capability-upgrade/memory-acceptance/context-new-tests.log)、实际原生来源桥接。会话检查点是受控运行状态；本轮没有把这些数据保存到作品 Manifest/Workspace。

### 6. 撤权后的外发、输出与回执

#### 场景：搜索之后撤来源，下一模型不收到旧正文

实际执行 AgentExecution 搜索→项目 revoke_source→compose 的调用链。初验发现撤权成功仍保留旧 memory 缓存；实现方修复后独立定向复验通过。外部版本改变、会话 TTL 到期或来源 ACL 撤权都使缓存失效；工具调用在失效时不开始。

#### 场景：响应在途或输出前发生撤权

使用完整 Runtime 的 search→compose→output.answer 场景，将来源权限分别在模型响应到达前和 compose 的 block.completed 后改为不可读。最终均以 `BLK-MEMORY-STALE` 失败，答案不返回旧正文。真实调用元数据的结构仍保留，生成正文和 toolCalls 参数清空；本轮替身的 model/request/transport/usage-null 能核对，未声称发生真实外部 API。

Host 重验直接抛出权限错误时，也先清空缓存及生成正文回执再传播错误，不能因异常绕过失效清理。工具循环和结构/文件输出相关位置已审阅接入同一重验方法；本轮实际运行证据以所列 compose、tool、answer 场景为准，没有外推完整自主循环质量或工具适配验收。

证据：[直接撤权初验](../../../../try/agent-capability-upgrade/memory-acceptance/context-revoke.log)、[响应期间撤权及输出前检查](../../../../try/agent-capability-upgrade/memory-acceptance/context-output-final.log)、[正文回执定向复验](../../../../try/agent-capability-upgrade/memory-acceptance/receipt-final-retest.log)、[重验异常修复复验](../../../../try/agent-capability-upgrade/memory-acceptance/last-fix-retests.log)。失败日志保留初验事实，不能按日志中历史失败误判为未复验关闭。

### 7. 桌面与 CLI 入口

#### 场景：用户在记忆面板查看、修改、删除和停止

独立 jsdom 组件操作真实 MemoryPanel：搜索显示条目、来源和人工/摘取摘要类别；选中条目读取当前版本，保存附带 CAS、保留时间和来源；删除更新版本、移除结果及清空内容；CAS 冲突提供重新读取说明。停止操作和切换项目后，晚到结果不显示，原生服务按协议结算。

CLI 的命令与 Schema 可发现，实际 request 文件、预检摘要、执行结果和稳定错误码工作。桌面与 CLI 源码使用同一 MemoryRequest、ProjectMemory 和 Host 管理接口。组件中的原生调用使用替身，因此没有将组件通过计作真实桌面原生审批或普通包 UI 串接通过。
