## 详细报告

### 1. 用户选择运行入口

#### 1.1 已覆盖流程

执行 `pnpm exec vitest run packages/runtime-core/tests/run.test.ts packages/runtime-core/tests/boundaries.test.ts packages/ui-editor/tests/runtime-visuals.test.ts tests/component/interaction.test.tsx`，退出码 0，23/23 通过。其中 runtime 两文件共 20 项、投影 2 项、interaction 组件 1 项。

入口测试真实运行所选 chat 栈，未消费预录执行事件。桌面通过 InteractionManifest 选项设置 interactionId，useStudio 将该值交 Runtime；CLI 的 --entry 也使用同一领域入口。此处没有重跑完整 CLI/Host。

#### 1.2 ENTRY-01：模块内合法相同块 ID 导致入口歧义（P2）

独立内联 Node/tsx 反例：从 createStarter 克隆 research-agent 的 Workspace 为 teacher-agent，并添加不同 moduleId/workspaceRef 的模块描述；保留其模块内块 ID，仅将教师模块根 ROLE 改为科学教师。未添加重复模块 ID 或重复 WorkspaceRef。

实际编译输出：diagnostics=[]；InteractionManifest 两个条目均为 interactionId=on-question，分别属于 research-agent 和 teacher-agent。用第二条目的 interactionId 调用 Runtime，实际 block.started 的模块集合为 research-agent、citation-service，未进入 teacher-agent，回答也不包含教师标题。

原因：模块编译只要求块 ID 在模块内唯一，而 interaction 投影直接使用 nodeId 作为全项目入口 ID；Runtime `.find`、RunPanel 的 option key/value 和 CLI --entry 都仅使用这一 ID。用户无法指定第二个入口，系统也不报告歧义。

修复应为交互入口建立稳定且全项目唯一的身份，或在当前版本明确拒绝歧义并输出可定位诊断；不得悄悄选第一个条目。应补同模块相邻入口和跨模块同块 ID 的对照回归。

### 2. 用户查看运行状态

#### 2.1 状态保留与来源

现有两项投影测试由 Runtime 产生事件，验证无资料警告在 block.completed 与 run.completed 后仍保留黄色状态，sequence 指回真正 block.warning；权限拒绝对应 block.failed 的红色状态及同一 sequence 被保留。后续正常 run.started 清空前次警告。

另外通过内联 Node/tsx 构造最小正式事件形状，分别测试 run.completed/run.failed/run.cancelled：当前模块警告不被另模块同 blockId 的 block.started 覆盖；终态清除另一个仍 active 的块；警告仍绑定原 sequence。三种终态均通过。

#### 2.2 限定非视觉结论

本轮只验证事件到 CanvasVisual 的投影逻辑和 jsdom 组件交互，没有调用 GUI，没有观察实际 Blockly 像素、颜色对比、轮廓尺寸、动画、DPI 或原生窗口。不能将这些测试描述为实际画布视觉验收通过。ENTRY-01 未关闭前，当前功能局部结论仍为不通过。
