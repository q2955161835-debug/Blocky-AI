#### 场景：持久行映射损坏

**F-3B-SEC-01（中风险，阻断局部完整性验收）：相同 offset 的缓存复用遗漏 key 比较。** 冻结源码 `apps/studio-host/src/knowledge/embedding.rs` 的 query 循环在 `previous` 中只缓存 `(offset, vector)`。当排序后的下一行 offset 相同，直接复用向量，不调用 `VectorReader::read(offset, key)`。

独立复现：两个不同文本/不同 key 的真实已发布向量记录，仅把 `embedding.json` 第二行 offset 改成第一行，保持第二行 key。下一次查询 `ok=true`，`git` 与 `plants` 都得到 `0.873341977596283`；第二行绕过 key 核验并获得错误排名。证据为首个探针结果 `tests.offsetAlias`。同一请求若仅选损坏行应经过 reader 并拒绝，但多候选遍历能绕过。

这不构成本轮已证明的跨用户授权突破：复现需要破坏本机持久化映射；它违反“损坏工件拒绝使用”和引用/排名可信要求。建议缓存复用同时匹配 offset 和 key，或显式拒绝同 offset 不同 key，修复后复用此负例验证，不能只测 bin 单字节损坏。
