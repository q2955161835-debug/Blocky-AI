## 详细报告

### 1. 来源、分段与同步

在全新蓝图“资料问答伙伴”中通过资源管理器添加本地测试资料 `try/stage3/quality-1789730071855/allowed/zh-01.txt`。资源弹层在当前 debug 构建中保持在视口内，来源行可见为“zh-01.txt 允许本机读取”，同步后实际读回“1 份文档 · 1 个片段”。该资料正文的第一行是：`青禾课堂的项目资料统一保存为 .blocky 文件。`

共享领域与 CLI 黑盒路径还验证了冻结质量集 20 份资料的新增、更新、删除统计，取消/分页恢复的 checkpoint 复用条件，以及同步状态的 generation/revision 读回。单来源失败不会发布不完整结果，失败来源和未完成范围在结果中保留。相关单元、组件与 CLI 合计 51 项聚焦测试通过。

### 2. 关键词、真实向量、混合与检索约束

桌面资源检索面板对问题“青禾课堂项目文件使用什么扩展名？”依次选择关键词、语义向量、混合检索。三次结果都显示一条资料、165 字节上下文，引用定位均为 `zh-01.txt (zh-01.txt:1–1)`，摘录均与来源原文一致。向量路径先在面板中读回“本地模型已就绪 · 384 维”，建立索引后显示“向量索引已更新 · 新计算 1 · 复用 0”；向量与混合查询分别读回约 70ms、68ms。

CLI 实际使用本地 `multilingual-e5-small-int8-v1`，读回 backend `onnx-cpu`、dimension 384、`externalApi:false` 及固定模型 revision。关键词、向量、混合三模式在冻结 40 题质量集均为 Recall@5=1、citation validity=1、leakage=0；运行结果为真实摘录加缺证据澄清，不宣称生成式答案。过滤命中、过滤无命中、上下文预算不足、minScore 无证据、unsupported rerank 拒绝均有读回证据。

### 3. 引用打开与失效

桌面点击“打开出处”后，资料出处区域展开并同时显示标题 `zh-01.txt (zh-01.txt:1–1)` 和实际摘录；引用可以收起。独立 stale-citation probe 先查询并打开旧引用，再修改来源并同步，旧引用打开被拒绝并返回 `BLK-KNOW-STALE`，当前查询只返回新内容，未把旧位置继续当作有效证据。

CLI 通过同一领域接口创建项目、添加来源、同步、建立向量索引、关键词/向量/混合查询，并在绑定到运行资源后返回原始摘录和 citation collection。模型缺失或模型不匹配时，CLI 返回 `BLK-EMBED-MISSING`/`BLK-EMBED-MODEL` 并在允许的 fallback 下转关键词检索，同时保留降级警告；未把失败伪报为向量成功。`doctor --json` 及运行回读均为 `modelApiCalled:false`。

### 5. F-3B-01：超时可见性缺陷

在同一项目和本地模型下执行：

```text
node tools/blocky-cli/dist/main.mjs knowledge query <project.blocky> \
  --collection frozen-corpus \
  --query "青禾课堂项目文件使用什么扩展名？" \
  --options '{"strategy":"vector","topK":3,"timeoutMs":50,"fallback":"keyword"}' --json
```

结果最终按契约回退为关键词，并带 `BLK-KNOWLEDGE-KEYWORD-FALLBACK`，但端到端耗时读回约 1.9–2.1 秒，而配置的 `timeoutMs` 为 50ms。`packages/knowledge-core/src/search.ts:131-180` 的策略层已经触发超时；`tools/blocky-cli/src/knowledge-transport.ts:7-44,95-105` 的串行 transport 仍等待/占用子进程，导致 fallback 不能及时返回。若不改变 transport 生命周期，用户会看到“已降级”但等待远超配置值；明确 fallback 语义本身是正确的。

原轮建议在 abort 时释放或隔离仍在等待的 transport 请求，并新增用户可观察的 timeout 上限测试；该建议已由 0082970 实施，复验见下节。该原轮问题不影响当时已完成查询的引用真实性，但当时阻止无条件通过检索超时场景。

### 5A. F-3B-01 修复复验（0082970）

在修复提交 `0082970d60e9166ab79bf7abaaad8969d77b3182` 上，使用 source CLI（`pnpm exec tsx tools/blocky-cli/src/main.ts`）和既有 `try/stage3/cli/work/project.blocky`，未重建 release helper 或桌面候选。环境指向既有本地模型目录，连续执行三次：

```text

  --query "青禾课堂项目文件使用什么扩展名？" \
  --options '{"strategy":"vector","topK":3,"timeoutMs":50,"fallback":"keyword"}' --json
```

三次均 `EXIT=0`、结果 `ok=true`、`strategy=keyword`、`warning=BLK-KNOWLEDGE-KEYWORD-FALLBACK`，且没有再次出现原轮约 1.9–2.1 秒的 transport 阻塞：

| 次数 | CLI 端到端 wall | 领域 `data.elapsedMs` | 结果 |
|---|---:|---:|---|
| 1 | 1539ms | 202.37ms | 回退成功 |
| 2 | 1388ms | 201.06ms | 回退成功 |
| 3 | 1381ms | 194.65ms | 回退成功 |

这里的 `timeoutMs=50` 是向量推理请求的时限，不是 CLI 冷启动、原生 helper 启动、首次关键词索引构建和降级后的 ACL 复读的总时限。上述约 1.38–1.54 秒的 wall 单列为 CLI 冷启动开销；约 195–202ms 的领域耗时包含 50ms 向量阶段、取消/重启轻量 session、关键词回退和最终 ACL 读回，符合修复后的职责边界。提交内新增的 `knowledge-transport` 测试通过，验证取消旧 session 后排队 ACL 检查启动新私有进程，旧 session 的晚到响应不会污染新请求。

修复后的 `knowledge-cancel` 会立即终止该 CLI 私有 knowledge session；下一次 ACL 读回使用轻量新进程，且测试覆盖晚到旧响应隔离。因此 F-3B-01 在本轮复验中通过，原轮的阻塞条件已解除。
