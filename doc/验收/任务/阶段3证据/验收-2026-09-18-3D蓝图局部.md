## 详细报告

### 用户功能：四个蓝图可生成、编译并完成首次领域任务

冻结提交中的官方蓝图为 `research-companion`、`code-guide`、`knowledge-tutor` 和 `task-helper`。`officialStarters` 为每个蓝图保存独立名称、目标、示例输入和步骤；前三个蓝图声明知识来源与本地整理模型，任务蓝图声明小时工具和分钟工具。蓝图清单与创建入口分别位于 `packages/block-catalog/src/starters/index.ts:12-72` 和 `packages/block-catalog/src/blueprints/official.ts:9-43`。

本轮直接执行领域探针：对四个 ID 调用 `createBlueprintProject`，再使用 `encodeProject` 和 `decodeProject` 往返。命令退出码为 0，读回全部 4 个项目的 `blocky.project/v1`，顶层 ID 均为 `research-root`，知识项目各生成 10 个声明文件，任务项目生成 6 个声明文件；实例分别带有 `official-<starterId>`、version 1 和 `blocky.blueprint-instance/v1`。读回实例的 `base`、`idMap`、资源/模块绑定和源码根 ID 均完整。

编译、资源替换和任务行为由 `packages/block-catalog/tests/starters.test.ts:42-150` 覆盖。三个知识蓝图用本地适配器返回测试引用，读回实际 collection `selected-knowledge` 和完整 Citation；任务蓝图把同一输入从小时模块切换到 `minutes-service`，输出从 0.75 变为 45。三种知识输出的角色、引用和无证据文案保持各自目标，未宣称生成式回答。

CLI 定向测试 `tests/cli/blueprints.test.ts:40-138` 还验证四个模板写入 `.blocky` 后由原生项目存储读取，实例蓝图 ID 正确；三个知识项目从真实 `lesson.ts` 导入并同步后返回引用，任务项目返回 0.75 并能切换至 45。这里的“真实”指测试写入的文件经过项目格式和 Host 存储边界读取，不代表目标年龄用户试用。

### 用户功能：公开插槽和真实 Blockly 项目序列化

个人蓝图捕获只复制选中的顶层 `WorkspaceBlock`，清除派生 `extraState`，将最小坐标归一化，并把资源、模块和角色转换为公开 slot。缺少资源、模块导出或 schema 不匹配会拒绝保存。实现位于 `packages/block-catalog/src/blueprints/index.ts:289-384`。

项目事实通过 `encodeProject` 分成 `project.json`、每个模块的 `workspaces/*.workspace.json`、声明的资源和 schema 文件，并由 `decodeProject` 重新组装后再次 `parseProject`；缺失 Workspace、路径穿越或未声明文件都会拒绝，见 `packages/project-format/src/index.ts:13-97`。`packages/project-format/tests/format.test.ts:4-25` 的往返测试确认项目声明、Workspace JSON 和资源边界，且不把 session、日志或历史写入项目文件。

插入蓝图会校验目标模块、资源种类、模块导出及输入输出 schema；所有块生成稳定格式的新 ID，检查跨 Workspace 冲突，应用坐标偏移，并保存 instance 的 source-to-target `idMap`、绑定、版本、digest 和 base。实现位于 `packages/block-catalog/src/blueprints/index.ts:399-494`。领域测试 `packages/block-catalog/tests/blueprints.test.ts:11-57` 验证两栈的相对布局 `[500,300]`、`[800,400]`、新 ID 和一次撤销恢复原项目；错误绑定拒绝 `BLK-BLUEPRINT-002`，复用旧 ID 拒绝 `BLK-BLUEPRINT-004`。

### 用户功能：版本迁移、更新冲突、恢复和撤销

v1alpha1 不是静默接受的当前格式。`parseBlueprint` 只接受 `blocky.blueprint/v1`，`migrateBlueprint` 先校验旧 digest，再生成 v1 `parameters` 和显式 `migration.from: blocky.blueprint/v1alpha1`、`sourceDigest`，见 `packages/block-catalog/src/blueprints/index.ts:36-103,196-274`。`packages/block-catalog/tests/blueprint-lifecycle.test.ts:15-39` 验证旧输入仍可读为原始字符串、普通解析拒绝旧版本、迁移后的 role/module slot 正确且原 digest 被保存。

实例生命周期保存 `instanceId`、blueprintId、version、digest、sourceRootId、idMap、公开 bindings 和 base；读取时会校验 base 与当前 root 的 ID 关系，非法实例返回不可识别状态，见 `packages/block-catalog/src/blueprints/lifecycle.ts:17-60`。更新实现是纯三方预览，直到补丁被接受前不会写项目；同一实例的成员、digest 和 source roots 不一致会拒绝 `BLK-BLUEPRINT-005`，见 `packages/block-catalog/src/blueprints/lifecycle.ts:80-131`。

三方合并保留用户改动并把冲突路径、base、user、incoming 显式返回；`keep-user` 保留用户值，`upstream` 才采用新值。删除的新版 root 会生成可审阅的删除变更，恢复模式只覆盖指定实例内容，同时保留资源/模块绑定、用户坐标和折叠状态，见 `packages/block-catalog/src/blueprints/lifecycle.ts:132-235`。定向测试 `packages/block-catalog/tests/blueprint-lifecycle.test.ts:40-125` 验证角色冲突、正文更新、用户值保留、restore 变更和一次 ProjectController undo；另一个测试确认同一蓝图的两次插入只更新选中的 instance，见同文件 `126-169`。

CLI 将无 resolution 的冲突作为 `ready:false` 预览返回，只有明确 `keep-user` 或 `upstream` 才写出补丁；`projectModified:false` 在预览结果中显式返回，见 `tools/blocky-cli/src/construction.ts:222-264`。`tests/cli/blueprints.test.ts:139-218` 验证用户角色修改在 v2 更新中保留，官方原文件字节未被覆盖，更新后 instance version 为 2，模块仍绑定 `citation-service`。

### 用户功能：个人蓝图与视图直接影响

个人蓝图测试覆盖从真实顶层积木捕获、多栈相对位置、公开依赖 slot、插入新 ID 和 ProjectController 一次撤销；非法非顶层选择、摘要篡改、敏感字段和 ID 冲突均有拒绝证据，见 `packages/block-catalog/tests/blueprints.test.ts:59-101`。

组件测试还验证四个官方项目可启动并无编译错误；用户修改角色后预览 restore，项目摘要在预览、拒绝和接受前保持不变，接受后可 undo 回原摘要，见 `tests/component/construction.test.tsx:53-108`。个人库损坏时仍保留原始 `localStorage` 内容，同时官方 starters 继续可用，见同文件 `110-120`。

本轮没有真实操作 Shift 点击、框选、多栈鼠标布局或入门/专业视图切换。根据 S3-15 标准，这些行为不能由函数测试替代，因此只报告领域证据，不把 GUI 子场景写成通过。

### 用户功能：CLI 与桌面共享同一蓝图领域

CLI 的 `project.create` 校验官方 ID 后直接调用 `createBlueprintProject`，再通过原生 `createProject` 写入项目并读回产物摘要，见 `tools/blocky-cli/src/commands.ts:133-181`。桌面 `startBlueprint` 也直接调用同一 `createBlueprintProject`，再替换当前 ProjectController，见 `apps/studio-desktop/src/composition/useStudio.ts:290-315`。这证明蓝图构造领域没有另起 CLI 专用模板副本。

本轮曾执行 `pnpm exec vitest run packages/block-catalog/tests/blueprints.test.ts packages/block-catalog/tests/blueprint-lifecycle.test.ts packages/block-catalog/tests/starters.test.ts tests/cli/blueprints.test.ts`，退出码 0，4 个测试文件、17 个测试通过。随后单独执行领域与项目格式验证：

结果为退出码 0，5 个测试文件、19 个测试通过。CLI 测试期间发行构建仍在运行；测试后读回到 `tools/blocky-cli/dist/main.mjs` 和 helper 的 SHA-256 已变化，说明 dist 存在构建竞态。本轮没有重建 CLI/桌面，也没有把竞态中的工件 hash 当成稳定发行证据；CLI 结论以测试命令当时的退出码和领域源码为依据，完整 CLI/桌面跨入口一致性仍待冻结工件后复验。
