## 详细报告

### D4-R01：完整 blueprintInstance 内的 base 尚未在 JS 侧按目录白名单校验

位置：`packages/builder-protocol/src/validate.ts` 的新增 extraState 检查、`packages/block-catalog/src/blueprints/lifecycle.ts` 的 instanceSchema/blueprintInstance、`apps/studio-host/src/patch_guard.rs` 的 blueprint_state。

JS parsePatch 已拒绝泛 extraState，要求只能有 blueprintInstance；实例本体字段严格、根 ID/idMap 关系检查和禁止 base 嵌套 extraState 均存在。但 `base` 使用通用 workspaceBlockShape，其 fields 为任意 JSON record；blueprintInstance 不校验 base 的具体积木目录字段/必需字段。parsePatch 的递归秘密检查匹配字符串模式，未像 Rust safe() 一样拒绝敏感对象键。因而仅“完整实例形状”不能证明 base 中没有未声明状态。

Rust blueprint_state 最后调用 block_shape(base, strict=true)，会校验目录字段并由 safe() 检查整个补丁，因此该边界更严格。阅读 useConstruction 确认其落地 applyPatch 传入 Host 校验；未发现本轮可据此声称的桌面 Host 绕过。问题是 JS 预览/领域 API 与 Rust 不一致，JS applyPatch 的 Host 回调又是可选参数，因此应在 JS 同样验证 base 的目录形状，不能宣称双侧白名单已完全匹配。

失败判据：目录未声明的 base 状态在 JS 被当作合法实例/补丁接收，而 Rust 拒绝；敏感信息不应通过 base 元数据进入补丁。这里只报告静态逻辑，未构造输入或执行复现。

### D4-R02：chunkRefs 恢复检查未绑定 document 与 chunk 的来源/文档关系

位置：`packages/knowledge-core/src/store-schema.ts` 的 chunkRefs 恢复与最终一致性循环、`apps/studio-host/src/knowledge/index_guard.rs`、`packages/knowledge-core/src/sync.ts` 的 reusable 构建。

恢复逐 ref 查找 published chunk，检查其 sourceId 存在 pending.sources，最终检查 chunkId 唯一和每个 document.chunkIds 可找到对应 chunk。缺少 `chunk.sourceId === document.sourceId` 及 `chunk.documentId === document.documentId` 的关系校验。Host 当前只分别核对 documents/chunks 的来源属于可读 source 集合，同样不建立两者关系。

因此在同项目两个均可读来源的损坏缓存中，文档可能引用另一来源/文档的合法 chunk，仍通过存在性与 ACL 检查；sync reusable 会按文档键拿到错误 chunk 列表并在摘要匹配时复用。这不是已证明越权读取，也不意味着公开接口泄露未授权来源，但违反损坏检查点不得错误归属/复用证据的要求。

建议恢复后建立 chunkId → chunk 映射，对每个 document.chunkIds 同时检查 sourceId/documentId；并验证 chunk sourceId 均在 index.sources。失败判据：缺失、重复、跨源或跨文档关系一律拒绝，不允许通过 ref 间接恢复错误关联。未动态验证。

### 现有控制与用户改动保护

蓝图插入核对当前目标项目的资源类型、模块导出和 schema，实例 ID 全新且检查所有 workspace 的冲突；资源绑定只保存引用。更新按所选 workspace 与 instanceId 聚合，验证 blueprintId/digest/sourceRoot 一致，用 base/user/incoming 三方比较，冲突默认保留 user，显式 upstream 才覆盖。预览不修改项目；应用前校验 projectId/baseDigest，异步检查之后再次比较当前项目，再单次事务提交。Rust 同样校验项目身份、摘要、资源/链接与能力差额。

`migrateBlueprint` 单独校验 v1alpha1 schema/digest，生成 v1 与 migration.sourceDigest；普通 parseBlueprint 不静默接受 alpha。桌面导入 File 只读原文件，旧版进入待迁移状态；本机库迁移先生成并检查全部新内容、再备份原序列化 localStorage，最后替换正式库。既有 3D 局部报告记载原件、冲突、恢复/撤销的领域证据，但本审查未重新执行，不将旧结果升级为本次动态证明。

检查点写出只把与 published chunk 同一对象的未变化正文替换为 chunkRefs，恢复再交由 schema 校验；Host 仍分别校验 published/pending generation、grant 与 ref 对应来源。跨项目 storage scope 未变化。ACL 收紧仍失效索引并拒绝过期 CAS；embedding 最终发布/查询返回前仍做 epoch/授权检查。

缓存复用改为每 16 行检查取消及 epoch，实际推理仍每次开始前检查；binary cache 顺序读取使用 256 KiB BufReader，每 64 条记录检查取消，单条 checksum/向量校验未取消。此为有界批次而非取消保障删除；本轮没有测量取消延迟。384 MiB stdio 上限没有在这次去重改动中放宽。
