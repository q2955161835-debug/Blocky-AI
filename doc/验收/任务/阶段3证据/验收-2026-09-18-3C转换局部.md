### 用户功能：解析源码并划定可转换边界

Haystack 的 6 个符号均为 `native-retained`，包括 `bm25_retriever.py` 的 `__init__`（41–80 行）、`_get_telemetry_data`（82–86 行）、`to_dict`（88–103 行）、`from_dict`（106–125 行）、`run`（128–163 行）和类 `InMemoryBM25Retriever`（13–163 行）；报告还保留 embedding retriever 的对应行级 SHA-256 证据。由于存在状态、成员访问、调用和外部文档存储，系统没有生成虚假的可运行积木。

数值仓库的 `math.ts` 行 1 `double` 判定为 `custom-block`，行 2 `flow` 判定为 `blueprint`，证据摘要与行号写入报告。`flow` 的依赖为 `double`，候选包含 `core.data.transform` 的有界表达式和来源 provenance。独立领域测试还验证了 Python 与 TypeScript 的纯数值函数、闭合函数组合、动态/副作用/递归/强制转换/坏语法保留，以及包含循环、状态和方法边界的类只生成 `compatibility-draft`（`packages/conversion-core/tests/analyze.test.ts:4-78`）。冻结实现中决策枚举及行号计算位于 `packages/conversion-core/src/analyze.ts:12-30,40-45,91-139,141-183`；转换候选只接受带可验证程序的 `custom-block` 或 `blueprint`，并重新读取许可证与源码字节（`packages/conversion-core/src/candidate.ts:13-66`）。

### 用户功能：候选预览、运行和过期保护

独立的 `packages/conversion-core/tests/real-conversion.test.ts` 已验证以下用户可见约束（本轮也单独执行相关测试）：候选生成前项目摘要不变（9–29 行）；候选预览无诊断、可编译，并对 `-3、0、1.5、8` 得到 `-3、3、6、19`（29–44 行）；字符串输入不会完成（45–51 行）；接受后整体撤销恢复原摘要（52–55 行）；用户在审阅后编辑项目时再次应用候选会拒绝 `BLK-PATCH-001`（56–61 行）。篡改缓存的表达式不会被信任，来源字节篡改会拒绝 `BLK-CONVERT-CORRUPT`（63–80 行）。

CLI 曾先以不存在的模块 `main` 请求候选，按来源协议返回 `BLK-CONVERT-003`；随后使用实际模块 `research-agent` 成功生成候选。这证明模块绑定不会静默写入错误目标。候选声明依赖未安装，运行时为 Blocky 有界数值解释器，错误为 `BLK-EXPR-001/002`，没有把上游 Python 或 TypeScript 当作可执行输入。

本轮没有完成“桌面候选预览 → 接受 → 保存重开”的真实可视操作，因此不把该子场景写成通过。保存/接受/撤销和过期保护有组件及领域测试证据，但不替代真实桌面保存重开。

### 用户功能：重复分析、增量缓存与大工件边界

Haystack 二次分析报告显示 `analyzed:0,reused:6`、`sourceBytes:36567`；数值报告显示 `analyzed:0,reused:2`、`sourceBytes:1202`。两者均保持同一 snapshot 与来源摘要，变化报告为 `projectModified:false`。扫描器在 `packages/conversion-core/src/scan.ts:105-137,143-217` 按 snapshot 和分析器版本复用完整且可校验的缓存，分页读取时逐页检查来源元数据；`packages/conversion-core/src/scan.ts:312-335` 对源文件读回继续核对 snapshot、commit、artifact、SHA、大小、子目录、仓库和 dirty 状态。

本轮实际报告写入预算为最多 20,000 个文件、100 MiB 源码、单文件 2 MiB、16 MiB 分析输入；相关值来自 `packages/conversion-core/src/scan.ts:263-267`。Haystack 39,670 bytes 的完整 artifact 没有触碰项目文件。扫描和候选生成均保持 `projectModified:false`，没有覆盖用户项目修改。

### 用户功能：桌面入口的实际复验与阻塞证据

桌面第一次使用真实 Haystack 目录和数值目录均曾完成扫描摘要读回。之后开发资源热更新使窗口报 React 错误：`Error: Should have a queue. You are likely calling Hooks conditionally`，定位在 `useConversion` 状态 Hook 附近（当前源 `apps/studio-desktop/src/composition/useConversion.ts:16-23`）。重新加载后再次选择数值目录，转换弹层持续显示“选择仓库并读取锁定版本…”，按钮保持禁用；刷新窗口状态后点击“取消分析”也没有得到完成或错误摘要。该复现发生在工作区存在根 agent 未提交源码、Vite 热更新资源覆盖桌面调试窗口的条件下，不能单独归因于冻结桌面二进制；但它使本轮无法完成桌面候选审阅和保存重开，故 S3-16 转换子集结论保留为有条件通过。
