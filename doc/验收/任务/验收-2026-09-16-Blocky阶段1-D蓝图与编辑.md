## 详细报告

### 1. S1-04 个人蓝图和编辑行为

`packages/block-catalog/tests/blueprints.test.ts` 使用真实 `createStarter()` 项目验证了两组顶层栈捕获与重插入。捕获结果将模型/知识依赖和跨模块调用转换为公开 slot；插入时以偏移后的最小坐标恢复相对布局。测试确认插入的根 ID 不再是原 ID，并通过单次 `ProjectController.edit` 添加后一次 `undo` 恢复插入前项目。

同一测试文件还覆盖了非顶层选区、蓝图 digest 被篡改、生成 ID 与现有 ID 冲突、敏感字段和缺失绑定。独立负例进一步以真实 `createStarter()` 构造缺失 `local-composer` 资源和不存在的模块目标，两者都返回 `BLK-BLUEPRINT-002`；独立遍历捕获结果的根及嵌套块，确认所有新 ID 唯一且不在原项目 ID 集合中。探针没有写入项目或产品测试目录，执行后已删除。

`packages/ui-editor/tests/selection.test.ts` 验证了选择成员切换和顶层矩形相交。为了补足其只测纯函数的覆盖，临时 jsdom 探针为 `installSelection` 提供最小 Blockly Workspace 双块夹具，实际派发 pointer 事件，确认 Shift 点击不启动移动、框选只选相交顶层块、整体移动按 `ws.scale` 换算并保持两个块的相对距离。该探针验证的是可执行手势逻辑，不构成普通 GUI 或桌面视觉验收。

`apps/studio-desktop/src/composition/useConstruction.ts` 的蓝图保存、插入、复制、剪切和副本操作均经 `ProjectController` 或 builder patch 事务进入真实项目；组件测试确认保存到本机蓝图库、幽灵预览中的块可编辑、接受后一次撤销恢复摘要。编辑命令入口和画布组件消费同一选择状态；命令启用状态、原生菜单布局和快捷键视觉未在本轮扩大验收。

### 2. S1-06 来源候选与补丁审阅

`packages/conversion-core/tests/conversion.test.ts` 实际读取仓库内锁定快照，验证固定 commit `d72ed6cb37abebaefda8da39e3e7a5d8fffb2065`、版本 `v2.9.0`、许可证 `Apache-2.0`、源码证据和依赖声明进入候选。候选生成前后 `projectDigest` 不变；篡改快照哈希和已取消信号分别拒绝。实现使用本地固定文件，没有下载、安装或执行上游代码。
