## 详细报告

### 用户功能：生成并保存可审查的应用页面

#### 场景：不可信声明、源码、依赖与桥接

TS `validateSurface` 与 Rust `surface_guard::validate` 都按锁定生成器重建全部文件并逐项比对。独立探针分别修改 page.js、package.json 生命周期脚本、额外文件、目录穿越路径、关联模块及权限，六类输入全部被拒绝。`buildSurface` 仅处理已接受且重新校验的来源，不启动包管理器或子进程。用户/模型文字写入 template 前转义 `&<>`，运行时只经 textContent 或 DOM 属性赋值进入页面。

#### 场景：TS 与 Host 接受同一个边界输入

错误汇报 1（已修复）：Rust 原先按 Unicode scalar 计数，而 TS 使用 UTF-16 单元。51 个 emoji 标题被 TS 拒绝、Rust `source_files` 接受。实现方修改 `surface_spec.rs` 的 text/description 与 `surface_guard.rs` 的 displayName 后，原独立探针从 `rustAcceptedUtf16OverLimit=true` 变为 `false`；当前 `surface_spec` 2/2 通过。

错误汇报 2（已修复）：TS 在完整 draft 超过 100000 个 UTF-16 单元时拒绝；Rust `surface_guard::validate` 原先没有相同聚合上限。使用 12 个合法 select 字段、每个 20 个 200 字符选项，生成实际源码与合法 manifest/bridge，完整 draft 113069 UTF-8 字节。TS 拒绝，同一文件被真实 `blocky_studio::surface_guard::validate` 接受。影响为 Host 可接受前端无法加载的作品工件，没有证明任意代码执行或权限提升。实现方已在 Rust 对同一 `{manifest,files}` JSON 表达增加一致的 UTF-16 总量规则。原独立探针复验 `rustAcceptedOver100kSurface=false`，同时正常跨语言夹具保持通过。

原始可重跑探针：`try/stage5/security/surface-security.test.ts`、`src/main.rs`、`utf16-spec.json`、`max-draft.json`。Rust 探针链接真实 Host guard；UTF-16 source_files 探针 include 当前产品文件，不复制其校验实现。

### 用户功能：隔离并管理页面预览

#### 场景：两个页面间不能共享工作台权限

真实 Edge headless 加载产品 `previewDocument` 生成的 HTML，在两个 `sandbox="allow-scripts"` iframe 中验证：localStorage、Cookie、父 DOM、兄弟 DOM 均拒绝；页面没有 Tauri Host 对象；动态追加脚本被 CSP 拒绝；fetch 被拒绝且浏览器网络路由计数为零，排除由测试路由拦截造成的假阳性。兄弟 iframe 发起 `blocky.bridge.init` 后提交按钮保持禁用，父窗口用独占 MessagePort 初始化成功。10/10 检查为 true。

桌面 `SurfacePreview` 的端口闭包绑定 surfaceId、project 对象和该页面的关联模块；确认前、运行前与 Host 授权异步返回后再次核对当前 project 对象。项目切换、关闭、刷新与停止 dispose 旧 bridge/ports，并 abort 活跃请求。Host authorize_surface 验证主窗口可见、完整项目和页面存在。不把本浏览器探针当作普通 Tauri 候选原生 GUI 证据。

### 用户功能：提交页面输入并控制副作用

#### 场景：附件和表单输入不能取得原生文件访问权

bridge 只收附件文件名与文本，不接收原生路径。`../secret.txt`、Windows 路径、斜杠子目录及控制字符文件名被拒绝。超过 16000 UTF-8 字节的非 ASCII 附件、附件未超限但拼接请求总量超限、未知表单字段均拒绝；声明关闭附件时不能提交附件。来源文件由浏览器 File API 读取，不调用 Host 文件读取接口。

#### 场景：取消、拒绝与迟到结果

每个端口最多一个 active 请求；请求 ID 不可重放、seen 数量有上限。独立探针先等待确认，再关闭 bridge、随后返回允许，run 调用数仍为零；用户明确拒绝也为零。重放完成请求仅运行一次。现有 task-bridge 测试另验证错误 ID 不取消、正确 ID abort 及迟到答案不返回成功。确认框属于工作台，不受 iframe 内容控制。

### 用户功能：受控构建与恢复

#### 场景：四工具和 Provider 不能扩大侧车权限

当前固定侧车启动路径校验锁定 manifest、文件长度和 SHA-256，Node permission/no-addons 与固定只读脚本路径、清空环境、Job Object 仍保持。Provider 只在 Host 秘密存储闭包内拿到密钥，传输目标固定 HTTPS、禁代理/重定向、有取消与响应上限；没有把密钥加入侧车 IPC。模型仅收到 inspect 的资源 ID/种类/显示名投影，verify 编译候选，不运行作品工具。Provider 当前 2/2 动态负例覆盖任意工具、坏 JSON、数组参数、重复工具 ID、错误消息配对及未知字段。

复用 A/B 的真实侧车只读/回收、九类凭据形状与取消预算事实，未重复全盘跑。本轮不声称对所有未知秘密形状自动识别，也未执行真实供应商调用。

#### 场景：重新打开或恢复不会重新接受候选

`useBuilder` 只把候选保留在 React 状态，generate 由用户显式事件触发；过期摘要和 scope 清理丢弃旧响应。相关组件测试验证候选不修改项目、取消清空、编辑后迟到候选被拒绝。`useRecovery` 仅保存/读回 Project，`restoreRecovery` 显式恢复后不调用 Builder、run 或用户终端；恢复不携带审批或活跃请求。
