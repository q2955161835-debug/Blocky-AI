## 详细报告

### 有人值守 RPA

#### 场景：批准后打开隔离浏览器并绑定目标

`RpaHost::authorize_request` 在原生确认成功后才调用 `Manager::open`；计划经 Rust 协议验证，浏览器起点须与计划来源一致，随后以随机浏览器身份、项目 ID 和来源绑定 grant。Node `BrowserHost` 为每次会话创建独立 context，拦截跨来源请求与重定向，关闭额外页面。Rust 管理器持有独立进程和 Windows Job，固定运行资产须与锁定清单逐文件哈希一致。此顺序与隔离约束由本次代码路径复核，未把应用界面 iframe 当成可操控浏览器。

本次独立读回：`browser.mjs` SHA-256 `a6de7d2aabc2a49cf06d8a30c5b214181bb7a547eeee43860e63d7d87a2c4d7e`，`packages/rpa-core/runtime-lock.json` SHA-256 `4b02ca738b4bd6e73e3cb815a9d8463e1ac8f5849d4cc86535d67bad21023485`，均与开发索引一致。当前 CLI helper SHA-256 `a43b5e16c34410187e1cf27914f047ad67f77208a060e89e7714a788b2178768`。这只是文件来源读回，不是发行包完整扫描。

#### 场景：语义步骤、回执和停止结算

独立执行 `cargo test --lib rpa::browser::tests::real_browser_private_pipe_and_job_cancel -- --ignored --exact`，退出码 0，1/1 通过。自有本机 HTTP 页面由真实 Edge、锁定 Node 私有管道和 Rust Host 访问；测试读回页面，调用一次点击后读回计数 1，完成回执写入加密 journal，重复点击被拒绝；暂停/继续后停止等待中的步骤，读回状态 `stopped`，旧会话失效。另开新进程可正常退出，过期会话回收后目标不可再查。此测试的原生批准由可信测试入口替代，因此不证明普通包用户实际点击审批。

独立执行 `pnpm exec vitest run packages/rpa-core/tests/browser.test.ts tests/component/rpa-panel.test.tsx tests/cli/rpa.test.ts`，退出码 0，3 个文件共 12/12 通过。检查了浏览器来源漂移时拒绝动作、桌面表单将项目 ID/URL 交给原生授权、CLI 参数与控件交互。另据源码复核，Rust `step_with` 在副作用前持久记录 `uncertain`，调用成功后才标 `completed`；停止等待活动步骤结算，失败不应伪报成功。浏览器适配器在动作前查唯一可见语义目标，密码或敏感输入控件拒绝；截图和坐标回退在本批原生预检中拒绝。

#### 场景：浏览器执行记录与恢复边界

浏览器与 UIA 进入相同 `RpaHost` 会话、步骤顺序、回执和加密 journal，浏览器快照存不透明 Page 身份、项目 ID 与来源；旧 Windows 快照保留相容读取。`journal::Snapshot::summary` 的 `resumable` 来自 `recovery::eligible`，后者第一步要求 Windows 目标，浏览器目标返回 `BLK-RPA-RECOVERY-002`。CLI 同时给出浏览器起点和恢复请求也先拒绝。已保存浏览器回执只供人工检查，不授予跨进程重连、重放或自动核验能力。此边界符合本批限定范围，但不满足冻结最终验收中的浏览器检查点恢复。

### CLI 与桌面

桌面 `RpaPanel` 创建浏览器语义定位步骤，经 `composition/rpa.ts` 调用 `rpa_authorize`；CLI `rpa run` 携带 `--browser-url`、`--project-id` 进入原生 runner。两端随后使用相同 `RpaHost::step/status/pause/resume/stop`，而非各自执行网页动作。检查了执行前先停止已有会话、表单关闭时取消待审批与停止会话的代码路径。当前桌面页面只有组件级接线证据，冻结角色要求的普通包直接操作未执行。
