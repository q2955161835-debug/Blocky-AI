#### P1-01：输入正文经页面元数据反射进入草案

- 复现：本地 route 返回一个 textbox；页面先注册 input 捕获监听，在真实输入事件时把 `event.target.value` 写入该控件的 `aria-label`。随后启动录制并通过 headless Edge 实际 fill 合成正文。
- 实际：产生 1 个 fill 动作，`actions[0].locator.name` 与 `plan.steps[0].locator.name` 均含完整合成正文，`sensitive=false`、`omitted=0`。

- 建议：避免将输入后页面提供的自由文本视为已验证安全定位元数据；对可录制目标采用交互前受控元数据绑定并拒绝交互中的名称变更，或使用不携带页面正文的受控定位表示。不要单靠增加秘密正则修复这一通路。修复须保留此反射负例。

### 详细报告

#### 原生录制草案：纯元数据与目标绑定

UIA 启动时先核验 target、窗口根及 runtime ID，再为同 PID 控件建立目录。有 AutomationId 时不读 Name；没有 ID 时只读取启动时 Name。事件回调只读取 runtime ID/PID 并投递动作枚举，不调用 Value/Text pattern、不读取运行时名称；密码标记使用 IsPassword。不存在从事件正文生成定位名称的直接通路，但这不把原生应用提供的初始名称当作可信内容或执行授权。

协议拒绝额外 value 字段、非 click/fill、跨目标定位器和秘密样式元数据。结果绑定 session/project/target，plan 必须与 actions 重建值相等，最大序列化长度 60000；缓冲在 actions+steps 超过 49152 前封存。Rust controlType 采用 UTF-16 长度上限 80，与 TS `.max(80)` 一致。停止先 active=false，再移除订阅，失败返回 SETTLEMENT；成功后排空已接收事件并封存，重复停止不会追加结果。

#### P2-03：runtime ID 唯一不等于草案 Locator 唯一

- 位置：固定来源 `uia.rs:62–77` 和 `:188–197`。
- 证据：catalog 的 HashMap 只按 runtime ID 检查重复；AutomationId 存在时生成的 Locator 只有 automationId+controlType，省略 Name。drain 根据 runtime ID 取快照就追加，未检查最终 Locator 的唯一匹配。
- 可构造输入：同一目标窗口含两个 Button，runtime ID 不同，但 AutomationId 都为 `submit`；或者都没有 ID 且 Name 相同。它们均进入目录，任一 Invoke 事件都会生成无法区分两个控件的相同 Locator。
- 影响：捕获产生不唯一定位的草案步骤，未按歧义边界省略。未宣称此路径会绕过后续执行端的歧义拒绝；该结果也不产生执行授权。
- 建议：按最终定位器判断窗口根内唯一性，将有歧义项标为不可录制并计 omitted；补可独立于 GUI 的目录去重逻辑测试。本轮为静态可确认路径，未启动双控件 GUI 复现。

#### P2-04：有界队列不保证一次 drain 有界

- 位置：固定来源 `uia.rs:188`，`for ... in self.events.try_iter()`。
- 证据：接收者一直读取到队列当下为空；并发回调此时仍 active，能持续补充队列。达到 100 动作或时间/字节上限只封存 buffer，drain 不检查封存状态，也不停收，必须等循环退出才由 status 调 stop。
- 影响：持续事件源能延长单次 status 的处理，极端情况下不返回，从而延后停止和到期结算。容量 32 只限制瞬时积压，不能限定本次处理数量。本轮未执行真实事件洪泛，不能给出实际卡住时长。
- 建议：一次最多处理固定批量（例如 32），缓冲封存后立即停止接收并进入结算；补持续生产条件下 status 有界返回的非 GUI 逻辑测试。

### P2-03 剩余同边界负例

`unique_catalog` 按序列化 Locator 的完全相等计数，不能证明每个 Locator 在 UIA 根内仅匹配一个控件。例如同类型 Button A 有 AutomationId=`submit`、Name=`Save`；Button B 没有 AutomationId、Name=`Save`。生成的 A 定位器为 ID-only，B 为 Name-only，两键各出现一次，均被保留。但既有 `rpa/worker.rs` 的匹配逻辑只检查提供的字段：B 的 Name-only 定位器会匹配 A 与 B。

此为原定位歧义缺口的剩余情况，静态路径已确认，未启动 GUI 复现。应按实际匹配语义证明唯一性，或保守省略无法证明唯一的 Name fallback；不需要通过读取全部带 ID 控件的 Name 来扩大元数据采集。
