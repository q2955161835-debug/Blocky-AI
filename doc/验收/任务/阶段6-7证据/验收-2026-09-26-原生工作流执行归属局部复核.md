## 详细报告

### 1. 工作流执行：先建立归属再运行

原生启动使用明确可执行文件路径、UTF-16 参数引用、CREATE_SUSPENDED / CREATE_NO_WINDOW / EXTENDED_STARTUPINFO_PRESENT。HANDLE_LIST 仅含子端 stdin/stdout 管道，父端清除继承标志，stderr 复用私有输出管道。Job 只配置 KILL_ON_JOB_CLOSE，没有 breakaway 标志，绑定进程后才读取句柄对应 PID 和创建时间。

`Execution::resume` 要求本机 owner 匹配且已 arm。Store 在持有任务 lease 与总写锁时准备 profile/task/lease/owner/worker/job 绑定，先完成加密暂存同步及原子替换，再 arm；写入错误不能经过 arm。真实测试验证未绑定 resume 拒绝，绑定后才可通过私有管道启动自有 worker 与 descendant。测试另验证含空格、引号、中文、尾反斜杠参数往返，以及无关可继承 event 句柄不能被子进程置位。

### 2. 工作流停止与恢复：停止证明不代替业务回执

Worker stop 关闭输入，调用真实 Job 终止/结算，再检查 worker 进程句柄已 signalled；不能确认时返回 UNCERTAIN。Stopped 不能从 JSON 反序列化，其内容来自实际 Execution 的绑定；Store 对完整绑定等值核验后才写 settled。跨任务、旧 lease、重复绑定、停止后 resume/begin 的负例均拒绝。

真实树测试读回两个 Identity 在停止前存活、停止后退出。将停止证明写入账本后，业务 active 仍存在、resolve 仍拒绝、release 仍拒绝。Drop 会尽力停止进程，但不伪写持久 settled。真实 owner 进程在绑定后直接退出，后续进程仍读到 unsettled 并拒绝 acquire，即使尚未开始业务 intent 也不自动接管。

### 3. 归属隔离与创建失败

命名 Job 已存在时立即关闭本次打开的句柄并拒绝，不先包入会触发终止逻辑的 Worker，也不修改已有 Job 限制。独立运行对应测试，已有 Job 内的自有隐藏进程仍存活，随后由其原持有者显式停止。

静态检查：创建前的管道、属性表、Job 使用 RAII 回收；CreateProcess 失败未产生可运行 worker。创建成功后 assign/Identity 失败则尝试 TerminateProcess 并等待最多 2 秒；无法确认时返回 UNCERTAIN，已分配 Job 的句柄关闭仍具有 KILL_ON_CLOSE。该错误分支没有 resume。未通过故障注入模拟 Windows API 拒绝、TerminateProcess 失败或极端调度竞态，不把静态检查称为实测覆盖。

### 4. 账本与旧格式

新增 execution 为可省略字段，旧格式按 None 处理，不把旧记录当作已获得本批进程树凭据。存在绑定时必须匹配原生 profile、文件 task、envelope lease 与 owner，worker 非零且异于 owner、Job UUID 规范。公开 summary 仍从 record 投影，不包含私有 execution/owner/job 元数据。绑定和停止证据只能由内部 Rust 接口传递，前端 action 添加 settled 字段被协议拒绝。

旧通道尚未迁入，仍允许没有 execution 的原有 lease 流程；本批不能用于证明旧 CLI/桌面已有原生执行树归属。失去 owner 的旧 active 拒绝接管规则没有被放宽。
