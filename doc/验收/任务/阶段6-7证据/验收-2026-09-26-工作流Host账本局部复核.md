## 详细报告

### 1. 私有状态保存与执行租约

原生 Store 的目录由启动侧传入，prepare 拒绝相对、父级和重解析祖先；文件读取同时核对普通文件、重解析属性和上限，读取长度有界。记录以 BLKWF1 标记加 DPAPI 密文保存；解密后核对 profile、taskId、协议、owner/lease 成对存在及 active 必须有 owner。序列化明文缓冲在加解密后清零，返回给内部执行器的 Value 是私有状态，不能用作公共日志。

写入持有资料目录级 OS 文件锁；acquire 同时持有任务级 OS 锁、核对完整 definition 和 revision，以 native 当前 PID+创建时间+随机 lease ID 写入归属。Lease.commit 只接受状态转换并验证 owner/lease/current process；resolve 在磁盘层提前拒绝。Lease.release 仅在无 active 时清除归属；Drop 不清除磁盘 owner，避免把“对象离开作用域”误称副作用已结算。

共享 process_identity 对查询失败不认定退出；PID 创建时间不符可辨认复用，WaitForSingleObject 确认退出。RPA owner 改为委托并保留原 JSON 结构和错误码，静态差异未改变已有判定语义。

### 3. WF-HOST-P2-01：中断写入遗留文件阻断整个账本后续写入

**优先级 P2；结果不通过。**

位置：`store.rs:150` 的 capacity 枚举；`store.rs:162` 对非 task- 名称直接拒绝；`store.rs:193` 写入却使用 `.workflow-` 临时文件前缀。

普通替换失败会让 NamedTempFile 的 Drop 清理临时文件，已有测试证明此路径正常。但进程被终止或崩溃不会运行 Rust Drop。当前 tempfile 3.27 Windows create_named 只使用 FILE_ATTRIBUTE_TEMPORARY，没有 FILE_FLAG_DELETE_ON_CLOSE；故写出临时密文、尚未 persist 时退出可以留下 `.workflow-*` 文件。

下次写入先执行 capacity；该临时文件不是 workflow.lock，也不符合 task-*.bin/lock，因此返回 BLK-WORKFLOW-STORE。所有 create/acquire/commit/release 都共用此写入路径，一个工作流写入崩溃可阻断资料根中其他工作流。旧记录仍可读，此问题是恢复可用性缺陷，不是明文泄漏或自动重放。

最小独立负例（模拟崩溃遗留形态，没有声称已杀进程复现写入窗口）：

1. 设置 BLOCKY_WORKFLOW_TEST_ROOT 为本次 `orphan-profile`，以测试程序显式执行 ignored process_probe 的 create 模式：退出 0。
2. 将其已加密 task-task-one.bin 复制为同目录 `.workflow-revieworphan`，模拟 sync 完成、尚未重命名的密文临时文件。
3. 另进程执行同夹具 read 模式：私有状态读回断言成功；随后 tests.rs:262 的 acquire 失败为 BLK-WORKFLOW-STORE，退出 101。

证据：`orphan-create.log`、`orphan-read.log`、`orphan-result.log`，以及隔离 `orphan-profile/`。仅合成数据，未读取用户真实资料。

建议：在同一账本锁内识别自身受控遗留临时文件，执行有界恢复/回收或隔离；继续拒绝重解析点与无关未知文件，保持容量保护，不把临时快照自动提升为正式记录。增加崩溃遗留后现有任务及另一任务仍可写的回归。已即时通知主 Agent。
