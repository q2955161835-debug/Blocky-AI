## 详细报告

### 1. 桌面运行与私有状态

runtime_session_open/run 要求 main 窗口可见且不在关闭中；继续等控制也校验可见，收尾请求允许窗口关闭期间完成。RuntimeHost 保留随机 session token、capsule 和 active run；Renderer 的 run 请求严格字段不接受 state、路径或执行程序。固定 worker 由原生选择/校验并放入 Job，前序权限继续由既有服务 adapters 承担，没有新解释器。

原生只向 Renderer 发 ready、event、service、settle，正常返回 result，capsule 留在 native Session。正式原生测试验证跨 run 状态、拒绝导入 state 和失败会话不可静默继续；独立 facade 负例验证异常 native result 若带 state 也拒绝发布并标记需重启。

### 2. 调试、取消和退出

active 先登记后发 ready；前端取消发生在原生注册前时记录 abort，ready 后重新发送取消。请求绑定 session/run；取消用原生原子标记，不依赖满队列 enqueue；服务和控制队列有上限。worker loop 有总期限及取消后的短期限，最终停止树并要求网关收尾。

DesktopRuntime 拒绝并发 run、disposed 或 broken 会话。未启动就取消不污染会话；已启动失败提示重启。useStudio 的实际 isTauri 分支选择 DesktopRuntime，退出 settle 明确等待 dispose；StrictMode 的假卸载通过延后实际 dispose 避免误销毁。原生 finish_exit 增加 RuntimeHost.shutdown，active 时先取消并拒绝退出成功回执。

未实测窗口可见性、通知区域或实际退出界面；本节窗口授权来自静态核对，组件是模拟 Tauri。

### 3. 结算失败与工作流租约

desktop_run 先调用 worker.settle_process，再发 settle 给前端网关。只有 services_settled 和真实 stopped 均成功，Custody 才保存各任务停止凭据；无 active 的任务此后才能 release。缺 ACK、ok=false、worker 停止失败均不写可复用 settled。业务 active 不因本地停止被清除，resolve/replay 未开放。

真实原生测试验证待审批任务成功结算后可重新 acquire；服务失败时 execution.settled 仍 false，结算期间无法抢占 lease。独立 facade 探针验证 agent.close 失败会发 settled:false、不发布伪 completed、不接受后续运行；原始异常正文被替换为公开错误。停止本地进程并不证明远端未知业务效果已结算。

### 4. CLI 共用 Custody 与构建边界

静态逐项对照 managed 提取：open/read/commit/close 约束保持；CLI 仍先停止整个 worker，再 custody.settle(true)，既有工作流当前通道检查未移除。没有重复解释器或新依赖。本轮不重复主方已运行的公开 CLI 全部直接回归。
