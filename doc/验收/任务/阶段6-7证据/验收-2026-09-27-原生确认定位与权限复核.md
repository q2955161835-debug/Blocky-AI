## 详细报告

### 原生授权

#### 明确批准与拒绝

`native_confirmation.rs` 仅在 `placement.placed()` 成立、父窗口仍有效且 RFD 返回 `MessageDialogResult::Yes` 时返回 true。无 HWND、安装钩子失败、定位失败、RFD 错误或 blocking 任务错误均不会返回批准。未发现以非空结果、任意按钮或错误结果代替批准的路径。

五处迁移保留预检及请求摘要，确认后仍调用 `window_lifecycle::visible`（通过 guard 或直接调用）。该检查要求 main 窗口、非 closing、可见且未最小化；外部调用无法借此替换父窗口标签或绕过原有预检。此判断只覆盖本次迁移，未审计无关业务内部实现。

锁定 rfd 在当前 `default-features=false` 配置下同步调用 `MessageBoxW`，`IDYES` 才映射为 Yes。其 `MB_YESNO` 不提供 Cancel 按钮；Escape 不能按取消按钮等价推断，实际拒绝应测试“否”。依据：[MessageBox 官方说明](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-messagebox)。

#### 父窗口失效

安装前、定位时、对话框结束后均检查同进程、可见及非最小化。调用方随后再检查应用 closing 状态。即使确认期间窗口隐藏，当前代码不会直接据先前位置或 Yes 结果授权。窗口关闭/隐藏期间对话框能否及时退出，仍需运行证据。

### 确认框定位

#### 确认框仅影响所属窗口

WH_CBT 使用 `GetCurrentThreadId()` 安装，RFD 同步调用也位于同一 blocking 线程。状态通过 thread_local 保存，已有状态时拒绝再次安装。匹配还要求当前进程、精确 GW_OWNER 和系统对话框类 `#32770`；未发现全局钩子、跨进程枚举、广播消息或模拟批准输入。

位置由父窗口矩形与最近显示器工作区的交集计算，采用 i64 中间运算，尺寸非正或无法容纳时拒绝；支持负显示器坐标。移动后读取实际矩形进行比对。钩子通过 RAII 释放，状态随之清除。只在第一次匹配激活时定位，因此本报告不宣称其会持续限制用户拖动后的范围。

#### 定位失败自动收尾

`windows.rs:87` 通过 `PostMessageW(dialog, WM_COMMAND, IDNO, 0)` 请求拒绝，但未检查投递返回值；随后返回 1 阻止激活。官方文档明确，HCBT_ACTIVATE 的非零返回阻止的是激活，不代表销毁窗口；PostMessageW 可以失败。因此源码可证明“不批准”，不能单独证明“无挂起地返回”。

补证已闭合正常定位失败分支的收尾疑问：独立读取 `windows.rs` 的 opt-in 测试 `native_unplaceable_prompt_returns_no_without_user_input` 及 `try/stage7/native-confirmation-review/native-refusal-test.log`。测试创建位于 (0,0) 的可见 80×80 自有 owner，安装实际 Placement 钩子，调用真实 `MessageBoxW(MB_YESNO)`；随后断言返回 IDNO、placed=false、调用耗时少于 2 秒、Drop 后 STATE 为空，并执行 DestroyWindow。日志显示该完整名称实际执行 1 项、1 项通过、0 ignored、耗时 0.29 秒；未将先前 0 项运行计为证据。测试不是模拟回执，也未点击按钮。

未检查 PostMessageW 返回值仍是实现事实，但当前没有可复现的同线程有效窗口投递失败路径；不能据泛化 OS 失败可能性将其列为本轮必修缺陷。此原生测试已证明所关心的“空间不足→拒绝→返回→状态清理”路径；不证明任意系统资源耗尽或所有 API 错误均可恢复。测试直接调用系统对话框，未走 Tauri/RFD 公共包装与普通包业务调用，后者仍由 GUI 验收补证。相关 API 语义依据：[CBTProc](https://learn.microsoft.com/en-us/windows/win32/winmsg/cbtproc)、[PostMessageW](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-postmessagew)。
