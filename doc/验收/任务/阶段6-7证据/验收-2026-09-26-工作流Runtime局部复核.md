### 2. WF-RT-P2-01：终态恢复重新投递已消费事件

**P2；不通过。** 位置：`packages/runtime-core/src/workflow/runtime.ts:203`–205。

当前仅在 completed/compensated 时跳过预算恢复，仍调用 agent.restoreCheckpoint；EventMailbox.restoreCheckpoint 允许将非空旧快照导入当前空队列。已完成任务重开因而会重新引入已消费事件，并可能恢复旧可变记忆。

独立探针仅使用公开 Runtime.run 和合成内存 WorkflowPorts，顺序为：

1. 完成一个发送 jobs={saved:true} 的工作流。
2. 同一 Runtime 的普通入口消费该事件并输出 {saved:true}。
3. 以原 workflowTaskId 重开同一已完成工作流。
4. 普通入口再次消费到同一 {saved:true}，运行 completed。

实际日志：first=completed、consumed={saved:true}、terminal=completed、replayed={saved:true}。恢复没有重新执行原动作栈，却重投了其队列结果，违背不可隐式重放边界。测试没有真实 Host 或外部副作用，不能声称已在产品产生重复执行。

建议：终态恢复只读投影保存结果，不重新注入可变 sessionMemory/mailbox；若要恢复终态关联事件需另有受控、可核对消费状态的契约，不能把空队列当未消费证据。增加同一Runtime完成→消费→终态重开→再次接收为空的回归。

### 3. WF-RT-P2-02：恢复引用重验绕过可取消等待

**P2；不通过。** 位置：`packages/runtime-core/src/workflow/runtime.ts:196`。

恢复有 collectionId 的引用时直接 await validateCitations，而现有 AgentExecution 同类服务调用使用 abortable。合成合法检查点含一条 collection 引用，重验服务返回永不 resolve 的 Promise；进入重验后外部 AbortController 取消，150ms 探针观察仍为 still-pending。源码没有将 signal/预算到期与该 Promise 竞争，若服务不配合，运行及 handle.close 都无法到达。

本探针使用受控内存记录和纯 Promise，没有网络访问；在打印结果后退出独立脚本进程，不遗留运行。它验证“服务不响应取消”边界，不声称实际引用服务已发生故障。

建议：复用既有 abortable 包装，取消后拒绝恢复上下文，确保 finally 可执行关闭；底层服务/实际Host任务结算仍按接口契约独立完成。

上述两项证据均为 `try/stage7/workflow-runtime-review/probe.ts` 与 `probe.log`，运行命令 `node node_modules/tsx/dist/cli.mjs try/stage7/workflow-runtime-review/probe.ts`，退出0（探针记录错误行为，并非通过断言）。已即时通知主 Agent。
