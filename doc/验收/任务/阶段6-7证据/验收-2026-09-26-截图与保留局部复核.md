## 详细报告

### 浏览器截图

#### CAP-P1-01：contenteditable 溢出正文未被遮盖

- 位置：`packages/rpa-core/src/browser.ts:80` 附近的 mask locator 与 `target.screenshot`。
- 条件：可编辑元素存在可见溢出；这是合法 CSS/DOM，不需要越过 Host 或执行权限。
- 实际复现使用冻结源码的 `BrowserRpaAdapter` 和无界面 Edge，路由到纯本地合成 HTML：外层 main 为 500×200 白色背景；内部 `contenteditable=true`、role=textbox，样式 `width:20px;height:10px;overflow:visible;outline:none;font:24px monospace;white-space:pre;line-height:30px`。
- 先 focus 该元素并截空值，再填写合成字符串 `SYNTHETIC_PRIVATE_CANARY` 并截图。两次都走实际 adapter 的 screenshot 分支，均返回 maskedRegions=1；去除焦点样式、保持焦点不变后，图片从 810 字节变为 3861 字节，equalAfterTyping=false。
- 实际读图证据：`try/stage7/capture-review-temp/overflow.png`。黑框仅覆盖左上 20×10，完整合成字符串仍可见。并非只依据 PNG 字符串扫描或字节差异判断泄漏。
- 实际命令方式：PowerShell here-string 作为参数，`node node_modules/tsx/dist/cli.mjs -e $captureProbe`；直接导入 `./packages/rpa-core/src/browser.ts`，Playwright `chromium.launch({channel:'msedge',headless:true})`；两次完成复现均退出 0。第一次 pnpm/tsx 启动未产生可观察输出，未计入证据。
- 影响：用户被告知输入区域已遮盖，但可编辑输入正文进入返回 PNG；后续 PNG 规范化、DPAPI 和导出不会移除这些已绘制像素。
- 建议：遮盖输入/可编辑渲染子树及其溢出内容，或无法确认时拒绝保存；补 contenteditable 溢出、子元素覆盖样式以及取消/失败后恢复的实际无界面负例。仅增大固定黑框或修改提示不能关闭问题。
- 状态：已通知主 Agent；修复开发中。本报告不预先关闭，358ef15 原失败证据保留。

### 图片保留与删除

#### CAP-P2-01：异常退出遗留暂存没有到期与容量管理

- 位置：`apps/studio-host/src/rpa/mod.rs:551`、`capture_windows.rs` 最后写文件分支、`captures.rs:135`。
- Windows worker 先把 DPAPI 加密 PNG 写入 `rpa/capture-staging/<TempDir>/capture.bin`，Host 读回后依赖 TempDir 的正常 Drop 移除目录。Host 在写盘完成后被强制结束/崩溃时不会执行该 Drop。
- 静态全局定位 `capture-staging` 只有 staging() 创建路径；没有启动/列表/写入时的遗留清理。Store.scan 只遍历 `rpa/captures`，24 小时有效期、32 项和 128 MiB 上限都不覆盖 staging。
- 影响：加密图片仍保留在用户资料根中，列表不可见，不能通过截图列表删除，也没有 24 小时清理或容量上限。这里未声称泄露明文；问题是实际保留超出声明与可管理范围。
- 验证方式：静态异常退出路径，不启动 Windows 捕获或人为杀真实目标。未把正常 TempDir 删除测试宣称为崩溃恢复证明。
- 建议：为暂存项建立持有者/跨进程锁与过期清理，在明确非活跃后回收；异常/到期暂存计入有界管理，不能清理其他进程仍在写的项。可先用纯文件存储 fixture 补回归。
- 状态：已通知主 Agent，待修复来源及定向复验。

### 授权、目标与图片传输

截图操作来自已批准 plan 的下一步，普通块新增 rpa.capture 权限；Host 未开放任意屏幕或任意路径截图接口。Windows capture_path 由 Host 的暂存目录生成。浏览器请求绑定随机 Page identity、token、stepId；分块再绑定 captureId、严格 offset 和过期 grant，不能把任意外部图片当作已批准步骤返回。

BrowserCapture 每块最多 32768 原始字节（Base64 43692 字符），在 64 KiB 私有帧内；Rust 接收检查总量、每块长度、连续 offset、done 与精确最终长度。最终块清零原缓冲并拒绝重放；新步骤、关闭、捕获错误清除会话缓冲，接收失败走 Manager shutdown，SETTLEMENT 错误不被成功图像结果替代。以上为静态检查和有序分块单元证据，没有虚构真实取消捕获的运行记录。

Windows 仅使用绑定 HWND 的 PrintWindow 到自有 DIB，不调用桌面 DC 拷贝；目标像素裁切要求完全在窗口内。捕获前后核对窗口矩形、根及元素 runtime ID、元素范围和完整遮盖目录；输入/文档/面板及密码区域加入遮盖，异进程提供者或查询失败拒绝。DIB 与 RGBA 正常路径回收清零。**真实 Windows PrintWindow、DPI/遮盖和目标变化运行验证未执行**。

### 正常存储与用户接口

PNG 限 4 MiB 和 2048×2048；解码内存有上限，拒绝动画并重编码去除附加元数据。Store 文件包含严格元数据、图片摘要和 PNG，由 DPAPI 加密；固定 UUID 文件名、重解析点拒绝、有界读取、锁内扫描/发布、独占发布不覆盖。正常 store 项到期后在访问/刷新清理，最多 32 项和 128 MiB；异常暂存缺口另见 CAP-P2-01。

桌面只有显式查看才请求 data URL，显示到期时收起；删除后移除当前图片。Host 接口限定可见 main 窗口；原生导出需用户选文件且 create_new 不覆盖。CLI 对 ID/Schema/摘要/PNG 签名核验，输出只含元数据与文件摘要，通过同目录临时文件加不覆盖链接发布。实际 CLI 正反例确认现有目标内容保留，删除后无法再导出。

运行时截图结果核对 checkpointId 和 stepId 后放入本次运行数据，只保留图片引用/元数据；没有 PNG、Base64 或 data URL 写入 RuntimeEvent。本轮运行时测试覆盖此界限，不外推其他任意数据块的行为。
