## 详细报告

### 桌面自动化

#### 场景：查询持久执行记录

使用独立资料目录 `try/stage7/native-desktop-gui/profile`，运行现有 `tests/e2e/studio.e2e.ts` 中的 `queries durable RPA receipts through the native desktop entry`。原生桌面打开命令搜索、进入桌面自动化面板、刷新执行记录，显示无记录且审阅按钮禁用。此项未执行 UIA/浏览器动作或恢复。

### 桌面运行

#### 场景：模板、多模块与条件输出

同一测试进程继续运行 `opens a starter and preserves legacy multi-module runtime and navigation behavior`、`runs stage 4 conditional JSON output and saves new semantics through native storage`。资料问答模板进入实际编辑器；固定回归夹具通过桌面运行得到包含“叶绿素”的回答与资料来源，轨迹链接可跳至“引用服务”并返回“研究助手”。阶段 4 语义项目经原生存储返回 `same=true`、`minimumReaderVersion=0.4.0`，两次桌面运行分别产生 `"ok": true` 与 `"ok": false`。这些夹具没有真实外部模型请求。

### 架构起点

#### 场景：状态机连续输入

运行 `creates an architecture starter and retains state through desktop input runs`。重新加载页面后选择“有限状态机”架构起点，三次桌面输入依次验证运行状态 `running`、`done`、`done`。这覆盖 WebView 发起的原生桌面 Runtime 连续运行路径，不覆盖独立任务审批或未知副作用恢复。
