## 详细报告

### 授权与几何绑定

Windows preflight 从当前有效 Target 取得新 Frame，坐标须同时在客户区和虚拟桌面内。Frame 包含窗口、物理客户区、虚拟桌面及 DPI；insert_checkpoint 对所有 Windows 坐标步骤要求匹配的有效 Frame，即使从内部 Prepared 进入也不能在无几何绑定时生成 session。Frame 保留于原生 Session，逐步请求从保存计划及 Frame 构造，调用方不能通过 step 请求改坐标或几何。

整体计划和逐步确认均说明高风险、物理像素、负方向坐标、聚焦目标和移动系统鼠标。worker 只有 approval::show 返回明确允许后才调用 activate；取消/关闭批准窗口不会进入激活分支。activate 先重新核对 Frame，随后请求前台并读回，失败不返回批准成功。原生确认结束后的取消/过期检查仍位于原有 Host 链中。

以上是静态与纯逻辑证据，不构成真实批准/拒绝时的焦点行为证明。

### 物理输入与拒绝条件

线程进入 PER_MONITOR_AWARE_V2，GetWindowRect、GetClientRect+ClientToScreen、GetSystemMetrics 虚拟桌面和 GetDpiForWindow 构造物理 Frame；SetPhysicalCursorPos/GetPhysicalCursorPos 与 CLI 的 screen-physical-pixels 一致。TS/Rust 都允许 Windows -32768..32767 有符号整数；浏览器仍拒绝负坐标，未混用 CSS 像素。

调度先观察并核验，再移动指针，第二次观察核验并要求实际指针等于目标点，才派发连续 left-down/left-up。观察拒绝目标身份/根异常、密码元素、不可用或离屏元素、Frame/DPI变化、非目标前台/命中根、遮挡、捕获/菜单/移动状态、任意已按下键及 ClipCursor 越界。最终 SendInput 前再做 Frame、前台、光标、命中根、按键和遮挡检查。顶层遍历有界且拒绝可能遮挡的禁用/透明窗口；没有通过坐标绕过 IsPassword 的代码分支。

这不是操作系统的原子“观察并点击”事务；窗口/输入状态仍可能在最后观察与派发之间变化。本轮没有运行真实 API 去证明所有原生竞态被消除。UIA/Win32 的实际可用性及自有窗口一次计数须后续独立真机证据。

### 取消、部分插入及回执

初次观察或边界失败时调度没有移动和点击；移动后的第二次观察失败时已有1次指针移动但0次点击。取消与拒绝的证据必须区分这两个时点，不能将后者写成“完全没有任何输入”，也不能宣称取消能撤销先前已完成的移动。

click_pair 返回2才成功；返回0或1均返回 COORDINATE-003，不自动重试。只有返回1时尝试一次 left-up 释放已插入的按下；释放结果不能被解释为重试成功。Host 在副作用前先持久化 uncertain，失败保留该状态，既有顺序及回执条件阻止自动重复步骤。本轮纯测试覆盖0/1的次数与取消分支；实际部分插入、原生取消及释放效果均未执行。

### 桌面、CLI 与权限

桌面明确显示屏幕物理单位、负方向显示器说明和当前客户区/DPI。坐标变化、添加后重置风险勾选，组件 key 绑定目标类型和 identity；切换目标重新输入并勾选。目标列表几何是只读发现，真正授权采用新快照，不把旧界面数字当作授权事实。

CLI validate 返回 screen-physical-pixels 和聚焦/指针风险；Windows负值通过 Schema、计划转普通块与 native patch guard。rpa.coordinate 权限不被 riskAccepted 代替：漏掉新增权限的补丁接受被拒绝，完整权限接受成功。补丁接受仍不产生运行 grant。非坐标/旧 UIA 路径保持可选 Frame 默认None。
