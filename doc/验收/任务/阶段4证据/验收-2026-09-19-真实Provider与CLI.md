## 详细报告

### 切换无网络与真实模型（S4-03）

#### 场景：受控文本分析工具与结构化结果

同一公开虚构两行文本先以 `--simulate` 运行，再以 `--live --interactive` 运行。两次均经 `text.analyze/v1` 完整摘要批准，结构化结果均为 21 个字符、2 行、4 个词，并生成可解析 UTF-8 JSON。模拟模式 `modelApiCalled=false`；真实模式逐字段核对 Provider 预检中的官方 HTTPS 端点、资源、模型、1024 输出上限和 60 秒超时后才回填完整摘要。

成功 live 响应：Provider `deepseek`，实际模型 `deepseek-flash`，响应 ID `68cee3e4-73a8-48fb-b9a6-6acbc6111c08`，输入/输出/总 Token 为 131/76/207，完成时间 `2026-09-19T14:28:02.124Z`。导出文件 `live-tool-output-v3.json` 为 50 字节，SHA-256 `8b1a0fa38ed26d5a8cd0fcd6907c95e12d284dfd84e6cc9cdbd466569d020234`。

首个 live 响应确实到达供应商并返回 109/130/239 Token，但模型生成了未授权来源标记，产品以 `BLK-GUARD-001` 拒绝整次运行，没有把部分结果冒充成功。第二个登记尝试因交互批准未匹配而以 `BLK-APPROVAL-001` 本地终止，`modelApiCalled=false`。验收随后收紧公开夹具指令并单独登记新尝试；没有自动重试。

结论：通过。

#### 场景：有效知识问答与无证据拒答

公开虚构资料经正式 CLI 增量同步为 1 个块。模拟模式从真实本地索引返回可定位引用且零外发；live 模式按预检批准后回答“每周三 16:00、携带蓝色预约卡”，只引用当前允许的块 ID。Provider `deepseek`，实际模型 `deepseek-flash`，响应 ID `10248f57-08dd-43d8-913b-6d8a5a6536c4`，输入/输出/总 Token 为 204/72/276，完成时间 `2026-09-19T14:30:21.406Z`。JSONL 事件序号 1–16 连续且有序，最终 `status=completed`、`modelApiCalled=true`、引用数 1。

无证据夹具先建立有效空索引（0 文档、0 块），再使用 `POLICY=require` 的引用护栏以 `--live` 运行。结果在本地返回“资料没有提供足够依据，请补充资料或澄清问题”，`generations=[]`、`modelApiCalled=false`，没有出现 Provider 批准提示，也未增加请求账本计数。

结论：通过。

### 读写及删除记忆（S4-07）

#### 场景：项目作用域跨进程重开、隔离和删除

正式 CLI/Host 以项目作用域写入公开虚构值；关闭该 CLI 进程后，以新进程重开同项目并读回完全一致的值。另一 `projectId` 的读取返回空值，随后因声明为字符串的输出 Schema 不接受空值而以 `BLK-OUTPUT-001` 结束，没有读出第一项目内容。删除操作通过完整摘要批准并完成；再次以新进程重开原项目读取时同样为空。Host 存储文件读回为 2 字节空对象，证明删除跨进程持久。

本轮动态结果与安全专项已经通过的单次批准、跨项目/会话拒绝、容量失败保持旧文件一致；该专项未在此重复执行。

结论：通过。
