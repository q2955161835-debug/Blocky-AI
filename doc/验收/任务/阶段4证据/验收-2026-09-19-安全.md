## 详细报告

### 授权并调用工具 / 读写记忆
#### 场景：批准跨 helper 生命周期、篡改及过期

独立 `cross-process.ts` 每次以 `spawnSync` 新启动实际 `apps/studio-host/target/debug/blocky-project-io.exe`，将 LOCALAPPDATA 仅在子进程中重定向至本项目虚构隔离目录。工具预检、首次执行成功；第二次执行和再次预检返回 `BLK-PERM-001`。更改输入、项目、run ID 的请求不能消费原批准，未篡改原请求仍可执行。记忆写同样只能消费一次。将该虚构 ledger 的对应条目设为合法结构的过期时间后，消费和重新预检均拒绝；损坏虚构 ledger 后返回 `BLK-APPROVAL-IO`。Ledger 文本不含输入中的虚构私人标记。

Provider 源码在调用网络前使用同一 `approval_ledger::consume`，身份含 provider/project/request；预检才 issue，完整请求摘要匹配。该共同控制已通过原生进程测试；没有真实 Provider 请求，因此不声称验证了供应商重复计费。Ledger 本地文件属于可信 Host 存储，本轮不将已能任意修改本机应用数据的恶意同用户进程作为阻断模型。

### 停止运行
#### 场景：响应头或正文一直等待

原先三秒响应头延迟的同一独立探针现为 **29ms** 返回取消。新独立本地 HTTP 探针对响应头阶段、部分正文阶段分别取消：返回耗时 **25ms / 31ms**；服务端确认连接 EOF/断开耗时 **54ms / 61ms**（从服务端进入等待起计，含取消前约 30ms）。均低于两秒，无迟到成功内容。使用直接包含生产 transport.rs 的 Rust harness，仅测试 endpoint 使用本地地址；生产 async exchange/select 路径未替换。

### 获得文件输出
#### 场景：写入、取消、目标冲突和发布失败

直接调用生产 `atomicOutput`，真实文件系统验证完整 UTF-8 内容。已有文件目标触发拒绝并保持旧内容；预先取消不创建目标；32 MiB 虚构内容写入中取消，最终目标不存在；以目录作为目标触发发布失败。所有场景后目录只有已确认完整文件、原已有文件和预建目录，没有临时文件。源码确认 `run-agent.ts` 已调用该实现，临时文件在同一目录写入并 fsync，hardlink 发布提供 no-clobber，finally 清理临时名称。未实施物理断电或真实磁盘满故障；不外推文件系统的断电持久性。

## 详细报告

### 授权并调用工具（S4-05）
#### 场景：重放已批准 CLI 请求

失败位置：`apps/studio-host/src/agent_data.rs:292`。`dispatch` 每次建立新的 `AgentData`，`used_tools` 只在当前对象内。独立用相同项目、运行、请求 ID、输入及 SHA-256 批准两次调用生产 `dispatch`，两次均成功。入口 `native-store.ts` 每次启动新 helper 进程，因此该边界与产品调用方式一致。当前登记工具是纯文字统计，本例未造成文件副作用；但 S4-05 明确要求拒绝票据重放。Provider `dispatch` 同样每次 `ProviderHost::default()`，静态可见同类请求去重失效；本轮没有真实请求证据，不能宣称已产生重复供应商计费。

验证标尺：入口可达、批准完全一致、重复执行真实函数、未替换权限实现、区分纯工具影响与模型潜在计费。五项均满足；Provider 实际重复计费明确未验证。

通过对照：同批准下改输入返回 `BLK-PERM-001`。桌面 Host 同实例使用 used 集合，未将 CLI 缺陷泛化为桌面重放绕过。桌面原生对话框对完整请求摘要确认，前端不能直接将 approved=true 传入原生命令。

### 停止运行（Provider 取消边界）
#### 场景：服务器已收请求但延迟响应头

失败位置：`apps/studio-host/src/provider/transport.rs:101`–`106`。独立 harness 直接通过 `#[path]` 编译生产 transport.rs，调用其测试传输入口；仅放宽 endpoint 到 127.0.0.1，其他 send/consume 为生产代码。服务收到请求后通知测试线程、延迟三秒再发送响应。此时设置实际 AtomicBool 取消标志；测试观察 3000ms 才返回 `BLK-PROVIDER-CANCELLED`，失败断言为少于 2000ms。

验证标尺：取消发生在请求收到之后；在实际阻塞 send 中；采用合法成功响应；读回稳定取消码；测量取消到线程结算。均满足。原因是标志不能中断 blocking send；consume 的阻塞 read 有相同静态边界，未额外重复构造该路径。

限制：Runtime 的 `abortable` 可提前结束 JavaScript 等待，迟到内容被丢弃。本失败是 Host 网络任务结算而不是断言用户聊天一定三秒才停止；真实供应商计费不在本轮证明范围。

### 获得文件输出（S4-10）
#### 场景：CLI 指定 --output 后写入失败或取消

失败位置：`tools/blocky-cli/src/run-agent.ts:38`。当前 `writeFile(..., {flag:'wx'})` 直接创建并写最终目标；没有同目录临时文件、原子发布及失败清理，也没有将 signal 传入写操作。wx 能防覆盖已有文件，不能保证磁盘错误或进程中止时没有半成品。属于高置信源码结论；未破坏用户磁盘、未制造真实 ENOSPC，因此不冒充动态故障证据。

验证标尺：CLI 公开 output 入口、完成结果触发、写最终文件 sink、无原子控制、说明动态缺口。前四项源码确认，第五项在此明确。桌面导出不接收客户端路径，原生选择目标后再临时写入并 persist/persist_noclobber；该实现不受上述 CLI 缺陷自动影响。

### 记忆和秘密（S4-07/14）
#### 场景：虚构标记、授权隔离与错误输出

独立动态通过四项：跨项目/会话/撤销 grant、超限写保持原文件并隔离第二项目、工具参数变化拒绝、畸形 Provider 返回不回显虚构错误正文。记忆存储文件名只接受稳定小写标识，没有客户端路径；生产实现保留 grant 锁到原子提交并限制单值/总容量。现有 Host 单测只作为代码背景，不计入本轮六项独立结果。

源审另外确认：main window 可见性/关闭状态门禁；模型、工具原生批准不可由前端 digest 字段替代；Provider 请求结构拒绝未知字段，资源绑定需匹配 Host user registry，目标固定，秘密仅在 Host 调用内解密；secret IPC 只有导入/状态/删除，没有明文 getter。导入在原生文件选择后返回 bool。模型选择仅变更模型资源引用；输出 DOM 使用 React 文本，不通过 HTML 注入结果。

未覆盖的证据必须保留：原生 UI 对话框实际操作、发行包四目标敏感扫描、传输层所有状态组合、授予记忆权限后的全部业务流程、最终交付版本。上述限制不得在汇总任务中被改写为本专项全部通过。
