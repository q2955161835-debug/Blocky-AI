## 详细报告

### 1. 领域级 Agent 配置与可移植项目

验证步骤：解包 `POC与演示视频/Blocky-自然科学课程助教-Agent.blocky`，读取 `manifest.json` 和 `project.json`；递归核对根 Agent、聊天入口、积木类型、知识源 ID、稳定 ID 和序列化文本；扫描固定回答、`core.data.literal`、秋叶专用知识源及额外 ZIP 项。

预期结果：项目只保存“自然科学课程助教”的通用处理链：拆解 → `knowledge.course.primary-science` 检索 → 证据重排去重 → 模型合成 → 无依据护栏 → 引用绑定 → 标题与列表排版 → 回复；不存在固定答案或为某一道题设置的判断分支。容器只含 `manifest.json` 与 `project.json`。

当前结果：通过。项目使用 Technical Spike 固定项目 ID `windows-core-spike`，递归统计 17 个积木，包含四种输入声明、课程资料分析 Skill、学习卡片插件动作，以及真实执行的 `core.knowledge.rerank` 与 `core.output.markdown`；无 `core.data.literal`、无旧 `knowledge.lesson.autumn-leaves`、无固定演示回答。产物为 1,218 字节，SHA-256 为 `ba52d6eaaf18b6693702eb4c6226a003e5a6d260462f206d4160f8f5fd9e20de`。单元测试直接解包赛事目录中的该文件，并将其中 `workspace` 与应用内置 starter 作深度相等比较。

### 2. 同一配置覆盖多个课程主题

验证步骤：对同一个 Agent 与同一个知识源分别输入秋叶变色、水循环降雨、光合作用问题；再输入同时包含秋叶与水循环的复合问题。比较检索命中、最终引用及未被询问主题是否泄漏。

预期结果：每个问题都经过同一条积木链；单主题问题只返回相关课程证据，复合问题可命中多份资料；更换问题不需要修改 Agent 配置、积木或答案字面量。

当前结果：通过。课程适配器单元测试与运行时集成测试覆盖三个独立主题和一个跨主题问题；重排测试证明候选按问题相关性排序且重复片段被删除；光合作用回答不包含秋叶或降雨内容，复合问题一次命中 `《秋天的叶子》§2` 与 `《水循环》§1`。

### 3. 无依据内容失败关闭

验证步骤：询问课程资料未提供的“树叶开始变红的具体摄氏温度”，并将该问题与两个有证据主题组合；检查模型草稿、护栏输出、最终引用和检索命中数。

预期结果：有证据结论保留对应引用；无来源草稿不能进入最终回答，统一改写为“课程资料没有说明，待核实”；只问缺失细节时不得复用其他主题答案。

当前结果：通过。单独询问温度时检索命中 0，最终只返回“关于‘叶片开始变红的具体温度’，课程资料没有说明，待核实”；复合问题保留两条有来源结论，并将具体温度单独标记待核实。

### 4. 回归、原生运行与边界

验证步骤：运行完整 Core 门禁；核对正常 release、测试能力隔离、敏感扫描与三项性能；在最终普通 release 中打开 POC、运行录屏唯一提示词并重新载入，确认空输入和无旧回答。

预期结果：既有编辑器、文档、权限、取消、错误、原生 E2E 和安全边界保持通过；真实请求取消必须用同一 `requestId` 从 WebView 传播到 Rust Host，并中止发送或响应读取；最终应用停留在 17 积木 Agent 的“对话测试”空输入界面。文档明确真实模型调用不等于生产级外部知识库或完整 RAG。

当前结果：通过。`pnpm check:core` 连续完整运行退出码 0；普通 release 一次复合输入返回真实二级/三级标题、两组正文与列表、两条课程引用、一条“待核实”和资料范围说明；展开执行过程可读回从 Agent、入口、四种输入声明、Skill、插件、消息、输出、引用、护栏、模型、重排、检索到计划的完整事件，并包含“真实模型调用完成”。聚焦测试证明 Abort 后立即得到 `AbortError`，并调用 `cancel_deepseek_completion`；Rust 测试证明活动请求可取消，且“先取消、后注册”的启动竞态失败关闭。100 积木性能中位数为加载 16.5 ms、运行 0.1 ms、保存编译 0.8 ms；最终 normal release 隔离检查通过。完整 soak 不在本次计划内，因为未修改事件上限、保存循环、WebView 生命周期或长期状态。

### 5. 结构化回答呈现

验证步骤：让运行时输出受控 Markdown 子集，检查对话组件中的二级/三级标题、段落、无序列表、加粗字段和引用说明；同时用普通纯文本回答回归旧消息样式。

预期结果：结构化输出被渲染为真实语义元素，不直接显示 `##` 或 `**`；输入文本不作为 HTML 执行；普通回答、失败提示和运行轨迹样式不退化。

当前结果：通过。组件测试读回 `heading`、`list` 和 `strong` 语义；恶意 `<img onerror>` 与 `<script>` 输入只作为惰性文本显示，DOM 中不存在 `img` 或 `script` 元素；真实桌面 UI Automation 分别读回“课程资料综合回答”、两个主题标题、资料完整性检查、课程依据列表项和资料范围说明。

### 6. 真实大模型 API 调用与安全回报

验证步骤：将用户提供的 DeepSeek 凭据提取到 `try/windows-core-spike/.env`，确认该文件被 Git 忽略；从普通 Windows release 的 17 积木 Agent 输入唯一录屏提示词；读取 `model.completed`、最终绿色 API 徽标及可展开详情；扫描跟踪文件、项目文档和差异，确认没有密钥、认证头或完整敏感请求。

预期结果：WebView 不持有密钥，模型调用只经过 Rust Host 的固定 `https://api.deepseek.com/chat/completions` 与模型白名单；成功时记录 Provider、API 返回模型、请求 ID、输入/输出/总 Token；模型草稿仍必须经过受信证据核验、护栏、引用和 Markdown 输出链。无可读响应与用量时不得宣称真实调用成功。

当前结果：通过。真实大模型 API 调用：**是（历史 live 证据）**。2026-08-26 普通 release 返回 Provider `deepseek`、实际模型 `deepseek-v4-flash`、请求 ID `c63082e8-5440-4c32-8372-25e9e4ab44e9`、输入 514 Token、输出 309 Token、总计 823 Token，状态成功；界面读回同一证据。密钥仅写入 Git 忽略的本地 `.env`，`.env.example` 只含占位值。2026-08-27 本轮自动化验证没有调用外部大模型 API；WDIO 构建不注册 DeepSeek 命令且注入确定性模型，因此不产生外部模型消费。
