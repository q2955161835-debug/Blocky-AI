## 详细报告

### 用户功能一：立即理解审查转变，并愿意继续看

#### 使用场景：三位搭子一起审查 Agent（P01）

独立从最终 MP4 每两秒抽一帧制作总览（0–58 秒，30 张），再使用本机 Edge 的 HTML5 播放器直接读取同一冻结文件。播放器从 0 秒以 1x 启动，状态依次记录 0.003、5.607、25.207、43.900 秒，最终 60.010667 秒、ended=true；另外定向从 12 秒和 46 秒以 1x 重播。状态记录和播放器截图保存在自有缓存。工具只返回离散画面，既没有连续视频输入也没有音频输入；截图与 AX 时间有少量更新先后差异，截图不能当作精确帧时间。`playing-wrong-target.png` 实际采到约 25 秒编辑画面，`playing-visible-run.png` 实际采到约 44 秒 CLI 画面，按内容判读，不按文件名误认。

0–2 秒直接以“代码审查 → 积木审查”小标题配同桌三角色出现；6–12 秒的长代码折卷有明确“简单审一眼”与过长对象的反差；12 秒定向截图显示 Clawd 将放大镜举到 Blocky 的眼睛，约 16 秒截图显示 Blocky 指向积木并说“审的是 Agent，不是我！”，Clawd 出现惊讶的小口型。这一笑点有可观察的错误对象与纠正反应，并非只有一条幽默字幕。46 秒截图显示 Codex 推着超大带轮放大镜，与 Clawd 的手持小镜、桌上大小两套积木对照；54–60 秒仍保留三角色工作台，品牌文字覆盖顶部，未变成全屏口号卡。

这些画面能支持“搭子协作”及道具回扣的具体设计判断：Codex 拿代码/推动大镜，Clawd 观察，Blocky 提供积木对象并纠正方向，三人围绕同一工作台互相反应。长卷和眼睛笑点与审查主题有关，开场没有长篇无关剧情。44 秒动画与 16 秒实际界面形成清楚的表达顺序：审查困难 → 对象纠正 → 实际修改 → 观察运行 → CLI 协作 → 从简单到专业。

仍未观察到连续动作的全部起止、笑点反应是否留够停顿、气泡是否在正常观看中来得及读完、音乐降低与刹车 SFX 是否兑现节拍，也无法判断观众是否觉得“抓人”“少广告感”。尤其 46 秒进入时超大放大镜已经出现，不能根据这一个画面声称已看见完整推入动作。**P01 保持阻塞，不能以三个设计笑点或播放器 ended 替代创意与节奏通过。** 最小后续是针对这个相同 SHA 的完整 1x 连续视听观察，记录具体动作、停顿及听感结果；无需重复产品测试或重做已核对来源。

### 用户功能二：看清谁在协作，以及 Agent 实际怎么组织和运行

#### 使用场景：角色连续、积木嵌套与运行轨迹（P02）

与本地两张参考图对比：Codex 保留蓝色圆润外形、深色面屏与亮色符号；Clawd 保留棕橙色阶梯状像素轮廓、方眼与短腿；Blocky 保留青蓝凸点积木外形与黑色圆眼。抽样中的 Clawd 在约 16 秒增加惊讶口型、末尾增加笑口，改变表情但未损害主要轮廓辨识。暖色工作台、左侧窗灯、背景植物与书架在六段保持；前景纸卷、手持镜、带轮大镜有桌面接触和阴影。所见样本没有明显失去支撑、通用连线图替代积木、角色消失或穿过桌面的交付阻断。此判断限于采样，不声称逐帧零瑕疵。

18–26 秒是实际前端字段编辑。最终画面聚焦可见新指令“先核对资料，再汇总工时；交付前读回检查。”；来源字段 `assistant-work-instructions_field_blockly-2j` 的 after 值一致，原采集 `editorClosed/valueVisible` 断言为真。既有界面使用 C 形容纳、上下嵌套的 Scratch 式积木，编辑字段属于现有结构，不是画在通用节点连线图上。本轮重新读取来源 MP4 SHA 与大小，不重新采集或执行模型。

26–32 秒的物理紫色容器是动画示意；32–40 秒为官网既有预设片段（源 6.5–14.5 秒）。画面明确写“界面演示”，来源积木 ID 与 `calculate/workspace_write/workspace_read` 轨迹关系有既有断言。当前截段从原预设中途开始，因此列表/首次读取的轨迹可能已存在；不能将其误写为本段新发生的真实调用。抽样显示高亮和轨迹同属该嵌套程序。未把动画积木发光称为实际 Runtime 事件。

大小积木对照解释同一语言从入门到专业，视觉结构仍是嵌套而非连接网络；但没有具体复杂项目效果的实测主张。**P02 在当前可见结构与辨识范围有条件通过**，全片瞬态连续性仍需连续观察补齐。

#### 使用场景：冻结成片、来源与音轨（P03）

六段采用 MP4 均独立重新计算 SHA/字节并与 MiniMax completed 回执一致：526,449、479,881、414,449、465,640、534,778、613,805 字节，六项一致。两份复用界面分别为 479,759 和 813,431 字节，SHA 与采集清单一致；原创 WAV 为 11,520,044 字节，SHA 与冻结音乐来源一致。ChatCut live 只读时间线读回为 1800 帧/1920×1080/30fps，与冻结段落位置一致，保存不含浏览器接入令牌的读回。

实际编辑、官网预设、虚拟角色协作三类来源区分清楚。40–46 秒终端面板可见 `blocky project create --template work-assistant --name "周报助手" --output agent.blocky --json`，原回执 `project.create/ok=true`，产物 7,821 字节；片内写“CLI 协作情景示意”。没有将 validate/compile 失败包装成成功，没有以 Codex/Claude Code 字样宣称官方集成或本轮执行了其品牌工具。原 `simulate` 的 `BLK-PROVIDER-DISABLED`、`modelApiCalled=false` 仍保留；预设展示不外推真实模型或桌面 Runtime 完成。

音轨客观统计：2,880,512 样本/声道，平均 -37.3dB，峰值约 -10.1dB，NaN/Inf 为 0。存在音频信号，峰值没有接近数字上限的削波迹象；不能据此评价音量是否合适、结尾是否听起来突断、SFX 是否突兀或无残留对白。冻结 item 参数中全部 V1 视频 `decibelAdjustment=-60`，即嵌入声衰减至 -60dB；这不等于数字零音量。制作方已确认按该准确措辞整理来源描述，电影参数不变。原音乐分段与两类库 SFX 可核对，但**真人听感未执行**，不得称“已听到仅音乐/SFX”或“已确认无无关语音”。
