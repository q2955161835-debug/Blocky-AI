## 详细报告

### S4-01 组合完整 Agent

#### 场景：在同一语言中搭建并编译最小闭环

Event、Agent、Prompt/Context、Model、Knowledge、Memory、Tool、Condition/Logic、Guardrail 和 Output 均有可执行目录项。未知字段产生 `BLK-TYPE-007` 并定位模块/积木；正式语义测试、独立边界测试和最终类型检查均通过。入门/专业视图继续投影同一项目语义。

结论：**通过**。

### S4-02 配置提示与上下文

#### 场景：组合用户输入、角色、知识与记忆

最终独立探针实际执行 Runtime、AgentExecution、nativeAgentServices 和类型化 Host 调用。捕获请求严格为 `system → user`：角色与可信补充指令只进入 system；记忆、工具结果、证据和用户输入只进入 user 数据边界，Provider preflight 与 call 的 request 完全一致。既有边界测试同时证明 UTF-8 总量超过 32 KiB 时以 `BLK-CONTEXT-001` 拒绝。该结论只证明权限分层和请求构造，不声称模型可抵抗所有语义注入。

结论：**通过**。

### S4-03 切换无网络与真实模型

#### 场景：两种 Provider 完成相同夹具任务

公开虚构工具任务、本地知识问答和零证据拒答均先走本地模式，再走限定真实模式。模拟模式 `modelApiCalled=false`；真实成功分别读回 DeepSeek、实际模型 `deepseek-flash`、响应 ID 及 131/76/207、204/72/276 Token。另一次 109/130/239 Token 响应因伪引用被产品以 `BLK-GUARD-001` 拒绝，没有冒充成功；零证据 require 路径在本地拒答且零外发。共 3 次真实外发，没有自动重试。

结论：**通过**。

### S4-04 处理模型服务错误

#### 场景：认证失败、限流、服务异常与畸形响应

冻结 Host transport 动态覆盖 401/403→`BLK-PROVIDER-AUTH`、429→`BLK-PROVIDER-RATE`、500/503→`BLK-PROVIDER-SERVICE`、302、坏 JSON、缺字段、异常完成原因、响应过大、超时与取消，供应商虚构错误正文未进入稳定错误。candidate3 打包 CLI 在隔离用户目录且未导入秘密时，真实产生 `model.started → model.failed → block.failed → run.failed`，均投影 `BLK-PROVIDER-CONFIG`，最终非零退出、`generations=[]`、`modelApiCalled=false`。GUI 工具拒绝显示停止状态和失败日志；GUI 局部未显示稳定码的缺口由上述 CLI 与 Host 证据补足。

结论：**通过**。

### S4-05 授权并调用工具

#### 场景：允许、拒绝、修改参数与重放授权

登记的 `text.analyze/v1` 在 CLI 和原生 GUI 均产生真实批准并读回统计结果。原生 helper 跨进程验证单次票据：第二次消费、改输入、改项目、改运行、过期、续签和损坏 ledger 均拒绝；Provider 使用同一持久批准域。GUI 批准框显示项目/运行、输入字节和摘要，不显示秘密。作品 Agent 未获得用户 PTY。

结论：**通过**。

### S4-06 停止运行并限制开销

#### 场景：运行中停止、超时及预算耗尽

步数、调用、输出 Token 和总时限均有实际消费者；后置较长预算不能放宽先前较短预算。非协作生成器迟到返回仍保持 cancelled，且不写输出。生产 transport 在响应头与部分正文等待中取消分别约 25/31 ms 返回，服务端约 54/61 ms 观察断开，均低于 2 秒；本地只承诺停止和结算，不外推供应商计费停止。

结论：**通过**。

### S4-07 读写及删除记忆

#### 场景：会话/项目记忆、重启与删除

项目作用域记忆通过 CLI/Host 写入，新进程重开同项目读回一致；另一项目读取为空；删除后再次新进程读取仍为空，Host 文件为 2 字节空对象。跨项目/会话、撤销 grant、批准重放和容量超限负例均通过，失败不破坏旧值；运行记忆没有写入项目 JSON。

结论：**通过**。

### S4-08 按条件选择执行路径

#### 场景：真假条件与无效输入

运行事件和调用计数证明只执行 THEN 或 ELSE 中的选中子树，未选分支无模型、工具或记忆副作用；无效操作和值类型失败。最终验收另发现两个 module.call 调用同一模型模块时 requestId 重复；主 Agent加入运行内单调调用序号，正式回归先红后绿，独立探针最终 2/2 通过，generation 与开始/完成事件 ID 一致。

结论：**通过**。

### S4-09 使用带护栏的知识回答

#### 场景：有效证据、过期/删除资料与伪造引用

真实知识回答的唯一来源 ID 属于当前返回集合并定位公开资料行；伪造来源的真实 Provider 响应以 `BLK-GUARD-001` 拒绝；空索引 require 路径在本地输出资料不足并保持零 API。资料版本和权限边界负例已覆盖，未把来源 ID 有效性扩张为开放域事实准确性。

结论：**通过**。

### S4-10 获得结构化与文件输出

#### 场景：JSON 输出与导出 UTF-8 文本/JSON

声明 Schema 实际拒绝错误类型、缺字段、额外字段及不支持声明。生产 atomicOutput 验证完整 UTF-8、拒绝覆盖、预取消、写入中取消和发布失败均无半成品。GUI 原生导出先取消，再保存 50 字节 JSON，并经过两层真实覆盖确认后读回 `characters=60, lines=1, words=3`；路径穿越和越权负例通过。

结论：**通过**。

### S4-11 在桌面聊天中完成任务

### S4-12 从 CLI 运行同一项目
