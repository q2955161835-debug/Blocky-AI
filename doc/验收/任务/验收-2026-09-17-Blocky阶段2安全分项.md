## 详细报告

### 使用受控任务与用户终端

#### 使用场景：伪造票据、读取/取消异主体运行、附加用户 PTY

通过（限定已检边界）。`TaskHost::start_agent` 由 Host 的票据映射校验 principal、任务与有效期，成功后消耗票据；TS 解析不签发票据。`grant_agent` 未注册 IPC，也没有 CLI/桌面调用路径。分别使用 agent/builder/skill/rpa 主体与伪造 capability 调用真实原生库，全部拒绝且 active=0；读取/取消虚构 foreign handle 同样失败。普通 IPC `attach_user_terminal` 固定拒绝；PTY 读/resize 限 main，创建/写/关闭要求 main 可见且不在退出阶段。

原生用户终端和具名任务分别使用 ConPTY 管道与独立 stdin/stdout，没有调用者传入的终端句柄或 arbitrary executable/cwd/env 字段。ConPTY 固定系统 Shell、禁用 profile/autostart、先 suspended 加入 Job 再恢复；任务 worker 先等待输入，加入 Job 后才释放任务内容。任务进程清空环境，当前注册任务只输出固定结构化计数。主 Agent 已运行的 native25 未重复执行，本分项不将代码审查写成普通 GUI 或真实多终端交互通过。

限制：当前 grant/start_agent 是库层受控原语，未接入可观察的完整 Agent 通道；这不是自助授权漏洞，但本证据不能用来宣称整个 Agent 产品旅程通过。

### 安全保存秘密与用户状态

#### 使用场景：秘密重复配置、路径越界和明文输出

通过（限定已检边界）。秘密导入仅返回 bool，状态仅返回是否存在，没有解密 IPC；DPAPI 使用当前用户，原子临时文件提交。虚构 KEY 首次导入后，再输入重复 KEY，实际拒绝且原值仍可由 Host 内部读取；密文文件不包含虚构明文。没有读取本机真实秘密。

UserStore 使用受限 kind 与稳定 ID，`../escape`、斜杠、ADS 冒号和连续分隔符均拒绝；原 settings 值完整保留。settings 是字段白名单，recovery 内嵌工程经 validate_files；其他用户对象仍依赖直接领域验证和敏感字段检查。本项未把“所有任意文本都能自动识别秘密”当作保证。

### 保留旧作品与迁移

#### 使用场景：恶意归档路径及提交竞争

通过（限定原生边界）。实际制作 ZIP 包测试 traversal、ADS、Windows 保留设备名和尾随点，`read_migration_archive` 均拒绝，源归档字节不变；解析流程只读取有界 ZIP/UTF-8/JSON，不执行源内容、不解压至调用者路径。普通读取在其后执行当前版本 validate_files。

新增 TOCTOU 负例：临时归档已写好但提交前，在目标位置创建 concurrent-original；`create_archive_checked` 拒绝提交，既有字节保持完整。`persist_noclobber` 保护迁移输出，常规保存以同目录临时文件、flush、sync_all、persist 提交。迁移语义等价与完整 CLI 不属于本分项。

### 阅读与清理日志

#### 使用场景：恶意日志字段和损坏记录

通过（限定原生边界）。持久 Record 只允许 timestamp/sequence/level/channel，未知 token 字段被隔离而不进入可读摘要；实际坏日志重开后 records=0，health 显示 quarantine。`droppedImportant > dropped` 被拒绝。日志导出复用同一受限记录与已校验过滤器，不含正文、用户输入或环境值。隔离文件保留坏输入用于诊断，不应误称原坏数据被自动抹除。

#### 使用场景：清存储后追溯用户清除动作

不通过，P2。S2-11 明确要求“清存储审计”，但 `apps/studio-host/src/log_store.rs:428` 的 clear 直接持久化 `Diagnostics::default()`，IPC 和 UI 清理路径没有补写持久审计。调用器在清理后读取实际磁盘字节，并与从未使用过的新 LogStore flush 结果比较，两者完全相同。没有清除时间、清除事件或计数，重新打开无法判断此前发生清除。

失败路径：用户选择清除本机诊断 → clear_diagnostics → LogStore::clear → 默认空 Diagnostics。实际影响为清除动作不可追溯，不是秘密泄漏或 Agent 越权。建议在 Host 内原子提交清除结果与无敏感内容的审计元数据，并增加重开读回；无需记录旧正文或用户输入。修复后只复验日志清理/读回/导出及白名单相关负例。
