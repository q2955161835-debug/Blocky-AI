## 二、详细报告

### A1 真实文档生命周期与原生文件安全

验证步骤：

1. 从空白启动依次执行新建、打开、保存、另存为和退出，覆盖菜单、`Ctrl+N`、`Ctrl+O`、`Ctrl+S`、`Ctrl+Shift+S`、`Alt+F4`。
2. 首次保存选择 `.blocky`，修改后原地保存，再另存为新文件；关闭重开后比较 workspace、稳定 ID、字段、连接和派生编译结果。
3. 在 dirty 状态分别触发新建、打开和关闭，验证“保存并继续 / 不保存 / 取消”三条路径以及保存失败阻断继续操作。
4. 打开非法 ZIP、错误格式版本、缺失/重复 `project.json`、路径穿越条目、超大/高压缩比容器、非法编码和派生数据不一致文件。
5. 检查前端 IPC 类型、日志、RuntimeEvent、项目 JSON 和错误提示，确认不存在任意绝对路径输入/输出或路径泄漏。

预期结果：

- 所有文档命令真实可用，取消原生对话框不改变当前状态；保存使用原子写入，失败不清除 dirty。
- `.blocky` 可移植重开且语义无损；不合法文件失败关闭，当前文档保持不变。
- 未保存保护无竞态、无重复模态、无静默数据丢失。
- 前端只处理显示名和不透明文档标识，不能指定或获知原生完整路径。

拟执行命令/检查：

```powershell
pnpm --dir .\try\windows-core-spike test:unit
pnpm --dir .\try\windows-core-spike test:component
cargo test --locked --manifest-path .\try\windows-core-spike\src-tauri\Cargo.toml
# 另执行 Windows Tauri 原生文档 E2E、恶意容器夹具与 IPC/日志字段审计
```

### A2 命令中心、菜单、快捷键与状态真实性

验证步骤：

1. 检查 `文件 / 编辑 / 视图 / 帮助` 的全部可见项，逐项从菜单、命令中心和快捷键执行并比较结果。
2. 用 `Ctrl+P` 搜索命令和真实积木；用上下键、Enter、Escape 操作，检查空结果与快捷键标签。
3. 制造有/无撤销历史、有/无选择、有/无文件关联和保存失败状态，检查命令启用条件与顶部直线左右箭头。
4. 从新建、编辑、保存中、保存成功和失败走完整状态转换，检查标题与状态文案。

预期结果：

- 三种入口读取同一 CommandRegistry，不存在同名不同义、快捷键冲突或虚假菜单。
- 撤销/重做使用直线左右箭头并读取真实历史栈；禁用态、提示和无障碍名称正确。
- 文档标题和 `未保存 / 正在保存… / 已保存 / 保存失败` 与真实状态一致，不再静态显示“天气助手 · 已保存”。

拟执行命令/检查：

```powershell
pnpm --dir .\try\windows-core-spike test:unit
pnpm --dir .\try\windows-core-spike test:component
# 浏览器与原生键盘路径人工复核
```

### A3 积木拖入、画布双模式、滚轮缩放与防重叠

验证步骤：

1. 对每个分类抽取至少一个真实积木，使用 pointer 拖入、单击插入和命令搜索插入；比较创建类型、释放坐标、字段、连接与撤销行为。
2. 选择模式验证单击、空白长拖框选、Shift 增减、Ctrl+A、Escape、Delete、剪切/复制/粘贴和多选整体移动；平移模式与 Space 临时平移验证不移动积木。
3. 在画布中心、边缘、积木上方和高 DPI 缩放环境滚轮，确认以指针为中心缩放，百分比实时更新；侧栏与对话区滚轮仍只滚动自身。
4. 分别收起左右栏，逐字段比较 `scale`、`scrollX`、`scrollY`、顶层坐标、连接和实际渲染尺寸。
5. 连续拖入、单击、搜索插入、复制粘贴、旧重叠项目与 100 块夹具执行两两边界检查；验证合法连接和嵌套不被拆开。

预期结果：

- 左侧拖拽在浏览器和 Tauri 中稳定创建真实 Blockly 积木，不再依赖失效的跨 SVG HTML5 drop。
- 双模式、多选和框选行为符合规格，撤销/重做和序列化无损。
- 普通滚轮只在画布内缩放，不再纵向平移 workspace；缩放组状态同步。
- 侧栏收纳只增加可见空间；所有自动创建路径不留下持久顶层重叠。

拟执行命令/检查：

```powershell
pnpm --dir .\try\windows-core-spike test:unit
pnpm --dir .\try\windows-core-spike test:component
pnpm --dir .\try\windows-core-spike check:core
# 浏览器真实 pointer/wheel 测试、Windows 原生 E2E、100 块两两边界审计
```

### A4 对话即运行与可理解的执行过程

验证步骤：

1. 空项目启动，确认默认搭建助手 CTA 能实际添加 AI 伙伴和聊天入口；无入口时对话输入给出可恢复动作。
2. 输入普通文本并按 Enter/发送，验证用户消息、流式助手回复、完成状态和折叠执行过程；验证 Shift+Enter 换行。
3. 覆盖编译错误、`/error`、取消、权限拒绝/批准、运行中再次发送和运行中打开/新建文档。
4. 对每类来源积木检查时间线颜色与分类元数据，覆盖无法定位来源的系统回退。
5. 检查普通界面 DOM 和截图，确认不显示原始事件 JSON、blockId、schema、IR 版本或测试数据。

预期结果：

- 发送消息是唯一普通运行入口，不存在独立“运行”按钮；每轮消息与唯一运行终态一一对应。
- 助手回复来自 `model.chunk` 投影，错误和权限流程保持 run token/修订隔离，旧回调不能污染新文档。
- 执行过程默认折叠，颜色来自真实积木目录且有文字辅助；内部事件数据不暴露。

拟执行命令/检查：

pnpm --dir .\try\windows-core-spike test:component

4. 仅用键盘完成打开、插入积木、选择、保存、切换右栏和发送消息；检查焦点顺序、焦点环、无障碍名称和状态播报。

- 用户界面只保留 Blocky 产品语言；测试夹具和尖峰信息仅存在受控开发/测试通道。
