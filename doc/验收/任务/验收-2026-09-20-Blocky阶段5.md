## 详细报告

### S5-01 自然语言搭建 Agent

#### 场景：输入两种不同任务需求，检查计划及生成的可编辑积木

通过标准：需求→计划→Build Spec→候选→接受→编译验证完整可用；内容符合各自需求，目录/资源/引用合法；未知能力明确诊断，不能用同一固定补丁冒充生成。

证据要求：普通候选 GUI、需求与脱敏结果、编译诊断和可运行项目。

结果：通过。普通候选 CLI 对植物课堂和图书馆两种需求输出不同角色字段候选；植物候选另存接受后验证/编译零诊断、原项目字节不变。旧授权的工单与资料查询两种真实任务候选均含不同的角色更新和页面操作，工单在普通 GUI 重开并运行，资料候选在本轮普通 CLI 另存接受、重编译零诊断。模型生成不等于自动应用，实际息壤响应另见 S5-06。证据：[候选读回](阶段5证据/运行证据/独立最终验收-candidate2-2026-09-25.md)、`try/stage5/final-acceptance/{offline-botany,offline-library,live-final-ticket-candidate,live-final-research-candidate}.json`。

### S5-02 解释所选积木

#### 场景：选择一块和多块，查看作用、依赖与权限解释

通过标准：解释准确定位当前模块及稳定 ID，不猜测未知数据；只解释不生成项目修改，选择改变后不显示旧结果。

证据要求：选择映射、解释输出、项目前后摘要及过期选择负例。

结果：通过。普通候选 CLI 分别选择 `research-root,call-citation` 与 `compose-answer`，解释按稳定 ID/字段变化；两次均 `modelApiCalled=false`，无语义补丁，原 `.blocky` SHA-256 不变。过期选择不会沿用上一条 CLI 解释；GUI 选择状态将在剩余桌面旅程复核。证据：`try/stage5/final-acceptance/{explain-candidate,explain-second}.json`。

### S5-03 最小修复项目

#### 场景：对定位诊断生成修复，审查后应用并撤销

通过标准：修复消除目标诊断，列明必要影响，不删除无关积木/资源，不静默扩大权限；不可修复明确失败，不以吞诊断通过。

证据要求：损坏夹具、修复前后诊断、差异范围和撤销读回。

结果：通过（candidate3 共享修复能力，CLI）。同一损坏夹具仅将 `call-citation.RESOURCE` 改成不存在的资源，编译前唯一 `BLK-RESOURCE-001`。candidate3 随包 CLI 先以离线真实 Host 路径验证一条字段修复可通过，再以用户已授权的息壤 `deepseek-v4-pro` 真实请求生成候选；两次响应共 9291 Token、`modelApiCalled=true`、验证通过。`builder patch/verify` 与 `patch preview` 审查只有 `research-agent/call-citation.RESOURCE=product-handbook` 一项、权限增量为零；另存应用后仅一处 diff、编译零诊断。预先保存损坏检查点，带当前摘要另存恢复后与损坏原件语义差异为零，原件字节始终不变。详见[candidate3 读回](阶段5证据/运行证据/独立最终验收-candidate3-2026-09-25.md)和[即时安全元数据](阶段5证据/运行证据/builder-evidence-xirang-repair-candidate3.json)。旧 candidate2 两次真实失败因 Host 原基线校验缺陷仍作为[失败证据](阶段5证据/运行证据/独立最终验收-candidate2-2026-09-25.md)保留；本项的 GUI 可见审阅/撤销归 S5-04/05，未据此判通过。
