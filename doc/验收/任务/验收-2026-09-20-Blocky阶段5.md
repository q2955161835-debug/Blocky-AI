通过标准：需求→计划→Build Spec→候选→接受→编译验证完整可用；内容符合各自需求，目录/资源/引用合法；未知能力明确诊断，不能用同一固定补丁冒充生成。

证据要求：普通候选 GUI、需求与脱敏结果、编译诊断和可运行项目。

## 判定与边界

以上 16 项必须分别判定，关联证据可复用但不重复计数：04 检查显示真实性，05 检查项目事务；07 检查助手权限，12 检查页面隔离；08 检查引擎生命周期，12 检查预览生命周期。最终验收须由未参与对应实现的独立 Agent 按已确认标准执行。

真实 API 范围草案：用户授权的供应商/模型，仅虚构公开资料，最多 4 次外发，每次最大 2048 输出 Token，不自动重试。须另核对本轮授权和本地凭据，不能默认沿用阶段 4。缺少 live 证据时 S5-06 为阻塞或未执行，不伪报总体通过。
