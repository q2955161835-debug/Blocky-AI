## 1. 本地 Blockly 编辑器

### 1.1 安装包本地加载

验证步骤：在普通 Windows release（发布构建）断开外部网络，启动应用并打开工具箱；扫描构建产物与出站请求。

预期结果：Blockly、媒体、样式和脚本全部来自安装包；除固定 Tauri IPC（进程间通信）外无远程资源或出站请求。

基线命令：`pnpm check:core`；当前结果：通过。

### 1.2 100 块编辑与持久化

验证步骤：载入精确 100 块，执行拖动、连接、折叠、缩放、保存、关闭、重开和重载；比较完整稳定 ID、规范 JSON、摘要和字节数。

预期结果：始终为 100 块；编辑状态保留；语义与稳定 ID 无损；保存来自本次真实 UI 操作而非旧磁盘文件。

基线命令：`pnpm check:core`；当前结果：通过。

### 1.3 现代桌面工作区、真实积木与侧栏收纳

验证步骤：检查统一深色自定义标题栏、积木分类与实际积木列表分栏、真实 Blockly SVG 预览、画布右上角保存、顶部选择/平移模式和右下角缩放/适配控件；确认普通界面没有独立“运行”按钮和 Blockly 垃圾桶；分别收起/展开左侧积木栏与右侧搭建助手/对话测试栏，并在 100 块夹具和三块视觉验收态中比较收纳前后的完整视图状态与顶层边界。

预期结果：常见操作使用标准 Fluent 图标；积木可由左侧直接拖入或单击插入；左右侧栏真实收纳且只增加画布可见区域；收纳前后 `scale`、`scrollX`、`scrollY`、顶层积木坐标和实际尺寸逐字段相等；自动插入、拖放结束、复制粘贴、夹具和旧项目载入后不存在顶层积木重叠；画布滚轮以指针为中心缩放，侧栏滚轮仍滚动自身；主画布横纵滚动条的可见滑块保持 6 px 细线且不缩小原交互轨道；只有用户主动点击“适配画布”才允许整体居中。

基线命令：`pnpm test:component`、`pnpm check:core` 与 1440×900 原生视觉对照；当前结果：通过。

## 2. 六类连接语法

### 2.1 event-hat（事件帽）、command（命令）与 statement-container（语句容器）

验证步骤：创建事件入口、命令链和 Agent/入口/Tool/流程容器，检查 previous/next/statement（前序/后序/语句）连接类型。

预期结果：事件帽没有前序；命令链只接受命令槽；容器命名输入只接受声明的精确槽类型。

### 2.2 typed-value（类型值）、boolean-condition（布尔条件）与 reference（引用）

验证步骤：分别尝试合法同类型连接和 Boolean→JSON 等非法连接。

预期结果：类型值和引用只连接精确 `type.*`；布尔条件保持六边形语义；非法连接在画布层被拒绝。

基线命令：`pnpm test:unit` 与人工连接检查；当前结果：通过。

## 3. 稳定 IR

### 3.1 语义确定性

验证步骤：对只改变坐标、折叠、注释和对象键顺序的工作区重复编译；再交换命令语义顺序。

预期结果：视觉等价输入得到字节相同的 `blocky.ir/v0-spike`；语义顺序变化得到不同结果；根和键顺序稳定；每个节点都显式包含必填 `fields`、`inputs`、`next`，不存在的链接写为 `null`。

### 3.2 诊断与来源映射

验证步骤：注入重复 ID、未知块和非法连接；运行正常、错误和权限路径。

预期结果：用户结构错误返回稳定诊断而非崩溃；每个运行事件 `blockId` 都映射到真实 IR 节点和 Blockly 积木。

基线命令：`pnpm test:unit`、`pnpm check:core`；当前结果：通过。

## 4. InteractionManifest 交互清单

### 4.1 零、单、多入口

验证步骤：删除全部入口、添加一个或多个入口、重命名和重排，同时保持稳定入口 ID。

预期结果：零入口仍可进入“对话测试”并获得“添加聊天入口”的可恢复操作；存在入口时默认名称、用户名称和路由正确；重排/重命名不改变身份。

### 4.2 六种能力与独立草稿

验证步骤：按入口增删文本、图片、文件、语音、Skill（技能）和 plugin action（插件动作），切换两个入口并保留不同草稿。

预期结果：右栏只读取 `InteractionManifest`；控件精确增删；草稿按稳定入口 ID 隔离，移除能力不会静默丢弃已有不兼容草稿。

基线命令：`pnpm test:component`、`pnpm check:core` 与人工六能力检查；当前结果：通过。

## 5. 一等 Tool 契约

### 5.1 稳定身份与唯一注册表

验证步骤：同一 Tool 同时由 Agent 附着和显式调用；修改显示名、参数名和必填项后重新编译。

预期结果：两种用法始终以稳定 `toolId` 解析同一只读 `ToolContract` 对象；不存在按显示名兜底或复制第二份 schema（模式）。

### 5.2 参数与权限

验证步骤：验证缺少必填、额外参数、错误类型、需批准和拒绝/批准路径。

预期结果：无效调用在运行前产生诊断；需批准不能被调用方覆盖；拒绝不产生 `tool.started`，批准后才完成 Tool。

基线命令：`pnpm test:unit`、`pnpm check:core`；当前结果：通过。

## 6. 确定性运行事件

### 6.1 正常、取消与错误

验证步骤：运行普通输入、取消和 `/error`。

预期结果：普通输入产生固定两段流；序号从 1 单调递增；每个事件由唯一工厂创建并带 `eventVersion=blocky.event/v0-spike`，`data` 始终为 JSON 对象记录；取消与错误各有唯一终态且不再产生 `run.completed`；错误只显示稳定安全码。

### 6.2 权限与生命周期

验证步骤：运行 `/permission`，分别拒绝和批准；在模型运行或待审批期间执行清空、载入或重开；尝试旧审批回调。

预期结果：审批绑定 run token（运行令牌）、投影修订和工作区摘要；替换先结算旧运行；旧回调不能影响新运行；时间线、终态和积木高亮一致；时间线卡片从实际来源块类型投影到统一分类元数据与颜色，缺失来源时使用文字明确的系统回退样式。

基线命令：`pnpm test:component`、`pnpm check:core` 与人工权限检查；当前结果：通过。

### 6.3 外部模型与工具接缝

验证步骤：在用户明确授权的限定 live 探针中，把真实模型固定文本通过现有 `RuntimeDependencies` 注入最小合法 IR；再执行一轮工具调用和一轮合成工具结果续传。

预期结果：真实模型输出不能绕过 IR、source map、事件版本、对象数据与唯一终态契约；工具参数为精确 JSON 对象，续轮使用同一 `tool_call_id`；探针不执行真实外部工具副作用，也不把凭据、正文或请求头写入仓库和报告。

基线证据：[DeepSeek Flash Agent 补充验证](../归档/2026-08-10/验收-DeepSeek-Flash-Agent补充验证.md)；当前结果：通过。该场景不等于产品已内置模型适配器。

## 7. Tauri Host 本地存储

### 7.1 路径、大小与模式约束

验证步骤：提交空/大写/斜杠/反斜杠/`..`/超长项目 ID、超过 5 MiB、无效 JSON、错误 schema、项目 ID 不一致及敏感字符串。

预期结果：返回稳定错误码；前端不能传任意路径；错误与记录不泄漏真实文件路径。

### 7.2 原子保存与派生数据一致性

验证步骤：通过真实 UI 保存唯一状态，核对 Rust 返回的项目 ID、UTF-8 字节数、SHA-256 和 JSON；重载后由工作区重编译 IR/清单。

预期结果：公开保存请求只有 `{ projectId, json }` 一种冻结形状，不存在同义私有请求；原子写入；记录精确匹配；派生数据不一致时以 `PROJECT_DERIVED_DATA_MISMATCH` 失败关闭。

基线命令：`cargo test --locked`、`pnpm check:core`；当前结果：通过。

### 7.3 可移植 `.blocky` 文档生命周期

验证步骤：通过文件菜单与 `Ctrl+N`、`Ctrl+O`、`Ctrl+S`、`Ctrl+Shift+S` 执行新建、打开、保存、另存为；覆盖原生对话框取消、保存失败、未保存保护和原生窗口关闭；打开非法 ZIP、路径穿越、错误格式版本与派生数据不一致容器。

预期结果：`.blocky` 保存与重开语义无损；取消不改变当前文档，保存失败不清除 dirty 且阻断破坏性后续动作；原生关闭遇到 dirty 文档时，“取消”保留窗口，“不保存”必须销毁主窗口；非法容器失败关闭且保留当前文档；前端仅处理显示名和不透明文档标识，不能指定或获知原生绝对路径；WDIO 文档夹具只在测试 feature 中以固定枚举开放。

基线命令：`cargo test --locked --features wdio`、`pnpm check:core` 与 Windows Tauri 原生 E2E；当前结果：通过。

## 8. 安全与测试隔离

### 8.1 项目、事件与日志敏感扫描

验证步骤：扫描跟踪文本、项目快照、前端日志和后端日志；覆盖 token（令牌）、Bearer（持有者认证）、私钥头、cookie（会话标识）、Windows/Unix 绝对路径、NUL、无效编码和 JSON。

预期结果：安全输入输出 `SENSITIVE_SCAN tracked=0 snapshot=0 frontend_log=0 backend_log=0`；异常文本/JSON 失败关闭；发现只报告目标、类别、文件名和数量，不回显匹配值。

### 8.2 普通包隔离与 CSP

验证步骤：分别构建 WDIO 测试包和普通 release，扫描前端标记、Cargo 依赖、Tauri capability 与 CSP（内容安全策略）。

预期结果：WDIO 只存在于测试 feature/mode/capability；普通包 `withGlobalTauri=false`、`cargo_wdio=0`、唯一 `main` capability，并只含 `core:default` 与最小化、最大化/还原、关闭、拖动标题栏四项窗口权限；CSP 不允许远程代码或连接。

基线命令：`pnpm check`、`pnpm check:core`、`pnpm check:full`；当前结果：通过。

## 9. 变更触发的复测要求

- 修改 Blockly 目录、连接或序列化：复测第 1–3 节及真实 100 块保存重开。
- 修改 IR、Manifest、Tool 或运行时：复测第 3–6 节、Core 原生 E2E 与三项性能。
- 修改 Host、权限、CSP、日志或安全扫描：按 L3 复测第 7–8 节、所有负例和普通包隔离。
- 修改长期运行状态、事件上限、保存循环或 WebView 生命周期：必须重新执行完整 360-cycle/30 分钟 `pnpm check:full`，不得沿用旧 soak。
- 正式产品迁移、契约版本变化或目录拆包：创建新的任务验收；本尖峰结论不能自动继承到发行或正式完整积木目录实现。
