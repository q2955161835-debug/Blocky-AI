## 当前差距与架构

`packages/builder-protocol/` 已提供 makePatch、previewPatch 和 applyPatch，包含基线摘要、权限差异、Host 复核及单事务编辑；复用此链，不另造项目写入通道。现有 `packages/app-surface/src/draft.ts` 固定生成“资料问答”，`manifest.ts` 与 `apps/studio-host/src/surface_guard.rs` 校验文件必须逐字等于内置来源；这只能证明固定夹具安全，不能支持本阶段真实页面生成。

采用共享构建领域、窄 BuilderAdapter 与 Host 管理的受控 sidecar。领域层管理请求、计划、Build Spec、候选和状态；引擎只能调用 inspect/draft/patch/verify。接受操作仍由产品 UI/CLI 授权进入现有项目控制器和 Rust Host。WebView 不接收密钥，sidecar 不继承用户终端、全盘文件权限或任意 Shell。

Pi SDK 作为首选候选，在批次 B 核对官方源码、版本、许可证、内建工具禁用能力、传输与生命周期后锁定。采用 SDK 不等于允许其默认文件或 Shell 工具。若无法满足边界，保留可审计失败证据并报告阻塞/替代方案，不静默省略候选评估或用假适配器宣称完成。

应用界面生成采用有版本的页面规格、文件差异与桥接清单，前端构建仅允许产品锁定依赖和白名单任务。生成源码作为不可信输入处理；不能通过任意 package scripts、路径穿越或安装钩子取得 Host 权限。旧固定页面继续可打开，新格式迁移显式、旧项目原件保留。

## 主要失败条件

并发编辑导致候选过期、引擎迟到结果污染新会话、生成前端经构建脚本越权、页面权限继承作品全部工具、恢复自动重放外发，分别由批次 C、B、D、D、E 的失败夹具约束。任何未满足的必需项均不得以其他测试通过替代。
