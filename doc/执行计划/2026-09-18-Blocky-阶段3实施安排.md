## 方案与模块职责

采用本地受控资源存储、共享纯领域服务、窄 Host I/O 的方案。外部向量数据库方案引入部署负担；把原文与索引放入项目 JSON 会破坏已有资源边界，因此不采用这两条路径。

- 新增 `packages/knowledge-core/`：来源/分段/索引契约、同步事务、关键词评分、混合召回、过滤、重排、预算、引用和评估；拆分子模块，禁止将全部逻辑放在单文件。
- Host：受授权根目录约束的文件/仓库读取、URL 获取、资源数据原子持久化与任务生命周期。桌面仅接收不含秘密和任意本机路径的句柄、摘要及定位信息。
- Embedding：可替换端口，明确模型标识、版本、维度、批处理、缓存与失败状态；优先采用锁定许可和哈希的本地真实模型。选型时核验官方资料与实际兼容性；不得以随机向量、哈希向量或关键词伪装真实语义 Embedding。远程适配器需 Host 秘密存储及明确数据发送边界。
- `conversion-core`：复用现有补丁领域，分离快照校验、语言分析、证据映射、产物决策和预算。仓库识别只依据读取到的内容；静态证据不足则保留或阻塞，不生成假功能。
- 蓝图沿用 `block-catalog` 入口并按职责拆分；新增 v1 与旧版显式迁移、版本来源、差异和恢复，不复制第二套编译或撤销引擎。
- 桌面来源管理/检索/转换审阅/蓝图体验分别做组件和 hooks；CLI 使用同一领域协议及 Host 存储，输出引用大工件的摘要、字节数和 SHA-256。

## 3A：真实摄取

1. 定义并实现稳定来源/文档/片段标识、定位信息、内容摘要、ACL、索引版本、事务状态与错误契约。
2. 文件首批支持 UTF-8 文本、Markdown、HTML 和代码文本；不能解析的格式必须显式拒绝并列出支持范围，不静默吞掉。PDF、Office、OCR 不因“文件来源”自动宣称已支持，若用户要求纳入则补充解析依赖和门禁。
3. URL 支持有界 HTTP(S) 内容读取和条件更新，逐跳验证目标、类型、长度与超时；本地测试端点仅用隔离测试策略，不能放宽普通发行安全规则。
4. 仓库读取锁定 commit 的受控文本快照，默认排除依赖、生成物、大二进制和秘密；不执行上游脚本、Hook 或子模块程序。
5. 增量同步只重算变化片段；删除和 ACL 收紧使旧缓存立即失效；失败不发布不完整索引，取消和重启可以恢复。
6. 接通 CLI/桌面创建资源、添加来源、同步摘要、错误重试和删除。

## 3B：真实检索

1. 先交付关键词检索，再加入真实 Embedding 与向量/混合检索；先做权限过滤，随后召回与重排。
2. 配置 Top-K、阈值、元数据/ACL、规则重排、候选上限、超时/降级、上下文预算与去重；所有设置有真实消费者。
3. 引用绑定当前文档版本和可定位行号/段落/URL/commit；证据不足按策略拒答或澄清，不让生成器编造来源。
4. 固定质量集先冻结再评测；分开汇报检索、Embedding、摘录合成和真实生成式模型调用。阶段 4 的真实 ModelProfile 不提前算作已完成。

## 3C：项目积木化

1. 通用本地只读扫描，锁定 commit、工作区差异处理策略、子目录、依赖声明/锁文件及许可证证据。
2. 至少以 TypeScript/JavaScript 与 Python 真实源码验证符号/输入输出/副作用分析；其余语言缺证据时明确保留。
3. 输出 SourceSnapshot、ConversionEvidenceMap、ConversionPlan、CompatibilityReport、PerformanceBudget、Build Spec 与 SemanticPatch；覆盖自定义积木、蓝图、兼容草案和原生保留四种可解释决策。
4. 生成可运行产物需证明接口、权限、依赖、失败与来源；不把仅添加 retrieve 积木叫作转换了上游算法。
5. 缓存键绑定 commit/路径/摘要；大证据使用受控工件引用；取消、重启恢复、升级差异不得覆盖用户修改。
6. U10 公开仓库建议继续选 `deepset-ai/haystack` 的 BM25 子范围，但重新读取真实仓库，锁定不可变 commit 与许可。2026-09-18 用户已确认此选项；不以既有三文件夹具代替。

## 3D：蓝图与首次体验

1. 资料问答伙伴、代码库讲解助手、知识小老师、轻量任务助手四个起点各有实际行为与互动任务；轻量任务只使用现有受控工具，不冒充完整自主 Agent。
2. v1 公开插槽覆盖角色/知识/工具及必须外部依赖；支持原子展开、版本差异、用户修改保留、明确还原与整体撤销。
3. 保持多选捕获、相对布局、新 ID、保存重开和入门/专业同源无损；新版本保留显式旧蓝图迁移。
4. 普通发行包完整执行选择蓝图 → 修改角色/知识/工具 → 运行 → 解释来源和轨迹。2026-09-18 用户确认目标年龄 10–15 岁，暂时无法安排真实用户试用；Agent 走查不能冒充目标年龄用户研究。

## 验证与交付

开发阶段按影响范围运行单元/契约、Host、组件、CLI、原生 E2E。最终冻结产品源码，构建 `0.3.0` 普通候选，独立验收绑定精确提交/产物哈希。由于涉及持久化、长期索引任务、事件与退出生命周期，最终执行未缩短的 Full 360 次五秒循环 / 30 次原生保存重开。

性能采用任务验收中的三档草案预算，阈值冻结后不得为通过而放宽。安全专项覆盖来源访问、ACL/缓存、跨项目存储、秘密隔离和不执行仓库内容；一次专项覆盖相应功能的安全断言，避免重复造验收项。

通过后更新当前产品文档、替换账本、AGENTS 与进展记录，归档已完成实施安排；内部证据不进入产品。团队项目合并 main 与推送分别请用户授权；完成开发不自动触发这两项操作。
