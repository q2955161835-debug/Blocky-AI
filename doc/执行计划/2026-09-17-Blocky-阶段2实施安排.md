## 2. 架构和范围

保持 `Manifest + 各模块 Workspace → 编译/链接 → IR、清单、诊断 → RuntimeEvent` 的唯一语义链。语言、迁移、命令、设置、资源及终端协议由共享 TypeScript 包负责；Rust Host 管理原生路径、应用数据、秘密、PTY/子进程、浏览器和窗口资源；React 只消费类型化接口。CLI 调用相同领域与原生存储，不建立第二份编译、校验或迁移逻辑。

选择逐层迁移并保留用户工程的方案。只补 UI 会留下 PTY、迁移和隔离门禁缺口；整体推倒重写会丢失已验证的阶段 1 路径，因此不采用这两种方案。

本阶段升级项目/语言地基至 v1，逐个登记变更协议和兼容关系；不对无关协议批量改字符串。旧正式 v1alpha1 与尖峰格式走显式迁移入口，普通加载不得静默接受尖峰格式。迁移以新文件输出、保留原件，失败不写半成品；未知版本和无法表达的语义返回可定位诊断。

用户终端必须是真实 Windows PTY，不能用普通任务 stdout 文本框替代。用户主动创建/输入、调整尺寸、多个会话、取消及退出均受 Host 管理；Agent/Builder/Skill/RPA 只能提交登记的类型化任务和能力票据，不能接触用户 PTY。第三方 PTY/终端显示依赖在选择时核对官方文档、许可证、版本及退出行为，锁定到项目依赖。

资源注册支持 model、knowledge、memory、tool、skill、mcp、guardrail、data、task 的定义与引用，提供专业十二类/入门七类投影；资源可登记不代表 Provider/RAG/MCP 执行器已经实现。未实现的消费者不得配假开关。

本次不提前实现阶段 3–9 的真实 RAG、项目源码转换、真实模型调用、完整构建助手、动态页面生成、完整调试器、RPA、六套兼容适配器和官方 Skills。阶段 1 的确定性知识/Provider/页面夹具在其约定替换阶段到来前继续保留，仅删除本阶段已经被真实地基替代的实现。
