# Blocky 竞品驱动完整开发计划

> 状态：已确认，作为后续完整开发的执行基线
>
> 制定日期：2026-08-23
>
> 适用范围：正式 Blocky 桌面产品、共享语言与运行内核、多模块画布、应用界面、RPA、Windows 生命周期、教育工作区、专业能力、设置中心、兼容模板与生态
> 不适用范围：把 `try/windows-core-spike/` 直接扩写为正式产品

## 1. 这份计划解决什么问题

当前仓库已经证明了本地 Blockly（积木编辑器）、稳定 IR（中间表示）、交互清单、一等 Tool（工具）、确定性运行时、窄 Tauri Host（宿主）和 Windows 原生测试通道可以成立。但它仍是可删除技术尖峰，不是缺少几个菜单就能发布的成品。

下一阶段需要同时解决六个产品矛盾：

1. **像 Scratch 一样易学，又不能被困在玩具上限。** 小学生应能用固定蓝图完成第一个 Agent（智能体），专业用户又能深入原子积木、代码和运行细节。
2. **一句话生成，又不能变成黑盒。** 内置构建助手应把自然语言变成可见、可编辑、可逐步调试的积木，而不是只返回一份不可解释的应用。
3. **Agent 语义完整，又不能堆成几百块的杂货铺。** 积木库应按 Agent 构建者的心智模型组织，并区分积木、资源、运行调试和部署配置。
4. **看起来专业，又不能只堆按钮。** 顶部菜单、命令中心、快捷键、右键菜单和多选操作必须共享同一命令系统，并随上下文正确启用、禁用和解释。
5. **能组合复杂系统，又不能把所有 Agent 堆在一个画布。** 项目必须支持多个模块画布、稳定跨画布连接和 Project Map，同时允许 Agent、RPA、规则、状态机与传统工作流共用一套语言。
6. **能交付定制操作页面和后台任务，又不能隐式扩大产品范围。** 应用界面只在用户明确要求时创建，浏览器预览、RPA 权限、Windows 最小化、后台运行与真正退出必须分别受控。

本计划将“原构想已设计但未实现”“竞品调研后新增或修正”“正式产品阶段”分开，避免把愿景、技术尖峰和当前完成度混为一谈。

## 3. 当前项目诊断

### 3.1 已验证、应迁移的基础

| 能力 | 当前状态 | 正式产品处理 |
|---|---|---|
| 本地 Blockly 编辑器与嵌套连接 | 尖峰已验证 | 按正式包边界重建并迁移契约，不整体复制尖峰 |
| 单 Workspace JSON → 版本化 IR | 尖峰已验证 | 正式产品扩展为 Project Manifest + 多个模块 Workspace；每个 Workspace 仍是对应画布的编辑事实 |
| InteractionManifest 与 ToolContract | 尖峰已验证 | 扩展为运行界面和能力授权的事实来源 |
| 确定性运行时与 RuntimeEvent | 尖峰已验证 | 扩展为暂停、单步、回放、上下文和工具轨迹 |
| Tauri 窄 Host 与原子保存 | 尖峰已验证 | 保留窄桥设计，新增权限、秘密和构建助手 Host |
| Windows 原生 E2E、性能、长稳、安全门禁 | 尖峰已验证 | 迁移为正式仓库的分层门禁 |
| 三栏界面与命令中心原型 | 可操作原型 | 重新设计为正式产品壳和统一命令系统 |

### 3.2 原构想已经设计、但尚未实现

以下不应被误报为本次新增想法：

- 完整 Agent 语义积木目录和组合积木；目录随已确认语义扩展，以稳定 ID、类型和迁移为约束，不维护会阻碍演进的固定总数；
- 模型、Prompt（提示指令）、上下文、记忆、知识、工具、Skill（技能）、多 Agent 和护栏；
- 内置搭建助手通过 Build Spec（搭建规格）和语义补丁修改画布；
- 自定义代码积木、组合积木和积木包；
- OpenClaw、Hermes、Pi、OpenCode、DeepSeek Harness、Codex 兼容模板；
- `blocky` CLI、官方 Agent Skills、Codex 等客户端插件；
- 教育版、专业版、社区、账号与订阅；
- macOS 桌面端和移动端运行客户端。

### 3.3 本轮调研后新增或修正的产品决策

1. 把 Pi SDK 明确为内置构建助手的首选底层候选，而不是用户可见的产品名称或不受控系统代理。
2. 将 Codex 加入首批内置兼容模板，形成 Pi、Codex、OpenClaw、Hermes、OpenCode、DeepSeek Harness 六个独立模板；Codex 适配优先覆盖 Skills、MCP（模型上下文协议）、沙箱、权限与 AGENTS.md 作用域。
3. 重新定义积木库分类，同时把“资源管理”“运行调试”“部署配置”从积木类别中分离。
4. 引入“Blocky 蓝图”作为低门槛固定结构，并允许逐层展开到原子积木和内部代码。
5. 为代码自定义建立中性、绿色、黄色、红色四态，并用图标和文字补充颜色。
6. 把顶部菜单、下拉选择、命令中心、快捷键、空白画布/单块/多选右键统一到同一个命令注册表。
7. 把“可观察 Agent 语言”列为首发壁垒；模板数量、积木数量和平台数量不能优先于完整可解释闭环。
8. 允许多选积木直接保存为用户自己的 Blocky 蓝图；内置兼容模板、官方蓝图和用户蓝图使用同一模板协议，但具有不同来源标识。
9. 运行状态使用瞬时外轮廓表达：激活积木加粗并绿色亮起，警告变黄，错误变红；代码自定义状态使用积木内部徽标，二者不得混淆。
10. Blocky 构建助手只使用此前确定的四个 Blocky 官方 Skills，不把需求澄清、测试生成等内部步骤伪装成新的官方 Skill。
11. 建立应用设置、项目设置、资源配置和积木配置四层边界；本阶段先固定设置中心模板，最终产品完成前必须按真实能力重新盘点一次。
12. 验收需要真实大模型 API 时，先完成无密钥自动化验证，再主动请求用户通过应用安全存储或本地 `.env` 配置测试凭据；缺少凭据时不得把 live（在线）验收写成通过。
13. 将 `$convert-github-project-to-blocky` 固定为 Blocky 官方 Skills 库的核心“项目积木化”入口，按源码证据选择自定义积木、可展开蓝图、兼容模板草案或原生保留报告，不把完整仓库机械包装成一个代码块。
14. 知识库/RAG 作为第一条真实 Agent 组件纵切，复用现有“来源→同步→解析→分段→向量化→索引→检索→重排→压缩→引用”通用积木，不为 LangChain、LlamaIndex、Qdrant 等项目复制品牌积木。
15. Codex、OpenClaw 可进入锁定源码与行为夹具；Claude Code 先使用官方公开配置、扩展和行为夹具，未完成源码与许可证审计前不宣称完整源码转换，也不擅自把首批六个模板改为七个。
16. 阶段 1 调整为首个可展示 Demo，但 Demo 只是一项开发阶段和交付结论：界面、项目格式、运行事件和设置中不增加后续要删除的徽标、横幅、水印、`demoMode` 字段或专用分支；固定夹具走正式接口并由后续真实实现直接替换。
17. 建立以真实用户操作顺序组织的跨模块人工验收基线，覆盖首次创建、配置、运行高亮、保存蓝图、项目积木化、保存重开、真实 RAG、Harness 兼容、性能和安全负例。
18. 中间区域增加项目标签栏，首批只有画布和浏览器两种标签；一个项目可打开多个 Agent、自动化或通用模块画布，并通过稳定、有类型的跨画布引用连接。
19. 应用界面默认不存在；只有用户主动要求或执行“创建应用界面”命令后，才生成 AppSurfaceManifest、最小前端桥和 Web 前端，并在隔离浏览器标签中预览。
20. RPA 作为“桌面自动化（RPA）”工具和可复用自动化蓝图，优先使用浏览器语义定位或 Windows UI Automation，绝对坐标只作高风险回退；阶段 7 先完成有人值守流程，阶段 11 再进入企业无人值守能力。
21. 正式项目语言从“Agent 项目”提升为可组合模块项目；Agent、RPA、状态机、规则系统、行为树、事件驱动、传统工作流和混合 AI 架构都使用同一 IR/权限/轨迹，不为每种架构复制产品模式。
22. Windows 最小化默认进入通知区域，保留任务栏选项；最小化、关闭、退出和后台运行分开设计，通知区域菜单可恢复窗口并安全停止/退出。

### 3.4 当前界面实查

| 检查场景 | 当前表现 | 健康度 | 对计划的影响 |
|---|---|---|---|
| 初始三栏工作台 | 暗色视觉和左右分工已有产品感，但空画布没有明确首要动作；“搭建助手”实际只有添加 AI 伙伴、添加聊天入口和打开快速上手三个静态动作 | 一般 | 用“从蓝图开始”和一句话构建替换空状态，把运行 Agent 与构建助手的职责写清 |
| 快速上手 | 只有“选积木、组织流程、测试对话、保存文件”四张说明卡，没有引导用户在画布上完成真实步骤 | 较弱 | 改为有完成状态、错误反馈和可恢复进度的互动任务 |
| 顶部菜单与命令中心 | 当前命令只覆盖文件、编辑、视图、帮助；文件菜单和命令中心可以同时展开并重叠 | 较弱 | 先建设共享命令注册表和统一弹层管理器，再扩展运行/构建菜单 |
| 空白画布右键 | 使用明亮的 Blockly 默认菜单，仅有撤销、重做、整理和删除等基础项 | 较弱 | 统一 Blocky 主题，增加快速添加、粘贴、注释、区域、全选、网格和视图命令 |
| 单块右键 | 仅有复制和删除，缺少检查、解释、编辑实现、断点、从此运行和保存为蓝图 | 较弱 | 建立单块、多选、积木库和运行事件的上下文命令矩阵 |
| 积木目录 | 代码中当前共 31 个目录项，分为 AI 伙伴、交互入口、消息、工具、数据、流程 6 类 | 尖峰可用，产品不足 | 用专业十二类作为稳定语义；入门七类只做同一语言的任务化投影 |
| 中间工作区与窗口生命周期 | 当前只有单个画布，没有项目标签栏、浏览器预览、多画布引用或通知区域最小化闭环 | 不足 | 正式阶段 1 建立画布/浏览器标签、跨画布链接和 Windows 通知区域最小闭环 |

这组问题不是要求继续美化尖峰；它们用于约束正式工作台的产品壳、首次体验和命令架构。

## 4. 竞品结论如何转成 Blocky 决策

| 竞品类型 | 值得借鉴 | Blocky 不应照搬 | 转化为 Blocky 的动作 |
|---|---|---|---|
| AI Blocks、Discer.io、Blockly AI Playground | 积木直接表达 Agent 能力、示例驱动 | 黑客松原型式功能堆叠、弱工程闭环 | 先完成可保存、可运行、可调试、可迁移的语言闭环 |
| PictoBlox、mBlock、Scratch、Tynker、MakeCode | 首次体验、课程、固定模板、积木到代码进阶 | 把 AI 只当单个能力块 | 蓝图模式、教师验证、同一 IR 下的渐进式复杂度 |
| Blocks Builder AI | Model/Prompt/Context 分类、引导教程、真实模型和对话 | 只把积木导出成提示词 | 加入 Memory、Knowledge、Tool、Skill、Guardrail 和运行轨迹 |
| Dify、Coze | RAG（检索增强生成）、插件、工作流、日志、资源管理 | 通用节点连线和无限功能面板 | 资源管理器独立于画布；画布坚持嵌套语言和受约束连接 |
| Replit Agent | 一句话创建、计划、实时预览、可应用变更 | 黑盒生成和反复修补 | 自然语言 → 搭建规格 → 幽灵积木/差异 → 用户接受 → 可追溯运行 |
| Pi、OpenClaw、Codex | 轻量循环、工具/Skill/插件边界、SDK、沙箱和作用域 | 直接暴露底层依赖细节、原始文件系统和 Shell | 建立 Blocky 适配层、权限层、项目语义工具和用途清晰的兼容模板 |
| LangChain、LlamaIndex、Haystack、Qdrant | 模块化摄取、检索、混合查询、重排和生产优化 | 为每个框架复制专用节点，或把向量库内部状态写进项目 | 用通用知识积木、资源适配器和可展开蓝图表达；大型索引留在受控资源存储 |
| Claude Code | CLAUDE.md、Skills、Subagents、MCP、Hooks、Plugins 的真实落地边界 | 根据公开仓库页面臆测完整核心实现或立即新增第七模板 | 先做配置/扩展/行为夹具，专项审计通过后再决定模板地位 |

Blocky 的竞争壁垒不是“积木比别人多”，而是：

> **可见积木 AST（抽象语法树）→ 稳定 IR → 受控 Runtime（运行时）→ 可回放 Trace（轨迹）→ 可逆模板/代码映射。**

GitHub 项目积木化、RAG 具体积木、Harness 夹具和性能边界统一以[《Blocky GitHub 项目积木化与 Agent 组件设计》](../产品设计/Blocky-GitHub项目积木化与Agent组件设计.md)为准。

中间项目标签栏、多画布引用、用户按需创建的应用界面、RPA、非传统架构和 Windows 通知区域统一以[《Blocky 多画布、应用界面与 RPA 设计》](../产品设计/Blocky-多画布应用界面与RPA设计.md)为准。

## 5. 面向用户的品牌与术语

底层依赖只出现在“关于、许可证、兼容详情和开发者诊断”中，不出现在主任务文案里。

| 产品对象 | 推荐名称 | 用户看到的含义 | 禁止用法 |
|---|---|---|---|
| 桌面产品 | **Blocky Studio** | 搭建、运行和调试 AI 伙伴的工作台 | Pi 前端、Blockly 壳 |
| 内置编程智能体 | **Blocky 构建助手** | 用一句话搭建、解释、修复和优化积木 | 基于 Pi 改造的 Agent |
| 固定/组合模板积木 | **Blocky 蓝图** | 适合第一次使用，可展开和深度编辑 | 低配模式、儿童块 |
| 运行调试器 | **运行轨迹** | 查看每一步输入、上下文、工具和输出 | RuntimeEvent Viewer |
| 专业输出工作区 | **底部面板** | 通过问题、运行日志、终端和输出完成定位、执行与诊断 | 调试控制台、Agent Shell |
| 完整项目起点 | **内置兼容模板** | 从锁定的上游能力映射创建可改造项目 | 六种产品模式、只写 Pi 版本 |
| 用户自建复合能力 | **自定义能力** | 可复用、可分享的组合积木 | 魔改块 |
| 用户创建的 Web 前端 | **应用界面** | 为 Agent/自动化提供操作页面，并在浏览器标签预览 | Blocky Web 版、自动生成网页 |
| 企业 UI 自动化 | **桌面自动化（RPA）** | 受控操作浏览器和桌面应用，可独立运行或作为 Agent 工具 | 录鼠标脚本、无限电脑权限 |
| 项目编辑页 | **画布** / **浏览器** 标签 | 分别编辑模块积木、预览应用界面 | 多个产品窗口、节点图标签 |

首批六个内置兼容模板使用任务名称；模板详情明确显示兼容对象、版本和验证等级：

| 用户可见名称 | 主要用途 | 二级兼容标识 |
|---|---|---|
| 轻量代码助手 | 本地、少工具、快速代码任务 | Pi 兼容 |
| 专业编程助手 | 仓库级开发、Skills、MCP、沙箱 | Codex 兼容 |
| 个人全能助理 | 消息、浏览器、自动化和多渠道 | OpenClaw 兼容 |
| 团队协作中枢 | 委派、协作和会话编排 | Hermes 兼容 |
| 工程开发工作台 | 工程型 Agent 与开发工具链 | OpenCode 兼容 |
| 可组合研究工作台 | 研究流程、Worker 和可审查产物 | DeepSeek Harness 兼容 |

最终名称需在实施前进行一次中文母语可理解性和商标检索；本计划先锁定命名原则，不宣称名称已完成法律审查。

## 6. 积木库新分类

### 6.1 专业视图：稳定的 Agent 语义分类

| 顺序 | 类别 | 负责内容 | 典型积木 |
|---:|---|---|---|
| 1 | **触发与交互** | Agent 何时开始、接收什么 | 收到消息、定时、文件输入、表单、Webhook |
| 2 | **智能体** | 角色、目标、委派和生命周期 | 创建 Agent、设定目标、调用子 Agent、结束任务 |
| 3 | **指令与上下文** | Prompt、系统约束和上下文组装 | 角色指令、追加上下文、选择历史、上下文窗口 |
| 4 | **模型** | 模型选择、参数、路由和回退 | 选择模型、温度、结构化输出、回退模型 |
| 5 | **知识库** | 文档摄取、检索、引用和更新 | 添加知识源、检索、重排、引用、刷新索引 |
| 6 | **记忆** | 会话/用户/长期状态 | 读取记忆、保存记忆、遗忘、作用域和保留期 |
| 7 | **工具** | 执行有副作用或外部动作 | 文件、浏览器、API、消息、代码、设备工具 |
| 8 | **技能与扩展** | 可复用方法、MCP、插件和积木包 | 使用 Skill、连接 MCP、安装扩展、调用自定义能力 |
| 9 | **协作与编排** | 多 Agent、并行、队列和人工协作 | 委派、并行、汇合、等待、请求确认 |
| 10 | **护栏与权限** | 输入/输出策略、能力授权和预算 | 允许工具、敏感检查、预算、确认、内容策略 |
| 11 | **数据与逻辑** | 变量、结构、条件、循环和转换 | 变量、对象、列表、如果、循环、映射、解析 |
| 12 | **输出与渠道** | 最终响应、界面和外部投递 | 回复消息、生成文件、展示卡片、发送到渠道 |

分类规则：

- Tool 是“能做什么动作”，Skill 是“如何组合能力完成一类任务”，Knowledge 是“可检索事实”，Memory 是“随交互积累的状态”；四者不得混为一类。
- 模型配置、知识源、密钥、Skill 包和 MCP Server 同时是可复用资源。画布使用“引用资源”积木，详细管理放在资源面板，避免同一配置到处复制。
- **运行与调试**是编辑器能力，不是积木库一级分类；断点、上下文检查、单步和回放进入运行轨迹。
- **项目、部署和账号**是工作台能力，不是积木语义；不得为了“什么都有”而积木化。

### 6.2 入门视图：任务化投影，不创造第二套语言

入门视图只显示 7 个易懂分组和 10–15 个高频蓝图，底层仍编译成相同原子积木与 IR：

1. 开始：什么时候启动、用户给了什么；
2. 角色：它是谁、要完成什么；
3. 会思考：指令、上下文和默认模型；
4. 会查找：知识库和安全的网络检索；
5. 会记住：短期/长期记忆；
6. 会行动：工具和技能；
7. 会回答：文本、文件、卡片和渠道输出。

“判断与安全”默认内嵌在蓝图的可见插槽中，展开蓝图后归入专业视图的“数据与逻辑”和“护栏与权限”。入门/专业切换只改变呈现和推荐，不改变项目格式。

## 7. 低门槛与高上限的同一条路径

### 7.1 四级创作层次

| 层级 | 用户操作 | 适用人群 | 必须保持的可逆性 |
|---|---|---|---|
| 1. 内置兼容模板 | 选择一个完整示例后直接运行 | 第一次使用者 | 可查看兼容对象、包含的蓝图和资源 |
| 2. Blocky 蓝图 | 修改角色、知识、工具等插槽 | 小学生、普通用户 | 一键展开为原子积木 |
| 3. 原子积木 | 自由组合完整 Agent 语义 | 进阶与专业用户 | 可保存为自定义能力 |
| 4. 内部代码 | 编辑受控实现或文本 DSL（领域语言） | 开发者 | 保留来源、差异、版本和回退点 |

### 7.2 蓝图必须满足的契约

- 不是截图或不可编辑黑盒；每个蓝图声明输入、输出、权限、资源和错误边界。
- 蓝图只能折叠已经合法连接的原子积木；展开与折叠应保持语义等价。
- 官方蓝图更新时保留用户差异，不静默覆盖已自定义内容。
- 蓝图可提供“解释给我听”“用示例替换”“只展开这一层”。
- 入门项目默认只暴露 3–5 个关键插槽，其他参数使用可查看默认值。

### 7.3 内部代码和状态表达

代码不直接藏进积木标题。用户通过右侧检查器进入“实现”页签，看到官方基线、自己的差异、校验结果和恢复操作。

| 状态 | 视觉与文字 | 行为 |
|---|---|---|
| 官方默认 | 中性边框 + “官方实现” | 正常运行 |
| 已自定义且有效 | 绿色左侧标记 + 对勾/铅笔图标 + “已自定义” | 正常运行，可查看差异和还原 |
| 有警告 | 黄色标记 + 警告图标 + “建议检查” | 可按策略运行，明确风险 |
| 无效 | 红色标记 + 错误图标 + “需修复” | 阻止相关路径运行，定位到错误 |

不得只依赖红绿颜色。校验链至少包含语法、类型、依赖、权限、秘密引用、沙箱策略和最小 dry-run（试运行）；错误必须映射回具体积木和代码位置。

### 7.4 自由创建蓝图

用户可以框选或通过 `Shift + 左键` 逐个多选积木，然后执行“保存为蓝图”。保存流程必须：

1. 预览选中积木、相对布局、连接、输入、输出和外部引用；
2. 要求填写名称，允许补充说明、图标、分类、公开插槽和默认值；
3. 明确列出模型、知识、工具、Skills、MCP、秘密和权限依赖；
4. 让用户选择复用现有资源引用，或把可公开配置复制为蓝图参数；秘密只保留引用，永不写入蓝图；
5. 保存为个人蓝图并生成版本、来源和内容摘要；插入时为积木生成新的稳定 ID；
6. 支持编辑、复制、导出、删除和后续发布到积木社区。

连通或不连通的多选内容都可以保存：连通结构成为可展开组合蓝图；多个独立顶层栈成为带相对布局的场景蓝图。若选区依赖未选中的必需积木，保存前必须把它显示为外部插槽或阻止保存，不能生成残缺模板。

### 7.5 运行状态高亮

运行状态与代码状态使用两个独立视觉层：

| 运行状态 | 画布表现 | 辅助表达 |
|---|---|---|
| 等待 | 原分类轮廓 | 轨迹显示“等待” |
| 当前激活 | 外轮廓加粗并绿色亮起，可使用克制的呼吸光晕 | 运行指针图标 + “正在执行” |
| 已完成 | 绿色轮廓短暂淡出后恢复分类色 | 对勾 + 耗时 |
| 警告 | 黄色加粗外轮廓 | 警告图标、原因和继续策略 |
| 错误 | 红色加粗外轮廓并保持到用户处理 | 错误图标、简短原因和跳转到问题面板 |

外轮廓不得改变积木尺寸或造成布局抖动；快速运行时按事件顺序显示但允许合并过短动画。开启“减少动态效果”后取消呼吸动画，保留粗轮廓、图标和文字。父蓝图折叠时，内部积木的警告或错误必须汇总到父蓝图，展开后仍能定位原始积木。

## 8. Blocky 构建助手

### 8.1 用户体验

构建助手与用户创建的“运行 Agent”是两个独立上下文：

1. 用户说“帮我做一个能读取作业文件并按评分标准给建议的助手”；
2. Blocky 构建助手先给出一句话理解和 3–6 步搭建计划；
3. 生成 Build Spec；
4. 把语义补丁显示为半透明幽灵积木、资源变更和权限清单；
5. 默认等待用户接受，也允许在已建立 Git/项目检查点后使用“直接搭建”；
6. 接受后编译、校验并运行确定性预览；
7. 如果失败，助手只能针对诊断提出新补丁，不能静默改写整个项目。

助手支持：搭建、解释所选、修复错误、补全缺口、转换为蓝图、生成测试、比较两种方案。它不直接编辑磁盘 JSON，不拥有无限文件系统或 Shell 权限。

### 8.2 Pi 的内部使用边界

候选实现是在 Tauri Host 管理的本地进程中嵌入 Pi SDK，而不是在 WebView 内运行。产品界面只出现“Blocky 构建助手”。

Pi 的最小四工具交互模型可保留，但必须替换为 Blocky 语义工具：

| 内部工具 | 对应基础能力 | Blocky 权限边界 |
|---|---|---|
| `inspect` | read | 只读积木目录、项目快照、选择区、诊断和已授权资源元数据 |
| `draft` | write | 只生成 Build Spec，不直接写 workspace 或任意文件 |
| `patch` | edit | 只生成版本化语义补丁、幽灵积木和可回退差异 |
| `verify` | bash | 只调用白名单编译、仿真、测试和格式化任务，不暴露宿主 Shell |

Host 为每次调用签发短时、最小作用域的 capability token（能力令牌）；模型只能看到当前任务允许的工具 schema。模型密钥、Cookie、路径和运行秘密不得进入画布、事件日志或项目导出。

正式采用 Pi 前必须完成：许可证审查、锁定版本、离线/更新策略、崩溃隔离、资源上限、取消/超时、事件映射、无凭据测试 Provider 和供应链扫描。若 Pi SDK 不满足这些门禁，Blocky 保留自己的 BuilderAdapter 接口，可更换底层而不改变产品语言。

### 8.3 内置 Skills

构建助手、CLI、Codex 插件和其他 Agent 客户端共用此前已经确定的 Blocky 官方 Skills 库，首批固定为：

| 官方 Skill | 职责 |
|---|---|
| `$build-blocky-agents` | 使用已有积木、蓝图和项目结构搭建或修改 Blocky Agent |
| `$create-blocky-blocks` | 创建、验证、封装和打包可视化或代码自定义积木 |
| `$convert-github-project-to-blocky` | 把普通 GitHub 项目的可用能力映射为工具、数据、流程和 Agent 积木 |
| `$reverse-agent-to-blocky` | 逆向现有 Agent，生成证据映射、覆盖报告和必要原生保留内容 |

需求澄清、目录检索、Build Spec、语义补丁、测试生成和错误定位是上述 Skills 的内部步骤或 Blocky 服务能力，不新增同名官方 Skills。四个 Skills 必须以真实 CLI、Schema、模板和运行结果为依据迭代；每次修改都要绑定失败夹具、修复证据、兼容范围和版本，不允许只凭提示词感觉改写。

不得把通用网络、任意终端或外部账号权限作为默认内置能力。扩展 Skill 必须声明版本、来源、输入输出、权限、网络域和可测试契约。

### 9.2 统一命令架构

顶部菜单、命令中心、快捷键和右键菜单必须引用同一条 `CommandDefinition`：命令 ID、标题、快捷键、图标、可见条件、启用条件、禁用原因、选择要求、执行函数和撤销策略。再由统一 Popover Manager（弹层管理器）保证同一时刻只存在一个一级菜单，修复当前“文件菜单与命令中心重叠”的问题。

命令应支持键盘搜索、最近使用、分类、模糊匹配、作用域筛选和“为何不可用”的说明。破坏性操作遵循可撤销、二次确认或检查点策略。

### 9.3 右键与框选菜单

| 上下文 | 必备命令 |

| 空白画布 | 粘贴、快速添加/搜索、添加注释、添加区域、全选、整理布局、网格、缩放、适应画布 |
| 单个积木 | 打开检查器、重命名、解释、展开蓝图、编辑实现、剪切/复制/复制副本/删除、启用/停用、注释、断点、从此运行、检查输入输出、保存为蓝图 |
| 多选/框选 | 剪切、复制、复制副本、删除、启用/停用、分组/取消分组、对齐、等距分布、整理、生成自定义能力、保存为蓝图、移动到区域、设置断点 |
| 积木库条目 | 添加到画布、收藏、查看文档、查看版本/来源/权限、加入自定义分组 |
| 运行事件 | 跳到来源积木、查看输入输出、查看上下文、重放到此处、复制脱敏诊断 |
| 画布/浏览器标签 | 激活、固定、重命名、复制路径、向左/右移动、关闭、关闭其他/右侧、在 Project Map 定位 |
| 浏览器预览 | 刷新、停止/重启预览、切换视口、检查元素绑定、打开日志/网络摘要、复制测试地址 |

所有菜单使用 Blocky 主题，不继续显示 Blockly 默认白色菜单；但保留 Blockly 原生命令的语义和撤销行为。

### 9.4 画布鼠标与快捷键

以 Windows 习惯和本机 ComfyUI 的成熟交互为参考，但通过 Blocky 的统一命令注册表实现，并允许在设置中修改：

| 输入 | Blocky 行为 |
|---|---|
| 左键单击积木 | 只选择该积木或顶层栈 |
| `Shift + 左键单击` | 在点击模式下把积木加入/移出当前多选；不进入拖拽模式 |
| 空白处左键拖动 | 框选；与框选范围相交的顶层栈进入选择 |
| 拖动任一已选积木 | 保持相对位置移动全部选中顶层栈 |
| 按住鼠标中键并拖动 | 无论指针位于空白还是积木上，都直接平移画布，不移动积木 |
| `Space + 左键拖动` | 临时平移画布，松开恢复原模式 |
| 鼠标滚轮 | 以指针为中心缩放；只在画布命中时生效 |
| 双击空白或 `Tab` | 打开积木快速搜索 |
| `Ctrl + A/X/C/V` | 全选、剪切、复制、粘贴 |
| `Ctrl + Shift + V` | 粘贴并按策略保留与未选积木的外部引用，冲突时先预览 |
| `Delete` / `Backspace` | 删除选择，可由撤销恢复 |
| `Ctrl + Z/Y` | 撤销/重做；同时支持 `Ctrl + Shift + Z` 重做 |
| `Ctrl + S` / `Ctrl + Shift + S` | 保存/另存为 |
| `Ctrl + K` | 打开命令中心 |
| `Ctrl + T` / `Ctrl + Shift + T` | 新建画布 / 恢复最近关闭的标签 |
| `Ctrl + W` | 关闭当前画布或浏览器标签，不等同退出项目 |
| `Ctrl + Tab` / `Ctrl + Shift + Tab` | 按最近使用顺序切换项目标签 |
| `Ctrl + G` / `Ctrl + Shift + G` | 分组/取消分组 |
| `Alt + Enter` | 在跨画布引用上打开目标画布；导航命令可返回来源 |
| `.` | 适应选择；无选择时适应全部积木 |
| `F2` | 重命名当前可命名对象 |
| `F5` / `Shift + F5` | 运行/停止 |
| `F9` | 切换断点 |
| `F10` / `F11` / `Shift + F11` | 单步越过/进入/跳出 |
| `Escape` | 取消当前拖动、关闭临时菜单；再次按下清除选择 |

快捷键设置必须检测冲突、显示命令作用域、支持恢复默认，并为 macOS 映射 `Ctrl` 到 `Cmd`。浏览器/WebView 保留快捷键不得无提示覆盖；不可用命令应显示原因。

### 9.5 积木配置与设置入口

模型、知识库、工具、Skill、MCP、护栏等积木可通过双击、右键“配置”或检查器按钮打开配置。模型积木不能直接把真实 API Key 写入积木：

- 积木保存 `ModelProfile` 引用和可公开的逐块覆盖参数；
- Provider 配置页填写类型、Base URL、模型 ID、兼容协议、超时和连接测试；
- API Key、Token、Cookie 和私有地址由 Host 安全存储或 Git 忽略的 `.env` 提供，项目中只保存不含密钥的引用；
- 配置页显示值来自应用、项目还是积木覆盖，并提供“恢复继承”；
- 缺失配置时积木显示可操作诊断，点击直接跳到对应字段。

设置中心的信息架构、字段模板和最终复核任务以[《Blocky 设置中心设计模板》](../产品设计/Blocky-设置中心设计模板.md)为准。

### 9.6 多画布与浏览器标签

- 项目标签栏位于中间工作区顶部，只提供画布和浏览器两种标签；右侧“搭建助手/运行 Agent”仍保持独立，不与中间标签混为一栏。
- 一个画布对应一个 Agent、自动化或通用模块 Workspace；跨画布引用保存稳定 `moduleId/exportId`，双击或 `Alt + Enter` 跳转。
- 浏览器标签只在用户主动创建/打开应用界面后出现；默认项目的 AppSurface 数量为 0。
- 标签打开状态属于用户会话，模块和应用界面属于项目；关闭标签不能删除对应模块或页面。
- Project Map 用于导航、依赖和影响分析，不成为可直接运行的第二套节点连线编辑器。

## 10. 正式产品目标架构

正式 monorepo 建议按职责建立包，而不是复制 `try/windows-core-spike/`：

```text
apps/
  studio-desktop/          Blocky Studio 桌面界面
  studio-host/             Tauri/Rust Host、权限、存储、秘密和 sidecar
packages/
  language-schema/         Workspace、Module/Project IR、source map、迁移与版本
  project-model/           Project Manifest、模块索引、跨画布引用与会话布局
  block-catalog/           原子积木、分类、蓝图与积木包协议
  compiler/                Workspace → IR、诊断与清单
  runtime-core/            调度、事件、预算、取消、回放
  runtime-observability/   轨迹、上下文、工具、记忆和成本检查
  observability/           Diagnostic/RuntimeEvent 投影、结构化日志、脱敏、诊断和审计
  terminal-protocol/       用户终端、项目具名任务和 Agent 进程请求的隔离契约
  resource-registry/       模型、知识、工具、Skills、MCP、护栏引用
  knowledge-runtime/       摄取、分段、索引、检索、重排、引用与评估
  settings-schema/         应用/项目/资源/积木设置、迁移、搜索与重置
  command-system/          菜单、命令中心、快捷键和上下文菜单
  builder-protocol/        Build Spec、语义补丁、幽灵预览和回退
  builder-host/            Pi/其他引擎适配、Skills 与受控工具
  conversion-core/         GitHub 快照、证据映射、产物决策与语义补丁
  adapter-sdk/             Pi、Codex、OpenClaw 等原生适配协议
  app-surface/             AppSurfaceManifest、前端桥、构建和隔离预览契约
  rpa-runtime/             浏览器/UIA 定位、桌面动作、录制转换、检查点与恢复
  ui-editor/               项目标签、画布、Project Map、检查器、大纲、问题、底部面板和资源面板
  ui-runtime/              入口界面、运行 Agent、运行日志、运行轨迹、终端和输出
  project-format/          保存、导入导出、迁移和恢复
  test-fixtures/           Provider、RAG、GitHub、Harness、轨迹和安全夹具
tools/
  blocky-cli/              官方 CLI
  codex-plugin/            Codex Skills/插件集成
```

必须维持七条不可破坏的边界：

1. WebView 不持有模型密钥、任意文件系统或 Shell 权限；
2. Project Manifest 管理模块索引和可选 AppSurface；每个模块的 Workspace JSON 是对应画布的编辑事实，Module/Project IR、清单和轨迹均可重新生成；
3. 打开标签、标签顺序、浏览器视口和分栏是用户会话状态，不得改变运行语义；
4. 应用界面和浏览器预览通过最小 FrontendBridgeContract 连接，不获得 Tauri 全局对象或作品 Agent 的隐式工具权限；
5. RPA 按应用、窗口、目标、动作和数据范围授权，录制器只生成待审阅语义补丁；
6. Builder、Runtime、RPA、终端 Host、日志系统和兼容适配器通过版本化协议协作，不互相直接修改内部状态；
7. 用户终端与 Agent 进程工具物理隔离；运行日志只投影 RuntimeEvent，日志在进入总线、UI、磁盘和导出前完成结构化脱敏。

**通过门禁**：官方夹具往返映射不静默丢语义；不支持项在导入前明确列出；第三方运行时崩溃不破坏 Blocky 项目；Codex、OpenClaw 和 Claude Code 的证据等级分别准确展示。

#### 阶段 9：Blocks ↔ Text、CLI、官方 Skills 与 Codex 插件

**交付**

- 可解析、可格式化、可生成 source map 的 Blocky Text DSL；
- Blocks ↔ Text 的稳定往返子集和冲突界面；
- `blocky` CLI：validate、compile、test、inspect、migrate、pack，项目积木化的 snapshot/inspect/plan/benchmark/apply，应用界面的 surface plan/diff/apply/build/preview，以及 RPA inspect/validate/recording-import；
- 四个仓库级 Blocky 官方 Skills 与 Codex 插件；每次优化绑定真实失败夹具和版本记录；
- 将 `$convert-github-project-to-blocky` 作为核心 Skill 在干净 Codex 会话和至少一个兼容客户端中前向测试，覆盖自定义积木、蓝图、兼容草案和阻塞报告；
- 编程 Agent 通过语义补丁协作，不能绕过编译器直接改项目 JSON。

**通过门禁**：支持子集往返无语义漂移；CLI/桌面诊断一致；Codex 权限和 AGENTS.md 作用域被正确尊重。

#### 阶段 10：教育工作区

**交付**

- 教师、班级、学生、作业、提交、评语和版本锁定课程；
- 教师可冻结蓝图/资源版本，学生项目仍使用统一格式；
- 无真实密钥的课堂 Provider、离线资源和设备容量检测；
- 教学进度、错误模式和最小隐私分析。

**通过门禁**：班级分发→学生完成→提交→教师查看完整闭环；未成年人数据、账号权限、遥测和删除策略通过专项 L3 验收。

#### 阶段 11：专业团队、应用部署与企业 RPA

**交付**

- 项目环境、Secrets、API/定时任务/渠道部署；
- 版本、审查、评测集、运行日志、成本和团队权限；
- 插件/MCP/知识服务的企业策略；
- 应用界面的认证、环境配置、域名/部署、版本审查、可访问性、安全和回滚；
- 无人值守 RPA 的 Worker/机器池、队列、计划任务、企业凭据、并发许可、审计、录屏保留和失败转人工；
- 安装签名、自动更新、崩溃恢复和回滚。

**通过门禁**：开发/测试/生产配置隔离；应用界面和自动化部署可回滚；无人值守 Worker 不获得隐式交互式用户权限；秘密不进入日志、录屏和导出；权限/数据/发布按 L3 验收。

### R3：生态与多平台

#### 阶段 12：积木社区与供应链

**交付**：积木包、蓝图、Skills、兼容模板发布；签名、权限清单、兼容范围、扫描、审核、撤回、更新和评分反馈。

**通过门禁**：恶意/失效包可阻止、隔离和撤回；旧项目可锁定版本；社区内容不会获得隐式 Host 权限。

#### 阶段 13：macOS 与移动运行端

**交付**：macOS 同等搭建能力；Android、HarmonyOS、iOS 只运行已搭建 Agent 的受控客户端；项目同步和平台能力降级提示。

**通过门禁**：共享 IR/Runtime 兼容矩阵通过；平台缺失能力不会静默失败；签名、权限、商店和设备专项验收独立完成。

#### 阶段 14：开放个人版、组织方案与商业化

2026-10-03用户更新：个人版完全开源，建设作品、蓝图、积木和教学资源社区；机构/K12付费包含组织后台配置与教学支持，模型Token订阅单独核算。不通过限制个人客户端创作能力切分软件权益。组织托管、部署、维护和算力各自界定交付与账单，账号或订阅不得改变项目语义、破坏离线打开或锁住用户自有项目。具体方向见[最新商业决定](../产品设计/2026-10-03-开源社区与机构收费方向.md)。

#### 用户增补：一键生成 Agent App

2026-10-03用户提出：结合Agent页面和积木结构，基于Pake或Tauri二次开发，形成一键生成Agent App的功能。它依赖阶段11应用部署及阶段13运行端能力，不改变当前阶段8–14仍需持续开发的事实。

- 输入：已校验的Agent项目/积木执行语义、Agent交互页面、模型资源和权限声明。
- 用户流程：选择目标平台及应用配置 → 校验运行依赖与权限 → 构建可独立运行应用 → 保存构建结果和版本。
- 候选路径：Pake的桌面封装能力或Tauri定制应用壳二次开发；Blocky运行内核、受控桥接和资源配置需自行集成，不能将网页封装视为Agent已独立运行。
- 平台：与既有Windows/macOS创作端及Android/iOS/HarmonyOS运行端计划衔接。Pake本身不是移动或HarmonyOS适配的完成证据，各端签名、权限、安装、实际运行和版本恢复分别验证。
- “一键生成”指面向用户整合构建流程，不默认包含商店上架或云端发布。

本段是新产品方向及依赖记录，当前材料任务不实施或发布该功能。

| 性能 | 多画布按模块增量加载/编译、标签切换、拖拽、搜索、浏览器预览隔离与回收、终端大输出/日志背压、RPA 定位/截图预算、轨迹上限、Memory/Knowledge 容量预算 |

- 新积木分类和 Blocky 蓝图；
- 真实知识摄取、检索、引用和项目积木化领域服务；
- 最小完整 Agent 语义闭环；
- Blocky 构建助手的可审查语义补丁；
- 运行轨迹；
- 问题/运行日志/终端/输出底部面板、受控用户终端和结构化日志系统；
- 统一命令系统和专业基础交互；
- 画布/浏览器项目标签、多画布稳定引用、默认零应用界面与用户显式创建闭环；
- Windows 最小化到通知区域、恢复和真正退出闭环；
- 设置中心、积木配置入口和快捷键自定义；
- 项目、权限、秘密、恢复和测试门禁。

### P1：形成专业上限和生态入口

- Pi/Codex 首批适配器；
- Blocks ↔ Text、CLI、四个官方 Skills/Codex 插件，其中项目积木化 Skill 优先；
- OpenClaw 源码/行为夹具与 Claude Code 公开配置/行为夹具；
- 用户明确要求后生成的应用界面、隔离浏览器预览和可审查前端文件差异；
- 有人值守 RPA v1、非传统架构蓝图、多画布 Project Map 与影响分析；
- 教育工作区；
- 团队、评测、应用界面部署和企业无人值守 RPA。

### P2：扩大供给和平台

- 其余兼容方案；
- 积木社区；
- macOS、移动运行端；
- 权益切分和商业化。

### 明确禁止

- 为了尽快展示而把尖峰目录改名成正式应用；
- 为 Demo 增加以后需要删除的 UI 标记、项目字段、设置项或运行分支；
- 先铺满积木目录再补运行闭环；
- 把 Pi、Codex、OpenClaw 等名字写进普通积木标题；
- 让构建助手直接修改任一模块 Workspace JSON 或执行任意 Shell；
- 让构建助手、作品 Agent、Skill、扩展或 RPA 附加、读取或控制用户终端，或让 UI 从普通日志字符串推断运行状态；
- 用户没有明确要求时自动创建应用界面、前端目录、浏览器标签、依赖或部署任务；
- 把浏览器标签做成继承 Blocky Host 权限、共享跨项目 Cookie 的任意网页浏览器；
- 把 Project Map 变成可以绕过画布语义的第二套节点工作流；
- 让 RPA 默认依赖绝对坐标、录制敏感输入、取得全局永久权限或盲目重放副作用；
- 混淆最小化、关闭和退出，或在通知区域图标消失后留下不可见 Host、sidecar、预览服务或运行时；
- 把每个设置、资源和部署动作都做成积木；
- 用红绿颜色作为唯一正确性提示；
- 只做静态“快速上手”卡片却声称完成新手引导；
- 在没有正式适配器验收前声称“原生兼容”；
- 在用户未授权前 push、发布、上架或提交外部平台。

5. `$convert-github-project-to-blocky` 是官方 Skills 库的核心项目积木化入口，知识库/RAG 是首个真实 Agent 组件纵切，Codex/OpenClaw/Claude Code 按不同证据等级进入夹具。

本轮阶段 0 执行只负责正式契约、正反夹具、状态账本、阶段 1 接口交接、基线同步和验收归档，不实施正式产品代码。阶段 0 完成后，后续开发人员从阶段 1 独立开发计划开始；在进入每个开发子任务前，必须按项目规则草拟相应验收项并询问用户确认。
