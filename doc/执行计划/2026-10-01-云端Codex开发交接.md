## 环境与验证

- Node.js 22.23.1、pnpm 10.23.0；安装：`pnpm install --frozen-lockfile`。
- 云端可先运行 `pnpm typecheck`、`pnpm test:unit`、`pnpm test:contracts`、`pnpm test:component`。Linux 环境下先观察每个测试的实际平台条件；涉及 Windows 的项保留未执行状态。
- Windows Host、Tauri、UI Automation、AppContainer、DPAPI、通知区域、真实桌面和普通 Windows 包必须使用 Windows 环境验证。云端 Linux 不能替代这些验收。
- `pnpm build:builder` 锁定 Windows x64 Node 的字节与版本；Linux 运行不能把平台校验删除来获得通过。需要时在 Windows CI 中构建。
- 文档开发测试：`pnpm --filter @blocky/document-parser test`；Windows 解析 runtime 准备：先 `pnpm build:builder`，再 `node scripts/build-document-parser.mjs`。
- 现有 GitHub Actions 为 Windows runner，只对 `main` 推送或 PR 触发。本次推送开发分支不自动触发该工作流，尚未建立 PR。
- Full 必须保留 360 个 5 秒循环及 30 次 Rust Host 保存/重载；旧 0.7.1 的 Full 证据不能作为当前开发快照的通过证明。

本机 .env、安全存储、模型权重、安装包、node_modules、try、构建产物均不随源码上传。云端需要按锁定配置重新安装/构建；真实 API 凭据需通过云端安全配置提供，不能复制进代码或聊天。
