# 阶段 1 CLI 同步开发补充

2026-09-16 用户要求同步开发 CLI，并优先使用 CLI 操作验收。此指令将 CLI 的已实现能力入口提前到当前阶段；A–F 的领域开发顺序保持，随领域实现开放对应命令。完整阶段 9、官方 Skills、外部客户端与六个兼容适配器仍不提前宣称完成。

## 交付范围

- `tools/blocky-cli/` 提供 `blocky` 本地命令，复用正式编译、运行、目录、项目格式和后续补丁领域接口。
- 首批命令：版本、doctor、目录与模板查询、从资料问答模板创建项目、项目摘要/模块查询/校验/编译、明确 `--simulate` 的运行预检与 JSONL 运行。
- 保存/读取 `.blocky` 使用与桌面相同的 Rust `project_store`，独立 `blocky-project-io` 进程只消费有大小上限的一次性结构化请求，不启动 WebView。创建使用原子 no-clobber，现存目标拒绝覆盖；不提供任意 Shell 或权限批准伪造接口。
- 命令只暴露当前实现，未知命令/参数、live 模式、未实现兼容模板均稳定拒绝。stdout 只输出版本化 JSON 或 JSONL，错误不含本机路径、输入正文或秘密；退出码沿用 CLI 产品设计。
- D/E 已同步开放蓝图/候选/补丁、显式页面、注册任务及诊断导出命令。新增 API 不使用临时 Demo 标记。

## 验证方式

以 CLI 进程运行端到端夹具，核对当前编译 IR、入口、诊断、答案引用、事件顺序、取消和磁盘字节。用同一 Host 库验证损坏/越界/未知版本/写入失败；测试输入全部虚构无秘密。原生画布显示、指针行为、通知区域及窗口关闭保护仍由必要的原生检查完成，不能用 CLI 结果冒充视觉验收。

本次验收追加 S1-12：CLI 的命令发现、结构化输出、稳定退出码、无隐式运行/覆盖、与桌面领域结果一致及无界面依赖。原有 S1-01–S1-11 不重复新增，改为优先引用 CLI 操作证据；最终独立角色追加 CLI 使用者视角，安全部分由独立安全验收 Agent 执行。新增标准已获用户确认后用于正式验收。
