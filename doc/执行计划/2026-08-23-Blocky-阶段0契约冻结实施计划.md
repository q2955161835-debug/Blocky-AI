# Blocky 阶段 0 契约冻结 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不编写正式产品代码的前提下，冻结阶段 1 Demo 必须消费的版本化契约、正反夹具、状态/替换账本和人工验收门禁，使下一位开发者可以直接编写阶段 1 实施计划并建立正式 monorepo 最小纵切。

**Architecture:** 以 `Project Manifest + 每模块 Blockly Workspace JSON` 为唯一编辑事实，经 `ModuleIR → ProjectIR → InteractionManifest/ToolContract → RuntimeEvent` 形成可重建投影；Builder、AppSurface、RPA、窗口、底部面板、终端与日志只通过版本化协议协作。阶段 0 只交付文档和契约夹具，`try/windows-core-spike/` 仅作只读证据，不复制为正式包。

**Tech Stack:** Markdown、JSON 契约夹具、PowerShell 只读验证命令、Git；阶段 0 不新增 Node/Rust 产品包、依赖或运行服务。

**Spec:** [完整开发计划](2026-08-23-Blocky-竞品驱动完整开发计划.md)、[ADR-005](../技术设计/ADR-005-多模块应用界面与RPA边界.md)、[ADR-006](../技术设计/ADR-006-底部面板终端与日志系统边界.md)、[设置中心设计模板](../产品设计/Blocky-设置中心设计模板.md)、[底部面板/终端/日志设计](../产品设计/Blocky-底部面板终端与日志系统设计.md)、[核心跨模块验收](../验收/跨模块/验收-Blocky核心创作与项目积木化流程.md)

## Global Constraints

### 范围

- 本计划只实现阶段 0。禁止创建正式 `apps/`、`packages/`、`tools/`，禁止修改 `try/windows-core-spike/`，禁止安装依赖。
- 阶段 1 仍是第一个产品代码阶段。阶段 0 可创建 Markdown 契约和 JSON 正反夹具，但不创建编译器、运行时、Host、PTY、日志总线或 UI 实现。
- Demo 只作为阶段名称写入计划、版本说明和验收结论。界面、项目、事件、设置和契约中不得出现 Demo 徽标、横幅、水印、`demoMode` 或专用运行分支。
- 默认项目 `appSurfaces` 为空。只有显式、可审查且被接受的 `app-surface.add` 补丁才能创建应用界面。
- 阶段 0 不需要真实大模型 API。自动化验证仅使用文档与固定 JSON；以后验收确需 live Provider 时，执行者主动请用户在安全存储或本地 `.env` 配置。
- 首批六项是内置兼容模板，不是运行模式、产品版本或 Agent 类型上限；官方 Skills 仍固定为四个，不在本计划新增 Skill。
- 积木总数不设固定目标；契约不得写死 311 或其他宣传数量。

### 事实优先级

发生冲突时按以下顺序处理并在提交前消除冲突：

1. 用户当前明确指令；
2. 本计划引用的完整开发计划；
3. ADR-005、ADR-006 及其专项产品设计；
4. 设置中心模板、完整积木/兼容设计；
5. Windows Core 尖峰只读证据。

不能用“以后再定”掩盖冲突。确实无法从现有规格推导的事项写入决策账本，明确：问题、候选、影响、负责人（产品负责人或阶段执行者）、最迟决策门禁；不得编造已确认结论。

### Git 与执行方式

- 执行前运行 `git status --short --branch`。工作区必须无未处理脏改动；复用相关任务分支，或从 `main` 创建 `codex/docs-stage0-contract-freeze`。
- 不创建 worktree。每个任务完成验证后独立提交；禁止把多个失败任务堆进同一提交。
- 不推送远端，除非用户在阶段 0 验收后明确授权。
- 最终交付顺序：完成文档与夹具 → 独立审查 → 用户确认已草拟验收项 → 验证通过 → 合并 `main` → 删除任务分支。

### 全局数据不变量

- `ProjectManifest` 与每模块 Workspace JSON 是项目编辑事实；IR、清单、诊断、运行事件、日志和轨迹均可重建或独立存储，加载时不得信任磁盘派生字段。
- 稳定引用只使用 `projectId/moduleId/exportId/blockId/resourceId/surfaceId`，显示名变化不能破坏引用。
- 打开标签、标签顺序、底部面板高度、筛选、终端布局、浏览器视口属于 `WorkspaceSessionState`，不影响运行语义。
- `Diagnostic` 驱动“问题”；`RuntimeEvent` 驱动画布高亮、运行日志与运行轨迹；`LogEnvelope` 驱动具名输出；`AuditRecord` 记录高风险决定。UI 不解析字符串猜状态。
- 用户终端 `UserTerminalSession` 与 Agent 进程工具 `AgentProcessRequest` 物理隔离。Agent 不能附加 PTY、读取历史/环境/输出或向用户终端发送输入。
- 项目、Workspace、IR、Build Spec、补丁、日志、终端记录、诊断包和文档不保存真实密钥、Token、Cookie、Authorization 头、私有访问地址或不必要的绝对路径；只保存秘密引用。
- RPA v1alpha1 只允许 `mode: "attended"`。`unattended` 必须以稳定错误拒绝，企业 Worker 留到阶段 11 新版本。
- 运行状态必须同时提供颜色、图标与文字；激活绿色加粗、警告黄色、错误红色，且不改变积木尺寸。
