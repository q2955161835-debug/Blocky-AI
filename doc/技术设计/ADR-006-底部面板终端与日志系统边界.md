## 1. 背景

Blocky 已有 `Diagnostic`、`RuntimeEvent`、运行轨迹、Host 日志脱敏和问题定位方向，但缺少统一的底部面板、终端与日志系统边界。若直接把 stdout、浏览器 console、模型响应和运行事件拼成一个控制台，会同时破坏用户体验、结构化调试、权限隔离和敏感信息保护。若让构建助手通过 UI 终端执行命令，还会绕过 Build Spec、语义补丁和 Host capability。

## 2. 决策

### 2.1 底部面板是编辑器视图，不是项目语义

首批底部标签固定为“问题、运行日志、终端、输出”。展开状态、高度、标签和筛选属于本机用户会话，不写入 Project Manifest、Workspace、Module/Project IR 或项目导出。隐藏视图不停止运行或终端；停止和清除使用独立命令。

### 2.2 运行事实、诊断、日志和审计分层

- 编译与配置事实使用 `Diagnostic`。
- Agent/自动化运行事实使用 `RuntimeEvent`。
- 用户可读运行日志是 `RuntimeEvent` 的投影，完整详情进入运行轨迹。
- 组件和终端诊断使用 `LogEnvelope`，不得由 UI 解析字符串推断业务状态。
- 高风险授权与外部副作用使用 `AuditRecord`，不与可任意清空的普通输出混为一体。

所有协议共享稳定来源、`correlationId`、脱敏类别和版本策略，但保留独立 Schema 与保留策略。

### 2.3 用户终端与 Agent 进程工具物理隔离

用户主动创建的 `UserTerminalSession` 可以承载项目 Shell/任务。作品 Agent、构建助手、Skill、扩展和 RPA 不能附加 PTY、发送按键、读取终端历史或消费终端输出；它们只能通过 `AgentProcessRequest` 调用已注册、类型化、限时、限目录、可取消且经过权限计划的进程工具。

### 2.4 日志先脱敏后分发

生产者提交结构化事件；Normalizer 统一版本和来源，Redactor 在进入内存总线、UI、磁盘或导出前处理敏感字段。UI 遮罩只是第二道防线。日志写盘失败不得阻塞项目保存或运行；高吞吐通过有界队列、批处理、虚拟列表和分级丢弃处理。

### 2.5 存储与退出

项目文件不持久化日志。诊断和审计进入本机应用数据目录的有界独立存储，普通项目导出默认排除；诊断包必须由用户明确触发并再次脱敏。真正退出时结算 PTY、子进程、日志刷新器、文件句柄、预览服务与托管运行时；隐藏到通知区域只改变窗口可见性。

## 3. 被否决方案

### 3.1 单一文本控制台

否决。字符串无法可靠驱动画布高亮、权限决定、来源跳转和结构化回放，也难以实施字段级脱敏与迁移。

### 3.2 让 Agent 操作用户终端

否决。该方案会继承用户环境、历史和开放 Shell 权限，绕过工具 Schema、审批、沙箱和审计。

### 3.3 把完整日志写进项目

否决。日志会导致项目膨胀、泄密、版本噪声和不可预测的协作差异；项目只保存可重建运行所需的声明式事实。

### 3.4 为 Demo 创建临时控制台协议

否决。阶段 1 的固定运行和终端任务夹具必须通过正式 `RuntimeEvent`、`LogEnvelope` 和 Host 接口注入，后续只替换实现，不删除字段或 UI 标记。

## 4. 阶段 0 必须冻结的契约

1. 底部面板四类标签、会话状态、命令和隐藏/停止语义。
2. `LogEnvelope`、`TerminalSessionContract`、`AuditRecord` 的版本、字段、来源、关联和错误模型。
3. `Diagnostic`、`RuntimeEvent`、运行日志投影、运行轨迹和组件输出的单向数据流。
4. `UserTerminalSession` 与 `AgentProcessRequest` 的权限与进程隔离。
5. 具名 `TaskDefinition` 的参数、目录、环境、秘密引用、超时、取消和平台差异。
6. 日志脱敏、背压、截断、保留、清除、损坏恢复、导出和真正退出结算。

## 5. 验收门槛

- 同一运行的画布高亮、运行日志和运行轨迹读取同一事件并可互相定位。
- 终端可以运行用户明确启动的项目任务；Agent 不能读取或控制该终端，只能调用独立受控工具。
- 大输出不会冻结画布或阻塞进程；截断、丢弃和写盘失败产生明确诊断。
- 项目、前端、Host 和诊断包的敏感扫描均为零泄露；复制与导出不能绕过脱敏。
- 隐藏底部面板不停止任务；真正退出后无 PTY、子进程、日志句柄或不可见服务残留。
- 对应人工流程以[跨模块验收 U19](../验收/跨模块/验收-Blocky核心创作与项目积木化流程.md#u19-底部面板终端运行日志与诊断导出)为准。

## 6. 影响

正面影响：用户可从入门摘要逐步进入专业调试；所有组件共享结构化、可关联、可脱敏的日志能力；终端不会成为 Agent 权限后门。

成本：正式应用需要 PTY/ConPTY Host、结构化日志总线、独立诊断存储、终端渲染与转义过滤、容量治理和退出资源审计；macOS 需要独立 Shell/Profile 与进程组测试。
