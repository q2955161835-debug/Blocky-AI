# 阶段 6–7 调试与有人值守自动化

状态：开发接口，阶段功能及最终验收尚未完成。本文件记录实际消费者与限制，不替代已冻结的八组验收标准。

## 调试与轨迹

`Runtime` 支持断点、暂停、继续、单步、从所选安全入口运行。事件时间使用 `now`，耗时度量使用独立的 `monotonicNow`；确定性夹具同时注入两者，生产默认使用单调时钟。截止时间与权限保护仍使用实际时间，测试时钟不能延长授权或运行预算。

`blocky.trace/v1` 是最多 10000 帧的导入/导出协议；桌面保留最近 500 帧。只重建白名单元数据；预算、Token 用量按字段复制，丢弃嵌套未知内容。数值 Token 计数保留，字符串凭据继续脱敏。历史回放不调用模型、工具或 RPA。

`TraceFrame.details` 记录实际执行中的上下文来源字节数、证据条数、有效输出 Token 上限、记忆操作/范围、工具输入输出类型/大小及证据护栏决策。证据统计复用实际消息的 `{id,title,text}` 投影，不计未发送的引用定位字段；其余计数是各组成值的 UTF-8 大小，不是完整请求字节或 Token 估计。无证据短路不继承此前模型调用的响应元数据。桌面详情和 CLI inspect/replay 共享白名单投影，字段只允许数字与固定枚举，不保存值、记忆键或工具正文。当前模型仅展示实际消费者使用的输出 Token 上限，不虚构温度等参数。

## 诊断关联与导出

运行事件的 project/run/module/block/correlation ID 进入同一日志总线，再由字段白名单投影到 Host 诊断存储。普通标识上限 200 个 ASCII 字符，组合 correlationId 上限 512；超限、未知或不合规字段不截断，保留 `scopeOmitted: true` 提示，桌面输出明确显示省略。正文、任意 attributes 和终端内容不进入诊断工件。旧记录没有 scope 时仍可读。

桌面输出支持选择关联字段、输入精确 ID 和填入当前运行；CLI `diagnostics export` 支持 `--project-id/--run-id/--module-id/--block-id/--correlation-id`，多个条件按 AND 组合。Host 导出复用相同过滤语义。作用域缺失的旧记录不会匹配指定条件；时间范围与通道筛选仍有效。总量仍限制 100000 条和用户保留策略，单文档读取上限调整为 204801024 字节以容纳有界关联元数据；该上限规模性能尚未实测，不能外推为容量性能通过。

## 画布大纲与迷你地图

大纲直接读取当前 Blockly 渲染积木，支持按名称、ID、分组、区域和注释查找并定位。迷你地图使用真实积木尺寸和未缩放的工作区视口坐标，点击只移动视口。导航不得改写 Workspace/IR；开合与查找词属于组件会话。几何采样合并到每帧一次，平移/缩放只更新视口，不重新计算所有积木标签。最多采样 2000 个积木，大纲每次显示 200 项；超过时有明确提示，当前仍需完整大型项目性能验收。

## 无 Agent 根架构与连续输入

### 自定义代码的四态显示

`core.data.transform` 使用 Project Model 的同一 `codeState` 判断；检查器、画布内部文字徽标与左侧标记、只读候选预览均消费该结果。徽标使用非序列化 Blockly FieldLabel，左侧标记为 SVG 投影，不进入 Workspace/IR；运行高亮继续使用独立外轮廓。Blockly 序列化的 `SOURCE:null` 表示没有源码说明，不触发警告。无效 PROGRAM 保留诊断，不能开始正常运行；这与未保存的编辑草稿分开处理。

独立 `core.interaction.chat_entry` 的 HANDLER 同时接受通用命令和运行步骤。当前状态机、行为树、优先级规则和规则/模型混合路由均由已有条件、数据、记忆及模型积木组合，保存为普通 Workspace；没有第二套架构运行内核。行为树 Sequence 只在 success 继续，Selector 只在 failure 选择后备，running 向外传播。规则按嵌套顺序首条匹配。状态机终态不再转移，状态以项目 ID 和当前 Runtime 会话隔离，不宣称跨重启持久化。

欢迎页与 CLI `template list/show`、`project create` 共用起点工厂。CLI `--inputs-file` 复用单个 Runtime，输入 Schema 为 `blocky.run-inputs/v1`，范围 1–32 个字符串、每项 16000 UTF-8 字节、文件 128 KiB。各轮有不同 runId，整批共享超时；遇失败/取消停止后续输入，模型和工具仍逐请求批准。JSONL 输出各轮事件，最终结果含 runs 与完成数量。轨迹工件仅为最后尝试的一轮，明确返回 traceScope=last-run。持久工作流起点尚未实现。

`core.event.send/receive` 提供当前 Runtime 内存中的项目通道 FIFO。跨模块共享通道，跨项目隔离；整体最多 128 条/256 KiB，每条 JSON 负载最多 16000 UTF-8 字节，等待者最多 32 个。接收支持 0–30000 毫秒等待；空队列/超时进入 EMPTY，有消息则将负载放入结果并进入 RECEIVED。等待取消不消费后续消息；消息交付即从队列取出，后续业务失败不会自动重入队，避免重做副作用。它没有持久化、确认重投、后台自动触发或并行 Actor 调度语义。运行轨迹只含积木类型/结果类型等元数据，不含消息正文。

`event-mailbox` 起点复用上述普通积木：普通输入入队，输入 next 消费最早消息，空队列返回 empty；CLI 连续输入和桌面会话共用相同实现。退出当前 Runtime 后未处理消息丢失，不能将其称为持久事件流程。

| 协议 | 生产/消费位置 | 持久性 |

### 当前 Windows 执行范围

- `rpa targets` 只列可见的本机同用户、非提升权限顶层窗口。身份绑定窗口句柄、PID、进程创建时间、类名及审批前获取的 UIA 根 runtime ID；每步重新核对。
- UIA 精确定位支持 `automationId`、`name`、`controlType`；只遍历目标进程子树。多匹配、读取失败、深度超过 32 或节点超过 2048 均拒绝，不自动取第一个。
- 已实现 `find`、`read`、`click`（InvokePattern）、`fill`（ValuePattern）与 `wait`。只操作可用且非屏外控件；密码控件和通用 SecretStore 引用拒绝。当前不支持坐标回退、截图和真实浏览器 Host。
- 初始原生确认绑定完整计划与目标，授权最长 10 分钟；填写内容再经原生确认，不落项目、日志或回执。读取结果作为显式业务数据返回，执行事件只保存步骤/动作元数据。
- UIA 和原生确认均在自身可执行文件的独立 worker 中执行，环境清空、无可见控制台，先附加 Windows Job 再放行私有管道输入。超时/停止先终止并等待 worker/后代，再报告结算；结算失败保持 `settlement-failed`，不能写成已停止。
- 暂停在步骤间生效；停止、过期、重复步骤及越序调用均拒绝继续。点击/填写调用前登记 `uncertain` 回执，成功返回后记 `completed`；后者表示调用返回，不等于业务状态已核验。未知结果不得自动重放。
- 审批请求与生成的 grant 保留绑定，迟到的取消也撤销对应会话。退出先广播取消，再收集所有结算结果；单个失败不阻止其他会话收到停止信号。

### CLI 控制与恢复边界

`rpa run` 的首帧包含计划和可选的临时填写值，限制 64 KiB；后续控制只允许 `pause/resume/stop/status`。输出区分安全执行事件、显式读取结果、checkpoint 和终态。checkpoint 包含 `state` 及 `settled`；即使结算失败仍返回回执。

SIGINT/SIGTERM 请求 Host 停止并等待退出；超期未确认结算返回 `BLK-RPA-SETTLEMENT-001`。当前回执只用于阻止本会话重复执行和人工核对，不支持跨进程自动恢复，不能把重新运行计划称为检查点恢复。
