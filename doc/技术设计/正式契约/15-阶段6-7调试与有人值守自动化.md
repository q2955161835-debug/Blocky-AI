# 阶段 6–7 调试与有人值守自动化

状态：开发接口，阶段功能及最终验收尚未完成。本文件记录实际消费者与限制，不替代已冻结的八组验收标准。

## 调试与轨迹

`Runtime` 支持断点、暂停、继续、单步、从所选安全入口运行。事件时间使用 `now`，耗时度量使用独立的 `monotonicNow`；确定性夹具同时注入两者，生产默认使用单调时钟。截止时间与权限保护仍使用实际时间，测试时钟不能延长授权或运行预算。

`blocky.trace/v1` 是最多 10000 帧的导入/导出协议；桌面保留最近 500 帧。只重建白名单元数据；预算、Token 用量按字段复制，丢弃嵌套未知内容。数值 Token 计数保留，字符串凭据继续脱敏。历史回放不调用模型、工具或 RPA。

`TraceFrame.details` 记录实际执行中的上下文来源字节数、证据条数、有效输出 Token 上限、记忆操作/范围、工具输入输出类型/大小及证据护栏决策。证据统计复用实际消息的 `{id,title,text}` 投影，不计未发送的引用定位字段；其余计数是各组成值的 UTF-8 大小，不是完整请求字节或 Token 估计。无证据短路不继承此前模型调用的响应元数据。桌面详情和 CLI inspect/replay 共享白名单投影，字段只允许数字与固定枚举，不保存值、记忆键或工具正文。当前模型仅展示实际消费者使用的输出 Token 上限，不虚构温度等参数。

## 诊断关联与导出

运行事件的 project/run/module/block/correlation ID 进入同一日志总线，再由字段白名单投影到 Host 诊断存储。普通标识上限 200 个 ASCII 字符，组合 correlationId 上限 512；超限、未知或不合规字段不截断，保留 `scopeOmitted: true` 提示，桌面输出明确显示省略。正文、任意 attributes 和终端内容不进入诊断工件。旧记录没有 scope 时仍可读。

桌面输出支持选择关联字段、输入精确 ID 和填入当前运行；CLI `diagnostics export` 支持 `--project-id/--run-id/--module-id/--block-id/--correlation-id`，多个条件按 AND 组合。Host 导出复用相同过滤语义。作用域缺失的旧记录不会匹配指定条件；时间范围与通道筛选仍有效。总量仍限制 100000 条和用户保留策略，单文档读取上限调整为 204801024 字节以容纳有界关联元数据；该上限规模性能尚未实测，不能外推为容量性能通过。

## 画布大纲与迷你地图

大纲直接读取当前 Blockly 渲染积木，支持按名称、ID、分组、区域和注释查找并定位。迷你地图使用真实积木尺寸和未缩放的工作区视口坐标，点击只移动视口。导航不得改写 Workspace/IR；开合与查找词属于组件会话。几何采样合并到每帧一次，平移/缩放只更新视口，不重新计算所有积木标签。最多采样 2000 个积木，大纲每次显示 200 项；超过时有明确提示，当前仍需完整大型项目性能验收。

## 无 Agent 根架构与连续输入

### 自定义代码的四态显示

`core.data.transform` 使用 Project Model 的同一 `codeState` 判断；检查器、画布内部文字徽标与左侧标记、只读候选预览均消费该结果。徽标使用非序列化 Blockly FieldLabel，左侧标记为 SVG 投影，不进入 Workspace/IR；运行高亮继续使用独立外轮廓。Blockly 序列化的 `SOURCE:null` 表示没有源码说明，不触发警告。无效 PROGRAM 保留诊断，不能开始正常运行；这与未保存的编辑草稿分开处理。

独立 `core.interaction.chat_entry` 的 HANDLER 同时接受通用命令和运行步骤。当前状态机、行为树、优先级规则和规则/模型混合路由均由已有条件、数据、记忆及模型积木组合，保存为普通 Workspace；没有第二套架构运行内核。行为树 Sequence 只在 success 继续，Selector 只在 failure 选择后备，running 向外传播。规则按嵌套顺序首条匹配。状态机终态不再转移，状态以项目 ID 和当前 Runtime 会话隔离，不宣称跨重启持久化。

欢迎页与 CLI `template list/show`、`project create` 共用起点工厂。CLI `--inputs-file` 复用单个 Runtime，输入 Schema 为 `blocky.run-inputs/v1`，范围 1–32 个字符串、每项 16000 UTF-8 字节、文件 128 KiB。各轮有不同 runId，整批共享超时；遇失败/取消停止后续输入，模型和工具仍逐请求批准。JSONL 输出各轮事件，最终结果含 runs 与完成数量。轨迹工件仅为最后尝试的一轮，明确返回 traceScope=last-run。持久工作流起点尚未实现。

`core.event.send/receive` 提供当前 Runtime 内存中的项目通道 FIFO。跨模块共享通道，跨项目隔离；整体最多 128 条/256 KiB，每条 JSON 负载最多 16000 UTF-8 字节，等待者最多 32 个。接收支持 0–30000 毫秒等待；空队列/超时进入 EMPTY，有消息则将负载放入结果并进入 RECEIVED。等待取消不消费后续消息；消息交付即从队列取出，后续业务失败不会自动重入队，避免重做副作用。它没有持久化、确认重投、后台自动触发或并行 Actor 调度语义。运行轨迹只含积木类型/结果类型等元数据，不含消息正文。

`event-mailbox` 起点复用上述普通积木：普通输入入队，输入 next 消费最早消息，空队列返回 empty；CLI 连续输入和桌面会话共用相同实现。退出当前 Runtime 后未处理消息丢失，不能将其称为持久事件流程。

## 工作流并行基础

`core.flow.parallel` 是共享 Runtime 中的两分支结构，LEFT/RIGHT 必须连接；各分支克隆输入时的 result/memory，只允许结果赋值、条件、等待、显式失败与最多四层并行嵌套。外部模型/工具、记忆修改、事件收发和输出步骤必须放在汇合之后，不获得隐式并发授权。分支最多 2000 个节点，仍共享全运行步数/时限预算；`core.flow.delay` 为 0–30000 毫秒的可取消等待，`core.flow.fail` 报告 `BLK-FLOW-003`。

全部分支结算后按 LEFT/RIGHT 顺序返回结果数组，汇合值不超过 32768 UTF-8 字节；失败时按插槽顺序选择首个错误，不执行汇合后的步骤。取消先结算所有等待者，不在运行终态后追加迟到事件。单步许可只供一个等待积木消费，其他分支仍暂停；已经开始的纯步骤可完成，到下个积木边界再停。CLI 与桌面使用相同目录、编译校验和执行器。这里没有第二套工作流运行时；持久审批、补偿和检查点恢复的当前接入状态见下文“传统工作流”，纯并行证明不能代替完整交付。

### 当前 Windows 执行范围

- `rpa targets` 只列可见的本机同用户、非提升权限顶层窗口。身份绑定窗口句柄、PID、进程创建时间、类名及审批前获取的 UIA 根 runtime ID；每步重新核对。
- UIA 精确定位支持 `automationId`、`name`、`controlType`；只遍历目标进程子树。多匹配、读取失败、深度超过 32 或节点超过 2048 均拒绝，不自动取第一个。
- 已实现 `find`、`read`、`click`（InvokePattern）、`fill`（ValuePattern）与 `wait`。只操作可用且非屏外控件；密码控件仅允许声明 `value.sensitive:true` 的人工填写，读取仍拒绝。通用 SecretStore 引用拒绝。截图实现见下文，Windows 真机证据待补；Windows 物理坐标实现见下文，实际系统输入尚待验证。浏览器使用下述独立适配器与同一 Host 账本。
- 初始原生确认绑定完整计划与目标，授权最长 10 分钟；填写内容再经原生确认，不落项目、日志或回执。读取结果作为显式业务数据返回，执行事件只保存步骤/动作元数据。
- UIA 和原生确认均在自身可执行文件的独立 worker 中执行，环境清空、无可见控制台，先附加 Windows Job 再放行私有管道输入。超时/停止先终止并等待 worker/后代，再报告结算；结算失败保持 `settlement-failed`，不能写成已停止。
- 暂停在步骤间生效；停止、过期、重复步骤及越序调用均拒绝继续。点击/填写调用前登记 `uncertain` 回执，成功返回后记 `completed`；后者表示调用返回，不等于业务状态已核验。未知结果不得自动重放。
- 审批请求与生成的 grant 保留绑定，迟到的取消也撤销对应会话。退出先广播取消，再收集所有结算结果；单个失败不阻止其他会话收到停止信号。

### 加密执行记录

桌面与 CLI 的正式 RPA Host 使用同一 journal 存储，按当前 Windows 用户 DPAPI 加密。快照绑定完整计划摘要、目标进程身份和 UIA 根；授权 token、填写正文和读取结果不进入快照。窗口标题与定位器仅存在于加密快照，不出现在查询摘要中。项目文件不包含 journal。

执行前先原子保存 `uncertain`，调用返回后再保存 `completed` 和下一步游标；前置写入失败不调用目标，完成写入失败禁止后续步骤。暂停、继续、停止同步保存状态，停止已完成会话不覆盖完成记录。文件锁和修订号 CAS 防止覆盖并发更新；每文件密文最多 256 KiB、明文最多 128 KiB、最多 100 份记录，目录总量有界。达到上限拒绝新授权，不自动删除未知结果。

CLI `rpa checkpoints` / `rpa checkpoint <id> [--plan <file>]` 与桌面“保存的执行记录”查询相同安全摘要。提供原计划时验证摘要绑定，不进行目标状态核验。`resumable` 只表示当前记录可以申请恢复，`requiresRecoveryApproval:true` 表示仍需新授权；`verified:false` 不将操作返回或用户声明的控件条件扩大为完整业务核验。

### 显式清理已结算记录

Host 停止会话并确认 UIA worker/浏览器已结算后，才持久化 `settled:true`；最后一步调用返回本身不构成结算证明。恢复接管清除该标记；旧格式缺少标记时按 false 处理。新查询给出 `deletable` 与 `deleteBlockedCode`，仅是查询时状态。

桌面选中“删除记录”后确认具体记录；CLI `rpa checkpoint-delete <id> --revision <n> --json` 通过 `blocky.rpa-checkpoint-delete/v1` 调用相同 Store。Host 在 journal 文件锁内重新读取并核对修订号、已结算终态、无未知副作用、原 owner 明确退出且不可恢复，全部满足才删除这一份密文；不递归清理、不自动过期。活跃/未知 owner、旧记录、未结算与可恢复记录继续保留。已完成但原桌面进程仍在运行时需退出原进程再刷新。回复只含 ID/修订号/删除结果；回执不确定时提示刷新核对，不推断记录仍存在。

### 显式检查点恢复

`rpa recovery-preview <id>` 与桌面“准备恢复”按用户操作读取原计划，不包含输入正文。`rpa recover <plan> --recovery <file>` 和桌面恢复草稿使用 `blocky.rpa-recovery/v1`：绑定 checkpoint ID 与修订号，为每个完成回执提供唯一 UIA 定位和“控件存在”或“文本等于”条件。最多 100 项、文本 1024 UTF-8 字节、整个恢复请求 32 KiB；预期文本、探测结果和新的填写内容不进入 journal。

原执行 owner 由 PID 和进程创建时间绑定。只有明确退出或 PID 已被另一进程重用时可申请；访问拒绝、查询失败、旧格式缺 owner、流程已完成、未知副作用或结算失败均拒绝。实现依据 Windows 的 [OpenProcess](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-openprocess) 与 [WaitForSingleObject](https://learn.microsoft.com/en-us/windows/win32/api/synchapi/nf-synchapi-waitforsingleobject)，零等待读取进程退出信号，不用 PID 存在性单独推断身份。

Host 先校验完整计划摘要、目标身份与 UIA 根，再向用户展示剩余起点和全部核验条件进行原生审批；批准后执行只读 UIA 条件探测，总限时 30 秒，取消或不匹配即拒绝。随后在文件锁内重验记录修订/owner 并原子更新 owner，竞争接管只能成功一次。新会话保留原回执与 next 游标、生成全新 10 分钟 grant；跳过已经完成的步骤。任意一项失败都不会执行剩余副作用。当前不提供未知结果自动和解、旧授权恢复或跨目标替换。

### CLI 控制与恢复边界

`rpa run` 的首帧包含计划和可选的临时填写值，限制 64 KiB；后续控制只允许 `pause/resume/stop/status`。输出区分安全执行事件、显式读取结果、checkpoint 和终态。checkpoint 包含 `state` 及 `settled`；即使结算失败仍返回回执。

SIGINT/SIGTERM 请求 Host 停止并等待退出；超期未确认结算返回 `BLK-RPA-SETTLEMENT-001`。跨进程恢复必须使用上述显式流程，普通 `rpa run` 新建会话不等于检查点恢复；不提供自动恢复服务。

## 浏览器服务与共享授权

`packages/rpa-core/src/browser-host.ts` 是仅限 Host 私有进程的服务，复用 BrowserRpaAdapter，不从 WebView 包入口导出。每个项目会话使用新的非持久 BrowserContext，绑定不透明 Page ID 和打开时来源；最多四个会话。禁止 service worker、WebSocket、弹窗、下载和浏览器权限。HTTP 请求只允许初始来源；[route.fetch](https://playwright.dev/docs/api/class-route#route-fetch) 禁用重定向/重试，所有 3xx 拒绝并释放响应，避免 Chromium 不重复调用重定向路由造成越界。当前不支持跨来源登录跳转或跨来源资源。

内部授权绑定项目、Page、完整计划、动作与到期时间；逐步顺序调用，不允许重复副作用。填写和显式读取最多 16 KiB，密码及敏感字段仅允许声明用途的人工填写、读取拒绝，输入不保存；取消/超时关闭 context 并等待活动步骤。浏览器关闭后身份失效。产品入口使用已安装 Edge 和锁定 Playwright 驱动；开发下载的 CFT 资产只作测试，未获分发许可结论。

Rust BrowserProcess 使用固定路径和逐文件 SHA-256 清单校验 Node/驱动；不接受客户端选择可执行文件，清空环境后只给 SystemRoot 和本会话 TEMP/TMP。先附加 Windows Job，再发送私有 init，浏览器此时才启动。`blocky.browser-ipc/v1` 使用 64 KiB 单帧、递增请求号和白名单操作；无 Shell、任意执行脚本、连接现有 CDP、文件读取接口。调用取消/超时终止整个 Job；Job 结算后仍有界核对子进程和管道，使用 CancelSynchronousIo 释放阻塞读写。任一结算不确定时报告失败并保留临时 profile，不删除仍可能被持有的目录。

桌面选择“隔离浏览器”和起始网址；CLI `rpa run` 传入 `--browser-url/--project-id`，计划 identity 为起始 origin。Host 为新页面生成随机 ID，向用户显示来源、项目、网址与全部步骤；批准后才启动浏览器并将该 ID 绑定新建页面。浏览器与 UIA 共用 RpaHost 状态机、10 分钟授权、加密 journal、回执及暂停/停止；每个原生浏览器会话持有独立 worker/Job，停止不会终止其他浏览器会话。过期闲置会话在后续授权前回收；关闭桌面面板、CLI 结束或应用退出时结算。原有 Windows v1 快照格式保持可读，浏览器快照保存项目/origin/Page ID，但不保存网址、Cookie、填写或读取正文；临时 context 无法跨重启恢复，恢复入口明确拒绝。

开发、CLI、原生测试与发行构建均准备锁定驱动；发行扫描/打包脚本包含 browser 目录和上游许可证。Playwright 上游驱动按锁定 vendor 物料检查，不把其自带 webdriver 字符串当成本产品测试通道；自有 browser.mjs 仍执行完整测试标记扫描。本批尚未运行完整普通包扫描/打包门禁，不声称发行验收通过。

## 浏览器坐标回退

隔离浏览器支持显式 `locator:{kind:"coordinate",x,y,riskAccepted:true}` 的 click，其他坐标动作由 TS/Rust 协议同时拒绝。坐标单位是 CSS 像素，原点为可见页面左上角，和系统桌面位置无关；不移动系统鼠标。当前页面视口为 1100×760，Host 在授权时保存视口，步骤前要求尺寸一致、整数坐标在范围内、页面身份/来源和 grant 有效。缺少 coordinateFallback 授权、越界或视口变化拒绝；已有 effectKey/顺序/未知回执/停止机制继续适用，不自动重试。

完整计划审阅和每次坐标点击前的原生确认均显示高风险/误点警告及坐标单位。桌面默认保留语义定位，展开坐标回退后输入数值并显式勾选风险；改坐标或添加一步会清除勾选。CLI `rpa validate` 返回 coordinateSpace 和稳定风险代码，Schema 描述同步；转普通积木必须审阅新增 rpa.coordinate 权限。Windows 坐标使用下述独立物理输入边界，浏览器临时会话仍不能跨重启恢复。本批只有开发/无界面页面证据，普通包和原生确认实际操作未执行。

## 独立资料目录

原生启动参数 `--profile-dir` 优先于 `BLOCKY_PROFILE_DIR`。仅接受绝对本地磁盘目录，拒绝上级跳转、网络/设备路径、非法 Unicode、尾随空格/句点和目录链接；失败为 `BLK-PROFILE-001`，不尝试默认根。WebView 不能传入或更改该路径。所选根统一承载用户设置/恢复/资源、秘密、记忆、知识/转换、Builder、日志、RPA 检查点及 WebView2 数据。随包只读模型与驱动仍在安装目录。

桌面按规范路径生成单实例标识；显式指定默认根时保留默认标识和 WebView2 位置，避免同根多实例。CLI `profile show` 仅返回路径摘要 `profileId` 与 `custom` 标志。默认桌面仍通过 Known Folder 取目录；默认 CLI 保留已有 LOCALAPPDATA 兼容行为。不同 profile 不复制旧秘密或恢复记录，也不改变 DPAPI 的同用户安全边界。主窗口先恢复已保存的物理位置再显示。

普通包 GUI 验收必须使用 try 内显式 profile；新包结论只能绑定其新源码，不能补写到不支持此入口的旧候选来源。

自定义 profile 的窗口由原生 `WebviewWindowBuilder::data_directory` 设置缓存根后创建；不能只写配置字段并假定其生效。2026-09-26 普通候选复核实际发现后者仍使用 C 盘默认目录，新源码须重新读回 WebView2 根进程的 `--user-data-dir`、目录落盘及退出结算。

桌面发起的打开/保存/选目录及原生确认对话框显式绑定发起窗口，保持模态归属。窗口位置是否遵守屏幕约束仍以普通包实际观察为准；RPA 独立 worker 的授权对话框另行验证。

## 尚未实现的冻结范围

UIA 与浏览器捕获、独立进程和专用录制授权管理已有开发实现；桌面录制控件、CLI 长会话及既有幽灵审查连接已有开发实现，尚无普通包真实完整录制证据，因此不称最终验收完成。浏览器采集使用[CDP 隔离执行环境](https://chromedevtools.github.io/devtools-protocol/tot/Page/#method-createIsolatedWorld)，开始时快照最多 2048 个控件的定位信息；之后事件仅发送索引/动作，名称或标签依赖变化的控件省略，不读取字段值/按键/剪贴板。只接受自有页面主 frame，跳转停止；页面不能替换隔离环境中的清理函数。最多 100 动作、10 分钟、32 个待处理事件；长定位器提前触及 48 KiB 预算即封存，完整结果限制 60000 UTF-8 字节以适配 64 KiB 私有管道。停止先断开采集/监听再封存，清理不能证明完成则关闭该自有页面。新控件或变更定位器不会静默重新快照，结果必须显示省略并交用户审阅。

显式录制到幽灵积木的普通包验收、截图保留/脱敏、敏感输入普通包验收、完整非 Agent 架构起点，以及普通包检查点恢复和完整 Full 均待完成。记录达到 100 条后拒绝新建，可通过上述入口显式清理符合条件的已结算记录；全部记录受保护时仍拒绝新建。模块集成与清理入口只有开发验证，真实模块完整操作与普通包证据待补，不能作为完整 RPA 交付。

## RPA 普通模块与运行轨迹

`core.computer.attach` / `core.browser.navigate` 会话容器的 STEPS 槽连接专用操作积木。LOCATOR 为 JSON 对象；编译器和原生补丁守卫共同拒绝孤立步骤、目标与定位类型不符、未知操作及隐藏嵌套控制流。普通独立聊天入口仅允许位于模块根。容器开始时对完整计划进行原生授权，子步骤使用同一 Host 依次执行，遵守 Runtime 的断点、单步和预算；关闭会话须等待结算，无法确认时保留失败状态。

桌面 RPA 面板的“转为积木草案”和 CLI `rpa draft` 复用计划转换、语义补丁与幽灵预览。所有新块重新分配稳定 ID，填写步骤只保留运行时输入来源，接受后通过 ProjectController 一次撤销。当前是计划转换入口，尚未捕获真实用户操作。

普通填写来源支持本次输入、前一步结果或逐步手动输入；`INPUT_KIND=sensitive` 只允许 `SOURCE=manual`，其 `rpa.sensitive-input` 权限增量进入普通候选审阅。新字段可选，旧项目缺省普通用途。桌面手动输入框在取消、停止及卸载时清空；CLI 用 `moduleId/blockId` 索引临时值，最多 100 项、每项 16 KiB UTF-8，不允许 NUL。`--simulate` 不提供真实 RPA 端口；`--live` 才允许申请 Host 授权，每次填写仍遵守原生确认。通用秘密引用拒绝。

敏感人工输入声明为 `value:{kind:"manual-input",sensitive:true}`，绑定完整计划摘要、步骤、目标与有限会话。完整计划和逐步确认显示用途，所有输入正文均不传给确认窗口；只经既有私有输入管道发送给获批目标，桌面填写/恢复输入均遮盖。浏览器先检查敏感元数据再索取输入，实际填写前再次校验来源与控件；敏感读取始终拒绝。录制 v1 原始结果及派生计划保持原格式，转换待审草案时根据敏感动作元数据补充用途，不能据此取得执行授权。当前有开发/无界面浏览器证据，普通包和真实 UIA 敏感控件仍待验证。

模块事件沿用 block/tool/checkpoint 事件和来源映射。轨迹仅新增目标类型、动作、定位方式、执行阶段和 checkpoint ID，不保存定位正文、网址、填写或读取正文。CLI 私有管道限制输入/输出大小、步骤顺序及等待时间；停止超过 7 秒后尝试终止，后续最多等待 500ms，未取得结算证明始终报告 `BLK-RPA-SETTLEMENT-001`。

## 录制会话与捕获进程

录制使用独立的 start/status/stop 请求，不复用执行 grant。原生确认绑定项目和窗口或全新浏览器来源；一场最多 100 步、10 分钟，取消可早于确认请求到达。UIA 在独立 MTA worker 内处理，私有帧上限 64 KiB，序号严格递增；每批最多 32 条事件，定位需在目标根内唯一。停止、目标丢失或到期先拆除订阅，封存元数据结果；失联 30 秒或总存活 11 分钟回收 worker。共享 PipeProcess 负责期限、Job、管道线程和结算错误优先级。

桌面录制状态与独立 CLI `rpa record` 会话已连接同一 Host；CLI stdin 仅接受 `status`/`stop`，EOF 触发停止。停止回执必须明确 `settled:true`，已结算的普通失败携带原错误码，未结算不能返回该回执。桌面停止后显式“审阅录制积木”，CLI 用 `rpa recording-draft` 产生普通语义补丁，复用现有接受/拒绝；录制结果不带执行 grant。浏览器捕获实例身份保留于原结果，待审计划以原始网址来源重新申请后续执行。

原生 RPA 确认窗口独立于 WebView，左上角显示完整只读滚动描述，默认聚焦取消。输入内容不进入确认描述；仅明确的允许按钮返回批准，关闭或取消不产生 grant。窗口由原私有 worker 管理并随取消/退出回收。

检查点原子替换针对 Windows 5/32/33 的短暂占用使用约 250ms 有界重试，始终持有 journal 锁和同一份加密临时文件。持续失败保留原回执，不推进 revision、不执行尚未持久化的副作用；其他错误直接失败。

### 已授权截图与短期图片记录（开发批次）

截图复用 `rpa.capture` 权限、完整计划原生审阅和唯一语义定位；仅截图所选目标，不捕获全桌面。原生确认提示输入区域遮盖以及其他可见文字仍会入图。Windows 采用目标窗口 PrintWindow 离屏绘制并裁剪，位图清零后绘制，前后复查窗口/UIA 身份、位置及遮盖布局；失败即拒绝。Edit、ComboBox、密码、Document、Pane 区域保守遮盖，不读取其正文。浏览器遮盖表单、可编辑控件及 iframe/frame/object/embed；截图期间临时隐藏这些节点整个渲染子树，覆盖边框外溢出正文，并在 finally 恢复原内联透明度。截图前后逐项核对实际 DOM 节点身份与隐藏有效性；观察现有文档/开放 ShadowRoot 的输入成员资格、相关子树和隐藏属性变更，同数量替换或改变后还原也拒绝。页面检查限 20000 元素/128 个文档根，超限拒绝，保存目标区域。单边 2048 像素、PNG 4 MiB。Windows 原生截图未实测，不能据此签发原生效果通过。

Windows worker 临时文件已按本机用户 DPAPI 加密，私有管道只返回遮盖数量；暂存目录绑定 Host PID/创建时间/UUID，创建与清扫受同一图片 Store 跨进程锁保护。查询和保存清除已确认退出 owner 的遗留，只删除固定 capture.bin 和空目录，不递归删除未知内容；活跃 owner 保留，未知状态拒绝。最多 16 个并行暂存，按单张最大体积预留，计入 32 张/128 MiB 总额。浏览器 PNG 仅在私有进程内存停留，通过严格会话/步骤/图片 ID 与顺序游标分块读回，消费/关闭清除缓冲。每块最多 32768 字节，控制帧仍为 64 KiB；取消和失败沿用原 Job/浏览器结算路径。Host 重新解码并编码 PNG，去除元数据，保存到当前资料目录的 `rpa/captures`。图片元数据为 `blocky.rpa-capture/v1`，包含 ID、检查点/计划/步骤、时间、大小、哈希、遮盖数量。普通积木返回此引用，项目/轨迹/回执不保存图片正文。

图片记录有效期为 24 小时；查询/保存时清理过期记录，读取已过期记录拒绝并移除。最多 32 张/128 MiB，达到上限报错；目录重解析、无效标识、损坏文件拒绝而非静默跳过。用户可显式删除受限 ID 对应文件。桌面刷新后显式查看、收起、删除，导出通过原生文件选择器；CLI `rpa captures`、`rpa capture-export <id> --output <new.png>`、`rpa capture-delete <id>` 使用同一 Store，导出不覆盖既有文件。导出的 PNG 是用户主动保留的文件，不受内部 24 小时有效期限制。普通包与独立局部复核另行记录，Full 仍按用户安排暂缓。


## Windows 物理坐标回退

只支持显式 riskAccepted 的 click。Windows 坐标为屏幕物理像素，可为负值；浏览器仍为非负页面 CSS 像素。完整计划和每次点击原生确认显示误点、聚焦目标与移动系统鼠标风险。取消不激活目标；允许后只激活已绑定窗口。目标列表通过同一 Host 返回 coordinateFrame / coordinateError，列出窗口、客户区、虚拟屏幕和 DPI；此发现信息不授予权限，授权时重新采集。

Host 的 Prepared/Session 在内存中保存几何绑定，禁止无绑定的 Windows 坐标计划取得 grant。私有 worker 使用线程级 PMv2 物理坐标，检查目标进程/创建时间、UIA 根、客户区/虚拟屏幕、窗口几何/DPI、前台/命中根、遮挡、光标裁剪、菜单/捕获及按键状态。坐标控件仍须通过 UIA 可用/非屏外/非密码校验。移动前后均验证；光标位置必须精确一致，最后同步复查后一次 SendInput 派发按下/释放。不完整插入只尝试释放本次插入的按下，不重试点击，返回 COORDINATE-003 并沿用不确定回执。检查与输入之间仍存在竞争窗口，因此保留高风险声明，不能保证等同语义定位。

几何不写项目或持久回执；恢复仍要求原有 UIA 核验、新原生批准和新几何绑定。桌面改变坐标、目标/来源、成功添加后清除风险勾选；CLI validate 返回 screen-physical-pixels 和系统指针风险，普通语义补丁使用相同 rpa.coordinate 权限。已做无系统输入的调度/拒绝路径开发测试；真正鼠标点击、原生批准、DPI/多屏及普通包仍待取证，不能按纯测试通过签发这些效果。


## 传统工作流（CLI与桌面已接入，人工核对及普通包待完成）

`runtime-core/workflow` 目前提供独立的严格快照协议、纯状态转换与逐步调度端口。`blocky.workflow/v1` 绑定任务/项目/模块/根积木、完整语义摘要和运行时协议版本；1–64个 action/approval/checkpoint 步骤，修订1–65535，单状态128 KiB、整记录1 MiB、深度32。正向进度 forwardCursor 与当前执行/回滚 cursor 分离，解析时要求完成前缀和反向处理后缀一致，拒绝凭空出现的审批或补偿历史。快照不包含权限 grant；前后上下文属于私有持久数据，summary只包含状态/定位/修订/回执状态和人工结算元数据。驱动异常正文一律不保存；不确定码仅允许 WORKFLOW-EFFECT / WORKFLOW-CANCELLED 两个公开常量，格式像错误码的正文也不能透传。

Store.commit 仅接收带期望修订的类型化转换，禁止提交任意替换快照；Host须在文件锁内重验、应用与持久化后返回。调度逐项核对读回，意图未保存或读回不一致则不派发。action 与 compensation 使用不同稳定 effectKey，意图在前、完成记录在后；派发失败或完成写入失败后保持执行中/不确定，下一次不重放。驱动端口必须在返回前结算自有子任务，不能在异步副作用仍存活时返回停止成功。

业务审批在持久状态边界结束当前推进，显式 approve 才继续；reject 或显式 rollback 按已完成动作逆序执行声明的补偿，未声明补偿的动作标为 skipped，不宣称外部效果已撤销。补偿逐步写意图/完成，未知补偿也禁止重试。取消在未派发时暂停，意图后取消保守留为不确定；已成功返回的动作先保存完成再观察取消。人工 resolve 仅记录“已完成”及经核对状态，或“未执行”；后者才允许同一effectKey再次派发，不能由引擎自行猜测。

**接入门槛仍未完成：** 原生 Host 的 DPAPI 账本与 Runtime 已通过CLI私有长会话连接，业务审批、显式恢复及拒绝后补偿已有真实新进程的模拟/本地业务证明。桌面通道及任务界面已有开发实现；原owner/业务子任务结算、未知效果人工核对仍须完成。四类普通积木及官方审批工作流起点已接入；真实普通包流程尚未验证，模拟/本地步骤不能代替真实外部副作用恢复证明。

### 运行步骤、上下文与恢复

目录新增`runtime.task.durable`、`runtime.compensate`、`core.human.approve`及`runtime.checkpoint.save`。持久根必须是输入入口的完整handler，不能有前置副作用、根外后续操作或嵌套工作流。STEPS只接受`workflow-step`连接；执行步骤的DO为原有普通子栈，UNDO为可选补偿。核心编译器在执行前拒绝错放标记、空步骤/超64步和嵌套边界；补偿开始时结果为`{before,after,current}`三个步骤值，其余上下文延续当前工作流，不回退已消耗预算，也不自动撤销未声明的外部效果。Blockly、TS目录与原生补丁目录读取同一新增定义。

`WorkflowExecution`把声明交给原有`advanceWorkflow`，DO/UNDO回调仍调用同一Runtime.execute，复用普通顺序/纯并行、模型、工具、跨模块和完整RPA会话。`WorkflowPorts.open`返回持久Store及长寿命会话关闭句柄；CLI提供原生私有stdio适配器；桌面主Host直接持有同一账本租约，通过主窗口受控命令连接。协调进程只拥有账本租约，不能用它的退出推断业务执行者及子任务已结算。缺端口明确返回`BLK-WORKFLOW-PORT`。

`blocky.workflow-context/v1`保存原始输入、Agent结果/记忆/指令/证据策略、生成文本/结构化输出/文件、当前项目会话记忆和FIFO事件，以及回答/引用/角色/样式、预算计数和剩余运行时限。总上下文仍受单状态128 KiB约束；超过上限明确失败，不截断数据。会话记忆恢复到当前执行会话，不覆盖其他项目；目标有不同的现存记忆/消息或活动等待者时拒绝覆盖。预算恢复只收紧上限并保留已用步数、调用和预留Token，人工等待时间不作为活动执行时间。服务、原生句柄、grant、运行事件和历史generations不在快照中，本次`modelApiCalled`及usage只来自本次运行实际响应。带知识集合的引用在恢复前经原有验证端口重新核验，等待遵循运行取消/时限，取消后不恢复状态。已完成或已补偿任务只投影保存的回答/引用与输出，不还原会话记忆、事件、问题、执行值或预算，也不再次推进状态机。

定义摘要绑定完整项目及解析后的资源配置。带taskId的恢复只能进入工作流handler，错误入口在任何block.started前失败；不从头执行普通入口来寻找检查点。完成回执严格读回后才报告checkpoint.created，绑定/修订不一致不报告成功也不派发动作。审批/暂停返回`waiting`和无正文工作流摘要，发run.paused而非run.completed或run.failed；当前调用随即结算，不占住等待循环。下一次显式恢复重新校验项目/资源和权限。未知效果保留执行中/不确定，返回失败且不重放；已结算任务的独立原生/CLI人工核对见末节；缺停止凭证仍拒绝。

### 原生工作流账本

`apps/studio-host/src/workflow` 与 TypeScript 采用相同严格协议、转换、摘要，4组固定双端夹具覆盖37次正向/审批/回滚/人工结算转换。原生文件封套额外绑定资料目录身份、任务ID、PID/创建时间和随机执行租约，不接收请求提供的owner或settled字段。资料根由原生启动选择；CLI提供摘要查询、私有运行会话和显式审批，不接受替换快照。

账本内容经当前Windows用户DPAPI加密；每个状态128 KiB、完整记录1 MiB、128条/128 MiB总量限制。总锁保护容量和原子变更，每任务的执行锁贯穿租约；保存先校验旧记录/修订与定义，再同步同目录临时文件和原子替换。替换被占用时只有限重试同一文件操作，不重派副作用。拒绝损坏记录、重复JSON键、异常锁文件、重解析根及跨资料目录复制；达到上限明确失败，不静默逐出旧检查点。临时密文文件名绑定原生PID/创建时间、UUID与随机后缀；拿总锁后有界扫描并整体校验，只删除已确认退出owner的普通暂存文件（包括零字节/部分写入）。活owner、查询失败、未知命名或重解析条目保留并拒绝继续；无身份的旧实验文件不靠时间猜测删除。暂存内容从不推广为成功回执。

租约由贯穿运行的原生账本协调进程持有，不能通过每次写盘启动/退出的辅助进程制造退出证明。Drop只释放系统锁，保留磁盘owner；旧进程仍存活或查询失败即拒绝接管。无active的持久边界可由显式release释放，或在原owner确已退出后重新取得；若已绑定受控执行进程，还必须有匹配的原生停止凭证。active/uncertain即使owner退出也拒绝恢复，不能由PID死亡推断子进程和外部副作用已结算。纯转换的resolve已具备协议，Lease.commit始终拒绝该操作；已结算任务只能经末节独立人工核对入口改变状态。业务审批须经独立命令明确确认，账本本身不授予工具/模型/RPA权限。


### 工作流任务发现

`workflow list --project-id <id>`与`workflow show <task-id> --project-id <id>`通过现有私有原生组件读取当前资料目录的workflow账本。查询显式限定项目；Host启动决定资料路径，请求不得提供任意路径、owner或状态替换。列表在同一总锁内检查有界目录、容量、密文完整性及项目绑定，按taskId排序，不返回损坏集合的部分结果；单项缺失与项目不匹配分别返回NOT-FOUND/BINDING。复用现有summary投影，state、步骤前后帧、审批label与owner不进入查询输出。

CLI发布`blocky.workflow-summary/v1` Schema并严格拒绝未知字段、注入私有帧或返回其他项目/任务。`command list`和`diagnostics explain`可发现命令及恢复提示。查询只读已保存的任务语义，不代表任务已结算，也不授予审批、恢复或副作用执行权限。账本既有崩溃暂存回收仍在查询锁内执行，只回收确认退出的原生writer暂存，不修改任务记录。

### 原生运行会话与显式业务审批

CLI Runtime按需启动私有`blocky.workflow-session/v1`协调通道。原生进程持有执行租约；帧上限1052672字节、严格顺序编号、最多1024个请求、总接收时限180秒。运行通道只允许read、begin/complete/checkpoint/await-approval/finish/pause/skip/uncertain和close，不允许注入decide/resume/rollback/resolve。关闭仅在没有active时显式释放，其他情况保留owner与意图；断管、超时和进程异常也不伪造完成。

取消后拒绝新read、begin或向前推进，允许complete/uncertain/pause及close写回已开始动作的结果。非收尾请求在取消时立即拒绝调用方，但保留对应序号以核验迟到响应；1秒内未收到有效响应则终止账本协调进程并保留持久owner/意图。收尾请求保留原10秒响应上限，close等待在途响应完成后发送，随后有界等待协调进程退出。这个关闭契约不证明外部模型/工具/RPA子任务结算。

`workflow decide <task-id> --project-id <id> --revision <n> --step <id> --decision <approve|reject>`先返回预检，不修改状态；加`--approve <requestDigest>`后重新核验并应用。摘要绑定资料目录身份、完整定义、任务、修订、步骤和决定；过期摘要、项目或修订不符拒绝。`blocky.workflow-decision-result/v1`仅返回公开摘要。审批本身不执行步骤，不替代安全授权。

`run start --workflow-task <task-id>`是显式继续入口，沿用完整项目/资源绑定。保存为paused的任务在该请求中恢复；等待审批的任务仍须独立业务决定。waiting返回退出码4和`run.paused`的`workflow-waiting`原因，不消耗调试暂停的stop动作。新进程恢复读取原上下文，不用新的输入覆盖原输入；本次模拟运行明确没有真实外部大模型调用。

### 桌面工作流任务与原生会话

桌面`WorkflowHost`由原生启动选择profile/workflow，长寿命Host持有同一执行租约；Lease拥有Store路径/身份副本，仍保持原文件锁、真实PID/创建时间、CAS和Drop保留owner规则。桌面与CLI共用open_task初始化及运行动作白名单，避免两套状态转换。最多一个会话，随机session token绑定项目，180秒新工作时限与1024次读写；取消或到期拒绝新推进，完成/不确定/暂停及关闭仍可收尾。query/decision复用原生已实现接口，不接收任意路径或自报结算。

打开、查询、审批和新推进限可见主窗口；cancel/close及complete/uncertain/pause允许主窗口在隐藏或退出期间完成清理，其他WebView无入口。正常退出调用工作流shutdown；无active可释放，有active只保留owner/意图，不声称外部任务结算。Runtime仍使用原有模型、工具和RPA权限链，尚不开放resolve。

运行面板提供当前项目任务列表、状态/修订、定位积木、批准/拒绝和显式继续。审批预检不改状态；用户确认前后检查当前完整项目与解析资源摘要，提交绑定digest后不自动运行。确认期间切换项目或卸载面板不提交旧决定，迟到查询不覆盖新项目。继续按保存的moduleId和工作流根查找原输入入口，使用与Runtime相同的resolveRunEntry定位独立chat_entry.HANDLER或Agent内chat.next，再由Runtime完整绑定校验；原入口不存在明确拒绝，不从其他入口寻找检查点。批准/拒绝发出后若回执丢失或校验失败，显示结果未确认并要求刷新核对，不声称未应用、不自动重发。未知效果只有需人工核对提示，无重放按钮。真实普通包交互仍待取证。


### 官方审批工作流起点

`durable-workflow`通过现有`architectureStarters`提供给桌面欢迎页及CLI的`template list/show`、`project create --template durable-workflow`。普通automation模块的独立输入入口，包含持久根、准备步骤、人工审批、交付步骤和检查点，无额外模型资源、应用界面或权限。准备将最初输入存入本任务上下文的会话记忆；批准后显式继续才输出该输入。拒绝后显式继续按已声明UNDO删除准备记忆并输出`compensated`，不执行交付步骤。积木可直接编辑，不使用模板专属解释器。

同一项目重开后以任务ID继续，仍由既有完整项目/资源摘要、修订和原生租约校验；审批决定不自动执行任务。该起点说明本地步骤的持久流程，不声称撤销任意外部效果，也不开放未知效果自动重放或人工resolve。普通包GUI仍需独立取证。


### 桌面IPC等待和迟到回执

桌面工作流的打开、查询、审批、运行读写、取消和关闭请求每次最多等待10秒。超时返回`BLK-WORKFLOW-CHANNEL`，不能据此判定原生操作未发生。未返回的打开和新推进等待可由运行取消立即结束；已发送请求仍占据串行槽直到回执或本次截止时间，取消不会并发提交第二笔状态写入。已经派发动作的complete/uncertain/pause仍有界等待回执。通道失败或读回绑定错误后关闭该通道的写入能力，迟到成功回复不能恢复执行。

关闭先有界等待本笔及取消回执，再尝试关闭已知租约；最坏顺序等待不超过三笔10秒请求，任何通道/取消/关闭错误均向上报告，不声称成功结算。取消或超时之后迟到的打开结果只按对应会话token与项目请求取消/关闭，绝不交给Runtime执行；清理本身也有界。若打开回执彻底丢失、无法取得会话token，UI能结束等待，但Host可能仍持有租约，须由原生退出清理；原生生命周期和业务任务树结算仍是独立待完成门禁。

错误只投影固定已知工作流错误码，格式像错误码的正文不透传。业务审批请求发出后失联仍显示结果未确认、要求刷新核对，不自动重发决定。普通包及真实IPC失联场景仍待独立取证，不能以组件计时器测试称原生退出完成。

### 原生执行归属基础

`process_worker`只接受Host内部启动器提供的可执行文件和参数，未开放桌面或CLI请求字段。使用CreateProcessW创建隐藏、挂起的进程，显式句柄继承列表只包含两端私有管道；在恢复主线程前加入唯一命名Job，设置KILL_ON_JOB_CLOSE且不允许breakaway。同名Job已存在时只关闭新取得的句柄并拒绝，不修改或终止原Job。创建后的附加/身份查询失败须终止并等待新进程，否则报告不确定。参数采用Windows argv转义，不经过Shell。

`workflow::Execution`封装该容器。资料目录、任务、随机租约、原生owner、worker的PID/创建时间与Job标识写入私有加密Envelope，只有持久化成功才允许resume；一个Execution不能绑定多个租约，已有active时不能补绑。`Stopped`不是可反序列化数据，只由真实Job结算且worker句柄已发信号产生，绑定字段须完整匹配才能写入本地settled证据。没有该证据不能释放已绑定租约，也不能因原owner退出而接管。停止后禁止该租约的新begin；Drop尝试杀掉进程树，但不擅自写成功凭证。

本地settled不改变业务record的active/unknown、不授权resolve、不证明远程服务的效果已结束。无execution字段的旧账本仍按旧规则读取，不补造新凭证；绑定元数据不进入公开摘要。CLI公开run start现已接入下述受控worker；桌面Runtime已接下述原生监督与私有状态发布；普通包验证及未知效果人工核对仍未完成。命名Job的跨原生进程恢复尚未实现，不能把本批测试写为完整产品恢复。

### Runtime 私有会话转交基础（2026-09-26）

实现 `d36ec1bddc13b424b5647126cec0823510d74cb2`、边界修复 `616a1b71dd54fde85471eabbcb5a821756a6d1ad` 提供 `blocky.runtime-state/v1`：固定 sessionId、最后事件序号、按 projectId/key 分区的会话记忆及完整项目/channel FIFO 队列。`captureSession()` 仅在 Runtime 空闲时允许，未完成的 receiver 同样拒绝；构造新 Runtime 时全量验证并复制，不覆盖已有实例。显式 sessionId 必须相同，自定义 nextSequence 不可与转交混用。EventFactory 只提高进程内序号下界，保持后续轨迹递增，不回放旧事件。

数据格式严格拒绝额外字段、访问器、循环、非 JSON 对象、重复记忆键和非法 ID。记忆按现有编码键计入 1 MiB，总队列 128 项/262144 载荷字节，单条记忆 32768、消息 16000 字节；整个封装有 2 MiB 上限，会话数据不新增固定 32 层深度限制，以字节及有限节点容量约束，保证普通运行器已成功保存的深载荷能转交。严格 JSON 验证使用迭代遍历并只序列化原始标量，拒绝 Array 子类与属性访问器，不调用对象的继承 toJSON；内部可选遍历额度支持大量有效小值，既有工作流默认 50000 节点/32 层不变。

该状态可能包含用户敏感记忆/消息，只供可信 Host 与固定 worker 内部瞬时转交，不加入项目、日志、公开结果、工具授权或工作流执行证明。不采集密钥配置、资源对象、grant、回调或历史 API 用量，恢复不赋予任何权限。当前已验证独立 Node 进程间数据语义，桌面 Native 通道与会话状态发布时的真实 worker/业务结算仍待接入；不能用本接口代替持久工作流检查点或未知效果人工核对。
