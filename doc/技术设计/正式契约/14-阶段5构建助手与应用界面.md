# 阶段 5 构建助手与应用界面

状态：实施中；验收依据为[阶段 5 任务验收](../../验收/任务/验收-2026-09-20-Blocky阶段5.md)，当前已确认 16 项，尚未独立验收通过。

## 共享构建边界

用户请求 `blocky.builder-request/v1` 绑定 requestId、projectId、目标 moduleId、选择的稳定积木 ID、build/explain/repair 意图及明确的 createSurface 动作。模型输出不能修改请求或把页面建议提升为授权。

`packages/builder-protocol/` 的 createBuilderSession 持有隔离的项目/资源快照，只提供 inspect、draft、patch、verify 四个语义工具；没有文件写入、网络、Shell、用户终端或项目控制器端口。

- inspect：返回目标模块积木、目录、选择、编译诊断与资源名称/类型，不返回秘密绑定、资源定义或本机路径。
- draft：形成 `blocky.build/v1`，包含目标、基线、计划和验收条件；解释只返回解释，不产出补丁。
- patch：复用原 SemanticPatch，校验目录、目标、权限差异和编译；repair 限定选择或诊断中的字段更新，拒绝越界改动。
- verify：只编译候选，不运行作品，不调用 Provider/工具副作用。未验证候选不能成为最终修改建议。模型一轮完成 patch 后若未显式调用 verify，引擎在该轮结束时通过相同工具端口执行真实编译验证，不为确定性验证额外外发；事件照常记录。

候选应用仍走现有 previewPatch → 用户接受/单独权限批准 → Host validatePatch → ProjectController 单事务编辑；拒绝与取消不修改原项目。异步结果必须检查取消，候选绑定生成时摘要；手动编辑后需重新生成。

输入有严格字段、长度、深度、节点与敏感模式限制；构建会话最多 64 次领域调用。`language-schema/src/credential-patterns.json` 由 TS 和 Rust 同时读取，在请求及侧车启动前拒绝常见凭据形状。规则不是通用秘密发现器；应用仍只能从 Host 安全存储读取配置密钥。

## 引擎与生命周期

固定引擎为 `@earendil-works/pi-agent-core` / `pi-ai` 0.86.0，来源 [earendil-works/pi v0.86.0](https://github.com/earendil-works/pi/releases/tag/v0.86.0)，commit `ecac0a9c4edad3dac5d9f8b40e0c7db7a56471fc`，MIT。仅使用 Agent 与自有 streamFn；不加载 AgentHarness、coding-agent、自动扩展发现或用户配置。打包仅保留公开 Agent 导出，并审计最终保留的模块与外部导入。

`blocky.builder-ipc/v1` 为单次请求的 JSONL 协议，包含 start、event、provider.call/result、complete/error。请求 ID、轮次、消息尺寸、消息总量和工具名必须匹配。固定 Node 22.23.1 与 bundle 的哈希由编译进 Host 的 runtime-lock 校验；环境清空，仅保留必要 SystemRoot；Node permission 禁止文件写入、子进程和原生扩展，Windows Job Object 在送入请求前绑定。该限制不宣称是任意恶意程序沙箱。

真实生成走 Rust 的 DeepSeek 工具调用协议，密钥不交给侧车或 WebView。一次会话最多四轮、每轮 1024 输出 Token、120 秒总时限；无自动重试。取消、退出、崩溃及结果返回均先结算侧车进程树。DeepSeek 工具响应支持官方可选 index 序号（有界整数），其他未知字段仍拒绝；依据 [DeepSeek 官方工具调用说明](https://api-docs.deepseek.com/guides/thinking_mode/)。CLI 真实请求需预检摘要和一次性批准；桌面通过原生确认绑定本次项目、模型与预算。

本地模拟仅用于角色字段调整与所选积木说明，不支持自然语言页面生成或修复；界面明确标识未调用外部模型。真实 API 的结果必须含供应商返回 ID、模型和 Token 用量。

`blocky.builder-event/v1` 记录请求 ID、递增序号、模型轮次和四工具开始/完成，不含提示词、模型正文或密钥；完成后进入 builder 输出通道。Build Spec 包含基线、目标/选择、资源引用、权限差异、目录版本来源和验收条件。

## 应用界面生成与构建

新页面用 `blocky.app-surface/v1`，页面任务规格为 `blocky.surface-spec/v1`，包含文本、长文本、枚举字段、必填、两种布局、操作/结果标签、附件及请求确认。`patch.surface` 仅在用户请求 createSurface=true 时可用，规格由受信编译器生成 HTML、CSS、JS、无外部依赖的 package/lock 与最小 Bridge。模型不能提供任意 npm 脚本、JS 或依赖。

TS 与 Rust 对同一规格重新生成并比较完整文件集合；路径、桥接目标、导出与 Schema 必须一致。任务字段经文本节点构建，规格嵌入 HTML 时转义；脚本 CSP 哈希固定，页面没有网络连接或任意 Host 入口。`buildSurface` 只从已接受项目验证并生成内联单页产物，CLI `surface build` 和桌面预览共用此函数，不运行 package scripts。

接受新页面时最低读取版本变为 0.5.0；旧 v1alpha1 固定来源继续读取，不覆盖原件。页面源码作为项目内容保存，构建 HTML、标签顺序和视口是派生或本地会话状态。关闭/停止预览不删除源码。

`blocky.bridge-request/v1` 仅携带本次页面声明的表单值与可选文本附件。附件不包含原生路径，仅支持 txt/md/csv，单文件至多 16 KB；合成入口输入还受运行时 16 KB 总预算约束。父窗口再次校验字段、目标、权限和请求去重，再调用已有 Agent 入口。人工确认由父工作台控制并绑定 AbortSignal，页面不能自行批准。运行事件实时投影为进度，最终答案保持运行时证据/护栏处理结果，不把拆分已完成答案冒充模型 Token 流。

每个 iframe 使用独立 MessagePort 和 opaque origin sandbox，不启用 same-origin；停止、刷新或关闭会中止所属请求并释放端口。支持桌面/平板/手机视口、返回关联画布、重开标签与状态显示。

## CLI 与工作标识

`builder inspect/draft/explain/repair/patch/verify` 复用上述领域与 Host；`patch apply` 仍是唯一接受写入入口。`builder work <id>` 提供四个稳定标识，输入输出版本固定：

| 标识 | 本阶段能力与边界 |
|---|---|
| build-blocky-agents | 同一构建请求与 Provider/侧车协议；生成候选，不自动应用 |
| create-blocky-blocks | 严格语义操作编译成可接受候选，未知积木/字段拒绝 |
| convert-github-project-to-blocky | 复用 ConversionScanner 和 realConversionCandidate，锁定源码、许可证、符号与证据 |
| reverse-agent-to-blocky | 锁定来源扫描、可表达符号和保留项报告；可选受支持符号候选，始终不宣称完整框架兼容 |

工作标识不是已发布 Skill 包。未知标识/格式为 BLK-WORK-001，缺失能力端口为 BLK-WORK-002，来源和转换失败保留已有 BLK-CONVERT 系列稳定错误。
