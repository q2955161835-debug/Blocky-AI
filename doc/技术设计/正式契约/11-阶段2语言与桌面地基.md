## 1. 项目与语言 v1

正式项目事实为 `Project Manifest + 每个模块 Workspace JSON`。当前项目格式为 `blocky.project/v1`，包含稳定 `projectId`、模块描述、模块用途、`workspaceRef`、类型化导出、项目/用户资源引用、页面引用和可选项目设置。项目解析会限制递归深度、节点预算、引用路径、重复 ID、Workspace 与模块对应关系以及秘密值混入。

编译链输出以下当前版本：

| 产物 | Schema | 约束 |
|---|---|---|
| 单模块 IR | `blocky.module-ir/v1` | 保留节点稳定 ID、模块导出和 source map |
| 跨模块 IR | `blocky.project-ir/v1` | 由当前模块摘要和类型化 `ProjectLink` 重新链接 |
| 诊断 | `blocky.diagnostic/v1alpha1` | 继续使用稳定错误码和来源定位 |
| 交互/工具投影 | `blocky.interaction/v1alpha1`、`blocky.tool/v1alpha1` | 阶段 2 未改变协议版本 |

IR、交互清单、ToolContract 和日志均为派生事实。加载项目后必须从声明式 Manifest、Workspace 和资源重新解析、编译和链接，不能信任磁盘中缓存的派生字段。

当前 `packages/block-catalog/src/text-primitives.json` 登记六个文本语言原子：

1. `core.agent.define`：智能体容器；
2. `core.interaction.chat_entry`：文本聊天入口；
3. `core.interaction.accept_text`：接受文本；
4. `core.data.literal`：JSON 值；
5. `core.message.create`：创建消息；
6. `core.message.reply`：回复消息。

六个原子已经接入目录、编辑器编译和确定性运行测试。它们是阶段 2 的语言地基，不代表完整积木目录、真实模型或真实 Provider 已实现；当前运行仍不真实调用外部大模型 API。

## 2. 显式迁移与增量编译

`packages/project-migration/` 提供 `blocky.migration/v1` 迁移结果。迁移输入受文件数量、字节数、引用路径和 JSON 边界限制，输出源版本、目标 `blocky.project/v1`、源摘要、候选项目和结构化诊断。迁移只生成新候选，不覆盖原文件；解析、编译或派生数据比对失败时不提供候选。

支持的来源包括旧正式 `blocky.project/v1alpha1`、已删除尖峰格式的受限迁移入口和当前 `blocky.project/v1`。尖峰格式只允许六个当前有等价语义的原子；单画布映射为 `main` 模块，保留块 ID、布局和字段值。未知积木、禁用/影子语义、未来版本、派生 IR 不一致或不支持的文件会返回可定位诊断。迁移不会静默接受尖峰文件，也不会把同名但语义不同的知识积木当成当前原子。

`IncrementalCompiler` 只缓存模块本地编译。缓存键覆盖项目 ID、模块描述和该模块 Workspace 的规范 JSON；模块不变时复用快照，模块变化时只重编译受影响模块。每次调用仍从当前模块结果重新执行跨模块链接和交互/工具投影，并公开 `compiled`/`reused` 统计。增量结果必须与同一输入的全量编译结果一致。

## 3. 命令、会话、设置与资源

`packages/command-system/` 登记菜单、命令中心、快捷键和上下文菜单共用的 `CommandDefinition`。命令包含分类、默认/备用快捷键、选择要求、危险级别和可用性；桌面菜单、命令中心和快捷键通过同一执行路径。快捷键文档使用 `blocky.shortcuts/v1`，冲突、保留键和恢复默认由共享绑定逻辑处理。

`packages/settings-core/` 使用 `blocky.settings/v1` 文档与 `blocky.setting/v1alpha1` 定义元数据，分离应用、项目、资源和积木作用域。当前真实消费者只有减少动态效果、积木视图、最小化到通知区域、终端输出预算、日志保留天数和日志存储上限。每项设置有默认值、校验、允许作用域、继承来源、重置和迁移版本；会话布局和秘密值不写入项目设置。旧的未版本化本机偏好必须显式迁移，损坏设置返回诊断。

`packages/resource-registry/` 登记九类资源：`model`、`knowledge`、`memory`、`tool`、`skill`、`mcp`、`guardrail`、`data`、`task`。资源定义提供类型、范围、公开 HTTPS、实现引用、字段校验和秘密字段；项目资源与用户资源严格区分，引用影响分析和缺失引用返回诊断。资源登记、配置和 `secretRef` 绑定不等于 Provider、RAG、MCP 或 Skill 执行器已经实现。

## 4. 用户终端、类型化任务与日志

Windows 用户终端由 Host 的真实 ConPTY 路径管理。`apps/studio-host/src/user_terminal/native.rs` 使用 `CreatePseudoConsole`、`ResizePseudoConsole`、管道读写和系统目录下的 `cmd.exe`/Windows PowerShell；进程进入 Job Object，并设置 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`。桌面可创建、读取、输入、调整行列、关闭和结算会话；输出使用 UTF-8 增量解码和字节预算，完成会话在显式关闭前仍可读，最多保留八个会话。用户终端没有任意可执行文件、参数、环境或调用方句柄入口，Agent、Builder、Skill 和 RPA 不得附加或读取用户 PTY。

`packages/terminal-protocol/` 与 Rust Host 共用登记任务。当前任务为 `blocky.project-check` 和 `blocky.project-inventory`，参数、超时、输出预算、Windows 平台、成功退出码、并发上限、取消宽限期和进程组结算均为类型化定义。任务 Host 不接受调用者提供的任意命令、工作目录或环境；Agent 只能使用带主体、任务清单、过期时间和一次性 capability 票据的 `AgentProcessRequest`。任务结果保留状态、退出码、输出、截断/丢弃计数和活动进程数。

日志路径使用结构化事件、Normalizer/Redactor 和有界存储。Host 日志存储限制记录数和字节数，保存保留策略、通道筛选、丢弃计数、重要级别丢弃计数和清除审计；损坏记录隔离到 quarantine，导出不能回显秘密。UI 读取 `Diagnostic`、`RuntimeEvent` 和具名输出通道，不解析普通日志字符串来推断运行状态。日志协议 `blocky.log/v1alpha1` 保持 alpha，阶段 2 只补正式消费者和本机存储实现。

## 5. 会话恢复与秘密边界

`packages/project-format/` 提供 `blocky.recovery/v1` 恢复副本，记录更新时间、项目 ID、编码后的项目文件和 SHA-256 摘要。桌面在项目已启动且存在未保存修改时排队写入用户状态；启动时校验摘要和当前项目格式，用户可以接受或放弃副本。恢复失败不覆盖原项目，不自动运行项目或重启终端任务；用户会话状态与项目语义分开。

Host 秘密存储只接受稳定 `secretRef`。导入 `.env` 时只读取指定变量，校验变量名和大小；Windows 使用 DPAPI 保护后原子写入本机数据目录。状态接口只返回存在性，解密值只在 Host 内部短暂消费并主动清零，不返回桌面、CLI、项目文件、IR 或日志。项目中只保存 `secretRefs`/`secretBindings`，不得保存凭据值、Authorization、Cookie、Token 或私有地址。

## 6. 保留 alpha 与当前非范围

阶段 2 只提升项目、模块 IR、项目 IR、迁移、恢复和设置文档中明确登记的版本。未改变语义的协议继续使用 alpha 版本：`blocky.interaction/v1alpha1`、`blocky.tool/v1alpha1`、`blocky.resource/v1alpha1`、`blocky.command/v1alpha1`、`blocky.setting/v1alpha1`、`blocky.app-surface/v1alpha1`、`blocky.frontend-bridge/v1alpha1`、`blocky.rpa/v1alpha1`、`blocky.window/v1alpha1`、`blocky.log/v1alpha1`、`blocky.terminal/v1alpha1`、`blocky.task/v1alpha1` 和 `blocky.audit/v1alpha1`。

阶段 2 不提前交付真实 RAG 摄取/索引、真实模型调用、任意仓库源码转换、完整构建助手、动态页面生成、完整运行轨迹、RPA 副作用、六个兼容模板、官方 Skills、Codex 插件或发布能力。当前阶段的真实大模型 API 调用结论为“否”。
