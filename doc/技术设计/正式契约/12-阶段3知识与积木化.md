# 阶段 3 知识与积木化契约

## 3C 接口补充

`ConversionScanner` 同时供 CLI 和桌面使用。Host `conversion-scan/read/cache-load/cache-save/cancel` 锁定 Git 对象与子目录，包含根许可证/依赖声明。工作树差异仅比较选定文本文件原始字节，不包含 index、untracked、EOL/filter 归一化或 mode-only 变化。

快照采用 `blocky.source-snapshot/v1`，文件 SHA-256、commit、范围和 dirty 元数据绑定快照 ID。受控 JSONL 工件与 offset 元数据均校验摘要，按最多 64 文件/4 MiB 分页；上限为 20,000 文件、100 MiB 候选文本、单文件 2 MiB。分析及缓存合计最多 16 MiB；每页后保存进度，取消不发布部分快照，重启复用匹配的路径/摘要/分析器版本。CLI 默认返回工件引用、字节数和 SHA；完整计划可显式导出。

计划包括源码证据映射、兼容报告、性能预算、依赖声明/锁文件和许可证正文。静态解析使用锁定 Lezer Python/JS/TS 语法。封闭纯数值函数可生成 `core.data.transform`，一元线性本地调用链展开为多个计算积木；运行循环/状态边界只形成兼容草案，其余明确原生保留。动态导入、外部调用、模块初始化与不能证明的算法不生成可运行候选。

数值契约 `blocky.expression/v1` 只含有限数、参数和加减乘除，最多 16 参数、256 节点、深度 32；输入/中间结果/输出绝对值不超过 1e9，除零拒绝。输入是参数名到数字的 JSON 对象，单参数也接受数字；无 eval、属性访问、源码执行或 I/O。候选重新读取完整快照与许可证、重新解析所选源码，生成 Build Spec 与既有 SemanticPatch；不信任缓存中提供的可执行程序。接受/拒绝/基线检查/整体撤销复用现有补丁领域。

真实公开源核对：`https://github.com/deepset-ai/haystack.git`，`v2.9.0` 的 commit `d72ed6cb37abebaefda8da39e3e7a5d8fffb2065`；范围 `haystack/components/retrievers/in_memory`，实际 6 文件（含根证据）、36,567 原文 UTF-8 字节。读取 Apache-2.0 许可正文与 pyproject 声明；BM25 类及 run 方法均标为原生保留，未转换其算法。克隆使用 no-checkout，因此原始字节检查报告工作树有差异，所读内容始终来自锁定提交。

## 1. 摄取与资源边界

纯领域入口为 `packages/knowledge-core/src/index.ts`。桌面通过 `knowledgeNative`、CLI 通过原生 `blocky-project-io` 实现同一 `KnowledgePort`；绝对来源路径只在 Host 授权记录中存在，项目仅保存资源引用和分段/检索配置。

| 标识/协议 | 用途 | 位置 |
|---|---|---|
| sourceId | Host 授权的文件/目录/仓库/URL 来源 | 本机集合元数据 |
| documentId / revision | 来源内部文档标识及内容版本 | 本机索引 |
| chunkId / digest | 内容片段稳定标识与 SHA-256 | 本机索引 |
| blocky.knowledge-index/v1 | 来源版本、文档、片段与分段配置 | 本机受控资源存储 |
| blocky.knowledge-store/v1 | 原子发布的 index 与可恢复 pending | 本机受控资源存储 |
| generation | 来源授权集合变更版本 | Host 可信状态 |
| revision | 索引 CAS 写入版本 | Host 可信状态 |

`KnowledgePort.sources()` 返回当前 generation 与可读取标志，权限由 Host 的本机用户上下文决定，查询不能随意传 principal 冒充身份。来源 ACL/remove 使旧索引不可用；保存必须同时比较 expectedGeneration/expectedRevision。WebView 不能用索引内的 ACL 自行授予权限。

`readSource(sourceId,cursor?,snapshotRevision?)` 返回有界文档页、快照版本、下一游标与排除原因。定位信息只含相对路径、源行号、公开 URL 或 commit。跨页版本变化拒绝继续，不能混合两份快照。

## 2. 解析、分段与同步

UTF-8 文本/Markdown/代码保留原始行号；HTML 使用 parse5 的源码位置并去除不可见或可执行区域，不在 WebView 执行来源。不能解析的格式显式报错。parse5 位置行为依据[官方 ParserOptions](https://parse5.js.org/interfaces/parse5.ParserOptions.html)，启用 `sourceCodeLocationInfo`。

来源 ID、documentId、片段内容摘要和同文档内同内容出现序号共同决定 chunkId；文档前插入其他段落后，未改变段落保持 ID，行号随当前版本更新。长段按显式 size/overlap 切分；资源配置不能使用无效重叠值。

同步读取实际来源，对比文档内容与定位/元数据摘要；相同文档和相同分段配置复用已解析片段。分页之间保存每来源的 pending 快照版本与下一游标；继续同步时核对 Host 来源版本和权限 generation，匹配则续读同一不可变快照，已完成来源复用；版本不匹配则重新扫描。一次同步完成后，下一次全量同步检查磁盘新变化。任何来源失败时不发布候选 index；原发布版本保留并显示具体失败来源，权限撤销优先于保留旧数据。

新增/更新/删除/跳过统计针对文档；失败时删除数为 0，不能把未读取来源中的旧文档算作已删除；chunks 为候选片段数。索引不是项目语义，禁止写进 `.blocky`。查询与运行适配已通过 3B 的共享领域接口接入。

## 3. 错误与兼容

领域错误使用稳定代码：`BLK-KNOWLEDGE-FORMAT`（格式/正文不支持）、`BLK-KNOWLEDGE-BUDGET`（超预算）、`BLK-KNOWLEDGE-STORE`（存储格式无效）、`BLK-KNOWLEDGE-SOURCE`（来源读取失败）与 `BLK-KNOWLEDGE-CONFLICT`（版本变化）。UI/CLI 显示通用安全文案，不回显异常对象中的路径、请求头或正文。

现有阶段 1/2 项目的确定性资源保留可读；用户执行“用于当前知识积木”或 CLI `knowledge bind` 后才切换到真实来源资源。原有模型摘录合成保持其真实性边界；真实外部生成式模型 API 不在 3A 中实现。

## 4. 检索与证据

`KnowledgeSearch` 是 CLI、桌面检索及 `hostAdapters` 运行适配的共享入口。关键词使用 Unicode 英文词/中文双字与 BM25；向量使用本机 Host 推理；混合使用倒数排名融合。权限及元数据筛选先于召回，结果返回前再次核对 generation/revision；缓存按项目、集合与发布版本隔离。取消通过独立 Host 通道结算，CLI 私有 stdio 会话只接收知识协议，不开放套接字。

查询配置有实际消费者：`strategy`、`topK`、`maxCandidates`、`minScore`、`contextBudget`（UTF-8 字节）、规则 `rerank`、`timeoutMs`、显式 `fallback`、锁定 `modelId` 与元数据等值筛选。不同召回策略的分数不可直接比较；阈值应用在重排前。没有模型、索引过期或超时默认报错，只有明确开启关键词降级才返回带警告的降级结果。资源编辑与运行通过 `resourceRetrieval` 读取同一配置；未支持的外部重排及非段落分段显式拒绝。

`EvidenceCitation` 保留片段 ID、sourceId/documentId、当前文档 revision、正文摘要、相对路径/URL/commit 和行范围。打开出处由 Host 重新检查授权与版本，再核对位置及摘录；剪裁只取原文前缀，不重新生成正文。删除、撤权或同步版本变化后失效，运行器保留原始证据元数据，不接受整理器篡改位置。

本地整理器只展示“相关资料摘录”，明确完整回答尚未得到确认，并在缺信息时请求补充。相似度不等于答案支持关系；本阶段没有生成式问答或蕴含判定器。无可引用内容时标为待核实。真实外部大模型 API 调用为“否”；本地神经 Embedding 为“是”，二者分开记录。

## 5. 本地模型与发行依赖

锁定模型为 `multilingual-e5-small-int8-v1`（384 维，ONNX CPU），来源、不可变版本、五个资产的大小/SHA-256、派生模型许可声明和运行库许可证见 `vendor/models/registry.json`。模型推理不联网。长文本使用真实 tokenizer 按 500 token 窗口完整处理、加权汇总并归一化，不默默截断到第一个窗口。

Host 验证五个文件后才加载；向量缓存键包含模型与分窗策略及原文，二进制记录有内容校验，行映射发布绑定索引版本和权限版本。取消保留完整记录检查点；未变内容复用，部分尾记录可恢复，完整损坏记录拒绝。

开发准备：`node scripts/prepare-knowledge-model.mjs` 与 `node scripts/prepare-native-runtime.mjs`。`BLOCKY_MODEL_DIR` 仅为 Host 进程环境覆盖，见 `.env.example`，不会自动载入 `.env`；普通包从固定的相对模型目录加载，WebView 不可传入任意模型路径。发行包共享 `models/multilingual-e5-small/`，两个原生程序旁各自放置 DirectML。Microsoft Visual C++ x64 Runtime 14.44+ 为系统前提，未随包分发。

开发评估：`pnpm exec tsx scripts/evaluate-knowledge.ts` 固定质量集摘要并运行真实 Host；`pnpm exec tsx scripts/benchmark-knowledge.ts 100`（另支持 1000/10000）生成有区别的合成记录并记录真实体积、Embedding、查询、内存与增量结果。结果是开发验证，正式结论由独立验收填写。

## 6. 蓝图 v1 与首次任务

`officialStarters` 提供资料问答伙伴、代码库讲解助手、知识小老师、轻量任务助手。前三个默认引用空的 Host 集合，用户添加资料后才能得到摘录；分别提供研究核对、源码路径/行号阅读和复述练习。轻量任务使用有界数值解释器计算总工时，可切换同接口分钟工具，不执行 Shell 或仓库源码。`createBlueprintProject` 同时供 CLI 和桌面使用，项目最低读取版本为 0.3.0。

`blocky.blueprint/v1` 保存来源、整数版本、规范化内容摘要、多栈相对布局及角色/知识/模型/外部模块公开插槽。插入生成新 ID，顶层块的严格 `blocky.blueprint-instance/v1` 元数据保存来源 ID 映射、默认内容和资源/模块绑定。真实 Blockly save/load 保留该信息；编译仍由展开的原子积木决定，元数据不提供权限。捕获个人蓝图移除实例元数据，避免嵌套默认副本。

更新使用默认内容、当前用户内容、新版本内容的三方合并。无冲突变更生成候选；冲突须明确选择保留用户内容或采用新版。多栈按同一 instanceId 一起更新，另一个插入实例不受影响。还原恢复默认角色与内容，同时保留位置、折叠状态及现有资源/工具绑定。所有结果经共享补丁预览、Host 复核、基线校验和整体撤销；生成或拒绝不写项目。

v1alpha1 蓝图不能隐式当 v1 读取。CLI 输出新文件，桌面导入生成新副本；本机旧蓝图库显式迁移前保存原序列化备份，不可读库不得被新保存覆盖。公开插槽必须完成绑定，工具接口不匹配拒绝插入。

开始页与右侧任务引导给出资料添加、示例输入及角色修改入口。首次体验面向 10–15 岁，用户暂不能安排参与者；工程走查不能代替该用户试用门禁。
