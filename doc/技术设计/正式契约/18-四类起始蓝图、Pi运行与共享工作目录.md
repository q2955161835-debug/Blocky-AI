# 四类起始蓝图、Pi 运行与共享工作目录

状态（2026-10-04）：四类蓝图、CLI 入口、Pi 循环及共享工作目录正在实现；本任务范围尚未完成独立验收。本文记录当前源码与已批准产品边界，不表示普通包交付、兼容认证或真实模型调用已通过。

## 1. 四类可编辑起点

目录 ID 固定为 `knowledge-assistant`、`work-assistant`、`coding-assistant`、`pi-agent`，桌面与 CLI 共用同一注册表及项目生成函数。蓝图创建的是普通 `blocky.project/v1` 项目与 Blockly `main` 模块；生成后可照常编辑，不引入专属运行器或不可见项目状态。顺序为知识问答助手、工作助手、Coding 助手、Pi Agent。

| 起点 | 默认画布内容 | 必需的用户配置与边界 |
|---|---|---|
| 知识问答助手 | Agent 与聊天入口、资料检索、证据护栏、模型回答；初始知识库没有用户资料 | 添加并同步资料、配置模型；按已同步资料与可核对来源回答，无证据时说明不足，不编造内容或引用 |
| 工作助手 | Agent 与聊天入口、Pi 工具循环、工作目录列举/搜索/读取/写入/撤销、会话记忆与回答 | 选择工作目录并配置模型；写入受目录、版本和回执约束 |
| Coding 助手 | Agent 与聊天入口、Pi 工具循环、以上工作目录工具加 JSON/JavaScript 语法检查、源码导览回答 | 选择工作目录并配置模型；检查工具只读语法，不执行项目代码或 Shell |
| Pi Agent | 通用 Agent 与聊天入口、Pi 工具循环及回答；默认不声明工作目录工具 | 配置模型和需要的工具；只能使用项目中明确声明且经 Host 授权的能力 |

四种项目起点都生成单一 `main` Agent 模块，不内置模型凭据；当前创建器没有把真实模型连接、密钥、外部文件夹或用户资料写入项目。知识起点只建立空资料资源，导入和同步由用户完成。空白 `project create` 继续生成无积木、无资源、无问句的 `main` 项目；它不是上述四个起点的别名，也不能据此声称已可运行。个人蓝图与既有 `.blocky` 文件不受此注册表替换影响。

桌面欢迎页和 CLI 使用同一组四个 ID。CLI `template list/show/status` 查询当前起点与既有项目配置；`project create --template <id>` 显式选择其一。未带 `--template` 的 `project create` 必须保持空白默认。未知或旧模板 ID 拒绝，不通过品牌别名静默映射到新方向。

## 2. Pi 工具循环与会话

Work、Coding 与 Pi Agent 使用 `core.reason.tool_loop` 的 `ENGINE=pi`、`SESSION=conversation`；知识问答使用现有知识检索、证据校验与模型回答链。`ENGINE` 接受 `blocky | pi`，`SESSION` 接受 `turn | conversation`。Pi 路径通过 `runtime-core/src/pi-loop.ts` 调用锁定的 Pi Agent Core `Agent` 与官方 loop/stream dispatcher；它不模拟 SDK 循环。Host 仍负责模型凭据、模型请求、工具权限、工具副作用及运行预算。真实上游来源、版本、许可证及完整性校验由 `vendor/pi-core-lock.json` 与构建前校验脚本绑定；未完成来源/许可证审计的第三方框架不得据此标成原生兼容。

对话历史最多 20 条、规范化 JSON 最多 16,000 UTF-8 字节。可复用会话按 `projectId + sessionId + moduleId + nodeId` 定位，并绑定角色、指令、模型、声明工具和引用摘要；绑定变化时不复用旧历史。历史内容只含 user/assistant 文本，不接受调用方注入 system/tool 消息。Pi 的模型/工具事件仍走 RuntimeEvent，不能用普通日志文本推断执行状态。

## 3. 共享工作目录工具

Work 与 Coding 将工具资源声明为 `implementationRef.adapter = workspace-file-v1`，通过 `blocky.workspace-request/v1` 送入受限 Host；CLI 私有进程帧沿用 `blocky.project-io/v1alpha1` 的 `workspace-bind`、`workspace-status` 与 `workspace-call` 操作。目录选择在 Host 建立项目绑定，Host 向项目仅暴露不透明授权状态；绝对目录路径、目录授权、撤销 journal 和凭据不进入 `.blocky` 项目。没有已绑定目录时，目录工具明确失败，纯对话、知识问答和当前项目上下文不因此获得任意文件访问。

| 操作 | 能力与输入限制 | 输出及权限 |
|---|---|---|
| `list` | 可选相对目录路径，最多 500 字符 | 有界相对路径清单；`workspace.read` |
| `search` | 查询最多 200 字符，可选相对目录路径 | 匹配相对路径、行号及片段；`workspace.read` |
| `read` | 相对文件路径 | 有界 UTF-8 文本及版本摘要；`workspace.read` |
| `write` | 路径、文本最多 16,000 字符、预期摘要；新建为空摘要，更新须带最近读到的摘要 | 受版本校验的创建/替换及前后差异回执；完整序列化结果超过 32 KiB 时在写入前拒绝；`workspace.write` |
| `undo` | 变更回执 ID | 仅对当前目录所有者及匹配版本撤回；`workspace.write` |
| `check` | 相对路径及 `json` 或 `javascript` 类型 | JSON 解析或随应用分发的 Node `--check` 语法结果；最长 15 秒；`workspace.check` |

每个工具结果最多 32 KiB，Host 在返回前再次检查。路径限制、拒绝秘密文件/重解析点及版本化文件发布复用 Host 文件边界。`check` 仅分析 JSON/JavaScript 语法：不执行用户代码、不解析或运行导入、不提供 Shell。该协议的 16 KiB 输入与 32 KiB 结果预算独立于契约 17 桌面构建助手原有的单文件 1 MiB Scope，不得互相扩张或替代。

## 4. 桌面构建助手默认行为

桌面 `coding_run` 发送任务时不再显示每任务 Yes/No 对话框。Host 仍在运行前生成并重算请求摘要，摘要绑定任务与模型版本；一次性 requestId、运行状态、目录授权和 Host 工具权限检查继续生效。这些摘要与守卫是 Host 的完整性/权限边界，不表示用户仍须逐任务确认。

默认工具上下文是当前项目的 `project_context` 与受限 `blocky_cli`。项目候选仅在项目身份、基线摘要、编译和 Host 权限校验通过且当前画布未并发变化时应用为单次可撤销编辑；项目变化时保留候选并报告冲突，不覆盖当前内容。新增项目权限及当前候选差异继续作为实际状态回执显示。

传入构建助手的 `runtimeContext` 只含稳定错误码、诊断级别、模块/积木来源 ID、事件类型及对应错误码；诊断和近期事件各最多 20 条，序列化总体不超过 8 KiB。不得夹带文件正文、任意日志文本、密钥或未经筛选的运行记录。

桌面构建助手此项变化不改写 CLI 的独立授权路径。旧 `coding run` CLI helper 仍显示原生任务批准对话框；普通 CLI `run start --live` 仍按其既有交互/批准摘要流程处理受限工具。CLI 的批准凭证、桌面 Host 请求绑定摘要及用户对候选项目的审阅状态是不同机制，不能互相代替。
