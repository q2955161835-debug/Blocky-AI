# 厂商与自定义模型管理设计

状态：2026-10-01 用户已确认设计及四组新增验收场景，选择“共用厂商配置，下面自定义多个模型”。[实施计划](../执行计划/2026-10-01-厂商与自定义模型管理实施.md)待审阅。本文件不代表功能已实现或验收通过。

## 用户流程

模型管理采用两层：先新建或选择厂商连接，再在该连接下添加多个模型。厂商连接管理名称、服务类型、受支持协议、地址与凭据引用；模型管理真实模型 ID、显示名称、已声明能力、超时及有界生成参数。默认模型选择具体模型，选择项按厂商分组；同一厂商可创建多份独立连接，例如不同账号或端点。

修改厂商地址或凭据后，下属模型的后续请求使用更新后的连接。正在执行的请求保持已批准的绑定；配置改变导致旧预检摘要失效，不能沿用旧批准发往新地址。既有作品保持原模型资源 ID，不自动替换作品内模型。恢复默认沿用现有本地模式行为。

桌面提供厂商列表、连接编辑、下属模型列表与模型编辑。新建、修改、删除、设置默认模型均提供同等 CLI 功能和可发现 Schema。删除仍被模型引用的厂商应返回引用列表并拒绝；用户先处理下属模型。删除当前默认模型后保留可定位的失效状态，不能偷偷选另一个模型。

## 方案选择

采用本机资源账本中独立的厂商连接记录，模型以稳定连接 ID 引用。备选的“只按厂商分组，每个模型独立保存连接”不能满足用户已选的共享配置；以一个模型资源充当其他模型的连接源，会把连接生命周期与模型生命周期耦合，因此不采用。

现有项目文件和积木继续引用模型资源，厂商不是积木分类，也不成为作品中的新资源种类。资源读取时统一生成有效模型配置供编译器、Runtime、Builder、评估和 CLI 使用；Host 请求时从同一账本再次解析连接，避免仅在界面上实现共享。

## 数据与接口

- 本机资源账本升级为 `blocky.resource-registry/v2`，保存 `providers` 和 `resources`，以一个原子写入维护连接与模型的引用一致性。
- 厂商连接记录保存稳定 `providerId`、显示名称、适配器类型、受支持协议、配置修订号及秘密引用。真实地址、Key、额外敏感请求头不进入该账本，仍由 Host 安全存储保存。
- 连接关联的模型资源保存 `connectionRef`、真实 `modelId`、显示名称、能力、超时、生成参数等模型字段，不重复保存厂商地址或秘密绑定。禁止模型覆盖连接凭据。旧式独立模型和本地确定性资源继续可读。
- 共享解析器检查连接存在、协议与适配器匹配、秘密字段符合既有白名单，再生成现有有效 Resource 形状。外部模型调用请求仍只接受模型资源引用，客户端不能指定地址、凭据或任意传输协议。
- Host 的正式模型网关、旧 Provider/Builder 绑定路径使用同一连接解析函数，并把连接修订和秘密版本纳入批准摘要。WebView 和 CLI 只收到公开配置与“是否已配置”的状态。
- 评估版本包含当前有效模型配置与连接修订；改变连接后，旧冻结评估不能被当作同一配置继续运行，沿用已有 fork 新版本恢复路径。
- CLI 计划提供 `provider list/set/delete` 与 `model-profile list/set/delete/default`，沿用现有 `model` 命令的本机模型安装与实际调用职责；公开文档仅使用占位配置。

本轮连接类型覆盖已存在且可执行的 DeepSeek、息壤、自定义 OpenAI Chat 兼容服务和 Ollama。本机托管模型保留其安装、后端和参数管理。协议选项仅显示已有可执行适配器；不以参考产品支持某协议作为 Blocky 已支持的证据。

## 旧配置迁移与回退

读取 v1 账本时先在内存迁移，保持原模型资源 ID、默认选择及秘密引用不变。只将服务类型、协议和秘密引用完全一致的旧在线模型归到同一个连接，绝不只按厂商名称合并不同账号。确定性、本机托管和非标准高级模型保留原配置。

首次持久化 v2 前，在同一资料根保存有界的 v1 回退副本，并原子写入新账本。迁移不读取或复制真实秘密；失败保留原账本，不能写半个连接或悬空模型。开发产物和隔离验证资料放在项目 `try/`。回退命令校验副本并恢复 v1，提示仅旧模型状态可恢复；用户明确执行回退，不自动丢弃迁移后的新增配置。

## 影响范围与验收草案

| 用户功能 | 场景与通过标准 | 证据 |
| --- | --- | --- |
| 管理厂商与模型 | 一份连接添加两个不同模型；CLI/桌面重开后字段一致；修改共享连接后两模型均解析到新修订 | 领域与 Host 测试、结构化 CLI 回执、后台普通包截图 |
| 切换模型 | 分组选择默认模型，新作品与构建助手读取该具体模型；已有作品引用保持；失效默认不自动换厂商 | CLI/组件与普通包读回 |
| 延续旧作品 | v1 迁移保留 ID/默认/秘密引用；不同账号不误合并；原子失败与明确回退保留旧状态 | 正反迁移测试、旧作品打开与重存 |
| 请求与数据边界 | 普通账本/作品/日志无真实地址或秘密；连接缺失、重复 ID、协议冲突拒绝；配置变更使旧批准/评估版本失效 | Host 契约、负例与无秘密回执 |

修改涉及资源注册表、Host 模型/Builder 绑定、桌面资源与默认模型界面、CLI/Schema，以及评估配置绑定的直接影响链。已有 B–E 与后台驱动证据保留精确来源，新普通候选和完整 360/30 Full 绑定最后冻结源码。最终独立验收继续采用已确认的 Blocky 交付角色；新增四组场景已确认，不把旧候选通过外推到新功能。
