# 内置代码 Agent 重塑实施计划

执行方式：已使用systematic-debugging、test-driven-development、dispatching-parallel-agents与verification-before-completion；实施后独立复核。用户已授权自主方案，不重复阶段确认。

**Goal:** 将现有Pi构建助手变成可连续读取/编辑工作文件、调用真实Blocky CLI的右侧代码Agent。

**Architecture:** 保留Pi Agent与模型Host，新增coding/v1协议和Host工作目录授权/文件工具/CLI任务。旧builder/v1继续兼容；桌面新入口使用新循环、实时事件、项目候选和独立会话。

**Tech Stack:** TypeScript、React、Zod、Pi Agent 0.86.0、Rust、Tauri、现有Blocky CLI；不新增产品依赖。

**Spec:** `doc/归档/2026-10-02/2026-10-01-内置代码Agent与右侧双会话设计.md`。用户已明确授权自主选择方案完成目标；实施方案由本轮自主确定，不再逐阶段等待确认。

## Global Constraints

- 工作目录由Host绑定不透明workspaceId，WebView不持有真实本机目录或凭据。
- 工具按顺序执行，不拼接Shell命令；普通文件可在任务内编辑，保留差异和CAS撤回。
- `.blocky`只经CLI/领域接口修改，当前未保存项目使用隔离快照，结果按baseDigest检查后进入编辑器可撤销事务。
- UI使用“构建助手 / Blocky Agent”右侧切换，模型沿用应用默认值，取消操作/模拟/创建界面的常驻选择。
- 兼容旧builder CLI，不静默使用模拟Provider替代已配置模型。
- Linux验证共享协议、Pi循环和组件；Windows原生构建/权限/CLI/Full结果不得伪报。
- 不合并/推送新功能或发布普通包，除非收到本任务的对应授权。

## Review Focus

- 换项目/换文件夹时旧请求的事件不能写进新会话；取消后不能开始新工具写入。
- 文件已被其他程序改动时编辑和撤回均拒绝覆盖，创建文件不允许覆盖已有文件。
- 工作目录内链接、硬链接、路径穿越、凭据文件以及CLI路径参数不能绕过权限范围。
- CLI失败/超时仍需结算子进程，实际输出不可被当作成功；CLI不得递归启动builder模型。
- 用户未保存的画布改变时旧候选不能覆盖新画布；新增项目能力保持权限审阅。

## 固定接口

共享协议放在`packages/builder-protocol/src/coding.ts`并从index导出：

- `CodingStart`：`schemaVersion:'blocky.coding-start/v1'`，`requestId/projectId/moduleId/prompt/originalJson/resourceId`，`selection:string[]`，`conversation:{role:'user'|'assistant',text:string}[]`，可选`workspaceId:string`。
- `CodingEvent`：`schemaVersion:'blocky.coding-event/v1'`，`requestId/projectId/sequence`，`kind:'text.delta'|'tool.started'|'tool.completed'|'tool.failed'|'file.changed'`；可选`tool/callId/text/code/change`。
- `CodingChange`：`changeId/path/before/after`（before/after字符串或null），`beforeDigest/afterDigest`（64位hex或null）；逆向回执可选`revertsChangeId`。
- `CodingResult`：`schemaVersion:'blocky.coding-result/v1'`，`requestId/projectId/baseDigest/text/changes/events/generations/engine/modelApiCalled`；可选`project:Project`（当前项目候选）。
- 工具名：`workspace_list`、`workspace_search`、`workspace_read`、`workspace_write`、`workspace_undo`、`blocky_cli`、`project_context`。工具JSON schemas放在`packages/builder-engine/src/coding-tool-schemas.json`，Host与Pi共同消费。
- `runCodingAgent(start: CodingStart, options: {generate, executeTool, onEvent?, signal?, modelId})`，返回CodingResult。worker进入`blocky.coding-ipc/v1`帧，start/provider.call/provider.result/tool.call/tool.result/event/complete/error/cancel均绑定requestId，tool调用另绑定callId。
- Tauri：`coding_workspace_pick() => {workspaceId,displayName}|null`，`coding_run({start,onEvent:Channel<CodingEvent>}) => CodingResult`，`coding_cancel({requestId})`，`coding_undo({workspaceId,changeId}) => CodingChange`。Rust管理`coding::CodingHost`，退出时shutdown。
- CLI访问：native envelope的`coding-*`操作必须复用Host验证与原生授权；可发现coding命令/Schema，不提供绕过目录选择的目录字符串权限。
- `blocky_cli({args:string[]})`使用实际打包CLI和参数数组；`$project`为Host隔离的当前项目候选，工具结果包含真实退出码和结构化输出。Host最终可返回候选project；工作文件写入工具禁止直接改.blocky。
