# 内置代码 Agent 与右侧双会话设计

状态：用户已授权自主实施；已完成本地源码开发与Linux开发验证，Windows原生/普通包/Full待验证。观察基线为`12005939811514bd919e0900f9d53df384f47281`，当前实现分支`codex/feat-built-in-code-agent`；详见契约17与本轮开发报告。

## 1. 用户目标

构建助手成为基于 Pi 的内置代码 Agent，交互参照 VS Code GitHub Copilot 和 Cursor Composer。用户在右侧输入自然语言，助手利用 Blocky CLI 完成项目构建，同时具备类似 Codex、Claude Code 的文件读取与编辑能力。右侧栏可以在构建助手与当前 Blocky 项目的 Agent 之间切换。

用户不需要先选择搭建、解释、修复等操作，也不需要填写一组构建参数。是否生成应用界面由需求决定。默认模型沿用应用设置，允许在输入框附近切换模型。

本轮实施采用以下工作范围：文件操作作用于用户选择的工作文件夹，可以是普通代码目录；助手完成已交代任务所需的普通文件编辑后展示差异，不要求每次写文件都弹出确认。新增文件夹访问、不可恢复操作和现有项目能力授权仍在需要时确认。原生目录选择与既有模型批准保持有效。

## 2. 改造前基线

- `apps/studio-desktop/src/app/StudioSidebar.tsx` 已有右侧 builder/agent 标签与键盘切换，两个面板通过 hidden 保留挂载。
- `BuilderPanel.tsx` 当前暴露 build/explain/repair、模拟/在线、模型资源、生成应用界面等选择，并展示固定 Build Spec 与候选方案。
- `composition/useBuilder.ts` 每轮提交一个 builder_run，最多四轮模型请求；请求携带当前模块、选区、项目快照与摘要对话，返回后才显示结果。
- `packages/builder-engine/src/index.ts` 使用 `@earendil-works/pi-agent-core` 0.86.0，但工具只限 inspect/draft/patch/verify，系统指令明确禁止文件写入与 Shell。
- `scripts/build-builder.mjs` 只打包已审计 Pi Agent 入口，禁止文件/进程等额外 sidecar imports；因此文件能力应通过 Host 工具协议提供，不能直接解除打包检查。
- `apps/studio-host/src/builder/` 已有请求、模型凭据、取消、进程结算和调用证据，可作为扩展基础。
- `RunPanel.tsx` 当前承担项目交互入口、运行结果、轨迹与持久工作流任务，不等同于通用代码助手。

## 3. 方案选择

推荐保留现有 Pi Agent 内核，扩展 Blocky 自有会话与 Host 工具协议。它复用现有模型、安全存储和桌面生命周期，并能调用真实 CLI；需要新增文件工具、实时事件和项目同步。

另一方案是直接引入完整 Pi coding-agent 的工具及会话，需要重新审核其文件、命令、Provider 与持久化边界，也会与现有 Host 重叠。仅调整聊天外观则不能完成用户要求的文件与 CLI 能力。

本轮采用第一方案。产品界面仍称“构建助手”，其角色是内置代码 Agent；Pi 是内部实现。

## 4. 右侧交互

右侧顶部只显示两个平级标签：“构建助手”和“Blocky Agent”。构建助手默认展示对话正文，底部固定多行输入框；发送后流式显示回复与工具进度。Enter 发送、Shift+Enter 换行，输入法组合输入不触发发送。

本轮入口为新对话、工作文件夹、模型选择、发送/停止；历史正文按项目保存，不新增历史会话管理或上下文附件选择器。输入附近显示当前工作范围和模型，不铺开操作类型、生成界面和 Build Spec 参数。工具细节与调用证据在对话内折叠；修改文件列表与差异可以打开审阅。

上下文包含当前画布/选中积木；文件由助手在选定目录内用工具读取。选择上下文不等于授权整个磁盘。模型未配置或默认资源失效时引导到设置，不静默以模拟响应代替代码 Agent；确定性 Provider 保留在开发测试路径。

Blocky Agent 标签用于与用户搭建的 Agent 交互，保留该项目声明的入口、运行/停止、输出与必要的工作流审批。轨迹、检查器等辅助内容按现有用途收起或定位，避免挤占主要会话。

两个标签分别保存会话与运行状态，切换不重新发送请求，不复制上下文，不清空回答。退出应用、切换项目或更换工作文件夹时结算受影响的活动请求。是否允许两者同时运行由操作是否修改同一项目决定，而不是简单按标签切换决定。

## 5. Agent 执行与工具

一轮自然语言任务进入持久会话；Pi 根据当前上下文选择工具，消费真实结果，继续完成任务或请求缺失信息。它可以只回答问题，也可以执行多步编辑和验证，不再要求每轮都产出固定计划/候选模板。循环保留内部预算、取消和明确终态，预算不暴露为常驻表单。

首批工具能力：

| 工具 | 行为 |
|---|---|
| 文件列表与搜索 | 在绑定工作目录中枚举和检索，返回相对路径、行号和有界内容 |
| 文件读取 | 读取有界文本文件并报告版本，超限拒绝，二进制不伪装文本 |
| 文件创建与编辑 | 创建或摘要匹配替换文本文件，检查原版本，记录前后差异 |
| Blocky CLI | 以可执行文件和参数数组调用实际打包 CLI，获取结构化结果/事件 |
| 当前编辑器上下文 | 读取当前项目候选、画布与选区；真实诊断通过CLI编译取得 |
| 变更与验证查询 | 读取本任务的文件差异、CLI验证结果与未完成项 |

Blocky CLI 首先发现版本、command/schema/catalog，之后使用已实现命令完成检查、候选、应用、编译与验证。调用参数由版本化工具 Schema 校验，不将模型文本拼接为 Shell 命令。CLI 构建步骤调用领域命令，不能递归启动另一轮 builder 模型任务代替当前 Pi 会话。

文件工具和 CLI 的实际执行位于 Host，Pi worker 只接收有界工具结果。原生 Host 保留模型凭据与资源连接，WebView 接收会话状态、用户文本、允许显示的文件片段与变更差异。用户终端仍由用户使用，助手使用独立任务进程。

通用任意 Shell、额外插件市场、多 Agent 编排、远程部署不在本轮默认范围；如用户需要通用编码任务的额外命令执行，先据具体命令补充此设计，不能把读取/编辑授权扩张为任意执行权限。

## 6. 文件与项目一致性

工作目录由用户选择并由 Host 持有授权引用。路径解析以真实路径和目录边界核验，拒绝通过链接或路径穿越逃逸。范围外文件只有用户明确增加上下文/目录授权后才能访问。凭据存储和敏感配置不因工作目录授权自动进入模型上下文。

普通文件编辑使用读取版本、预期内容或摘要核验；其他程序已修改文件时报告冲突，不覆盖。每次成功写入形成可检查差异，保留本轮撤回所需状态；撤回也核验当前版本。失败或取消后报告已完成与未完成的编辑，不声称自动回滚全部外部副作用。

`.blocky` 是结构化项目包，通过 Blocky CLI 与项目领域接口修改，不能当作文本文件任意写字节。当前桌面未保存状态先形成隔离快照，CLI 在候选上操作；结果经校验、基线比对和编辑器事务进入当前画布，保留撤销与显式保存。画布在执行期间变化则报告冲突，不能用旧候选覆盖新状态。

原有能力/资源授权不由新代码助手绕过。CLI 在任务工作目录中执行，输出有界、进程可取消，任务结束后等待子进程结算，避免停止后继续写入。

## 7. 协议与迁移

为 Agent 会话、工具调用、实时事件、授权范围、文件差异与任务终态定义新版本协议，保留旧 builder/v1 的明确兼容路径；不能给旧严格 Schema 偷加字段。新的桌面入口调用新会话接口，已有外部 CLI 命令通过兼容入口过渡。

新会话与 Blocky Agent 运行会话分别拥有项目/工作目录/请求标识，事件带单调序号。迟到事件、重复终态或已取消任务的结果不能写入另一个会话。旧builder-chat存储保持独立，当前代码会话使用coding-chat，不把旧方案注入为真实工具结果或已应用文件修改。

原有“Pi不能写文件”的设计更新为“Pi只能通过Host授予的文件与CLI工具请求操作”；WebView凭据隔离、资源授权和项目格式仍遵守现有契约。正式实施时同步修改AGENTS、CLI产品设计与对应正式契约，并更新测试/打包审核清单。

## 8. 验收与实施边界

1. 普通自然语言任务无需选择操作类型；可读文件、创建/修改文件、查看实际差异并继续追问。
2. 一条构建请求经真实Blocky CLI完成发现、修改、校验，桌面画布正确同步，保存重开与撤销有效。
3. 两个右侧标签分别保持会话和活动状态，切换不会重发请求或混淆模型/项目上下文。
4. 流式回复、工具成功/失败/等待状态、停止与进程结算可观察；取消后无迟到编辑。
5. 路径逃逸、链接、并发修改、过大输出、失效模型、陈旧项目与秘密上下文均有负例。
6. 共用会话工具协议在CLI/Host可验证，桌面保留必须实际观察的交互证据。
7. 修改Host与持久会话后按仓库映射执行组件、Host、CLI、原生E2E、普通包隔离与敏感扫描；改变长期状态/生命周期后执行未缩短Full。

本轮环境是Linux，可先验证共享协议、Pi循环和组件；Windows原生权限、实际文件交互、普通包和长稳必须在Windows完成。不得用共享测试代替Windows验收，也不得在尚未完成时更新普通包或桌面入口。

本轮未实际调用外部大模型API；新增源码与锁定bundle，不引入新的第三方产品依赖。Windows原生权限、进程结算、保存重开与Full仍需实际验证；未推送新功能、发布普通包或更新桌面入口。
