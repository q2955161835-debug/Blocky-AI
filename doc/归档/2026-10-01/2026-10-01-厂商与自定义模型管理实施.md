# 厂商与自定义模型管理 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** 一份厂商连接供多个自定义模型使用，桌面与 CLI 可配置并切换具体默认模型。

**Architecture:** 在本机资源账本 v2 中保存连接和模型引用，领域层与 Host 分别校验并解析为现有有效模型 Resource。项目继续引用模型 ID；网络请求继续经 Host 网关及配置绑定批准。

**Tech Stack:** 现有 TypeScript/React、Rust/Tauri、Vitest、原生后台测试驱动；不引入新框架或全局依赖。

**Spec:** [已确认设计及四组验收场景](2026-10-01-厂商与自定义模型管理设计.md)。执行前基线 `f343436`，复用 `codex/feat-agent-capability-upgrade`；Root 顺序实现，最终独立验收按项目既有角色执行。

## Global Constraints

- 同一厂商可创建多份独立连接，例如不同账号或端点。
- 既有作品保持原模型资源 ID，不自动替换作品内模型。
- 真实地址、Key、额外敏感请求头不进入该账本，仍由 Host 安全存储保存。
- 协议选项仅显示已有可执行适配器。
- 新普通候选和完整 360/30 Full 绑定最后冻结源码。
- 所有一次性脚本、合成 profile、截图和原生 TEMP 放项目 `try/`；不抢前台、不调用全局输入。

## Review Focus

1. 同厂商不同账号：仅按完全相同的连接字段与秘密引用归并，名称相同不足以合并。
2. 已打开的旧作品：模型 ID 不变；用户配置连接的变更不能绕过 Host 的新请求批准，也不能影响其他资源种类的秘密引用检查。
3. 保存失败或并发修改：不能出现界面已保存而磁盘未保存，或后写者静默覆盖连接/模型列表。
4. 不可用默认或厂商删除：错误定位到具体引用，不能自动换厂商或删除下属模型。
5. 模型选择限制：声明图片/工具能力不等于供应商支持；运行仍检查能力、预算与实际响应，不能把配置作为真实 API 成功。

### Task 1：领域账本与迁移

**Files:** 新建 `packages/resource-registry/src/model-providers.ts`；修改 `user-registry.ts`、`validate.ts`、`definitions.ts`、`index.ts`；新建 `packages/resource-registry/tests/model-providers.test.ts`。

**Interfaces:**
- `ModelProvider`: `schemaVersion: blocky.model-provider/v1`、`providerId`、`displayName`、`adapter`（deepseek/xirang/openai-compatible/ollama）、`protocol: openai-chat`、`revision`、`secretBindings`。
- `UserRegistry`: `schemaVersion: blocky.resource-registry/v2`、`revision`、`providers: ModelProvider[]`、`resources: Resource[]`。
- `parseRegistry(unknown): UserRegistry` 接受旧 v1 并内存迁移；`resolveRegistryResources(UserRegistry): Map<string, Resource>` 生成有效资源。
- `upsertModelProvider(registry, input)`、`removeModelProvider(registry, id)`、`upsertUserResource(registry, input)` 返回新的完整账本，不执行 IO。
- 关联模型 definition 保存 `connectionRef` 与模型参数，原始 `secretBindings` 必须为空；有效资源增加可校验的 `connectionRef/connectionRevision`，实际绑定来自该连接。

- [x] 写迁移与引用负例：同名不同 secretRef 不合并；ID 重复、悬空引用、项目范围关联模型、未知字段/协议、模型自行绑定秘密及被引用连接删除均拒绝。

### Task 2：Host 持久化与请求绑定

**Files:** 新建 `apps/studio-host/src/model_registry.rs`；修改 `lib.rs`、`user_store.rs`、`provider/gateway/binding.rs`、`provider/types.rs`、`builder/mod.rs`、`provider/builder_model.rs`；测试放新模块 tests 与已有 provider/gateway/tests.rs。

**Interfaces:**
- `model_registry::resolve_resource(registry: &Value, resource_id: &str) -> Result<Value, String>`：与 Task 1 同规则，返回有界的有效模型，不读取秘密。
- v2 账本写入执行递增修订 CAS；过期修订返回 `BLK-RESOURCE-CONFLICT`，不覆盖。使用已有标准库文件锁能力，在该资料根资源文件旁加跨进程锁；拒绝超时，不添加全局锁服务。
- 首次 v1→v2 原子持久化前保存 `resources/app.v1-backup.json`，既有副本不覆盖；明确回退校验该副本并使用当前修订 CAS，不自动回退。

- [x] 红灯测试：v1 文件备份与迁移成功；无效 v2/过期修订/模拟写失败保留原账本；两个 Host 实例并发更新只能有一方成功。
