## 当前差距与架构决定

`packages/runtime-core/src/adapters.ts` 的模型端口只返回 Citation 数组；`runtime.ts` 目前执行检索、摘录组织、回复和模块调用，没有完整生成式响应、记忆、护栏、通用受控工具和可配置运行预算。`host-adapters.ts` 仅连接真实知识服务。CLI 的运行入口仍限定模拟；桌面沿用相同 Runtime。现有 Host 已有 DPAPI、安全资源、登记任务及原生项目保存，继续复用。

采用“共享运行语义 + Host 内 Provider 与副作用”的方案：Workspace → 编译/链接 → 统一运行内核 → 类型化 Host 请求 → 结构化 RuntimeEvent → 桌面/CLI。生成式响应与引用证据分别建模，不能将生成文本假装成原文引用。保留无网络适配器及旧项目行为，显式增加新能力，不静默把旧模型资源切换到远程。

首个真实适配器采用用户提供的 DeepSeek 配置所对应的文本聊天协议；模型 ID 读取用户配置并核对供应商当前官方契约，不猜测或硬编码未经核实的可用模型。其他协议已有配置项不等于实现，未支持时明确报错。联网请求、密钥解密和响应大小限制均在 Host，WebView/Node CLI 不获取密钥。

## 重点失败场景

1. 已停止但供应商仍返回结果：批次 B/C 拒绝迟到事件和持久化。
2. 重开项目意外联网或重放工具：批次 D 只恢复编辑状态。
3. 模型输出伪造引用或带指令的检索内容：批次 A/C 保持信任层级并验证引用。
4. 工具批准后参数被改或跨项目票据重放：批次 C 按完整请求绑定授权。
5. 用量缺失、预算边界或部分输出被当完整成功：批次 B/C 明确未知用量、预留输出预算和失败状态，不伪造 Token 数。
