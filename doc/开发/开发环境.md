# Blocky 开发环境

## 当前范围

本阶段已准备 Windows Core 及未来 Android、HarmonyOS 使用端需要的系统工具链和可复现检查入口，并在 `try/windows-core-spike/` 完成一次性 Windows Core 技术尖峰。尖峰不是正式 Blocky 应用、可分发产品或跨平台工程骨架；`packages/cli`、正式 Agent Skills（智能体技能）和第二、第三阶段能力仍未创建。Android 与 HarmonyOS 工具链的存在仅表示本机具备后续验证条件，不代表这两个平台进入首发，也不代表它们提供积木编辑器。

## 使用方式

在项目根目录打开 PowerShell：

```powershell
. .\scripts\use-dev-environment.ps1
.\scripts\check-dev-environment.ps1
```

第一条命令只修改当前 PowerShell 进程，把 Android 与 HarmonyOS 工具加入 PATH；不会永久改写 PATH。第二条命令执行只读健康检查，任一必需项缺失时返回非零退出码。

doctor 始终返回固定 26 项检查；父级 SDK 路径无效时，相关子项明确标记为 `FAIL`，不会从 JSON 中消失。它同时要求 Java 17 及以上、Android SDK Platform/API 29 及以上、Android Build Tools 29 及以上、HarmonyOS API 12 及以上，并校验外部版本命令的真实退出码。

机器读取可使用：

```powershell
.\scripts\check-dev-environment.ps1 -Json
```

修改环境脚本后运行契约测试：

```powershell
pwsh -NoProfile -File .\tests\dev-environment\doctor-contract.ps1
```

契约测试使用隔离子进程覆盖健康环境、无效 Android/DevEco 路径、失败版本命令、过旧 Java、进程级路径覆盖和缺失 NDK，不会改写用户环境变量或 SDK。

## Windows Core 尖峰验证命令

以下命令从仓库根目录执行，依赖由 `try/windows-core-spike/pnpm-lock.yaml` 与 `src-tauri/Cargo.lock` 锁定：

```powershell
pnpm --dir try/windows-core-spike check
pnpm --dir try/windows-core-spike check:core
pnpm --dir try/windows-core-spike check:full
```

- `check`：快速门禁，运行 unit/component（单元/组件）、TypeScript/Vite 构建、Rust fmt/clippy/tests（格式/静态检查/测试）和敏感扫描。
- `check:core`：在快速门禁后构建并运行原生 Windows Core E2E（端到端）与 5 样本性能门禁，再恢复普通 release（发布构建）并验证隔离。
- `check:full`：在 Core 门禁后增加完整 360-cycle（循环）/至少 30 分钟 soak（长稳）。不得用 `check` 或 `check:core` 替代 L3 长稳。

普通构建最终可执行文件路径：

```text
try/windows-core-spike/src-tauri/target/release/blocky-windows-core-spike.exe
```

WDIO 仅用于测试：Rust 插件只在 Cargo `wdio` feature（特性）启用，前端钩子只在 Vite `wdio` mode（模式）导入，权限只在独立测试配置内存在。验证器在每次原生测试后重建普通版本，并要求 `NORMAL_ISOLATION markers=0 cargo_wdio=0 capability=main`。

完整结果、性能样本和外部临时目录记录见 [Windows Core 技术尖峰报告](../技术设计/Windows-Core技术尖峰报告.md)。

## 下一阶段边界

Windows Core 尖峰已通过 L3 验收。下一步只获准设计正式 monorepo（单体仓库）与共享包职责，并重新评审尖峰临时契约版本；不得把 `try/` 整体复制成产品。正式业务骨架、第二阶段 Windows 完整能力、macOS 对等桌面端以及 Android、HarmonyOS、iOS Agent 使用端仍须分别建立计划与验收，现有系统版本也不直接构成正式发布版本矩阵。
